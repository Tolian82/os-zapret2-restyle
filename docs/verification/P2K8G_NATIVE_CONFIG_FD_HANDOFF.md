# #1052 P2k8g — native original OPNsense Config + queue FD handoff gate

**Source candidate:** `v0.6.5_37`, 14 November 2026. **Real disposable native FreeBSD guest; NOT installed/owner appliance acceptance or activation of Auto-detect.**

## Genuine gap and required observation

P2k8f provided one Python queue-owner → PHP `Config::lock()` → Python original-FD bridge, with Linux process and synthetic PHP Config fixtures. The public source had **no proof that the actual OPNsense `Config::getInstance()` PHP object and its private original config.xml stream survive a native FreeBSD `proc_open` FD mapping**. A child could silently lose the Config lock on `Config::save()` unlocking, or PHP-parent termination could drop the original kernel locks despite the Linux tests.

In the already-qualified existing [P2e/P2g/P2i OPNsense 26.7 VM](../../.github/workflows/p2e-original-shared-build-native.yml), `scripts/test-p2k8g-original-config-native.py --native` now requires **real FreeBSD, EUID 0, GitHub Actions and explicit disposable-native opt-in**. It creates a 0700 temporary test queue under `/tmp`; it does **not** create or alter the product queue, service, native runtime or IPFW. The existing PHP source fixture can select the **real original** `OPNsense\Core\Config::getInstance()` with `require_once('script/load_phalcon.php')`, instead of its synthetic Config stand-in; the unchanged P2k8f callback reads the original Config file handle, revalidates inode and hands it plus the real P2a queue FD through actual PHP `proc_open` FDs 3 and 4 **through the existing qualified `python_runtime.sh` wrapper** (using checkout `compatibility.json` and native `/usr/local/bin/python3`), rather than a test-only direct Python bypass.

## Native evidence-driven ownership correction

The first genuine guest test [run #43541642014](https://github.com/Tolian82/os-zapret2-restyle/actions/runs/43541642014) failed **before acquiring any source locks** with `ORIGINAL_NATIVE_CONFIG_INODE_UNSAFE`, while P2e and P2g passed. A bounded metadata-only rerun [#43541975221](https://github.com/Tolian82/os-zapret2-restyle/actions/runs/43541975221) established the actual isolated OPNsense image has both `/conf` and `/conf/config.xml` owned by **UID 789**, root **GID 0**, directory `0755`, file `0640` and link count 1. The assumption `original Config file == root-owned queue file` was disproven. The test and production P2k8f check now recognize the **original fixed `/conf/config.xml` path** as a distinct native trust boundary: the open descriptor, named inode and parent must have **the same owner UID**, GID **0**, safe owner-controlled permissions, exact path, original dev/inode, and independently contested exclusive flock. **There is no accepted hard-coded UID 789 or arbitrary path and no exception for queue/pending, which remain root-only.** The corrected Config-UID path now reached its **next** native boundary in [run #43542559682](https://github.com/Tolian82/os-zapret2-restyle/actions/runs/43542559682), where the original PHP/Python child refused (`original_config_child_refused`). This is **not a PASS**. The diagnostic candidate invokes the same native PHP Config and qualified Python wrapper under a temporary test-only queue, emits only a fixed exception class/stage and a private child refusal code, and keeps production stderr intentionally suppressed. The next exact-head native run [#43543076144](https://github.com/Tolian82/os-zapret2-restyle/actions/runs/43543076144) got past the Config ownership gate but the direct PHP smoke returned exit 69 **before a child diagnostic marker** (NOT PASS). The test fixture now prints only fixed-name native guard reasons, known PHP exception classes/stages, and private test-child refusal codes, while the public product worker continues discarding stderr. Fifth [native run #43543536132](https://github.com/Tolian82/os-zapret2-restyle/actions/runs/43543536132) confirmed the exact missing gate: **`P2K8G_NATIVE_GUARD_REFUSED=posix`**. The stock OPNsense PHP CLI does not provide the optional POSIX extension. This also previously prevented the P2k8a read-only root CLI from executing on this guest. The shared native PHP class now uses POSIX if present, or direct absolute `/usr/bin/id -u` with an exact `0\n` response, exit zero and verified root-owned non-group-writable executable, never a supplied UID or a shell. The native fixture calls **that same** `nativeRootAllowed()` helper. In a separate test-only command, the fixture uses `/usr/bin/env` to supply **only** its explicit checkout Python policy, interpreter, and private hold/diagnostic marker paths to the original `python_runtime.sh`: production `commitWithInheritedOriginalLocks()` intentionally replaces the child environment with `LC_ALL=C` and is not changed. The exact native result still must pass before merge; the temporary fixture does not activate FD9, a real observer or queue acknowledgment. New native acceptance remains conditional on that corrected exact-head run.

Expected independent, observable test conditions:

- Whole actual `run_original_pending_cycle()` with real PHP Config and original queue lock produces a deliberately **inert, unacknowledged** child receipt; the test pending inode is unchanged.
- After native Config is locked, its **own `unlock()`** is invoked to simulate the effect of `Config::save()` **without calling `save()`** and without writing to the guest's real config.xml; the existing child must refuse an unlocked Config.
- The child writes a private readiness marker only **after independently proving** both queue and Config open-file-description locks. The test SIGKILLs its PHP parent, lets the original Python queue-lock context exit, and observes separate conflicting flock attempts on **both** original inodes fail until the child releases them. When the child exits both locks become available; no pending file is acknowledged.
- Before and after all operations, real `/conf/config.xml` SHA-256, device/inode, size and mtime must be identical. Only disposable test-owned files under private `/tmp` may be created and deleted.

The native fast host guard `--self-test` executes on Linux but must never claim FreeBSD success. The existing VM's P2e/P2g/P2i native original generator/engine proofs are retained, and P2k8g is run **in that one guest** before the pinned dvtws2 build/loopback; there is no second KVM machine or historical full matrix. All scenario failures fail the native job; no manual bypass or skipped-as-PASS.

## Exact qualification boundary

This tests **original OPNsense `Config` lock/FD semantics and the P2k8f real queue→PHP→Python process handoff**. The Model fixture intentionally provides sample YouTube/User/Exclude values, **not the owner GUI's actual Model**, and its Python child returns an **inert checkpoint-shaped receipt**, not a P2k8d destination write. It does **not** authorize a production CLI, start or modify a running engine, enable schema-2 raw/debug observer, initialize known-domain automatic ownership, perform old-generation FD drain/pending ACK, deploy cron/configd, or change WAN/Voice/IPFW/Lab. It cannot be cited as installed appliance acceptance. Future real observer/FD9 and ACK require their independent gates; `commit_authorized=false`.

The exact PR-head/native run and postmerge main CI results are recorded in [Issue #1052](https://github.com/Tolian82/os-zapret2-restyle/issues/1052); no native success is presumed merely because this test exists.
