The one original P2a queue already performs fsynced hardlink+atomic raw cut with 4 MiB strict input and all-PID P2b old pending FD gates. The source native debug reader also strictly refuses files exceeding 4 MiB, but the previous source lacked ANY nonpausing debug high-water cut: at scale, native debug grows until it is unreadable, and a new original raw pending can never be safely prepared. _61 proved in the EXISTING disposable original native P2i/IPFW harness that a hardlinked old debug inode plus atomic replacement can keep known HTTP flowing through the same RUNNING original `dvtws2` PID/birth, whereas the earlier stopped-engine experiment stalled real diverted HTTP. ## One exact original source seam, bounded refusal

- `src/opnsense/scripts/OPNsense/Zapret/backend/auto_detect_original_v2_prepare.py` now performs ONE 2 MiB **high-water**, not 4 MiB overflow detection, inside original held queue and **only when no original P2k8n intent is open**. `_require_debug_window_before_raw_cut` validates unmodified native prefix/cursor (so same-inode tampering cannot be hidden as raw-first). If 2 MiB is exceeded while still under the existing 4 MiB MAX_DEBUG/MAX_WINDOW strict limits, original P2c/FD9 generation/owner and all-PID P2b debug inode FDState.DRAINED are required BEFORE cut.
- Source prepares the next empty root:writer_gid `0660` inode (root-owned `0600` in portable UID fixtures), exact debug parent, same filesystem; fsyncs file + directory. It hardlinks old `debug.log` into one deterministic `.original-debug-retained` protected alias; fsyncs; then `os.replace(prepared, debug.log)` and fsyncs. The live debug path is **never temporarily missing**, and no SIGSTOP/CONT, restart, transport/packet/Config action or new worker is added.
- Source only unlinks an **unpublished empty prepared** inode or an EXTRA retained hardlink when the live old debug is still the exact same two-link inode (crash before replace). It NEVER truncates either original debug or raw; a crash after replace is recognized by separate protected previous/current file identities and all-PID old inode FD drain. Unknown/active historical FD, suspect symlink/wrong inode/gid/mode, incomplete current debug, changed original cursor/owner, or second cut before safe retirement strictly refuses with original pending retained. An old debug inode that continues to grow remains retained and blocks unsafe cleanup.
- The existing original `CursorChain.prepare` detects a changed debug inode and switches the whole authenticated generation to **raw-first UNKNOWN**, preserving the native debug cursor anchor without advancing it. Original Config/P1/PSL/manual exclusions and durable GUI-locked target checkpoint/ACK continue unchanged. Raw and debug are intentionally NOT asserted to be atomically synchronized.
- Any old archive present at next FD9 generation must be qualified/retired first: the strict original `auto_detect_storage._prepare` and `auto_detect_post_drop._check_layout` remain untouched and intentionally refuse foreign producer-layout entries. This increment does not silently permit reuse, migrate/merge legacy archives or delete unknown data.
