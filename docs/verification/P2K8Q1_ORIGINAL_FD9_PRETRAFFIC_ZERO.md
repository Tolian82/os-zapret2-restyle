## Same authority, strict first-launch gate

Use **only** original shared FD9 `apply_runtime_original_launcher_once()`, which already invokes `auto_detect_post_drop.py capture` before `launcher_start_once` and `restore` before IPFW. The source-only native `authorize` remains absent and therefore refuses all live `--hostlist-auto` by default. P2k8q1 extends the **existing** `OriginalProducer._capture` before native launch, not a new CLI, daemon, process owner or second queue.

`DurableInbox.exclusive()` takes the same existing root-only original P2a `worker.lock` to serialize new prelaunch file reads against pending rotation/ACK. Reject a busy/foreign original queue, any retained original pending or unknown pending entry. Validate exact root-owned producer layout and independently open `inbox.txt` + `debug.log` with `O_NOFOLLOW`, matching path/open dev/ino/mtime/size, verified root and named engine group, owner/permissions, **zero actual bytes**, two distinct inodes and unchanged ownership/entry layout. All checks precede one original dvtws2 launch. Do **not** silently clear stale debug/raw or delete an older generation's unacknowledged pending to make startup pass. The checked same original producer inode baton survives native `--user=nobody` and its unchanged P2k8i post-drop root reownership before IPFW; after launch append is allowed, but *a second prelaunch* with nonempty debug/raw is refused.

## Evidence and security boundary

`scripts/test-auto-detect-post-drop.py` now covers real P2a lock contention, nonempty original raw/debug refusal **without truncation**, unacknowledged and foreign pending retention, and legal native append after launch; existing original P2k8i inode and FD9 witness tests remain. The existing single OPNsense 26.7 native P2e/P2g/P2i runner exercises actual root FreeBSD original FD9 and startup/post-drop with a newly created legitimate original queue lock, no additional native VM. **FreeBSD native bug fixed at the P2a owner:** native BSD group inheritance initially created root:nobody-group `worker.lock`, which the already-qualified original FD9 guard rightly rejected. The one canonical `DurableInbox.exclusive()` now uses `O_CREAT|O_EXCL`, corrects the GID of **only the freshly created inode** using the original private pending directory group, fsyncs file+parent and verifies root:root 0600 on the named and inherited original queue FD. An existing malformed lock is never implicitly repaired or migrated; it remains a refusal. The fixture additionally checks exact group/mode/inode reuse across subsequent captured witnesses. Exact-HEAD CI and separate native proof must pass before merge.

**Native acceptance correction:** The first prospective P2g native fixture pre-created `worker.lock` with `Path.touch()`, which on FreeBSD inherited its *parent nobody group*, bypassing canonical P2a creation and correctly triggering `unsafe_original_queue_lock`. The fixture was corrected to have **the actual original `DurableInbox.exclusive()` create** root:root 0600, verify its inode/group/mode, check the dropped `nobody` user cannot read it, and reuse that very same inode. This is not an exception for a foreign existing lock: production and inherited native queue callers both reject mismatched mode/group. Original FD9 P2i after that must still pass its full packet/first-match and cleanup proof.
