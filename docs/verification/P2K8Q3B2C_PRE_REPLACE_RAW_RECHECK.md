# #1052 P2k8q3b2c — original raw hardlink last-boundary recheck

**Source increment:** `v0.6.5_53` (14 November 2026). This is a correction to the **single original P2a DurableInbox.rotate()** on the existing future original Config-held P2k8o/v2 path, not a new source, journal, inspector, lock, producer, worker, parser or Config writer.

## Prior failure and actual correction

The `_51` initial `_stat_regular(inbox, max_size=MAX_SEGMENT)` prevented unlinking a raw file **already** larger than 4 MiB. It did not check what the native engine did **during** the subsequent temp-inode fsync and `os.link(inbox, pending)`/pending-dir fsync. If a writer appended after the first snapshot, `_52` still executed `os.replace(temp, inbox)`: the original linked inode became detached, possibly >4 MiB and permanently refused by the existing P2k1/v2 reader and original P2a ACK. A changed smaller batch could still be coupled with an unqualified debug window.

Before `os.replace()`, the **same** original `rotate()` now performs a fresh `_stat_regular(..., max_size=MAX_SEGMENT)` of both live and linked names under the already-held original queue lock. It requires exact original dev/inode, *two* hardlinks, original file size and mtime on both names; any mismatch raises `QueueSafetyError("raw_changed_between_link_and_replace")`, and >4 MiB raises `oversized_segment`. The originally linked alias remains in `pending` on refusal, the original raw remains named at `inbox.txt` with every byte, and the temporary empty replacement is removed by the unchanged `finally` cleanup. An in-bound, stable same-generation link is then recoverable through the ORIGINAL crash-link path; an oversized inode is retained and refuses future attempts without deletion. One slot, one sequence, one original ownership source. The native writer is **not** serialized by the queue flock: this detects a bounded race, not full lock-free writer quiescence.
