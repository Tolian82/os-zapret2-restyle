# P5b2a — Disposable original native build coordinator (source-only)

**Feature #936 / P5.** Source candidate `v0.6.4_38`; NOT an authenticated public GUI/API action, installed runtime acceptance, or full P5. Stable `v0.6.4_1.pkg` unchanged.

## Reuse, never recreate the native generator

The new import-only `backend/strategy_preview_build.py` accepts a **complete, already model-validated** detached `<opnsense>` XML candidate. This source stage does not generate that XML from a browser request and has no CLI/configd route. A subsequent P5c endpoint must use the original SettingsApply/Config model to prepare an unsaved overlay without saving it.

For production FreeBSD the module refuses non-root callers, injected test callbacks or an absent original FD9 lifecycle owner. It creates a fresh root-only `/tmp/zapret-p5b-<16 random hex>` directory (mode 0700) and writes only `candidate.xml` (0600) there. It invokes the **installed original** `shared_apply_render.render_detached()` with the detached OPNsense Config and original `+TARGETS` registry, targeting `work/templates` rather than `/usr/local/etc/zapret2`. It then sources the SAME backend module list as `zapret_service.sh` in a separate bounded shell process and runs the ORIGINAL:

```text
orchestrator_build_release <work/templates/.../zapret.conf>
                           /usr/local/etc/zapret2
                           /usr/local/etc/zapret2/runtime-v2
                           <work> <work/release> <work/build-stage.status>
                           shared-candidate <work/candidate.xml>
```

The static module list and shell command are **not** built from user text, and this function never invokes the `zapret_service.sh` dispatcher, `shared_apply_run/execute`, `orchestrator_native_start`, `Config::save`, `ipfw add` or any runtime activation. The orchestrator's build-stage status and all generated `dvtws.args`, hostlists, port files and merged Voice candidate live **only** in its disposable work root. The original P5b1 validator checks that prebuilt release and performs mapped validation plus native `dvtws2 --dry-run` when installed.

Timeout kills only the dedicated builder process group. stdout/stderr are discarded to protect candidate Config, domains and arguments. The result never exposes generated argv or private XML. An error or keyboard interruption still triggers work-root removal. The module verifies the original inherited FD9 and a **narrow before/after fingerprint** (SHA-256 of saved `/conf/config.xml`, read-only `ipfw list` and table listing, and active runtime directory identity) on normal, failure and cancellation paths. If the snapshots differ or cleanup fails, it refuses. No Apply journal is written.
