# #1052 P2k8q3e6 — original Config/FD9 partial destination replay with sealed pre-write identities

**Candidate:** source `v0.6.5_65`, 15 November 2026; no `_65.pkg` asset published, no active original schema-2 observer or minute cron.

## Real user-visible defect on _64

The original single queue/Config-held worker prepares a native-debug event and makes an immutable P2k2b plan for **Auto Hostlist and an existing automatic known-list component**. If the first physical Auto Hostlist replacement succeeds but the second known-owned replacement fails (I/O, ENOSPC), the destination plan exists without a checkpoint. An independent native debug inode swap then strands the original pending, even if the original owner/FD is live and safe. Worse, previous before-SHA-only retry could **restore an Auto Hostlist row manually deleted after the first write**, even without debug rotation; the GUI deletion may produce precisely the original before bytes. This is the pre-fix red regression and must never be treated as an acceptable at-least-once duplicate.

## ONE original destination journal, safe recovery

1. The experimental nonactive canonical P2k2b plan becomes schema **2**, not an alternate schema-1 compatibility path or second journal. Before the first physical destination write, existing original `DestinationCommit._locked_commit` records the strict root-owned previous target's **dev/inode/ctime_ns/mtime_ns/size** plus before and after content SHA for each target under the existing shared GUI flock. Plan identity includes the original generation, native-debug or raw-first evidence, pending SHA, cursor end and exact canonical target paths.
2. Every subsequent Config/ACK chain reader validates plan schema, exact keys and per-target identity fields. In the same original queue lock, authentic P2c/FD9 running owner and P2b all-PID pending FD DRAINED remain required, with source pending inode/size/SHA intact and complete native raw names. Once a plan sealed a real native-debug event while its debug inode existed, a later **different protected diagnostic inode** cannot invent a new observation, known HOSTLIST or unplanned positive: current P1 gets the original authenticated raw as UNKNOWN and rechecks all current manual, global and `!` domain exclusions.
3. The original `_validate_partial_plan` forbids replay of effects no longer eligible from current P1 and additionally refuses **new current P1 effects outside the sealed old plan**. The existing original Config-held owner remains sole authorized writer.
4. Before writing **any** missing target, the original GUI-locked writer scans and checks **all** plan destinations. A file equal to its intended `after` SHA is left byte-identical, even if another target failed. A file equal to its `before` SHA may be changed ONLY if current st_dev/st_ino/st_ctime_ns/st_mtime_ns/st_size exactly match the pre-write plan; any GUI atomic update (including deletion that returns bytes to old before hash, or identical-content re-save) changes identity and causes **full refusal without starting another target write**. Any unexpected digest/owner/unsafe symlink also refuses. A previous write interrupted after replace but before checkpoint is therefore replay-safe when its actual contents are still `after`, and a previously untouched target is provably unchanged.
5. After all remaining safe replacements, the same single destination journal creates one original immutable fsynced checkpoint, and original P2a physical pending ACK advances only that intent's already sealed native-debug cursor. No separate recovery receipt, watcher, queue, lock, service signal, IPFW action, fake debug-prefix or second Config writer. A plan with new debug but unproven target identity retains pending.
6. This source increment does NOT by itself implement production debug/raw rotation, finite rollover of the 512-slot original v2 history, original FD9 live schema-2 activation or installed appliance acceptance. A native package build is not a published/testing-installed package.
