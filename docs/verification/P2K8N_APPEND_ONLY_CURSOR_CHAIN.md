# #1052 P2k8n — append-only multi-minute cursor chain (source-only)

**Candidate:** `v0.6.5_44`, 14 November 2026. This is a **dormant source-only** transaction primitive. No enabled observer, cron/configd invocation, original FD9 release mutation, extra engine, installed owner package or Auto-detect acceptance.

## Problem and implemented boundary

The previous P2k2a epoch is an immutable witness of the original **empty** native debug inode. Its single `intent-*.json` and P2k2b `destination/plan.json`/`checkpoint.json` allow exactly **one** first-minute pending/cursor=0, even after pending ACK. Overwriting them, resetting a debug inode or assuming a new generation for the second minute violates durable provenance.

P2k8n adds an explicitly separate `cursor-chain-v2/` subtree **inside the same protected generation folder**, without modifying `epoch.json`. Each monotonically numbered slot (`00000000`, `00000001`, ...) has its own root-private `intent.json`, `destination/plan.json`/`checkpoint.json` and `ack.json`, protected by original P2a queue flock and root-only nofollow/immutable create/fsync. Prepared intent binds exact original P2c generation, original pending dev/inode/content SHA, original debug inode and native P2k1 start/end offset/prefix digest, prior protected ACK hash and `ack_authorized=false`.

`CursorChain.prepare()` requires the genuine current P2c and P2b `FDState.DRAINED` witnesses in the eventual native caller; offline tests inject them. It reads the physically detached original queue inode, verifies exact native debug/raw correlation via `propose_window()`, and refuses historical/mixed pending or a second unacknowledged predecessor. Retrying an already prepared intent checks the pinned **debug prefix** instead of incorrectly requiring the entire growing debug file to remain identical. `CursorChain.commit()` reuses the existing **real** P2k2b `DestinationCommit._locked_commit()` under its common GUI destination flock with strict P2k2b CAS and post-write checkpoint; P1 effects still require a future real PHP Config-locked original source and are not manufactured here. `CursorChain.acknowledge()` checks the exact original child checkpoint and immutable plan, re-attests current owner, independent old inode FD `DRAINED`, durable debug prefix, then delegates to existing P2a inode-safe unlink/fsync **before** writing the slot's append-only `ack.json`. A crash after physical unlink but before ACK receipt can finish that marker if the exact same original generation and checkpoint are attested again, without rerunning target edits. The next debug cursor is derived only from this durable prior ACK. No checkpoint or detached receipt alone is an independent ACK permit.

`EpochReceipts` still exposes earlier v1 methods needed by not-yet-replaced original PHP Config-held single-segment code, but v2 **rejects** all older one-intent states, rather than migrating or reading them as a fallback. The obsolete P2k8m rotation module/test/CI were removed under DEV-050 in `_45`, and [P2k8o](P2K8O_ORIGINAL_QUEUE_V2_PREPARE.md) is the one selected forward-only original raw→v2 prepared-intent path. Completing the v2 original PHP child must retire its older one-intent writer/ACK APIs and tests in the same replacement scope. No migration, cleanup or import of the obsolete `zapret-hosts-auto.txt` is introduced.

## Focused evidence

`scripts/test-auto-detect-cursor-chain.py` executes 15 **physical** filesystem scenarios, including two sequential minutes against one original debug inode, per-slot destination write and ACK, busy/unknown P2b FD, debug append after prepare, old-generation pending retention, checkpoint/cursor corruption, retry without undoing a manual GUI edit, crash between physical pending unlink and ACK journal, legacy/v2 coexistence refusal and no public native worker. The original P2c owner and P2b FD are **injected test witnesses**, never a claim of actual running OPNsense dvtws2 or PHP Config owner. Exact-head source/CI qualification must be recorded independently.

## Remaining production gates

The v2 chain **does not yet connect** to P2k8m native raw rotation, P2k8l original PHP Config-held P1 decision, or the installed `auto_detect_minute.py`. Original FD9 has not sealed/activated an actual schema-2 observer or created a trustworthy initial zero-debug epoch before traffic; historical generations still require independent FD/process/debug evidence. **Finite capacity** (512 immutable slots per generation) and P2k1's bounded debug log require an explicit safe compaction/rollover and recovery protocol before continual 60-second scheduling. The source-only P2k8n proof is NOT a live native working Auto-detect, published `_44.pkg`, or owner-installed acceptance. Preserve one dvtws2, shared Apply/Config/FD9, explicit-only `<HOSTLIST:auto>`, GUI edits and Strategy Lab.
