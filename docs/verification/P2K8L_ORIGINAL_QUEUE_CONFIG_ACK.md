# #1052 P2k8l — held original queue → original Config child → guarded ACK

**Candidate:** `v0.6.5_42` (14 November 2026). Source-only continuation of P2k8k; no cron, native observer, installed package or user-appliance acceptance.

The original `run_original_pending_cycle()` used P2a `DurableInbox.exclusive()` and held its original queue file descriptor during PHP `Config::lock()` and a child that performs P2k8d/P2k2b commit. It then returned the child JSON **after releasing the original queue lock**, so passing that result later to P2k8k could not guarantee a single original owner across transaction and ACK.

P2k8l extracts the same original subprocess path into `_original_completion_locked()`; the old import-only `run_original_pending_cycle()` preserves its previous unacknowledged behavior. The new `_original_commit_then_ack_locked()` first re-attests the current P2c generation and native observer binding for the exact generation-prefixed pending, runs the unchanged original queue-FD → PHP Config-locked Model → Python P1/P2k2b child, re-attests that same owner and passes the actual child result to the P2k8k protected checkpoint + P2b FD-drain + P2a inode-safe unlink **before releasing the original queue flock**.

`run_native_original_pending_ack_once(pending_name)` is a dormant import-only native boundary restricted to FreeBSD root, strict generation-qualified pending basename, fixed original queue, actual PHP Config and native target paths, original real P2c/P2b default attestations, and a 25-second outer PHP timeout. There is no CLI path to call it, no configd command that references it, no cron entry, no new daemon and no writer for `config.xml`.

The focused offline test reuses the real P2k2a/P2k2b physical-file fixture. It supplies only a controlled test-only completion in place of the original PHP subprocess, while existing `scripts/test-auto-detect-original-lock-handoff.py` and native P2k8g retain their independently qualified real PHP/Config original descriptor proof. Success requires an original exclusive queue lock across physical destination commit, second owner reattestation, P2b `DRAINED` and actual inode removal. Busy/unknown FD, changed process, malformed/failed PHP child, mismatched generation and crash-after-destination-before-ACK retain pending; repeated genuine completion can finish ACK without duplicate target inserts. Such test fixtures do **not** claim real installed end-to-end collection.

**Open:** no active sealed schema-2 observer generation has been issued on the user's appliance; old-generation FD/debug replay, real native pending rotation/epoch staging, actual worker dispatch, cron interval, and FD9 observer authorization remain incomplete. The obsolete `zapret-hosts-auto.txt` is never imported.
