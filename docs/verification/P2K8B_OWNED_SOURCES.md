# #1052 P2k8b — root-private known-HOSTLIST auto-owned sources and single-file-lock read

**Source candidate:** `v0.6.5_32`, 13 November 2026. **Dormant, unregistered, nonactivating P2/P3 prerequisite.** No original FD9 caller, collector, destination update, pending acknowledgment, cron, new Config writer or user-installed package.

## Observed gap, pre-change failure and concrete user path

The previous P2k8a native PHP reader provides the genuine original OPNsense Config's `hostlist.youtubedomains`, `hostlist.userdomains`, `hostlist.excludedomains` and a root-locked editable `auto-domains.txt` final snapshot. It correctly reports `auto_owned_components=null`; no separate, authenticated storage for known-HOSTLIST automatic rows exists. A future background writer cannot safely infer ownership from manually edited YouTube/User fields or from the `auto-domains.txt` contents; it must not remove manual rows on relocation. Making up `auto_owned_components={}` would suppress known previous ownership and enable unsafe policy decisions.

The changed path is now **native PHP `Config::lock()` → one root-only Python CLI read → the same P2k4/P2k5 final-file flock → final `auto-domains.txt` + root-private known-owned components**. The lock surrounds **both** file-source reads; it remains acquired by native PHP throughout. Nothing in this read-only path enters Config::save(), shared FD9 Apply or P2k4's destination writer. It is still **not** a transaction-scoped Config lock for writes.

## Implemented primitive

`backend/auto_detect_owned_sources.py` introduces a checked, canonical, **root-only** ownership source directory at `/var/db/zapret2/auto-detect-owned`, behind the existing root-private `/var/db/zapret2` parent. It has only three files: `manifest.json`, `youtube.txt`, `user.txt`. The private directory is `0700` and files are `0600`, root-owned, single link, no symlink. The manifest pins schema, the exact two registered *known* HOSTLIST identities and the original Config digest from an explicitly authorized clean bootstrap. Neither IPSET nor `auto` final file is part of this private directory. No old `zapret-hosts-auto.txt` path is used.

`read_owned()` is strictly read-only; it distinguishes **missing/uninitialized, including a not-yet-created parent on first install** (returns `None`, never `{}`), a fully sealed canonical source set (returns both known names, possibly with empty strings) and **partial/foreign/unsafe/corrupt** storage (refuses). Plain, canonical, bounded domain rows only: duplicates, noncanonical case, `!/^` modifiers, invalid IDNA, symlinks, group/world modes and changed FDs refuse. A trusted original native Config+FD9 owner can eventually call the *library-only* `bootstrap_empty(..., authorized_clean_start=True, original_config_sha256=...)`, but **no CLI/configd/installer/starter calls it in this increment**. The boolean is an explicit internal gate, **not itself a proof of clean native ownership**; the real original owner, original Config lock and no prior worker data must still be proven before invoking it. On a crash after partial initialization, later reads refuse rather than silently reinitialize or erase files.

The new root-only `read` CLI takes the **existing destination lock once** across reading the final Auto HOSTLIST and the separate known auto-owned components. It uses the existing P2k5 file reader and revision digest, returns `auto_owned_components:null/auto_owned_complete:false` until a qualified bootstrap is performed, and returns both canonical sources only after a completed trusted seed. No worker writes or ACK are authorized. The existing P2k8a native PHP CLI uses this reader in place of the single-file reader while holding **one native Config lock**, validates the complete two-component shape and types and increases the bounded private response cap to 150k. It continues to emit `status=read_only_unqualified`, `commit_authorized=false` regardless of whether the explicit empty seed exists. No GUI/configd action, profile generator, reload or scheduled task was changed.

**Do not claim live provenance from a PHP snapshot alone:** this source-only store gives separate physical ownership, not authenticated *increments*. A future P2k8c must bind each automatic addition/removal to the original generation, verified P2k2b immutable destination receipt and a durable write/ownership record; it must integrate the known components with native generator output and hold native Config ownership **through the entire P2k4 P1 decision + destination transaction**. Native `Config::save()` itself releases the lock and must not be treated as a persistent cross-operation lock. A standalone `bootstrap_empty(True)` is never sufficient as P2k4 write authorization.

## Minimal acceptance / proof limits

The new `scripts/test-auto-detect-owned-sources.py` checks actual filesystem modes, first-install absent-parent handling, absent-vs-sealed ownership, explicit seed and repeated/unauthorized seed refusal, component isolation, symlinks, invalid modes, incomplete/foreign manifest and noncanonical domain text, GUI file-lock collision and the disabled native bootstrap command. The P2k8a PHP test now additionally checks **both** uninitialized and complete two-component native returns and rejects malformed ownership shapes, retaining original Config lock and no-save assertions. Existing P2k4/P2k5 tests and CI version/links/package gates remain.

Local S0 uses a dependency stand-in for the already-qualified existing writer/normalizer and a digest stand-in for the OPNsense model; **exact-head CI runs these tests with the actual repository modules and original digest/registry**. Both are source/CI evidence only, not owner-appliance acceptance. A CI package artifact is not a published `_32.pkg`. Existing installed stable `_1.pkg` is unchanged.
