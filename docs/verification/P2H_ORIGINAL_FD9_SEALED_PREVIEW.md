# #1052 P2h — sealed original FD9 observer preview, never native collection

**Scope:** `v0.6.5_19` source, **not a published .pkg or an installed/live observer**.

## The original lifecycle constraint

The genuine shared Apply path in `zapret_service.sh` runs **original** `orchestrator_build_release` → native PHP model `preflight` → release-mode finalize → single `shared_apply_bundle_service seal` → repeated native PHP preflight → read-only runtime probe → journal/kernel/Config transaction. Altering `dvtws.args` *after* the existing seal would invalidate the whole release and rollback contract. Introducing a second FD9 owner, Config parser or service is forbidden.

The P2f planner already proves the candidate original-source map and final native profile numbering; P2g already established a `nobody`-compatible producer namespace, but that alone does **not** provide the pending durability, replay and writer-FD/process/debug correlation needed to enable recording. Starting `--hostlist-auto` before the 60-second worker is available could fill the raw inbox indefinitely; truncation/age deletion is explicitly forbidden. We therefore **do not activate native discovery at P2h**.

## Concrete production path

In the **existing** `shared_apply_prepare_service`, immediately after the original common candidate builder emits the P2d source map and before the original seal, the same native `shared_apply_config.php preflight` returns the authentic candidate SHA. For enabled Auto Target Mode, `backend/auto_detect_origin_map.py preview` reconstructs the P0-qualified trailing no-action observer from the exact same-build source map, Voice/Extra ancestry, final original argv and TCP ports. It serializes only the following inert, sealed release artifacts:

- `auto-detect-observer-preview.args` — augmented future native argv, **not** `dvtws.args`;
- `auto-detect-observer-preview.json` — schema-2-shaped metadata with `P2H_ORIGINAL_FD9_SEALED_PREVIEW_NONACTIVATING` and `activation_authorized=false`.

Both bytes are included in the **existing single release seal** and checked via `verify-preview` after the repeated native PHP preflight and **before** any existing journal/engine/IPFW/Config mutation. The verifier reconstructs the future argv and attribution from the preserved original `dvtws.args` and P2d map, checks exact candidate digest, rejects stale/mutated metadata/argv and confirms that the actual P2c authorized-generation validator **refuses** the inert preview. There is deliberately no `auto-detect-generation.json`, no real `--hostlist-auto` or `--hostlist-auto-debug` option in the running engine argv, and no external file/queue provisioning in this increment. For disabled service or absent source capture, the original existing path remains nonactivating.

The preview CLI is restricted to the original FreeBSD root FD9 owner; no independent worker action or public API is installed. Its Python internal function is testable against a disposable same-generation original-builder workspace.

## Targeted proof and strict limits

The existing P2e original-builder fixture adds original-generation/Voice provenance, exact source digest, preview refusal by P2c, no-action live argv unchanged, modified preview/digest refusal and FD9-before-seal/hook-before-kernel ordering. Its already used disposable OPNsense/FreeBSD workflow is reused; ordinary changed-path CI covers Project/Voice and native `.pkg` compilation. Only actual exact-head CI outcomes count.

P2h does **not** establish real native `dvtws2 --dry-run` acceptance of the proposed argv, traffic first-match/raw+debug append using the protected production storage, committed owner process birth/FD, an authorized live schema-2, durable worker ack, periodic configd/cron, P3 destination ownership or owner-installed acceptance. These remain P2/P3–P5 requirements. **Do not publish/activate a package merely because a source-only preview passes.**
