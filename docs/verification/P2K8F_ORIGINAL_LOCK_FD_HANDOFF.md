# #1052 P2k8f — original P2a queue and native Config locked-FD handoff

**Source candidate:** `v0.6.5_36`, 14 November 2026. **Not registered in cron/configd and not an installed or owner-accepted native Auto-detect.** Existing published owner-installed stable package remains `0.6.5_1.pkg`; no `_36.pkg` published.

## Actual previous failure and changed source path

P2k8e could synchronously hold a PHP native `Config::lock()` around a P2k8d destination operation, but no queue-owning process could invoke that PHP operation while preserving the **same** original P2a `DurableInbox.exclusive()` lock in its Python child. A Python child calling `queue.exclusive()` a second time blocks itself (queue lock inversion), while merely passing a model tuple cannot prove Config remained locked at commit time.

P2k8f provides one real call chain under exact, existing file locks:

1. `auto_detect_original_lock_handoff.py::run_original_pending_cycle()` acquires the **actual existing** P2a queue lock, validates a same-generation-shaped pending segment, and synchronously starts the original native PHP Config class with that **same locked queue file descriptor** inherited (no second independent queue lock).
2. `AutoDetectConfigSnapshot::commitWithInheritedOriginalLocks()` executes within P2k8e's **original OPNsense Config::lock()** and fresh original MVC Model, reads the current original private `config_file_handle` and file path, matches the original config.xml inode, then passes the actual already-locked queue and Config stream handles to the fixed Python child through `proc_open` descriptors 3 and 4. `Config::save()` is never called; PHP waits for the Python result before unlocking Config, revalidates the original Model and accepts only unacknowledged durable checkpoints.
3. The child resolves the native engine group through P2g's original `auto_detect_storage.ENGINE_USER` and `pwd.getpwnam(...).pw_gid`, not a guessed same-named group. `DurableInbox.inherited_exclusive()` and `inherited_original_locks()` validate original parent inode/owner/mode/nlink and independently probe conflicting queue/Config flock; an unrelated or unlocked FD is rejected before P1/destination writes. This same-open-file-description handoff holds a kernel lock even if the parent PHP process exits while the child is active. There is no secondary queue lock, Config writer or competing durable receipt. The **existing P2k8d/P2k2b** transaction then runs under the established destination GUI flock, actual original pending FD/debug and P1 policy. All completions preserve `ack_authorized=false` and the original pending inode.
4. The native Python `commit-fds` child is root/FreeBSD-only, has no injected native attester, and reads only the complete size-bounded original Model payload. Without authentic original sealed schema-2 FD9 process/epoch evidence, it refuses; no cron or registered worker can invoke it.

The direct `php://fd` and `proc_open` mapping is needed because native OPNsense `Config::lock()` uses an exclusive `flock` on the **open config.xml inode**, while `Config::save()` explicitly releases it. Locking a guessed second file or releasing between native read/P1/P2k2b is invalid. The native Config handle is obtained from the original `Config` instance, not by a new Config parser; the private-property shape must be qualified on the actual target OPNsense version before activation.

## Bounded verification and gates

The added `scripts/test-auto-detect-original-lock-handoff.py` and companion `.php` fixture cover real **Python queue → PHP Config flock → Python proc_open child** processes, the original P2a queue mutex, source Model payload, retained pending, and independent negative cases: unlocked queue, foreign queue FD, unlocked Config (as if `Config::save()` prematurely released it), incorrect Config inode, and disabled native CLI. The Python child produces an **inert checkpoint-shaped fixture**; existing P2k8d/P2k2b tests separately exercise actual source→physical destination writes with synthetic owner/FD proof. This is **portable source and OS process evidence**, not a native FreeBSD `dvtws2`/Config acceptance. The focused test is added to the existing fast affected P2k4 CI step; no separate broad VM/legacy workflow is introduced. Exact-head results will be recorded with Issue #1052.

**Remaining before activation:** actual OPNsense/FreeBSD native proc-open/Config handle/inherited flock and parent-death qualification; original shared FD9 authorized schema-2 observer with post-`--user=nobody` raw inode repair before IPFW; authentic known-list new-origin evidence; old-generation pending FD and durable checkpoint ACK; bounded 60-second cron→configd worker; real installed runtime/GUI verification. No automatic restart, manual Config writer, Strategy Lab, Voice, WAN, IPFW or published package change.
