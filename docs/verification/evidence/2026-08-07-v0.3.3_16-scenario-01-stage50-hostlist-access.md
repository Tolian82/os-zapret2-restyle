## Candidate runtime evidence

Unlike the earlier stage-50 aborts, `_16` created the complete candidate-runtime working
set. DNS resolution succeeded and selected IPv4 `104.21.32.39`; the temporary binding was
recorded for rule 19100; the candidate arguments selected divert port 9989, TLS/443, the
job-owned hostlist, and the multisplit smoke strategy.

The decisive dvtws2 log is:

```text

Loaded 1 hosts from /var/run/zapret2-restyle/strategy-lab/jobs/job.VmWk32/candidate-runtime/hostlist.txt

```

This proves that the `_16` asynchronous daemon correction works far enough for dvtws2 to
start, load the hostlist initially, bind the candidate divert socket, and drop privileges
to `nobody`. The process then fails when its post-drop file-access check reopens the same
hostlist path.

The hostlist itself is created as mode 0644 by Strategy Lab. The remaining access boundary
is directory traversal: the launcher creates each random job directory with `mktemp -d`,
which is private, while the hostlist is nested below that directory. A mode-0644 file is
therefore still inaccessible to the post-drop `nobody` process when a parent job directory
does not grant search permission.

`readiness.json` after the failure recorded:

```json
{"pid":null,"process_identity":false,"socket_ready":false,"log_clean":true,"stable":false,"ready":false}
```

The missing PID/socket are consistent with dvtws2 exiting after the permission error.

## Corrective scope for `_17`

The job directory must remain private outside temporary candidate execution, while a
hostlist-backed candidate is allowed only the minimum directory traversal needed after
`--user=nobody` takes effect. `_17` therefore uses a bounded access lease:

1. the random job directory remains mode 0700 by default;
2. immediately before a hostlist-backed dvtws2 candidate starts, its job directory becomes
   search-only for non-owner users (0711) and candidate-runtime remains traversable;
3. the hostlist remains read-only data (0644);
4. every candidate cleanup path restores the job directory to 0700 after dvtws2 stops;
5. the regression starts with a private job directory, models post-drop access as a
   non-owner/non-group process, requires the candidate to run, and proves the job directory
   is private again after cleanup.

This does not make the complete job tree generally listable and does not weaken the normal
long-lived job privacy state.
