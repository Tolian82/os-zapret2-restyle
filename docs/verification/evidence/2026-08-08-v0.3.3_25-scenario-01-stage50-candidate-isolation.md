## Source diagnosis

The Python candidate owner writes a structured JSON result even when an individual
candidate encounters a candidate-local runtime/error condition. The compatibility
`strategy_lab_candidate_runner.sh` returns status 1 when that JSON contains `"error":true`.

Before corrective `_26`, `strategy_lab_py/family.py` treated every nonzero candidate-runner
status as a fatal Stage-50 exception *before reading the candidate JSON*. This made one
candidate-local error abort the entire family catalog, discard continuation after an
already accepted family, and surface the generic Stage-50 internal-error message.

Correct behavior is:

- timeout remains a rejected candidate and screening continues;
- a nonzero runner status accompanied by a fresh, valid structured candidate result with
  `error:true` is also a rejected candidate and screening continues;
- only missing/invalid structured evidence, runner launch failure, cancellation, or another
  true screening/system failure may abort Stage 50.

Corrective source candidate `_26` implements and regression-tests that boundary.
