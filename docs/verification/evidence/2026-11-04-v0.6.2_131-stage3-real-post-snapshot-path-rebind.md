## Exact native attack-and-defense scenario

1. Build unchanged official Mk successor native `0.6.2_131.pkg`, preload real target-OPNsense dependencies, install immutable authentic old `0.6.2_1.pkg` with original four manual hooks and qualify STOPPED/foreign Config/IPFW/pkgdb exactly as prior _130.
2. The only detached worker receives **original** FD9 by `configd -> SCM_RIGHTS`; configd restarts while worker stays the same PID and original lock inode. Existing same-runner CI-only RSA signed operator grant is checked TWICE and the product candidate gate hashes actual archive. Still **not owner-approved trust**.
3. Worker opens one root-owned regular one-link official archive inode, reads exact bytes (≤512 MiB), independently verifies SHA against signed selected digest, then publishes private root-only READY marker `frozen_snapshot_complete=true` with exact project head/PID/original FD9 inode/nonce digest/frozen SHA/original candidate inode. **Only at this barrier, BEFORE any pkg invocation**, controller may act.
4. Controller validates READY is from authentic worker and original FD9 remains exclusively busy. It creates an independent root-only new archive inode with exactly one flipped byte (same file length; different SHA), keeps old inode at a test-owned same-directory single private link, and atomically `os.replace`-rebinds the **same candidate pathname** to attacker inode. Requires new inode != old inode and actual active candidate SHA != approved SHA. No in-place modification masquerading as path race. It must not call pkg or close FD9.
5. Controller releases worker. Worker must observe the forged pathname inode/digest **before** native pkg, run final old-owner gate again under same original FD9, feed *only frozen bytes* to real native `pkg ... add -f -` via stdin and require true historical hook delegated lock calls. After real pkg returns 0, the forged pathname must still show changed inode/SHA.
6. Worker writes the original frozen archive bytes to an exclusive private root-only manifest reference and checks its SHA matches signed digest. Compare **installed real pkgdb identity/real dependency graph/four original native manual hooks/all actual files/modes** against the frozen reference, not the forged pathname. Require new cold Status, preserved unrelated Config, no unrelated kernel owner changes and continuously held original FD9. No fake `pkg`, no disabled hooks or dependency ignore. A failed native pkg remains UNKNOWN/FAIL.
7. Controller validates the positive native DONE/GRANT result, actual forged-path digest/inode matching attack witness, original package file verification, old hook FD9 marker, then restores the original pathname using precisely saved original inode **only after full positive proof**. It subsequently verifies original archive SHA and regular existing cleanup and no foreign changes. On unknown worker or pkg failure do not claim safe rollback; disposable VM fails.
8. Existing _127/_128/_129 negative tamper and _130 positive stdin jobs remain mandatory in parallel with new dedicated genuine OPNsense 26.7 path-rebind job. One CLI-only source helper provides atomic swap/restoration; no installed product, hooks or stable package changes.
