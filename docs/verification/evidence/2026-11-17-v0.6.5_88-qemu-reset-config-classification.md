## One-test separation of native Config flush from mid-pkg crash

The prior disposable test saved new Config seconds before non-graceful `system_reset`. The correction changes **only the disposable fixture**: after the real native `configctl` Apply returns, open the existing saved `/conf/config.xml` without following symlinks, share-lock, `fsync` that same inode, verify same owner-visible bytes/metadata, close. It does not write XML, introduce a second Config writer, forge ownership or guarantee that native pkg hooks won't change Config later. A separate unsynced native Config crash remains OPEN until qualified; do not misreport this as a general product fix.

The test's original protected package archive lives in the native `prepared.stage` under root-only `/var/db/zapret2/pkg-update`, not the disposable worktree `dist/` (which is re-synced by the VM action). After QEMU reset, protected stage digest + guard + owner retirement + Config preservation + zero physical `dvtws2` must all hold.
