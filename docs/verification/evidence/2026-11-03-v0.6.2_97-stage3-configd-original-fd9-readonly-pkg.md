[_95 original FD9 native handoff](2026-11-03-v0.6.2_95-stage3-original-fd9-scm-rights-handoff.md) proved the true configd launcher takes and holds the existing `/var/run/zapret2-lifecycle.lock` before transferring the same locked file description by `SCM_RIGHTS` to a detached FreeBSD root worker; the worker survives actual configd restart. [_96 genuine crash/ACK negatives](2026-11-03-v0.6.2_96-stage3-configd-fd9-ack-fault-matrix.md) proved that a zero configctl return and provisional ACK alone are not durable FD9 ownership. Neither proved that an actual native `pkg` command runs while the transferred worker continues holding that original FD9.

This increment extends the existing **one-use test worker** with a separately guarded read-only command. After authentic root-owned READY, the detached worker verifies historical original FD9 and old STOPPED owner, executes exactly `/usr/sbin/pkg -o REPO_AUTOUPDATE=false query %n|%v os-zapret2-restyle`, requires exit 0 and exact `os-zapret2-restyle|0.6.2_1`, and checks the same original FD9/cold owner again. It writes a root-owned 0600 query attestation with exact source SHA, nonce hash, PID and original FD9 inode and `native_mutating_pkg_invoked=false`. **Only after a successful query/second owner check is ACK sent.**

The caller reads the attestation and requires exact original worker PID, nonce, original inode and SHA, independent `lockf` BUSY after the launcher returned and again after *real configd restart*, unchanged authentic old package pkgdb/files/modes, Config bytes, markers, owned process inventory and IPFW, cooperative worker release, and owned-only one-use cleanup. On missing/incorrect query or lock/attestation mismatch the operation refuses. There is no package replacement or new actual lifecycle manager, and the original lock path is never changed.
