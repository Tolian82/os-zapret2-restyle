## Timing and resource comparison with Model A

The accepted Model A cold reference on the same retained workload recorded these medians across 25 samples:

- total cold candidate: `1580 ms`;
- readiness: `1046 ms`;
- probe: `220 ms`;
- RSS: `4332 KiB` median per candidate process.

The `_16` Model B accepted run records:

- three-worker pool startup: `1162 ms` total;
- dispatch median: `12.0 ms`;
- probe median: `200.5 ms`;
- per-worker RSS: `4320`, `4320`, and `4324 KiB`;
- aggregate warm-pool RSS: `12964 KiB`.

The per-worker RSS is essentially the same as the Model A cold-process RSS, while keeping three workers warm costs about three times one candidate process in aggregate memory. The steady warm dispatch-plus-probe median is about `212.5 ms` after pool readiness versus the `1580 ms` Model A cold total-candidate median.

A simple three-candidate amortization using only the metrics actually retained by both reports gives approximately `1162 + 3 * (12 + 200.5) = 1799.5 ms`, or about `600 ms` per candidate, compared with about `4740 ms` for three Model A candidates at the cold median. This is a roughly 62% lower amortized estimate for that narrow comparison.

This is **suggestive performance evidence, not yet a production performance decision**. The current Model B report does not retain one directly comparable full-corpus wall-clock metric and this is one owner-live run rather than a repeated distribution. Route deletion, final pool cleanup/restoration, candidate mix, timeout-heavy failures, and run-to-run variance must remain part of the later model-selection decision.

## Architectural conclusion

Model B has now passed its planned owner-live coexistence gate on the accepted Model A reference workload. Correctness, isolation, deterministic attribution, independent stop/death behavior, numeric RSS collection, and semantic restoration all passed on the live OPNsense appliance.

The measurements also show a potentially material warm-path latency reduction at the cost of approximately linear aggregate RSS for three resident workers. That performance signal is strong enough to continue Model B evaluation, but one accepted run and the current timing schema are not sufficient to approve the warm-worker architecture for production Strategy Lab use.

The separately confirmed failure-control defect remains open: when a future Model B run has `all_workers_ready=false`, the current implementation continues into route/probe/stop/death work instead of failing immediately at the readiness boundary. That corrective remains the next separate logical patch before any production-approval decision.
