# Stage 2.23 — Genuine installed package lock versus unsafe native replacement

**Candidate:** v0.6.2_76 (source-only). **Real native execution pending.** This is NOT LH-08 or AC-11 product acceptance, not an installable release, and not a managed upgrade implementation.

## Hypothesis and scenario

Prior [real native _74 experiment](2026-11-02-v0.6.2_74-stage2-real-unsafe-owner-native-pkg.md) confirmed that a genuine old service Status=2 and refusing incoming PRE_INSTALL do **not** prevent a real unprotected `pkg add -f` from installing its successor and changing Config bytes. Earlier Stage 0 [synthetic package lock proof](2026-11-01-v0.6.2_41-native-firmware-and-pkg-lock.md) tested a private fixture rather than the real installed Zapret2 package.

This increment qualifies the actual published 0.6.2_1, on disposable OPNsense 26.7 KVM, with a **real native metadata `pkg lock`** in place under the same orphaned managed-range `ipfw 19000 divert 989 tcp/65431 out via lo0` negative condition. Build an exact native 0.6.2_76 successor before installing the old package; verify its package SHA-256. Install and authenticate the old archive, verify cold status, then add only the test-owned kernel rule after safe default-accept preparation. Require authentic installed service Status=2, lock the real original package, verify lock-l output, issue actual `pkg add -f` using the native successor and compare before/after pkgdb raw record, installed version, service SHA, Config bytes, restart-marker absence, exact IPFW rule and successor archive SHA. Log the result before test-owned-rule cleanup; never unlock. A replaced/changed package must mark the experiment FAILED, not be recast as evidence of safety. No packet traffic, WAN or device operation.

The [official OPNsense firmware source-route audit](2026-11-01-v0.6.2_48-stage0-firmware-route-admission-boundary.md) is re-run **read-only**; stock firmware install/remove/reinstall/upgrade/unlock routes are not plugin FD9-aware. Only the measured locked `pkg add -f` case can pass. A privileged root can explicitly unlock, and **lock does not cover admission-to-pkg races or installed GUI updates**. Even with a PASS, **LH-08/AC-11 remain BLOCKED**: no protected supported OPNsense package-upgrade entrypoint is established.
