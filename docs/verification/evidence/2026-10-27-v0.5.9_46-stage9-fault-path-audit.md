## Source-confirmed uncovered failure mode (OPEN)

**Scenario:** a previous cache shows `installed=true` and 25 Lua/100 BIN. Native Remove successfully commits leaving only upstream 6/46, but `extra_resources_inventory_cache.refresh()` fails (invalid destination/staging path, write error, or generated-cache refusal). In `extra_resources_operation.py`, `_refresh_help_cache()` catches the failure and only prints `WARNING`, while the normal caller records terminal `not_installed`. `extra_resources_inventory_cache.read_cached()` validates the prior JSON but does not check its agreement with the new resource generation or receipt. The API `resourcesInventoryAction()` accepts well-formed prior data as `status=ok`; Full Help can therefore render *stale installed extras* after a successful Remove. The reverse mismatch is possible after successful Install when stale cache still says `installed=false`.

This is grounded in the **actual production call path**. The existing `test_modified_tracked_files_and_drift_fail_closed` asserts that old atomic cache remains readable after a failed **non-mutating** refresh; that behavior is not sufficient once a real transaction changes files. The owner's successful R6–R9 runs **did not encounter** this error and their acceptance remains valid. There is no claim of a reproduced installed-device outage.

**Required narrow repair:** avoid any second Git scanner/catalog and do not change transactional Stop→Apply/Start, native owner, Config/Voice, or IPFW. Make outdated cache **unavailable rather than `status=ok`** after a resource-set mutation when a fresh cache cannot be published. Preserve last-good cache only for a failed *non-mutating* refresh. Introduce a focused **executed** fault-injection test of the actual changed functions proving both Remove and Install directions, with failure after the resource-state change, plus rollback/recovery and cache safety. Run local fast test/syntax checks before PR/full Project/Voice/FreeBSD15 CI; a new packaged source candidate must use the existing immutable GitHub testing-package delivery process. A successful cache refresh must keep today's owner-proven behavior unchanged.
