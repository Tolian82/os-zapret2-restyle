However root can remove the last complete record: the remaining local hash-chain may be completely self-consistent and report an earlier sequence. ## Essential honest negative: no external monotonic storage means no production protection

Native disposable CI generates a THIRD independent ephemeral RSA key, distinct from operator approval signer and package-provenance signer. It signs a checkpoint at sequence 2 and pins the exact SHA. Deleting the last local spent entry produces a **valid** local ledger of length 1; the unchanged pinned sequence-2 checkpoint MUST REFUSE (WITNESS_LEDGER_SEQUENCE_OR_HEAD_ROLLBACK).

Then CI deliberately creates an earlier correctly signed sequence-1 checkpoint and substitutes BOTH its old snapshot bytes AND its matching expected SHA. On the rolled-back sequence-1 ledger this combination **can PASS**, but must report checkpoint_out_of_band_latest_authenticated=false and root_rollback_resistance_proven=false. Keeping the actual latest sequence-2 externally pinned SHA instead MUST refuse (WITNESS_LATEST_CHECKPOINT_SHA_MISMATCH).

This is an intentional demonstration of an UNSOLVED ATTACK, not successful production anti-rollback. RSA proves possession of the test signing key, not approved issuer identity; because key and expected latest digest originate on the same VM, CI does not establish independent latest evidence. With local-root authority an attacker can restore the entire old ledger and old signature/expected digest. A genuine owner-approved, independent monotonically witnessed latest checksum is an unresolved prerequisite. There is no online witness service, independently provisioned owner signing identity, trusted time or trustworthy external store.
