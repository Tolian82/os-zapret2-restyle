## Pinned upstream and observed production-entrypoint mismatch

Official `opnsense/plugins` **stable/26.7** SHA `79a5f88b7b27a706c10511ea5587c9d0e0dbdced` (checked on 2 November 2026) supplies `Mk/plugins.mk`, `Mk/defaults.mk`, `Mk/common.mk`, `Scripts/` and `Templates/`. Its production `package` target creates `+MANIFEST`, `plist`, carries four authoritative `+PRE_INSTALL`, `+POST_INSTALL`, `+PRE_DEINSTALL`, `+POST_DEINSTALL` via `scripts-manual` overriding auto-hooks, and resolves `pkg query %n/%o/%v` of real installed OPNsense providers. `PLUGIN_PYTHON` is derived from real `/usr/local/bin/python3 -V` and generic Python must be OPNsense-owned. Only the project Makefile should provide the project's `PLUGIN_HASH`/website identity, independent of upstream.

The **current product builder** `scripts/build-pkg.sh` still bypasses `Mk/plugins.mk` and manually writes fake `version=0` dependency metadata and chmods all staged `*.sh`. The tracked `src/opnsense/scripts/OPNsense/Zapret/zapret_service.sh` currently has Git mode **100644**, not required **100755** (LH-05); real native staging preserves that nonexecutable mode. Production `Makefile` still declares `python313` rather than unified `py${PLUGIN_PYTHON}`. Source-only Stage 0 must **observe** these debts, not mask them by modifying staged source or installing the resulting package.

## Isolated qualification scenario

The [test-only native witness](../../../scripts/stage0-opnsense-official-mk-source-package.py) and [negative contracts](../../../scripts/test-stage0-opnsense-official-mk-source-package.py) run only in an explicitly opted-in fresh OPNsense 26.7/FreeBSD15 KVM CI guest. 1. Verify installed OPNsense-owned generic Python and real `python313` package name, version and origin; evaluate official `make -V` ABI, name, version, `PLUGIN_PYTHON`, project hash and website independently of the old shell builder.
2. Stage the actual project's present `src/opnsense`, `src/etc` plus four unchanged official manual hooks into a temporary `security/zapret2-restyle` alongside the pinned official `Mk/`, `Scripts/` and `Templates/`.
3. Invoke **real `make package`** against the upstream framework and inspect the resulting temporary `os-zapret2-restyle-0.6.2_57.pkg` manifest: exactly four manual hook bodies under canonical `pkg` serialization, actual installed `pkg` dependency origin/version and archive source-service byte equality. The raw native `+MANIFEST` uses **literal `%` → `%25`** and removes exactly one final LF; `scripts-manual` staging remains byte-identical with the four source files. Only these exact transformations are accepted, because the FreeBSD `pkg` manifest decoder reverses `%25` before execution.
4. Require the **negative observation** that native package preserves 0644 for the historical Git 100644 service, and that separately built private signed curl-impersonate assets are missing from this partial source-package rehearsal. Archive is discarded with isolated guest work directory; never install, distribute or publish it.
