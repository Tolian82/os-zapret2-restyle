## Verified upstream, bounded test scenario

The [FreeBSD pkg upstream scripts contract](https://github.com/freebsd/pkg/blob/main/features.md) defines `pre-install`, `post-install`, `pre-deinstall`, `post-deinstall` with `PKG_PREFIX`, `PKG_ROOTDIR`, `PKG_UPGRADE` and process-reaper semantics; it supports rootdir-friendly install. This source-level contract is **not proof of exact replacement phase ordering**. The archived [published immutable `v0.6.2_1.pkg`](https://github.com/Tolian82/os-zapret2-restyle/releases/download/v0.6.2/os-zapret2-restyle-0.6.2_1.pkg) at SHA-256 `1e21fbcac847529b94fea940241b4da7f86a42d33c129b7003ad04a72f4e5a0f` is independently downloaded in a disposable FreeBSD 15.1 VM. The new `scripts/stage0-real-pkg-scheduler.py` first refuses any archive digest, predecessor identity, target ABI or four nonempty authoritative hook metadata mismatch. It records SHA-256 and byte counts for every **actual archived package hook** as separate provenance; these hooks **are not invoked by the fixture**.

The script then creates two explicitly named **synthetic fixture packages** (`zapret2-stage0-phase-order-fixture`, versions `0.6.2_1` and `0.6.2_27`), each with **four short trace-only hooks**. No package named `os-zapret2-restyle` is installed or replaced. It calls native `pkg create -M`, `pkg add`, and `pkg add -f` in the disposable VM to measure real `pkg` old/new phase scheduler behavior. All fixture-owned files live inside a fresh private `/tmp` directory; `PKG_DBDIR` and `PKG_CACHEDIR` are separate private directories, with `REPO_AUTOUPDATE=false`; no configured repository, production package, OPNsense service, rules or real host user configuration is changed.

The required provisional sequence to test (and to **fail/report on a real disagreement**) is:

```text
old:pre-install
old:post-install
new:pre-install
old:pre-deinstall
old:post-deinstall
new:post-install
```

Any missing, duplicate or reordered phase is `NOT_VERIFIED` with an artifact containing **observed** and **expected** order; no artificial reordering is allowed to make CI green. The new runner is rejected outside **root-owned disposable FreeBSD 15.1 amd64**; the fixture package is deliberately named differently so it cannot be confused with actual `os-zapret2-restyle` installation.

**What PASS would establish:** the **real native FreeBSD15.1 pkg scheduler** executes this observed order for *synthetic tracing hook bodies*, while the historical stable `.pkg` bytes and its four embedded hook hashes are separately validated. It would not prove actual historical hooked service execution, old `+PRE_DEINSTALL` inherited FD9, status/stop, configd worker identity, Python-loss path, full OPNsense binary/install dependencies, or a new native OPNsense package. No successor `os-zapret2-restyle-0.6.2_27.pkg` is produced/published or installed. This **cannot close LH-01–LH-07** or Stage 0.09/0.13 acceptance by itself.
