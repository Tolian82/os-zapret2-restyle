**Date:** 2026-08-15
**Package:** `os-zapret2-restyle-0.4.1_15.pkg` / `v0.4.1_15`
**Status:** OWNER-LIVE FAIL — investigation required

## Observation

The owner installed the published `_15` testing package and ran Strategy Lab in **Extended** mode against `rutracker.org` with Enable QUIC ON and Generic UDP port `53` entered.

The Generic UDP file path still did not become configured. The owner reports that attaching a valid small file does not work. In the supplied GUI evidence the file control remains in the state `Не выбран ни один файл`, the form shows the `1–4096` byte / port+file validation message, and the completed Stage 80 result reports that UDP testing was not configured.

The same run completed successfully on the TLS path and showed QUIC candidate execution evidence, so this finding is specifically about the Generic UDP input/file path rather than the whole Strategy Lab job.

## Current conclusion

`v0.4.1_15` **does not pass the Generic UDP owner-live acceptance row**. Automated exact-byte/Base64/job-local tests are insufficient to close this path because the real browser → API/job-local handoff still fails in the owner environment.

Confirmed product-level fact:

- a selected Generic UDP file is not reaching a usable configured-UDP state in the live GUI flow.

Not yet proven:

- where the failure occurs;
- whether the browser file-selection/read path loses the file before the API request;
- whether the API receives no payload;
- whether launcher/job-local file creation fails;
- whether filesystem ownership/permissions on the Strategy Lab job directory or payload path prevent creation/readback.

The owner's current hypothesis — **the file may simply not be uploaded/saved, possibly because of directory permissions** — is recorded as an investigation hypothesis only, not as the established root cause.
