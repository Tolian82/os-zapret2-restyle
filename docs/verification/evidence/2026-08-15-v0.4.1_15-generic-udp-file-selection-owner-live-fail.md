# v0.4.1_15 owner-live — Generic UDP file-selection report (historical, superseded diagnosis)

**Date:** 2026-08-15
**Package:** `os-zapret2-restyle-0.4.1_15.pkg` / `v0.4.1_15`
**Status:** HISTORICAL OWNER REPORT · DIAGNOSIS SUPERSEDED BY `_16` EXACT-BYTE PASS

## Original observation

The owner installed the published `_15` testing package and ran Strategy Lab in **Extended** mode against `rutracker.org` with Enable QUIC ON and Generic UDP port `53` entered.

At that time the owner reported that attaching a local payload file did not produce a usable configured-UDP state. The GUI showed file/size validation behavior and the completed Stage 80 result reported UDP as not configured. The same run completed successfully on the TLS path and showed QUIC candidate execution evidence, so the investigation focused on the Generic UDP browser-to-job boundary.

The owner's then-current hypothesis — that the file might not be uploaded/saved, possibly because of directory permissions — was explicitly recorded only as an investigation hypothesis, not as an established root cause.

## Later correction

Subsequent controlled `_16` verification changed the diagnosis materially.

The owner identified that the files repeatedly described as roughly "140" were actually approximately **140 KiB**, not 140 bytes. The Generic UDP contract is **1..4096 bytes**, so those files were correctly rejected by size validation.

A controlled Windows fixture `udp-140.bin` was then created and filesystem-verified as exactly `140` bytes. On published `_16` it immediately entered ready-to-send state, started configured UDP on port `53`, executed all three UDP candidates, preserved the correct no-reply semantics, and completed Stage 90 successfully.

Durable accepted evidence:
[`2026-08-15-v0.4.1_16-generic-udp-owner-live-pass.md`](2026-08-15-v0.4.1_16-generic-udp-owner-live-pass.md).

## Current interpretation

This file remains as chronology of what was observed and suspected during `_15` testing. It must **not** be cited as proof of a browser upload, server upload-directory, or filesystem-permissions defect.

Current accepted facts are:

- Generic UDP does not use multipart file upload; the browser reads the file and sends Base64 in the ordinary start POST;
- the payload size contract is `1..4096 bytes`;
- approximately 140 KiB input is invalid by design;
- exact 140-byte input is valid and owner-live PASS on `_16`;
- no product regression remains open from this historical report unless new contradictory evidence appears.
