## Purpose and safety boundary

This experiment tests **actual native root pkgdb and actual historical four-hook bytes** after a fault, not an inert private synthetic pkgdb. Unlike the original genuine RUNNING experiment in `_54`, no Start or Stop is attempted here. Existing cold preflight deliberately requires: authenticated installed historical archive/pkgdb/service, real original Status STOPPED through FD9, no shared journal/restart markers/PID files, no recognizable residual processes, and **unloaded** ipfw/ipdivert with exact ENOPROTOOPT response. Loaded shared kernel modules after a previous Stop are **not accepted as cold** merely because plugin rules are gone.

Run only in a **fresh, disposable OPNsense 26.7 FreeBSD15 amd64 KVM CI guest**, explicitly opted in with `GITHUB_ACTIONS=true` and `ZAPRET2_STAGE0_DISPOSABLE_REAL_PKG_RECOVERY=1`. The ordinary owner appliance is out of scope. No custom repository, owner config, foreign `FreeBSD.conf`, private network or WAN touched.

1. Check guest is a fresh qualified virtual OPNsense; authenticate published archive SHA, actual post-install fault-injection point and package ABI/hook content.
2. Install genuine historical package with genuine native hooks, then snapshot actual pkgdb/service and immutable owner Config; require strict cold/FD9/process/IPFW gate.
3. Execute genuine `pkg -o REPO_AUTOUPDATE=false add -f` on **the same exact published package** with the genuine OPNsense register helper's executable bits temporarily removed (after exact root-owner/regular-file/package-owner validation), causing the original post-install `-x` guard to fail before configd-worker reload or runtime start. The original permissions must be restored in a `finally` region only when inode, digest and ownership remain identical. Caller environment override was **not** observed to produce this failure in initial native CI, despite `pkg` return code 0. **Do not trust native pkg exit status** as transaction commit proof: require actual historical hook diagnostic.
4. Independently recheck installed pkgdb/hook/service provenance, Config, genuine FD9 Status, processes and kernel. Any uncertainty **refuses compensation** (never forcibly kills, unloads global modules or overwrites foreign ownership).
5. Re-verify archive SHA and re-run native `pkg add -f` with the failure override removed. Require successful post-install signature, actual original package provenance equal to pre-fault, unchanged Config and strict original cold ownership.

## Explicitly not proven

- No new-version native successor is built or installed; **same-version forced reinstall is not an upgrade**.
- No RUNNING → new-version → RUNNING transaction, marker replay, successful service restart, new `PLUGIN_PYTHON`/official `Mk/plugins.mk` build or version cross-grade.
- No crash/power-loss atomic rollback. Direct privileged `pkg` remains able to bypass this coordinator. The preflight and actual pkg are not one uninterruptible FD9 lock region (original hooks reacquire FD9).
- No safe admission of old Stop's **loaded** ipfw/ipdivert modules; no foreign rules/processes may be modified. A hook exit failure is not a native pkg abort barrier.
- No owner-appliance execution, product safety acceptance, Stage 0 closure, Stage 1 unblocking, package publication or release.

**Acceptance achieved for only this restricted scenario:** the 14 offline/negative contracts and exact-head isolated OPNsense job both pass. The original injected post-install hook failed even though native pkg returned 0; the original package was reverified, reinstalled to compensate, then checked as STOPPED/cold with original Config and OPNsense register-helper permissions restored. This does not widen the unproved product-upgrade or owner-appliance claims. An error/CI failure remains a recorded refusal, not positive evidence.
