# Stage 3.04 — Real configctl-launched independent FD9 worker across configd restart

**Source candidate:** `v0.6.2_94`, parent `main=62be89533d6c0d8b1adfed4c50de3eaa0aa88061`. **Native target result not yet observed at source creation.** Single disposable root OPNsense 26.7 test, no mutating `pkg` inside configd or detached worker; no product hook/firmware change, no owner appliance, no published package. **LH-08/AC-11 BLOCKED.**

## Why this is a new engineering gate

Stage `_93` invoked a registered, temporary real `configctl/configd` action, but its exact worker pattern census returned `REAL_CONFIGD_WORKER_PGREP_NO_MATCH`. Native [CI #41666422249](https://github.com/Tolian82/os-zapret2-restyle/actions/runs/41666422249) therefore reported `PASS_TEST_ONLY_REAL_CONFIGD_UNKNOWN_WORKER_VETO`, **not an identified worker**. The old authentic +POST_INSTALL does an explicit configd-worker SIGTERM/reload, so calling modifying `pkg` synchronously within that worker is an unsafe, unqualified design. `_93` genuinely proved the fail-closed no-`pkg` outcome and old package/Config/IPFW preservation, not the worker relation. The previous `_89` genuine external-root successful native pkg and `_91` late journal/orphan no-pkg negatives remain separate accepted CI and are retained unchanged.

**Proposed worker-independent candidate:** FreeBSD [`daemon(8)`](https://man.freebsd.org/cgi/man.cgi?manpath=freebsd-release-ports%26query=daemon%26sektion=8) documents `-f` for closing stdio and `-P` for a supervised, locked supervisor PID file, with a separate child process. Genuine OPNsense [`configd`](https://docs.opnsense.org/development/backend/configd.html) supports a fixed action with no parameters called through `configctl`. Test the real combination, rather than assume the detached executor survives and owns FD9.

## New bounded native one-use test

1. Install and attest the **unchanged published old 0.6.2_1 package** inside a fresh OPNsense 26.7 disposable VM. Check historical SHA256 `1e21fbcac847529b94fea940241b4da7f86a42d33c129b7003ad04a72f4e5a0f`, actual cold STOPPED state, and complete original pkgdb/listed file byte/mode/ownership/Config/markers/owned processes/IPFW owner snapshot.
2. Create one **temporary** no-parameter, root-only configd action with `O_EXCL | O_NOFOLLOW`, mode `0600`, fixed source SHA, fixed script path and explicit CI-only environment. Register with `service configd restart`; require actual `configctl configd actions` discovery; call `configctl zapret2_stage3_detached_ci launch`. This action does not install, update or remove packages.
3. Actual action launches `/usr/sbin/daemon -f -P <one-use-test-pidfile> /usr/local/bin/python3 <script> --worker <exact SHA>`. This must run a **separate root child** after the configd action returns; no sudo/pkexec/untrusted input or user-controlled parameters.
4. The independent worker opens the **authentic** `/var/run/zapret2-lifecycle.lock`, verifies historical inode, moves it to FD **9** and obtains kernel-exclusive BSD `flock`. It runs existing `_81/_91` genuine old cold owner read-only verification **under FD9**, with independent `/usr/bin/lockf -s -t 0 9` busy challenge. Only then does it write a bounded root-owned `0600` READY witness recording exact worker PID/SHA and no-pkg status.
5. Controller waits for READY, checks original FD9 is independently **BUSY (75)**, then performs real `service configd restart` **while the holder remains alive**. It checks original FD9 still independently BUSY and the READY worker identity remains exactly the same. It signals release with a one-use root-owned `0600` marker (never PID-based blind kill); the worker revalidates owner under FD9 and writes DONE with **the identical PID**, then closes FD9.
6. Compare full original package/Config/process/IPFW snapshot to baseline; remove only expected owned action and markers; require the FreeBSD daemon supervisor PID file to disappear after worker completion. On failure, release marker is created if absent and the one-use VM is disposed. No other processes are signaled by this test. A pass cannot be substituted by offline mocked unit tests.

## First native result and explicit correction (PR #862)

The first [native run #41674460719](https://github.com/Tolian82/os-zapret2-restyle/actions/runs/41674460719) of source SHA `60e3efd0912ea4cdcf9a005307446e22a9353ad3` was **RED**, not accepted: the genuine configd action started its detached launcher but a READY file did not appear within 45 seconds. This was not a successful daemon/FD9 proof, and no mutating `pkg` was invoked. The following test-owned root-only diagnostic was added to surface bounded child startup refusal instead of a silent timeout.

The second [native run #41675163349](https://github.com/Tolian82/os-zapret2-restyle/actions/runs/41675163349) of SHA `30afb609a1efd9884d6cebe632bbe1786910426b` exposed **`ORIGINAL_FD9_FILE_ABSENT`**, meaning the genuine **STOPPED old 0.6.2_1 installation does not yet have `/var/run/zapret2-lifecycle.lock` on disk**. The prior `_89/_91` tests created the historical inode first via shell `exec 9>...`, which this independent worker initially lacked. This is an initialization oversight in the lab supervisor, not evidence that daemon cannot supervise or that BSD FD9 locking failed.

The corrected test worker exclusively creates **only the exact authentic path** with `O_EXCL | O_NOFOLLOW`, root mode `0600` if absent, or opens and verifies an existing root-owned regular inode without truncation/replacement; then duplicates the descriptor to **FD9** and takes `flock`. READY and DONE record the same inode and explicit `created_original_lock_inode` boolean. Controller cross-checks the inode against prior existence; after fully exited supervisor and released FD9 it can unlink **only the known originally absent, exact test-created inode while holding its own exclusive flock**, leaving a preexisting inode alone. The final old package/Config/IPFW snapshot still must be exactly unchanged. **This corrected native result is pending**; no synthetic passing claim.

## Acceptance ceiling and next step

A positive result proves only **a viable process-lifetime separation and original FD9 hold across configd restart**. It does NOT prove a secure **configd-to-independent-worker initial admission atomicity**, nor transferring a lock already held by configd, preventing racing external root IPFW modifications after final owner check, rejection of all supported firmware/Web entrypoints, old/new production hooks during such detached execution, SIGTERM/crash/recovery, RUNNING owners, or real pkg rollback. To close these, a later stage must implement a durable, explicitly authorized transaction handoff with atomically tracked owner/nonce/state; negative mutations MUST be stopped before real `pkg` for all **supported** callers, and stock firmware/Web support policy must be resolved under owner-approved architecture. **Do not publish `_94.pkg` or modify the installed appliance. LH-08/AC-11 remain BLOCKED.**
