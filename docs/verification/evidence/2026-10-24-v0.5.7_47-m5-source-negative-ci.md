## Confirmed remaining deficiency: explicit clean plugin reinstall

The approved [operator-selected repair contract](../../architecture/ZAPRET2_EXTRA_RESOURCES_GUI.md) **requires** a fresh operational plugin installation when a conventional package replacement cannot be trusted. Its success does *not* require preserving previous plugin-owned strategies/settings/job history, but must preserve unrelated OPNsense/other-plugin state.

Current shipping `pkg/+PRE_INSTALL` and `pkg/+PRE_DEINSTALL` correctly **fail closed** on status code 2 / incomplete native owner; normal `pkg add -f` is **not** a clean repair procedure and is not assumed to bypass those hooks. `pkg/+POST_INSTALL` registers the plugin and reloads its OPNsense configd actions/templates; simply bypassing all install scripts would not establish a usable plugin. The existing `extra_resources_upstream_guard` and `setup_transaction` rollback paths are **normal preservation/recovery tools**, not operator-selected clean-plugin reinstall.

A separate, bounded console repair must be designed and separately qualified. FreeBSD 15 pkg supports script-suppression during removal (`pkg delete --no-scripts`), but that API alone does **not** establish that native engine/IPFW state is quiescent, that pkg deletion safely targets only this plugin, or that a later normal install recreates every required runtime/configd state. Do not instruct its use against the running owner merely because the option exists.

See [M5 bounded repair qualification contract](../EXTRA_RESOURCES_CLEAN_REPAIR_GATE.md).
