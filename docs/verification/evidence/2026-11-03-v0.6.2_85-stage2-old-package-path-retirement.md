# Stage 2.28 — Retire stale stock-FreeBSD package CI and testing-publication callers

**Scope:** source-only candidate `v0.6.2_85`, based on exact `main=3ea14fdebad11ef1e98dc8f64145c02700b5a099`. Approved native TЗ/plan editorial v1.4 remain unchanged.

## Actual obsolete path and contract conflict

The single official builder `scripts/build-pkg.sh` already invokes `scripts/native-opnsense-package.py`, requires `ZAPRET2_NATIVE_BUILD_CI=1` and target-managed `/usr/local/bin/python3`. However `.github/workflows/publish-prerelease.yml` and `.github/workflows/testing-package-delivery-ci.yml` still invoked it under a stock `vmactions/freebsd-vm@v1` 15.0 runner with only `pkg install -y jq`. Moreover `scripts/test-github-branch-hygiene.sh` REQUIRED the obsolete runner: the outdated test blocked architecture compliance. The stale VM was an active caller, not a viable second package engine.

## Minimal fix and preserved boundaries

Both workflows now use the same pinned official OPNsense 26.7 VM action as the existing native CI and release workflow, with guest identity check, verified target package bootstrap, generic Python, explicit opt-in and exact source SHA. Testing-delivery CI checks the actual candidate version, target ABI/arch and package-embedded compatibility policy bytes. Publisher preserves its immutable source/tag ancestry, prerelease-only scope, SHA verification and separate documentation-record PR. It does not publish automatically from ordinary PR CI. Governance and package CI tests explicitly reject reintroducing a stock FreeBSD production caller.

The already-native builder, production package hooks and installed files are unchanged. The historical old-package archive, real FD9/unsafe-pkg and lifecycle regressions remain needed and are NOT deleted. `scripts/build-pkg-repository.sh` writes **pkg repository metadata** from an existing package rather than building a competing package; `scripts/verify-release-package.sh` verifies metadata without building. No product functionality or compatibility matrix change.

## Evidence boundary

Prepared-source/static preflight checked exact builder references, OPNsense runner and legacy rejection; the exact-head GitHub CI must execute before merge. A disposable OPNsense native build is qualification of a source-only candidate, **not** installed/owner/Web acceptance, pkg rollback proof, new testing-package publication or stable release. **LH-08/AC-11 remain BLOCKED** until Stage 3/4 enforce actual pre-pkg admission with continuous FD9 ownership. Stable `v0.6.2/0.6.2_1.pkg`, the original four hooks and the owner appliance stay unchanged.
