## Observable scenario and source provenance

The previous [real FreeBSD15.1 `pkg add -f` scheduler PASS](2026-11-01-v0.6.2_27-stage0-real-freebsd-pkg-phase-scheduler.md) proved that a **synthetic fixture** forced replacement executes incoming `pre-install` and `post-install` but does **not** invoke the old package `pre-deinstall` or `post-deinstall`; a separate explicit `pkg delete` invokes deinstall hooks. This **does not qualify** the historically deployed hook bodies or real FD9 behavior. This increment addresses that exact gap with a **separate, bounded execution harness**, while *not* confusing it with a full OPNsense package transaction.

The new [`scripts/stage0-archived-hooks-native-fd9.py`](../../../scripts/stage0-archived-hooks-native-fd9.py) runs **only in disposable root FreeBSD 15.1 amd64**, and first downloads (in CI) and SHA-256-verifies the immutable published `os-zapret2-restyle-0.6.2_1.pkg` digest `1e21fbcac847529b94fea940241b4da7f86a42d33c129b7003ad04a72f4e5a0f`. It reads the actual `+MANIFEST` directly from the archive and requires exact `name`, `version`, `abi` and all four nonempty shell hook text bodies, preserving their individual content hashes. **No Git source hook substitution, code patching or re-interpretation is allowed.**

It writes the **verbatim archived script contents** to private temporary executable files and directly executes each under `/bin/sh`. The hooks use **real `/usr/bin/lockf` and kernel-inherited FD9**. All service/firmware/configd command paths and state/restart/journal/lock paths are redirected into the disposable `/tmp` fixture via the hooks' existing environment variables, with mock status/stop/worker and signal commands; the real host configd watcher, PIDs, service, packages and IPFW are not used or touched. No production `pkg add` or actual OPNsense runtime is invoked in this step.

## Eight bounded observations actually PASS in FreeBSD 15.1 CI

| Scenario | Hook body from immutable archive | Required observable behavior |
|---|---|---|
| F01 — RUNNING / FD9 | original `pre-install` | Status first refuses without inherited FD9 when shared journal exists; original hook retries through **actual native lockf FD9**, safely stops known RUNNING and preserves restart marker; verifies STOPPED with FD9 again. |
| F02a — old Status rejection at POST_INSTALL | original `post-install` | When mock old service **still requires FD9** after incoming post-install calls its direct Status, it starts using mock configd but fails the final status verification and **preserves restart marker**. This is a bounded negative, not a successful rollback or an actual OPNsense deployed service. |
| F02b — modeled successor restore | same original `post-install` | Model the **new service generation** explicitly (mock Status no longer requires the old FD9 workaround). Fake existing watcher/worker, mock `SIGTERM` only, registration/configure/template and `configctl zapret start` restore **only preserved** RUNNING intent and consume marker on verified success. This does **not** prove the real native successor behaves this way. |
| F03 — already STOPPED | original `pre-install` + `post-install` | No Stop, no fabricated RUNNING marker, no Start. |
| F04 — old `PRE_DEINSTALL` / FD9 | original `pre-deinstall` | Calls mock old Status without inherited FD9 and gets incomplete/unknown; lacks own retry and **refuses without Stop or marker loss**. This is separately invoked to characterize the body; `pkg add -f` does not invoke it. |
| F05 — genuinely incomplete owner | original `pre-install` | Even after valid lockf FD9, Status remains incomplete: refuse before Stop and preserve unknown runtime. |
| F06 — Stop failure | original `pre-install` | Refuse without promoting running state, and clear inappropriate restart intent. |
| F07 — no-op cleanup | original `post-deinstall` | No worker/config/service/global Web GUI activity, and preserve unrelated restart marker. |

Eight offline positive/negative tests in `scripts/test-stage0-archived-hooks-native-fd9.py` cover archive SHA, identity/ABI, absent/invalid historical scripts, sandboxed process and filesystem targets and refusal on Linux. The exact-head CI job `stage0-historical-hook-fd9` executes the actual archived scripts on FreeBSD15.1, retains `stage0-historical-real-fd9.json` with old script SHA hashes, scenario names, provenance and explicit `actual_pkg_transaction=false` / `old_service_actual=false` / `opnsense_native_acceptance=false`. **No actual owner gateway operation is requested.**

## Acceptance limits / future work

- **Now proven by native CI: archive-body/real-lockf behavior with *mocked* old Status and configd helpers.** It does not show behavior of actual deployed old `zapret_service.sh`, the real OPNsense configd worker/FD9 process tree, a real old/new `pkg` replacement, exact new native package modes, Python-loss ownership or gateway recovery.
- The scheduler and this archive-hook test are **different** evidence. For `pkg add -f`, do not assume old `PRE_DEINSTALL` runs; for normal `pkg upgrade` and explicit `pkg delete`, collect their actual qualified native sequence separately. LH-02's mandatory old-hook acceptance and LH-07's real target **remain open**, as do LH-01/LH-03–LH-06.
- No automatic recovery/restore/delete/overwrite of the foreign/unproven `FreeBSD.conf` with no backup. The stable tag/package `v0.6.2` / `0.6.2_1.pkg` remains unchanged. `VERSION=0.6.2`, `PLUGIN_REVISION=28`: **no `0.6.2_28.pkg` published**; any CI package build is unpromoted testing evidence, not a user release.
