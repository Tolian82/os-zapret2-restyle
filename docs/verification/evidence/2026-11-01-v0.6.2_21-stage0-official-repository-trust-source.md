# Stage 0.08 — pinned official OPNsense repository trust-source gate

**Date:** 2026-11-01. **Source baseline:** `main=4b2a8bf1ccc1c3ad23103e52e71da7e2faf46051` (`v0.6.2_20`); delivery source revision `v0.6.2_21`. **Technical specification and plan:** independently approved **v1.3**, without editorial revision or requirement changes. **Evidence level:** pinned official public Git source plus offline negative/positive tests and CI artifact, **NOT installed repository trust/cryptographic signature verification**.

## Official authority and explicit source contract

The official [OPNsense core stable/26.7](https://github.com/opnsense/core/tree/ac08367416c1d66dea87df0ef0de24c315b5d5bc) is pinned at **`ac08367416c1d66dea87df0ef0de24c315b5d5bc`**. CI downloads two exact immutable raw source files:

- [`src/etc/pkg/repos/OPNsense.conf.shadow.in`](https://github.com/opnsense/core/blob/ac08367416c1d66dea87df0ef0de24c315b5d5bc/src/etc/pkg/repos/OPNsense.conf.shadow.in): main repo `OPNsense`, `signature_type: "fingerprints"`, `fingerprints: "/usr/local/etc/pkg/fingerprints/OPNsense"`, `enabled: yes`, `priority: 11`, URL `%%CORE_PACKAGESITE%%/${ABI}/%%CORE_ABI%%/latest`.
- [`src/etc/pkg/repos/OPNsense-aux.conf.shadow.in`](https://github.com/opnsense/core/blob/ac08367416c1d66dea87df0ef0de24c315b5d5bc/src/etc/pkg/repos/OPNsense-aux.conf.shadow.in): secondary `OPNsense-aux` uses the **same fingerprints directory** and `signature_type`, URL `%%CORE_PACKAGESITE%%/${ABI}/%%CORE_ABI%%/aux`, but **`enabled: no`** by default.

An OPNsense **product ABI** placeholder (`%%CORE_ABI%%`) and the pkg/FreeBSD **architecture ABI** placeholder (`${ABI}`) are independent; neither is permission to claim a target ABI based on a hardcoded fallback.

## New automated, fail-closed source verification

- `scripts/stage0-opnsense-repo-trust-source.py` accepts exactly these two downloaded template files; strict length, UTF-8, block name, required field values, unknown/duplicate directive and channel/enabled-mode checks. It emits SHA-256 of **both input source files** and a JSON artifact for the PR/main SHA; it never reads or mutates the owner's appliance.
- `scripts/test-stage0-opnsense-repo-trust-source.py` has **eight** offline tests: positive source acceptance, disabling signature, switching trust directory, replacing independent ABI placeholders with fixed literals, enabling auxiliary repo, extra/duplicate directives, wrong block/multiple injected blocks and oversized/binary input refusal. Test source is invoked from the existing Stage 0 source-audit CI job.
- `.github/workflows/ci.yml` downloads official files by **fixed Git SHA** beside the previously inspected official `core/plist`, `Mk/defaults.mk`, `Mk/plugins.mk` and unsigned public mirror candidate index; it preserves `stage0-official-repo-trust-source.json` in the same exact-head public OPNsense provider artifact. Existing package/hook/source checks and all actual product code are untouched.
- Exact evidence flags explicitly remain `installed_repository_configuration_qualified=false`, `installed_trusted_fingerprint_qualified=false`, `signed_pkg_catalog_cryptographically_verified=false`, and `stage0_closed=false`. A template with correct `signature_type` is **not** a cryptographically verified repository or installed target trust anchor.

## Relation to the owner-executed appliance evidence and STOP

The previous [read-only owner OPNsense witness](2026-11-01-v0.6.2_20-stage0-owner-opnsense-target-witness.md) already confirms actual product ABI 26.7, pkg ABI `FreeBSD:15:amd64`, generic Python symlink owned by `opnsense`, `python313`, and installed predecessor `0.6.2_1`. That witness's `pkg -o REPO_AUTOUPDATE=false rquery -r OPNsense` proves cached package records visible to `pkg`, **not** that the cached catalog signature and the active repo's trusted fingerprints were independently validated. Existing `git-lite` from `FreeBSD-ports` must not be silently considered a qualified OPNsense native dependency.

**Still NOT VERIFIED:** actual installed repository config/fingerprints, authenticated catalog and target package name/version/origin trust chain; actual target private ELF dynamic load and Chrome/ECH/QUIC operation; actual predecessor package bytes and real old/new hooks, FD9 and rollback. Foreign/unproven `FreeBSD.conf` with absent backup remains protected from any automatic restoration or modifications.

**Handoff:** Stage 0 / I-00 **OPEN**, Stage 1 **BLOCKED**. Next qualification uses separately authorized isolated/target evidence for **actual** signed repository trust, ELF runtime and native package lifecycle; do **not repeat** the completed owner read-only baseline. No test package/tag/Release/Pages publication, installer, service, IPFW or appliance change is implied by this `v0.6.2_21` source/CI revision. Stable released `v0.6.2`/`0.6.2_1.pkg` remains immutable.
