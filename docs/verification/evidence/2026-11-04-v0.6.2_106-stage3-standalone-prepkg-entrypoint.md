## Current concrete pre-pkg scenario

`scripts/native-prepkg-standalone.py` can run from a **separately provisioned root-owned path** outside the plugin installation and outside the source repository on FreeBSD 15 amd64. It needs no previously installed managed CLI. Its *only* command is:

```text
python3 -E -B /root/native-prepkg-standalone.py inspect-predecessor ABSOLUTE_NEW_NATIVE_PKG NEW_VERSION INDEPENDENT_TRUSTED_NEW_SHA256 ABSOLUTE_OLD_NATIVE_PKG OLD_VERSION INDEPENDENT_TRUSTED_OLD_SHA256
```

It requires a root-owned regular copy of itself in a root-controlled directory and checks that both `.pkg` files are root-owned, regular, non-symlink, stable opened inodes with the **caller-supplied independent SHA-256**. The original old `0.6.2_1` package is unchanged. Before installing/replacing anything, it reads only four explicitly named Python modules from the already SHA-bound new native archive, requires matching native name/version/ABI/manifest declarations, and creates a private root-owned `0700` temporary directory holding exact `0600` source bytes. The actual `native_pkg_managed.py inspect-predecessor` executes in a fresh subprocess with the candidate's four modules and sanitized Python environment, not from checkout, with existing independent worker and historical original FD9. The bootstrap rehashes both archives after completion and cleans up its private temporary directory.

Only `PASS_STANDALONE_PREPKG_READ_ONLY_COLD` is a valid output. Negative or unknown input exits 78; `upgrade`, `reinstall`, `pkg add`, `pkg upgrade` and other mutation modes are **not implemented**, and a valid cold result **does not authorize later pkg**. The output mandates `pkg_invoked=false`, `old_owner_qualified=false`, `supported_mandatory_entrypoint=false`, `web_firmware_root_pkg_protected=false`, `lh08_ac11_accepted=false`. It does not inspect RUNNING owner or hold FD9 between separate future commands.

## Deliberate trust and safety boundary

This proves the source can be launched **without an installed previous CLI or a project checkout**, but **does not** authenticate how `native-prepkg-standalone.py` reaches the administrator's machine or how independently trusted digest values are delivered. A printed script self-hash is informational and is **not** a signature or provenance check. Root ownership alone does not establish trustworthy software origin. The script must be independently authenticated before it is executed; its current source-only GitHub existence is not an approved standalone deployment channel.

The entrypoint is not registered on, or unavoidable for, stock OPNsense firmware/Web/plugin-managed upgrades; root `pkg` remains a bypass, and no mutating package operation may follow from its result. Full predecessor STOPPED/RUNNING owner, PID/PGID/start-time, IPFW and Config ownership, historical hook cooperation, continuous FD9 through genuine `pkg`, concurrent operations, interruptions and rollback **remain open**. Owner appliance, four production hook bodies and stable published `0.6.2_1.pkg` are untouched.
