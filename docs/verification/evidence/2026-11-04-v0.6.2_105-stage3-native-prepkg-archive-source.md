## Scenario and exact acceptance boundary

The immutable published predecessor `0.6.2_1` does **not** contain the new managed CLI. A test-owned root executable **must not require installation of its successor to read candidate code**. Run the already-implemented `inspect-predecessor` from precisely the four production backend Python modules carried by the official OPNsense Mk incoming `0.6.2_105.pkg` **while the authentic old `0.6.2_1` is still installed**, and without executing any mutating `pkg` operation after that old install.

`scripts/stage3-native-prepkg-archive-bootstrap.py` is an **isolated CI experiment**, not a supported updater/firmware entrypoint. It verifies the root-owned candidate archive inode/path, independently supplied SHA-256, name/version/FreeBSD 15 amd64 ABI, unique package members, manifest file ownership declarations and exact byte equality of four modules to the checked-out exact-head production source. A private test-only root-owned `0700` directory receives exact bytes with `0600` modes, no symlinks or overwriting; candidate archive SHA/inode is verified again afterward. The actual extracted `native_pkg_managed.py` then performs read-only `inspect-predecessor` with original FD9 and independent worker as in _104.

**Required negative checks:** modified bytes/manifest/member lists, duplicate or missing members, existing output/symlinks, incorrect incoming archive digest (before any file staging), incorrect old archive digest, attempted `upgrade` refusing code 78. Assert unchanged old package database, authentic old service bytes/hook bodies, Config bytes and cold IPFW. Distinguish tracked-source staging from an OPNsense-supported pre-pkg update gateway.

This experiment does not supply an unavoidable signed/verified bootstrap *installation/distribution mechanism* to the owner appliance, OPNsense firmware/Web registration, managed mutating operation, complete owner identity for RUNNING/foreign IPFW, interruption/rollback or global privileged root `pkg` interception. The old `0.6.2_1` package and its four hooks cannot be retroactively modified. `old_owner_qualified=false`, `pkg_invoked=false`, `supported_entrypoint_implemented=false`, `lh08_ac11_accepted=false` are mandatory.
