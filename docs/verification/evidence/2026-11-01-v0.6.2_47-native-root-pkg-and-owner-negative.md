## Why this boundary is necessary

Existing [_36/_37](2026-11-01-v0.6.2_36-original-unknown-owner-native-refusal.md) experiments demonstrated native FreeBSD pkg continues destructive transactions even after scripts return failure. [_39](2026-11-01-v0.6.2_39-pkg-fd9-hook-contention.md) shows FD9 contention during pkg is not a veto; [_40](2026-11-01-v0.6.2_40-sidecar-native-direct-pkg-bypass.md) shows direct pkg bypasses an external sidecar lock. [_41](2026-11-01-v0.6.2_41-native-firmware-and-pkg-lock.md) shows native metadata pkg lock blocks the tested ordinary operations. [_43](2026-11-01-v0.6.2_43-orphaned-unlock-kill.md) confirms direct privileged native pkg can remove a synthetic fixture after unlock. [_46](2026-11-01-v0.6.2_46-auto-start-synthetic-pkg-reconcile.md) qualifies only an **experimental private automatic boot reconciliation**.

Pinned [official opnsense/core stable/26.7 source SHA `874c32d7e5e337f19f256066b9689e91e56d5277`](https://github.com/opnsense/core/tree/874c32d7e5e337f19f256066b9689e91e56d5277) shows distinct Web firmware API/configd/launcher paths: install, remove, reinstall, lock, unlock, update, upgrade and auto-update. Official firmware `lock.sh` and `unlock.sh` delegate directly to `pkg lock -y` and `pkg unlock -y`. `install.sh` uses pkg install, `remove.sh` pkg remove, `reinstall.sh` can delegate to opnsense-revert, and update/upgrade have other commands. **The firmware launcher's progress flock is not global package-manager transaction ownership.** OPNsense official API even exposes lock and unlock to authorized administrators. The [FreeBSD Handbook](https://docs.freebsd.org/en/books/handbook/ports/#ports-pkg-locking) notes that native pkg lock acts on **already installed** package identities, not fresh package installation. An arbitrary trusted root can unlock, use direct pkg, or use alternate privileged tools. A plugin package cannot make an unbypassable pretransaction veto for arbitrary root without controlling those privileged entrypoints. This is an **architecture/security trust boundary**, not a claim to prevent authorized root actions.
