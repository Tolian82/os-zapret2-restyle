## _113 exact source-only contract

A separate detached **RSA SHA-256 signature over the unmodified exact byte stream of `operator-pins.json`** must now verify against a distinct approval-authority public PEM **before parsing JSON or executing the SHA-checked RSA claims evaluator**. The initial operator-reviewed `python -I -B -c` seed accepts only the exact read-only command:

```text
python3 -I -B -c '<already independently authenticated seed bytes>' \
  --operator-receipt /root/private/operator-pins.json \
  --operator-authority <independently authenticated 64-lower-hex authority-PEM SHA> \
    /root/private/operator-approval-authority.pem \
    /root/private/operator-pins.sig \
  --verified-verifier /root/private/stage3-prepkg-verified-eval.py \
  --signed-provenance /root/private/approved-public.pem \
    /root/private/claims.json /root/private/claims.sig \
    /root/private/native-prepkg-standalone.py \
  inspect-predecessor /root/private/os-zapret2-restyle-0.6.2_113.pkg \
    0.6.2_113 /root/private/os-zapret2-restyle-0.6.2_1.pkg 0.6.2_1
```

**Not deployable; do not invoke on a production appliance.** The command's authority SHA is still an input from the caller and can be forged if no independent operator review verifies it. `seed_sha256` inside the signed receipt cannot bootstrap the already-executed seed's identity. A valid detached signature proves a private key corresponding to the caller-pinned authority PEM, **not** real-world signer identity or permission to upgrade.

The seed now opens `operator-pins.json`, authority PEM and detached signature with `O_NOFOLLOW` and refuses non-root owner, other-than-`0600`, multiple hardlinks, symlinks, untrusted ancestor/parent (exact `0700`), bad basename, oversized file or inode/size/ctime/mtime changes during read. The authority PEM must hash to the separately supplied 64-hex digest and differ from the key for the package-claims signer. OpenSSL is invoked at **absolute `/usr/bin/openssl`** only on captured immutable receipt and copied private file bytes in a temporary root directory. No external Python source or `pkg` executes before signature success. Receipt then passes strict exact-key, schema, duplicate, commit/old+new package semantic tests, verified interpreter SHA, provenance RSA/public PEM pin, signed current/old archive SHA and original historical FD9 read-only inspection.
