## Next selected product task — Laboratory IP targets

The owner selected support for entering an IP address in Laboratory and searching for a bypass strategy analogously to domain targets.

The current architecture already declares domain-or-IP target support, but the implementation is only partially wired. The audit found:

- the PHP API and shell `target.sh` currently reject IP literals, so both input boundaries must be changed;
- Stage 00/40 presentation, Python clean-baseline logic, search-epoch state, firewall pinning, and final profile generation already contain IPv4-target scaffolding;
- the final profile builder already emits `--ipset-ip=<target>` for an IP target;
- Generic UDP is naturally compatible with a fixed IP target;
- current TLS candidate probing is **not** safe to unlock unchanged: for an IPv4 endpoint it falls back to a plain TCP connect, which is insufficient evidence for a TLS/DPI-bypass PASS;
- current native TLS search includes host/SNI-oriented operations (`pos=host`, `midsld`, `hostfakesplit`) and hostlist target binding, so a bare IP cannot truthfully reuse every domain candidate without an explicit service-identity contract;
- QUIC candidate probing explicitly requires a hostname for SNI/certificate verification;
- the current search-epoch implementation canonicalizes IPv4 only, so initial IP support should be IPv4-first rather than silently claiming IPv6 support.

## Selected implementation direction

The safe design direction is:

1. one Laboratory target field accepts either a domain or canonical IPv4 and persists `target_type`;
2. domain behavior remains unchanged;
3. an IPv4 target bypasses DNS and is pinned directly for firewall attribution;
4. Generic UDP may operate directly on the IPv4 target;
5. web/TLS/QUIC probing must keep destination IP separate from service hostname/SNI and certificate identity;
6. add an optional/conditional `Host / SNI` input for IP targets; when supplied, connect to the fixed IP while preserving that hostname for HTTP Host, TLS SNI and certificate verification;
7. bare-IP branches that cannot be validated semantically must be reported as unsupported/skipped rather than converted into false PASS results;
8. production recommendation for an IP target uses an IP selector (`--ipset-ip=<target>`), not a domain hostlist selector;
9. retain Model C, lifecycle, timeout, cleanup/restoration and result-attribution contracts unchanged.

No product source is changed by this evidence record. The next package-affecting patch must implement the target/service-identity contract with focused regression coverage before owner-live testing.
