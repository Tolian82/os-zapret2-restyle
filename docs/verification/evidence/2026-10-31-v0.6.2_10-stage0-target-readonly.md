# Stage 0 / I-00 — safe OPNsense target qualification witness

**Status:** source and fixture evidence only; the target host witness has NOT been executed on the owner's OPNsense. Stage 0 remains OPEN and Stage 1 remains blocked. The independent specification and plan editorial revisions remain v1.2.

## Exact upstream qualification anchors

- Official OPNsense [core stable/26.7](https://github.com/opnsense/core/tree/stable/26.7) exact source SHA `ac08367416c1d66dea87df0ef0de24c315b5d5bc`: [`plist`](https://github.com/opnsense/core/blob/stable/26.7/plist) contains `/usr/local/bin/python3`, and [`src/etc/rc.d/configd`](https://github.com/opnsense/core/blob/stable/26.7/src/etc/rc.d/configd) explicitly uses it. A *source-level* owner of the generic link is therefore identified as the core package; target `pkg which` must verify actual installed ownership, not assume `python313` provides it.
- Official [plugins stable/26.7](https://github.com/opnsense/plugins/tree/stable/26.7) exact source SHA `79a5f88b7b27a706c10511ea5587c9d0e0dbdced`: [`Mk/defaults.mk:45–54,68–77`](https://github.com/opnsense/plugins/blob/stable/26.7/Mk/defaults.mk) reads installed `/usr/local/sbin/opnsense-version -a` if available and evaluates `/usr/local/bin/python3 -V`. Its fallback `26.7` when `opnsense-version` is missing is **not proof** of a qualified build host.
- A public [OPNsense 26.7 FreeBSD:15:amd64 package mirror snapshot](https://mirrors.nycbug.org/pub/opnsense/FreeBSD:15:amd64/26.7/latest/All/) lists candidate archives `python313`, `git`, `jq`, `pkgconf`, `luajit`, `gmake`. It does not by itself verify actual target signed catalog origin, installed package files or ABI. `git-lite` was not found in that snapshot; target provider is still subject to confirmation.

## Single nonmutating host witness — source prepared, not run

- `scripts/stage0-target-opnsense-readonly.sh` reports product and FreeBSD/pkg ABI, installed package names/versions/origins, cached **OPNsense-only** package-query results with automatic repository update disabled, generic and versioned Python path owner via `pkg which`, direct service entrypoint mode, and bundled curl ELF magic/libs read-only with `file` and `elfdump -d` (never executes the ELF).
- It reports only file metadata/digests and equality for `/usr/local/etc/pkg/repos/FreeBSD.conf` versus `/var/db/zapret2-restyle/FreeBSD.conf.backup`, **never prints repository contents or credentials** and **never restores/deletes a file**. Even matching hashes never prove the override was plugin-owned; witness always says `REPO_OWNERSHIP=NOT_PROVEN_BY_THIS_PROBE`.
- No `pkg update/install/upgrade/remove`, custom symlink creation, Config changes, service restart, IPFW commands or WAN traffic occur. It is designed to run only when the owner separately authorizes an OPNsense host read-only check; Linux CI is not target acceptance.
- `scripts/test-stage0-target-opnsense-readonly.sh` checks shell syntax, mandatory witness fields, static mutating-command prohibition and a Linux negative smoke: positive read-only boundary and truthful ownership-unknown markers. CI runs this narrow test within the existing Stage 0 exact-head audit job.

## STOP boundary

Actual owner OPNsense 26.7 product/pkg ABI, `pkg which` generic Python provider, package names/origins, real private ELF dynamic library loading and old repository/backup ownership remain unverified. The already qualified [published archive baseline](2026-10-31-v0.6.2_9-stage0-published-package-audit.md) is source-package evidence, not installed target evidence. Do not claim Stage 0 closure or start Stage 1 without required proofs; do not require repeated manual one-line tests from the owner.
