# Stage 2.23 — Genuine stock configd firmware Unlock of an unsafe old package

**Candidate:** `v0.6.2_78` source/native **investigative test**. **Evidence state at PR creation: NATIVE OPNsense 26.7 RUN PENDING**, not a measured PASS and not product acceptance. The real protected native updater, LH-08 and AC-11 remain **BLOCKED**. This test only runs in one-use GitHub Actions disposable OPNsense 26.7 KVM; no owner appliance, publication, production hook change or firmware modification.

## Why this specific experiment

The real unlocked published `0.6.2_1` predecessor under old `Status=2` and the orphaned test-only `ipfw 19000 divert 989 tcp/65431 out via lo0` was [replaced by root `pkg add -f` despite a refusing incoming PRE_INSTALL](2026-11-02-v0.6.2_74-stage2-real-unsafe-owner-native-pkg.md) (CI #41515449795). The [same real published old package under `pkg lock`](2026-11-03-v0.6.2_76-stage2-real-locked-unsafe-owner.md) was **not** replaced by the forced native package (CI #41533724870): pkg rc 1 and old pkgdb/service/Config/markers/IPFW unchanged. The [finite entrypoint matrix](2026-11-03-v0.6.2_77-stage2-entrypoint-admission-matrix.md) and the [read-only installed firmware route audit](2026-11-01-v0.6.2_48-stage0-firmware-route-admission-boundary.md) found no Zapret FD9-aware stock admission. In the pinned official OPNsense 26.7 source, `actions_firmware.conf` [unlock] routes via `/usr/sbin/daemon -f .../launcher.sh unlock` to `unlock.sh` which calls `pkg unlock -y`. Source evidence is not execution proof.

**Tested path:** genuine installed `configctl firmware unlock os-zapret2-restyle` as the actual privileged **configd firmware backend action**, followed separately by native root `pkg add -f` against an exact official Mk-built successor. This is **not a browser GUI click** or a claim that a Web GUI itself performed package replacement.

## Fixed, fail-closed sequence

1. Gate exact CI root/OPNsense 26.7/FreeBSD 15 amd64 KVM, single-source `VERSION=0.6.2`, `PLUGIN_REVISION=78`, explicit disposable opt-in and exact source SHA. Build and hash official native successor **before** installing the immutable published old `0.6.2_1`; verify old archive SHA, installed hooks/service/pkgdb, cold status, no preexisting managed marker and read-only real stock firmware source.
2. On the isolated guest only, safely initialize IPFW with default-accept and add exactly one test-owned loopback-only orphan managed-range divert rule. Require the actual installed old service `status` to exit 2. Lock that genuine old package through native `pkg lock -y`; verify lock-list and full old native raw pkgdb record.
3. Call actual `/usr/local/sbin/configctl firmware unlock os-zapret2-restyle`. Because official `configd` dispatch uses a detached firmware daemon, **submission success alone is not proof**: poll lock-list with a hard 20-second bound, require genuine lock removal and verify unchanged old pkgdb identity/raw record, old service bytes, Config bytes, restart-marker absence, Status=2, exact orphan IPFW and successor archive SHA before native pkg begins.
4. Only after the stock action is *observed* to remove the lock, issue native `pkg add -f` of the official successor, without mock hooks. Capture the actual exit, actual installed pkg identity, authentic incoming PRE_INSTALL refusal text, Config-byte comparison, exact original orphan IPFW rule and SHA before cleanup. The expected hazard classification requires genuine new pkgdb identity despite refusal; other results are **test refusal**, not fabricated PASS.
5. Safely delete **only** the exact test-owned orphan; keep modules loaded and dispose of the VM. Emit both the pre-cleanup raw result and final bounded classification. Do not globally flush IPFW, reset firmware, manipulate user Config or publish the candidate.

**Reproducibility:** [guest runner](../../../scripts/stage2-opnsense-real-firmware-unlock-bypass.py), [source-only negative contracts](../../../scripts/test-stage2-opnsense-real-firmware-unlock-bypass.py), [pinned workflow](../../../.github/workflows/stage2-real-firmware-unlock-bypass.yml).
