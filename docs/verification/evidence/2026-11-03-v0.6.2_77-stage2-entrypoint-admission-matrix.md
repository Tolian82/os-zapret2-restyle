## Entry point / privilege / earliest-veto table

| Route / actual installed source | Privilege and package mutation phase | Demonstrated pre-pkg Zapret owner veto? | Proof status |
| --- | --- | --- | --- |
| Web/configd `firmware install` → daemon `launcher.sh` → `install.sh` → `pkg install -y` | Privileged firmware action; progress flock before pkg | **NO**: stock flock is independent of FD9 and process/IPFW ownership | Source verified; real unsafe-owner Web install **NOT TESTED** |
| Web/configd `firmware remove` → `remove.sh` → `pkg remove -y` | Privileged firmware action; may remove installed payload | **NO** proven gate; old PRE_DEINSTALL refusal is not sufficient | Source verified; actual unsafe-owner Web remove **NOT TESTED** |
| Web/configd `firmware reinstall` → `reinstall.sh` → `opnsense-revert -l` | Privileged reinstall helper; exact downstream pkg phase not traced in this scope | **NO** demonstrated FD9 gate | Source verified, downstream real unsafe replacement **NOT TESTED** |
| Web/configd `firmware lock` → `pkg lock -y` | Privileged pkg metadata lock | **NO**: lacks FD9/owner admission and hold | Exact real locked native `pkg add -f` refusal **PASS** only for _76 |
| Web/configd `firmware unlock` → `pkg unlock -y` | Privileged native metadata unlock before subsequent pkg | **NO**: explicit ability to remove the metadata lock | Route source verified; real old-package Web Unlock + unsafe pkg **NOT TESTED** |
| Web/configd `firmware update` / `upgrade` → `opnsense-update` | Broad privileged firmware update, possibly many packages | **NO** per-plugin FD9 gate demonstrated | Source verified; actual plugin effects **NOT TESTED** |
| Scheduled `auto-update` → `/usr/local/etc/rc.firmware -r 1500` | Privileged scheduled firmware update | **NO** per-plugin FD9 continuity demonstrated | Source verified; unsafe-owner effect **NOT TESTED** |
| Arbitrary root `pkg add -f` / `pkg upgrade` / `pkg delete` | Native pkg without a managed gate | **NO** unavoidable global plugin veto proved | Unlocked forced add mutates (_74); locked forced add refuses (_76); other variants **NOT TESTED** |
| Proposed Zapret-managed CLI/Web upgrade adapter | Not implemented; would need a veto before native pkg | **NOT IMPLEMENTED**: must prove a single nonrecursive old FD9/process/IPFW/Config admission held through pkg or equivalent | **DESIGN ONLY, NOT TESTED** |

**Available before pkg, but not atomically held:** installed old pkgdb identity and file bytes/modes, old status and FD9/journal, Config bytes, process census/PID identity, restart markers, IPFW rules. No observed coherent snapshot is guaranteed while other Apply/Start/Stop or privileged Web actions can execute. OPNsense firmware progress flock is a different lock and supports an unlocked mode; `pkg lock` can be undone by privileged stock Unlock. An external FD9 lock might conflict with authentic package hooks which attempt to lock the same resource, so it must not be assumed nonrecursive.

## Stage 2.23 decision and next empirical gate

**No existing stock OPNsense Web/firmware/pkg route has been qualified as a supported, owner-safe Zapret updater.** Neither a `pkg lock` snapshot nor a rewrite of incoming `+PRE_INSTALL` qualifies LH-08/AC-11. A dedicated managed path is a candidate, not a selected implementation. Do not modify global firmware or assert that merely declaring direct-root operations unsupported makes the ordinary Web route safe.

Next, on **disposable native OPNsense only**, separately prove or disprove real stock firmware Unlock of the genuine locked `0.6.2_1` old package under the _76 orphaned-rule/Status=2 condition, and a prospective continuous old FD9 admission-to-pkg interval with authentic hook calls. Record actual pkgdb, Config, markers, service bytes, PID/IPFW and archive SHA *before any test-rule cleanup*. Include busy FD9 and concurrent owner negatives. Only if a real supported entrypoint can guarantee denial **before native pkg mutation** should Stage 3.04/3.24 implement it and then revise all four hooks. Otherwise STOP.

**Evidence honesty:** this _77 change adds no new native experiment and publishes no new package. It classifies precisely the existing _48/_73/_74/_76 outcomes; LH-08/AC-11 and final one-package-SHA Stage 4 acceptance stay OPEN.
