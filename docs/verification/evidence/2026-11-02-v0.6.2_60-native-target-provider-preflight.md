## Why the production wrapper is not yet safely swappable

The existing production `scripts/build-pkg.sh` still evaluates the Makefile through a private `sed` parser, manually resolves `dep_origin()`, writes a hand-crafted `+MANIFEST` and `pkg-plist` with fabricated dependency versions `0`, invokes `pkg-static create`, and blanket-chmods staged scripts. The old `.github/workflows/ci.yml` and `.github/workflows/release.yml` *both execute it under stock FreeBSD 15.0*, not target OPNsense. The old `scripts/test_freebsd15_package_ci.py` positively asserts manual builder internals and fixed `python313`. Changing only `build-pkg.sh` would break CI and release and does **not** satisfy the native specification; leaving both package engines running is not allowed by Stage 2.19–2.28.

The approved next cutover therefore must be atomic: target OPNsense bootstrap and signed repo provider qualification; `Makefile` target runtime/build dependencies with native `PLUGIN_PYTHON` evaluation, no fabricated versions; one thin `scripts/build-pkg.sh` official `Mk/plugins.mk` adapter; signed private current `curl-impersonate` staging already proven in [`_59`](2026-11-02-v0.6.2_59-signed-private-native-mk.md); preservation of four manually staged hooks; retire old make-parser/plist/pkg-static/chmod; rewire both CI build and release packaging workflows to real OPNsense; replace positive tests for obsolete hand-builder details. Preserve the CLI and `dist/` artifact interface. **Do not activate release publication or automatically install a production candidate until later native installed/replacement/rollback gates pass.**
