**Scope:** `v0.6.2_31`, source-only, based on merged `v0.6.2_30` main `8e7ec1d4844de82414252607b60c62f8599cd867`. Approved specification and per-file plan retain editorial **v1.3**. Stage 0 OPEN / Stage 1 BLOCKED. No new package or owner-appliance action.

## Observable defect in existing read-only witness

The previously qualified [`_29` installed-predecessor checker](../../../scripts/stage0-installed-predecessor-readonly.py), after the [`_30` native JSON/pkgdb correction](2026-11-01-v0.6.2_30-stage0-native-pkgdb-format-qualification.md), accepted an installed manifest with `abi=FreeBSD:15:amd64` **even if its `arch` differed** from the SHA-verified published original. It also never compared `origin`, and accepted an additional, unexpected installed lifecycle hook whenever the four expected hook bodies matched. This left a provenance gap before qualifying any genuine installed predecessor / service / FD9 experiment.

## Bounded correction

The unchanged published `os-zapret2-restyle-0.6.2_1.pkg` SHA-256 `1e21fbcac847529b94fea940241b4da7f86a42d33c129b7003ad04a72f4e5a0f` remains the source of truth. The read-only `verify_data()` consumer now requires:

- exact nonempty archived and installed `arch` and `origin` matching **even if installed `abi` is present and correct**; an absent installed ABI still requires the independently observed `pkg config ABI` and exact archive architecture;
- exactly the expected four lifecycle-hook **names** in both archived and installed manifests, with no extra/missing scripts, and unchanged byte-for-byte hook bodies;
- previously required package name/version, OPNsense product and package ABI, virtual guest, installed service bytes/0755 mode and `pkg which` owner.

The [offline predecessor tests](../../../scripts/test-stage0-installed-predecessor-readonly.py) now include negative cases for contradictory/missing `arch` and `origin` and extra archived/installed hooks. The existing [native FreeBSD15.1 real `pkg` roundtrip](../../../scripts/stage0-installed-pkgdb-native.py) remains the positive fixture for `origin`/architecture and actual installed hook identity; its CI changed-path selector now responds to changes in the read-only verifier itself.
