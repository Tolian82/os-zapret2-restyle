## Code-verified causal boundary (do not guess user data size)

`SharedApplyEnvelope.php` currently enforces exactly **65,536 bytes** for URL-safe Base64 of JSON `{page, fields, sync}`. `SettingsController.php` builds `fields` by taking the **whole value of each changed leaf** (including User Domains) rather than only newly appended entries, and the original privileged `shared_apply_request.php` enforces a corresponding 65,536-byte request limit. The exact user's User Domains length has **NOT** been measured and raw domain content was not collected. This is an independent **transport-size** failure, not proof of invalid domain grammar. A single short added line can push an already-large changed list beyond the bounded configd argument envelope.

**Remediation requirement:** make real edits to existing large User Domains reliable with safe bounded transfer without simply increasing configd argument cap, bypassing the original FD9 or creating a second Config writer; preserve WAN-first, owner/process/IPFW safeguards, model semantics, normalized Python content, exact-failure rollback and untouched large saved lists. The design may choose one narrow secure staging/transfer mechanism after reviewing existing native boundaries; avoid new speculative infrastructure. Once fixed, one focused real Apply/saved Config/managed HOSTLIST acceptance path on owner OPNsense is the decisive gate. A repeat of the existing long Lab matrix is not required.
