# v0.4.0_23 Model C owner-live evidence — HOLD for source-port corrective

## Status

`v0.4.0_23` proved that production Model C works on the owner appliance, but it is **not
accepted as the final source-port behavior** because a second live run reproduced the
controlled-source-port collision boundary and amplified it through the fallback chain.

## Successful Model C path — `job.FaLtIk`

Target/mode: `rutracker.org`, Extended.

- Stage 60 execution model: `C-warm-bucket-source-port-dispatch`.
- 16/16 candidates completed; `graph_exhausted`.
- Working Stage-60 candidates: `seqovl-host`, `seqovl-midsld`.
- Model C used one physical warm `dvtws2` worker per bucket.
- Multi-candidate batches observed the expected candidate overlap and exact selector source
  ports/rule ownership.
- No fallback was required.
- Stage 70/80/85 completed and the final result was successful.
- Stage 90 restored the original normal Zapret2 runtime.

This establishes that the one-worker source-port dispatcher is viable in real production
Stage 60.

## Collision / timeout path — `job.G0wC5l`

Target/mode: `telegram.org`, Extended.

Network precheck: IPv4 available; IPv6 unavailable; QUIC/IPv4 closed. IPv6 and QUIC work was
therefore excluded from this run.

Stage 60 evidence:

- top-level preferred model remained `C-warm-bucket-source-port-dispatch`;
- first warm batch failed with:
  `Model C unavailable (controlled source port is already in use: 42004); Model B fallback failed (controlled source port is already in use: 42004)`;
- the same static concrete source-port plan was passed from Model C into Model B;
- warm execution was disabled and the stage continued as `A-cold-fallback`;
- 13 candidates completed, zero winners;
- `stopped_reason=insufficient_stage_budget` and the orchestrator reported Stage-60
  `TIMEOUT`.

Lifecycle evidence is clean and exact:

- initial state `RUNNING`, final state `RUNNING`;
- semantic restoration is therefore exact `RUNNING -> RUNNING`;
- child and supervisor running before and after;
- runtime args hash unchanged;
- effective config hash unchanged;
- normal firewall hash unchanged;
- `temporary_runtime_clean=true`.

Therefore this run is **not** evidence of a Stage-90 restoration defect. It is evidence that
a foreign/stale use of one deterministic `420xx` source port can disable both warm models
when they share the same concrete plan, forcing the much slower cold path until the current
Stage-60 budget expires.

## Corrective decision

The next packaged corrective is `_25` (owner instruction; `_24` is intentionally skipped).
It must retain exact source-port attribution but lease a free concrete source port for each
admitted warm batch, skip foreign port owners without destructive action, and make Model B
perform a fresh lease if Model C falls back.

Timeout values are intentionally not increased as part of this correction.

## Follow-up budget design explicitly retained

After source-port collision amplification is removed, Strategy Lab budget should become
adaptive to the **actual eligible work matrix**:

`number of endpoints × IPv4/IPv6 × TLS/QUIC × Generic UDP × Standard/Extended mode`.

If IPv6, QUIC or Generic UDP are available/selected, the job should automatically receive a
finite additional budget proportional to the work it can actually perform. Do not replace
this design with one guessed oversized static timeout.
