## Observable scenario and narrow implementation

_118's `status` returns only a **local, unsigned operation record**. It is not a trustworthy independent witness reply after a lost commit response. This increment defines and checks an **offline simulated signed response**; it is a CI protocol primitive, not deployment.

New `scripts/stage3-prepkg-signed-status.py` verifies a byte-exact RSA-SHA256 detached signature with OS OpenSSL and an exact caller-provided expected public PEM SHA-256. The strict 12-field response binds a CI-only issuer, repository, 64-lowercase-hex operation ID, payload SHA, checkpoint SHA, positive checkpoint sequence, expected witness sequence, 64-hex challenge, `RESERVED`/`CONSUMED`/`ABORTED` action, issued and expiry timestamps. The maximum signed window is 120 seconds; current time is explicitly caller-supplied and **not independently trusted**.

The source imposes input-size caps, strict JSON duplicate-key rejection, exact schema/no extra fields, integer-not-Boolean checks, exact expected digest equality and exact RSA signature verification **before** status interpretation. The CLI accepts only a `ZAPRET2_CI_SIGNED_STATUS_ONLY=1` opt-in and private regular single-link `0600` files through `O_NOFOLLOW` descriptor reads. It runs no network client, package transaction or appliance mutation. Its output deliberately declares all remote/production/clock/replay/atomicity claims `false`.

## Security limitations — NOT a supported update gate

- The witness signer/private key and expected public-key hash are generated inside CI, not by a separately approved operator; the response is not obtained over an independently authenticated network transport. This proves cryptographic byte binding only.
- A repeated identical signed reply with the **same challenge** remains valid. There is no server-issued fresh nonce, trusted challenge provenance, replay cache, independent clock, durable off-host monotonic checkpoint, current revocation oracle or true cross-store transaction.
- A signed `CONSUMED` state is a *test event*, not authoritative proof that real `pkg` was safely invoked or the original FD9 remained owned. No production seed, current hooks or managed Web/firmware/CLI updater is connected.
- Direct privileged root `pkg add -f` still bypasses the hypothetical gateway and is unsupported for protection claims. **LH-08 / AC-11 BLOCKED.**
