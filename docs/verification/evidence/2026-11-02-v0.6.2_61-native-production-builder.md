## Production cutover and observable result

The sole `scripts/build-pkg.sh` is now a thin fail-closed OPNsense CI adapter executing [the native package driver](../../../scripts/native-opnsense-package.py). Old hand-built `pkg-static create`, `dep_origin()`, `version:0` fake provider metadata, internal manifest/plist generation, `sed` Makefile evaluation and blanket script chmod are **removed**; there is **no second production packaging engine**.

The driver requires an **explicit opted-in disposable OPNsense 26.7 / FreeBSD:15:amd64** guest, exact authenticated project Git SHA, pinned unmodified official `opnsense/plugins` SHA `79a5f88b7b27a706c10511ea5587c9d0e0dbdced`, legitimate generic OPNsense-owned Python, and actual signed target repository providers. Makefile now derives its installed minor via **native `PLUGIN_PYTHON`**, not a fixed `python313`; explicit installed runtime/build dependencies `python<PLUGIN_PYTHON>`, `gmake`, `pkgconf`, `luajit`, `git`, `jq`, `ca_root_nss` must all match installed package names/origins and actual versions. No fake origin or version, no FreeBSD system repo fallback on the appliance, and no `pkg install` from the production wrapper. Target repo bootstrap is restricted to isolated CI and named OPNsense providers.

The same signed **FreeBSD `latest` private extraction only** as [_59](2026-11-02-v0.6.2_59-signed-private-native-mk.md) stages real `curl-impersonate` ELF, signed source and binary digests, diagnostic Chrome version, licenses and original two executable private launchers within the **temporary official upstream source tree**. Real target `ldd` must resolve all shared libraries to base or installed OPNsense package providers, and actual launcher Chrome/ECH-off loopback invocation is required. Genuine `make package` runs against official upstream and four unmodified authoritative manual pkg hooks. The final archive validator checks exact source bytes and all native staged entries, generated project SHA marker, original hook phase/serialization, executable 0755 mode for service/private ELF/launchers, and real package dependency names/origins/versions. Only after verification does it copy the exact archive into the existing `dist/os-zapret2-restyle-0.6.2_61.pkg` contract. Its SHA-256 is computed from final bytes, not inferred from source commit.

Both **CI package job** and **release build job** now use real OPNsense 26.7 KVM (not stock FreeBSD 15.0), native provider provisioning, source-SHA-bound build and `copyback: true`; obsolete FreeBSD 15 `python313`/manual-builder positive tests are rewritten while retaining unrelated Strategy Lab Model-C tests and historical lifecycle regression tests. Existing Release and Pages output shape is preserved for a future **explicitly approved** release. The release validation is **fail-closed until an independently accepted installed-product proof file exists** (`docs/verification/evidence/native-product-installed-acceptance.json` with true closure/admission/publication flags). That acceptance record is intentionally not present or fabricated in this increment. Publishing the source-only candidate is forbidden.
