## Proven integration cause for HOSTLIST failure

Current `domain_policy.py` explicitly accepts `!`/`^` in local include lists. However `src/opnsense/mvc/app/models/OPNsense/Zapret/Zapret.xml` retained `Mask` which accepted only `a-zA-Z0-9.*-\n\r\s`. The native Model's `performValidation(false)` runs in GUI preflight and the privileged `SharedConfigCommit::validateOwnedModelFields` under FD9, rejecting the modifiers before use. Existing Python-only and shell-adapter tests did **not** exercise this integrated model path: green isolated tests did not demonstrate the actual user action.

**Owner-approved architecture change:** canonical `domain_policy.py` for domain content and `ipset_policy.py` for IP/CIDR content. Remove competing native Model Regex `Mask` only on the nine actively Python-governed lists (YouTube/User/Exclude Domains and six IPSETs). Keep native OPNsense Model types/fields, WAN InterfaceField, numeric/PortField, enum/BooleanField, `setNodeByReference()`, `serializeToConfig()`, `Config::save()`, one Config writer and original FD9. The root privileged worker rechecks edited list semantics with the same bridges **before native save** even when GUI was bypassed. Unchanged older lists are not silently rewritten. Final native strategy validation stays `dvtws2 --dry-run` and cannot prove DPI bypass.
