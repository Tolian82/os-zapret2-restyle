- `opnsense/core` `stable/26.7` at Git SHA `ac08367416c1d66dea87df0ef0de24c315b5d5bc`, [`plist`](https://github.com/opnsense/core/blob/ac08367416c1d66dea87df0ef0de24c315b5d5bc/plist) **line 3** explicitly includes `/usr/local/bin/python3`. This source indicates the OPNsense **core** package installs the generic path, but is not evidence that `pkg which` identifies it on the user's device.
- `opnsense/plugins` `stable/26.7` at Git SHA `79a5f88b7b27a706c10511ea5587c9d0e0dbdced`, [`Mk/defaults.mk`](https://github.com/opnsense/plugins/blob/79a5f88b7b27a706c10511ea5587c9d0e0dbdced/Mk/defaults.mk) lines **45–54** executes actual `opnsense-version -a` *if present*, otherwise substitutes a **fallback 26.7** (not acceptance). Lines **68–79** use `/usr/local/bin/python3 -V` to derive `PLUGIN_PYTHON`, and missing link cannot be bootstrapped merely by declaring `PLUGIN_DEPENDS`.
- The same upstream [`Mk/plugins.mk`](https://github.com/opnsense/plugins/blob/79a5f88b7b27a706c10511ea5587c9d0e0dbdced/Mk/plugins.mk) lines **140–150** obtains real dependency package names, versions and origins from `${PKG} query`; missing installed package exits nonzero. The current bespoke manifest's version `0` placeholders are not a valid native substitute.

- Six offline tests reject missing required candidates, fake directory identity, absent generic Python, missing native `pkg` provenance, unsafe filename links, and verify variant `git-lite` fallback matching independently of version numbers. GitHub CI downloads immutable raw GitHub source SHA paths plus the live public mirror index; this is a **read-only source provenance comparison** and uploads JSON without binaries or private owner data.
