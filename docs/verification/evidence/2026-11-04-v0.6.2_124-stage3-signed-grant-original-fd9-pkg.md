## New actual control before the real pkg boundary

New `scripts/stage3-native-configd-operator-grant-ci.py` issues an ephemeral detached RSA SHA-256 operator signature in the **CI controller before configd launch**. It measures the published old package and exactly selected current official-Mk-built unpublished successor, binds explicit `source_commit`, exact old/new version, measured package SHA-256, `RESERVE` action and exact operation/payload/checkpoint identity. Operator private signer and separate ephemeral status role private signer are deleted **before handing off FD9**. The detached worker receives only a root-owned `0700` private directory, public key and signature; expected trust/identity digests are in a separate, owner-only `0600` authorization-role file. The historical configd control ticket stays under its **unchanged 500-byte limit**. The status and client SHA roles in this fixture are **synthetic**; no TLS peer or off-host status signer is operated in this test.

The existing `stage3-native-configd-fd9-handoff.py` requires the signed grant ticket when `ZAPRET2_STAGE3_NATIVE_MUTATING_PKG=1`, retains exact configd/worker PID and original FD9 ownership contract, and requires the worker to report signed grant validation. `stage3-native-configd-mutating-pkg.py` now rejects missing/foreign grant tickets **before any actual pkg**. Inside the same detached worker, the grant verifier repeatedly calls the **authentic original FD9 independent-lock checker**, verifies exact raw signature and re-measures both old/new archives, proves correctly re-signed false old/new digest and foreign source commit refused, and checks matching single `RESERVE` operation identity. Immediately before the actual `delegate.admitted_pkg_dispatch`, the same worker under the same original FD9 performs the **entire signed grant verification again**. The existing original old-owner cold check still runs immediately before `pkg`; the historical old hook uses its pre-existing one-use lock delegation without editing its bytes. A real native install in a disposable VM remains eligible only after both distinct checks pass.

The existing late-journal negative under the transferred FD9 must continue to deny **before the actual pkg dispatcher**, with unchanged original installed package, Config, marker and IPFW state. The grant files are cleaned only when their names/modes/owner and containing directory match; unknown files are not erased. Scope changes to CI scripts and its workflow only.
