## Scope and upstream provenance

Earlier [_43](2026-11-01-v0.6.2_43-orphaned-unlock-kill.md) showed test-child SIGKILL leaves private pkg unlocked and privileged direct pkg delete bypasses the unlocked window. [_44](2026-11-01-v0.6.2_44-fresh-process-pkg-recovery.md) showed a new Python process on an already-running guest can relock unchanged private fixture but must refuse absent/tampered/unknown state. Neither established a real OS reboot.

The official [OPNsense boot documentation](https://wiki.opnsense.org/development/backend/autorun.html) provides the /usr/local/etc/rc.syshook.d/start directory. Official [OPNsense core stable/26.7 /etc/rc](https://github.com/opnsense/core/blob/stable/26.7/src/etc/rc) executes rc.syshook start after network initialization. The pinned [vmactions/opnsense-vm implementation](https://github.com/vmactions/opnsense-vm/tree/abaa977e3dbc77a0d1eeed4d82c8d9914b018235) implements cache-after-prepare with an actual clean VM shutdown followed by new QEMU boot before the run command. This must NOT be disabled with disable-cache=true. A prepared disk image may be reused by subsequent CI runs, which does not independently authenticate its upstream bytes.

## Observable native scenario

On disposable OPNsense 26.7 FreeBSD 15 amd64 KVM only, install the immutable published genuine os-zapret2-restyle-0.6.2_1.pkg for read-only original old service/FD9/native pkgdb/four-hook/IPFW provenance. Never start, stop, update or delete this original plugin, or touch production gateway/firmware.

All package add/lock/unlock/delete operations use a harmless DISTINCT synthetic package zapret2-stage0-sidecar-only-fixture, three root-owned 0700 private PKG_DBDIR/cache/payload directories and 0600 fsynced pending-intent records below /root/stage0-fresh-process-recovery-v0.6.2_45 on the disposable VM disk. The prepare command writes a kern.boottime witness, authenticates genuine original cold owner, installs three private synthetic packages, locks them, fsyncs an exact pending-intent record for each, then SIGKILLs ONLY its own child after private pkg unlock. All three native packages are still installed but unlocked.

The prepare command also installs ONE exact test-owned executable start-syshook file 99-zapret2-stage0-private-boot-witness that writes ONLY the current kern.boottime to an isolated root file. It does not run pkg, Zapret2, IPFW or any recovery command. Then the VM action cleanly shuts down the disposable VM and starts it again from the prepared qcow2. The run command refuses unless the new kernel kern.boottime differs from the old value AND the official start-syshook wrote exactly the new value. All original old published package proof and cold owner evidence are independently read back. Each private native pkgdb must still show its synthetic installed package unlocked across boot.

After the real guest boot, NEW independently spawned recovery interpreters from the previously qualified _44 module handle three cases:
- unchanged: verify durable record, real old cold owner and exact native private identity/payload; explicitly relock only unchanged private original, verify repeated recovery idempotent and direct pkg delete is refused while locked;
- direct_delete: after reboot delete a second unlocked synthetic package using genuine native direct pkg delete -y, then require fresh recovery exit 2/refusal, absent identity and NO false relock;
- tampered_intent: corrupt only the third private intent package name, then require fresh recovery exit 2/refusal and unchanged-but-unlocked native package.

Finally remove ONLY the exact original test-owned boot witness, never unrelated OPNsense syshooks. The unit suite covers wrong boot IDs, wrong syshook marker, ownership/mode/symlink, historical cold Status, exact disposable scope and no product-safety overclaim.
