## Observable operator trust gap

_108–_110 enforce a signature/key/code/expected commit chain **only after** a caller independently pins the verifier source, public key and expected commit. In previous CI, every pin came from the *same checkout and ephemeral CI signer*. The exact check works, but **who authorized these values in a real operator setting is not established**. Generating another key, checking a digest downloaded alongside the binary, or setting `operator_signer_authenticated=true` just because CI passes would be a security error.

_111 introduces a **separate, explicit, private operator pin receipt workflow**, with no self-certifying publisher claim. The receipt exists *outside* the incoming `.pkg`; an interactive operator must supply eight values based on independent review/source:

| Field | Required independently reviewed meaning |
|---|---|
| `seed_sha256` | Expected bytes of the first `python -I -B -c` trust seed |
| `verifier_sha256` | Expected bytes of the RSA-claims verifier executed only after seed check |
| `public_key_sha256` | Expected exact authorized public PEM bytes; not a key from the package |
| `source_commit` | 40 lowercase hex source commit explicitly selected for this operation |
| `incoming_version` / `incoming_sha256` | Target version and exact incoming native archive digest |
| `predecessor_version` / `predecessor_sha256` | Installed old version identity and separately authenticated original archive digest |

**Actual execution:** `scripts/stage3-prepkg-operator-approval.py` provides only `record` and `inspect`, never `upgrade`, `pkg` or signing. It runs only as root on FreeBSD amd64 and requires a human-accessible input/output TTY to record pins with a final exact `APPROVE <commit> <version>` phrase. It refuses placeholders, malformed version/hash/commit fields, source==predecessor, duplicate/missing JSON keys, untrusted path or mode, symlinks and overwrites. The output is a single exclusive, `0600` root-owned file `/root/<private-0700-parent>/operator-pins.json` with `schema=zapret2-prepkg-operator-pins-v1`, fixed repo identity and **`trust_status=PINS_RECORDED_NOT_AUTHENTICATED`**.

The separate `inspect` path **does not execute** any archive/seed/verifier bytes or signed manifest. It checks the root-owned private JSON receipt and single-link `0600` staged seed, verifier, `approved-public.pem`, incoming archive and original archive against the eight entered pins using SHA-256 over one stable opened FD per file; it also checks exact expected archive filenames/versions. It returns `PASS_RECORDED_PINS_AND_PRIVATE_BYTES_ONLY` and explicitly `operator_source_authenticated=false`, `signer_authenticated=false`, `signed_manifest_verified=false`, `pkg_invoked=false`, `pkg_authorized=false`, `lh08_ac11_accepted=false`. **The receipt is not currently consumed by the _110 seed or a managed updater**; its addition alone cannot authenticate a signer or guarantee future automatic admission.

## Operator usage boundary (read-only / no installs)

Before running even this helper, the operator MUST independently authenticate **this helper's own source bytes** from a trusted, reviewed distribution channel; do not execute an untrusted downloaded script as root. Stage files privately under `/root` with directory mode `0700` and individual file mode `0600`. On a qualified, explicitly authorized test environment only, the two command shapes are:

```text
python3 -I -B <independently authenticated operator approval helper> \
  record /root/private-review/operator-pins.json

python3 -I -B <independently authenticated operator approval helper> \
  inspect /root/private-review/operator-pins.json \
  /root/private-review/stage3-prepkg-trust-seed.py \
  /root/private-review/stage3-prepkg-verified-eval.py \
  /root/private-review/approved-public.pem \
  /root/private-review/os-zapret2-restyle-0.6.2_111.pkg \
  /root/private-review/os-zapret2-restyle-0.6.2_1.pkg
```

**Illustrative syntax only; no installed owner-appliance procedure is authorized.** There is no endorsement of any production key, 40-hex source commit, public-key hash, seed hash, archive digest, signer or distribution channel in this repository. Human typing is not an independent cryptographic issuer attestation. This is a method for keeping operator-supplied values separate and refusing obvious substitution/replay during one operation, not an assertion that the values are legitimate. Never fill fields from the claims, new package, adjacent checksum or test CI signer. Never infer product acceptance from a successful `inspect`.
