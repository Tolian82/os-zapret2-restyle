## Defect diagnosis

`v0.4.0_10` added RSS collection to the FreeBSD candidate system adapter. The adapter's
`snapshot` action correctly emits numeric `rss_kb` after validating the candidate PID.

The Python candidate runtime then calls `_runtime_snapshot()` from `_readiness()`. The
snapshot contained `rss_kb`, but `_readiness()` reconstructed a smaller readiness object
and copied PID, executable, command, divert port, process/socket readiness and fatal-log
state without copying `rss_kb`.

That reconstructed object became both `candidate-runtime/readiness.json` and the
`runtime` object persisted in every candidate result. Consequently all 25 Model A samples
reported `rss_kb=null`, and the summarizer correctly kept the reference
`inconclusive` with only `rss_observed` missing.

## Corrective handoff

The next packaged candidate must make one logical correction only:

1. propagate `snapshot.rss_kb` through Python readiness evidence;
2. preserve `rss_kb=null` when no snapshot is available;
3. add a candidate-runtime regression proving a numeric adapter RSS value survives into
   persisted candidate evidence;
4. keep Model A coverage semantics unchanged;
5. do not promote Model B/C or change search/runtime behavior.

After the correction is installed, one comparable Standard `rutracker.org` run is
sufficient for the first recheck. If RSS is present and the other already-observed
coverage remains available, `model-a summarize` should be able to return
`reference_collected`.
