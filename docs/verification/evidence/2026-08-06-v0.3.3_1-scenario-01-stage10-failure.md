# v0.3.3_1 live scenario 1 stage 10 failure

## Context

- Tester: repository owner
- Date: `2026-08-06`
- Appliance: OPNsense `26.7.1_1` on FreeBSD `15.1-RELEASE-p1 amd64`
- Package: `os-zapret2-restyle-0.3.3_1.pkg`
- Scenario: standard blocked-domain check with Zapret2 initially running
- Observed job: `job.vNAhsL`

## Result

Scenario 1 did not reach network testing. Stage 10 (`lifecycle_snapshot`) failed immediately with:

```text
Zapret2 is in an incomplete or unknown state.
```

The terminal job state was `error`, outcome `ERROR`. Stages 20–85 were skipped. Stage 90 reported that no Zapret2 state changes had been performed.

## Appliance evidence

The normal runtime was actually healthy:

- dvtws2 PID file: `5968`;
- supervisor daemon PID file: `52162`;
- supervisor monitor PID file: `53321`;
- dvtws2 process PID `5968` was running;
- `supervisor_loop.sh` process PID `53321` was running;
- `/usr/local/etc/zapret2/runtime-v2/dvtws.args` existed;
- `/usr/local/etc/zapret2/zapret.conf` existed;
- normal IPFW rule `19000` existed;
- no Strategy Lab rules `19100–19131` remained after the failed attempt.

## Root cause

FreeBSD `ps` excludes processes without a controlling terminal unless `-x` is specified. The process identity checks queried daemon-managed dvtws2, supervisor, Strategy Lab worker, and circular owner PIDs without `-x`. The semantic snapshot therefore treated the two healthy daemon processes as absent.

The same calls also omitted unrestricted command width, which could truncate identity evidence.

## Corrective requirement

Candidate `0.3.3_2` must:

- include no-TTY processes with `ps -x`;
- request full command width with `-ww`;
- apply the correction consistently to every related PID identity path;
- pass a regression test that simulates FreeBSD omitting daemon processes without `-x`;
- repeat scenario 1 on the owner appliance.

This record is a failed live attempt, not a scenario PASS.
