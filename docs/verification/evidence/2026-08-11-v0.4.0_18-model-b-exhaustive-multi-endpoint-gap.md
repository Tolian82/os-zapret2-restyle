# v0.4.0_18 owner-live evidence — exhaustive benchmark multi-endpoint input gap

Date: 2026-08-11
Tester: repository owner
Target: `telegram.org`
Testing line: `v0.4.0_18`
Result: **EXHAUSTIVE BENCHMARK INPUT-CONTRACT REJECT; RESTORATION PASS**

## Purpose

`v0.4.0_18` added the first experiment-only batched exhaustive Model B benchmark. The
owner-live goal was to create a fresh complete Standard no-candidate cold reference and
then replay the exact Stage-60 corpus through Model B warm batches.

## Standard cold-reference preparation

An initial ordinary Standard run, `job.qtLmTY`, remained within the normal 150-second
search budget. It ended truthfully with `TIMEOUT` after Stage 60 completed 15 candidates:

- `working=[]`;
- `stopped_reason=insufficient_stage_budget`;
- the 16th candidate was not admitted without the full bounded execution/termination/
  cleanup/guard envelope;
- Stage 90 restoration was verified.

This was safe but deliberately not accepted as the exhaustive benchmark reference because
its Stage-60 corpus was partial.

The owner then created measurement-only Standard job `job.tMYnFA` with
`STRATEGY_LAB_STANDARD_BUDGET=210`. The override was scoped only to creation of this
reference job and was removed immediately after launch. Normal product defaults were not
changed.

`job.tMYnFA` completed with:

- state `completed`;
- outcome `NO_CANDIDATE`;
- target `telegram.org`;
- mode `standard`;
- Stage-60 `total_available=16`;
- Stage-60 `completed=16`;
- `working=[]`;
- `stopped_reason=graph_exhausted`;
- `partial=false`;
- persisted candidate count `16`;
- persisted schedule count `16`;
- restoration `verified=true`;
- initial state `RUNNING` -> final state `RUNNING`;
- `strategy_unchanged=true`;
- `temporary_runtime_clean=true`.

The live Stage-00 presentation for the target listed the required endpoints as
`telegram.org` and `web.telegram.org`.

## `_18` exhaustive attempt

The owner ran:

`strategy_lab_model_b_exhaustive.sh job.tMYnFA /root/model-b-exhaustive-job.tMYnFA.json`

The launcher completed normally and produced a report, but the measurement conclusion was
`reject`. The relevant report fields were:

- `reference=null`;

- final `conclusion="reject"`.

No warm batch or candidate probe was started. Therefore this result does **not** reject
Model B coexistence or warm-candidate equivalence.

## Root cause

The `_18` exhaustive implementation and its synthetic regression required exactly one
search-epoch binding. That matched the earlier single-endpoint Model B coexistence fixture
but not a real worst-case target such as `telegram.org`, whose fixed search epoch contains
multiple required endpoints.

The benchmark must preserve the actual Strategy Lab candidate semantics: a target-bound
candidate applies to all required endpoint names, every pinned endpoint is checked against
its fixed selected IP, and candidate `all_pass` is true only when all required endpoints
pass.

## Corrective selection

`v0.4.0_19` is selected as the narrow corrective:

- accept and validate one-or-more pinned endpoint bindings;
- write every reference endpoint to target-bound warm-worker hostlists;
- replay all pinned endpoints sequentially for every candidate;
- preserve endpoint-level attribution and candidate-level `all_pass` equivalence;
- add a two-endpoint focused regression;
- keep production Model A, worker width, sequential-probe policy and normal budgets
  unchanged.

Fresh complete reference `job.tMYnFA` should be reusable after `_19` installation if its
persisted Zapret2 `ResourceInventory` still matches the installed inventory.
