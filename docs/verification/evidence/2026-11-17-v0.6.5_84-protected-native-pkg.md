## Qualified execution — one identical archive in one disposable guest

The old/current installed plugin owns its original FD9 for service preparation and restoration, while ordinary FreeBSD `pkg -o REPO_AUTOUPDATE=false add -f` runs only after that descriptor is released; original native package hooks execute unchanged. A private, root-owned durable record binds the staged package bytes, target version, previous RUNNING/STOPPED state and guarded handoff. `+POST_INSTALL` defers automatic restart when that record exists. Success requires native successor identity, hook receipts and full service-verified restoration under original FD9, not `pkg` return code alone.

- `NATIVE_PROTECTED_STOPPED`: `protected_update_rc=0`, STOPPED before/after, same package hash, native pkgdb identity and original Config unchanged, no final update record or restart marker.
- `NATIVE_PROTECTED_PENDING_REFUSAL=PASS`: injected incomplete product-owned operation blocked a second update **before** another `pkg` invocation and without changing Config.
- `NATIVE_PROTECTED_LIST=PASS_COMMON_STOP_PKG_BOOT`: actual common engine was RUNNING, original engine/monitor were stopped through the native owner, actual `pkg` ran and a *new* engine PID became RUNNING. The original committed common journal ID was preserved, as required for a non-Auto-detect cold boot; Config/pkgdb/guard all verified.
- `NATIVE_PROTECTED_AUTO_PREFLIGHT`: native Strategies Apply explicitly enabled Auto-detect, its old observer epoch file existed and service was RUNNING.
- `NATIVE_PROTECTED_AUTO=PASS_COMMON_STOP_PKG_BOOT`: previous original Auto-detect epoch retired, new journal ID and `epoch.json` committed, new engine PID running, Config SHA and native package version unchanged; `protected_update_rc=0`, no leftover update record or restart marker.
- `NATIVE_PROTECTED_PREMATURE_FINISH=PASS_REFUSED`: the native FD9 finish command refuses **before** real pkg, even when the prior pkgdb version equals the target version. Comparing versions alone is insufficient.
- `NATIVE_PROTECTED_INTERRUPTED_BEFORE_PKG=PASS_RECORD_GUARD_FD9`: after real FD9 prepare/stop, a durable `prepared` record rejects new Start, Apply and repeat update without replacing package bytes or modifying Config.
- `NATIVE_PROTECTED_INTERRUPTED_AFTER_PKG=PASS_GUARDED_STOPPED`: after genuine pkg extraction/POST_INSTALL but before FD9 finish, the SAME private journal changes to `postinstall-attested` through the installed native hook and original service FD9. New Start and repeat pkg remain blocked; Config and STOPPED preserved.
- `NATIVE_PROTECTED_INTERRUPT_HANDOFF=PASS_REAL_NATIVE_PKG`: a separate explicit successor FD9 finish verifies same archive, installed version, old Auto epoch retirement, new committed epoch/new dvtws2 PID, restored RUNNING, preserved Config and removal of both guard journal and restart marker. No second witness, external installer or automatic recovery.
- **Fix for false same-version success:** the real native `+POST_INSTALL` marks its completion inside the existing root-private `operation.json` under original FD9. `pkg-update-finish` requires this exact phase, rejecting a premature invocation or missing real hook. Failure to complete the hook remains durable `requires-review`/prepared state; this protects against pkg's observed failure to abort on refusing PRE_INSTALL.
- Exact source-specific **bug corrected**: `shared_apply_boot_service()` had compared all output from `shared_apply_execute_service` to one `applied-id`. The native PHP Config worker first prints the `unchanged` JSON receipt on saved-unchanged Boot, then the terminal `applied-id`; the new exact two-line parser independently requires correct JSON shape, unchanged/false/zero fields and the matching 32-character operation ID. Seven negative offline receipt cases reject extra/missing lines, changed result, malformed JSON, invalid snapshot and wrong ID.
