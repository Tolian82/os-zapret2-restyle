## Baseline and reason

Real OPNsense 26.7 experiments established (a) original `PRE_DEINSTALL` and incoming `PRE_INSTALL` refusals do not reliably prevent destructive native pkg operations (`_36`/`_37`); (b) genuine original installed `0.6.2_1` cold Status can refuse a synthetic invalid journal before a fake package callback (`_38`); (c) an external original-style FD9 held during pkg causes incoming FD9 hook failures while pkg continues (`_39`); (d) an independent sidecar lock does not constrain direct pkg (`_40`); (e) a **native pkg metadata lock** on a harmless synthetic package prevents measured direct `pkg delete -y` and `pkg add -f` until explicit unlock (`_41`). These facts must not be conflated into a production-safe upgrade claim.

## Exact bounded new scenario

[Runner](../../../scripts/stage0-opnsense-pkg-relock-failures.py) is restricted to a newly created **disposable OPNsense 26.7 FreeBSD:15:amd64 KVM**. First install exact immutable published original `os-zapret2-restyle-0.6.2_1.pkg` in the disposable guest using the existing native original-predecessor installer and qualify installed native pkgdb, old service bytes/mode, SHA and all four original hook bodies. The original service is **never** replaced, removed, started, stopped, or modified here; neither IPFW nor configd nor official firmware files are changed.

Package mutations use an **entirely separate name** `zapret2-stage0-sidecar-only-fixture`, with only temporary `PKG_DBDIR`, pkg cache, native synthetic hooks and temporary payload. Install original private fixture `0.6.2_1`, set real `pkg lock -y` and verify it in pkgdb.

A qualified cold preflight is the existing bounded `stage0-opnsense-prepkg-readonly.py` snapshot against the real historical service: authenticated old installed archive and native pkgdb, original Status under its own private FD9, no journal/markers/PID/process evidence and uniquely **cold/unloaded** IPFW/IPDIVERT. Its report *must* say `safe_pkg_transaction_authorized=false`; our experiment does not alter that truth.

The three mandatory phases:

1. **Unknown owner denial before unlock:** inject only the previously qualified synthetic malformed common Apply journal; require authentic old installed service Status rc=2. Calling the model controller must refuse before `pkg unlock`; the synthetic original package must remain **both installed and locked**. Remove only the exact test-owned journal; original historical installed package must remain unchanged.
2. **Injected failure after unlock:** on a clean original cold snapshot, explicitly unlock only the private synthetic package; re-read authentic original cold snapshot and inject a deterministic refusal **before any private pkg replacement**. Require unconditional re-lock of original private fixture, verify private pkgdb and payload still old, and verify the lock persists. A missing/ambiguous package or failed re-lock is a **failed experiment**, never a safe recovery success.
3. **Successful synthetic replacement and re-lock:** recheck the same genuine old cold owner on both sides of explicit synthetic unlock, execute only native private-pkgdb `pkg add -f` of fixture `0.6.2_41`, verify native pkgdb/payload, and re-lock the **new** package in `finally`. A subsequent uncoordinated `pkg delete -y` of the locked successor must fail without altering the synthetic package. Finally re-authenticate the unchanged genuine original installed `0.6.2_1` and exact cold state.

## Important negative boundary

This design **does not implement a production transaction guard**. Between unlocking the private package and final re-lock, an independent privileged/root `pkg` can act on it; two read-only snapshots do **not** make this window atomic. The active RUNNING old service, foreign IPFW owners, missing Python, real concurrent root process, actual native successor package, full old/new hook phase order, Web firmware integration, interruption by real SIGKILL/power failure and rollback of partial native package mutation are **NOT VERIFIED**. A Python `finally` executes for handled Python failures, not for SIGKILL, power failure or kernel crash. Native pkg's direct `-f` variants and privileged explicit unlocking also remain a bypass boundary. No owner appliance modification, old package replacement or `FreeBSD.conf` rescue is allowed.

Even with all tests PASS, report **`production_transaction_guard_implemented=false`, `product_safety_acceptance_passed=false`, `stage0_closed=false`**. LH-01–LH-07 and Stage 1 remain OPEN/BLOCKED. The next scope must qualify privileged bypass and orphaned-unlocked crash recovery and a genuine package-manager-enforced owner preflight before any product rollout.
