## Important negative boundaries and remaining Stage 3/4 blockers

The tests still operate on disposable CI infrastructure. The approved operator grant **and its expected issuer/pin** are generated on the test runner; no actual owner trust root has been provisioned. The old package SHA is pinned from the published asset, but the incoming archive is **only a non-publishable Stage 2/3 native build candidate**, not an owner-installed successor. No proof that a `pkgdb` entry matches the specific grant exists beyond the separate already-qualified installed old predecessor steps, and this new standalone measurement is not a transaction lock.

A privileged attacker can swap **identical bytes** for a different inode; no read-only digest can prove exclusive identity or prevent a later replacement between the final measurement and actual `pkg`. The witness/DB/clock/operator keys are **still on the same CI runner** and root can roll them back, invalidate anti-replay history, or replace both trust inputs. No separately administered witness, out-of-band owner approval, real off-host monotonic store, uninterrupted original FD9 through a supported pre-pkg gateway, race-resistant cross-store atomic transaction or complete _74 native no-mutation qualification has been shown. **Never count this positive source/CI proof as LH-08/AC-11 or a safe production update.**
