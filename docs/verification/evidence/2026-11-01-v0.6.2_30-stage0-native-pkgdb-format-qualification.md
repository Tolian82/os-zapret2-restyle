# Stage 0.09 — Native FreeBSD pkgdb format qualification for predecessor provenance

**Revision:** source-only `v0.6.2_30` based on [`v0.6.2_29`](https://github.com/Tolian82/os-zapret2-restyle/commit/f0209f10c5c0a9bf7db9420d1f2beb1acdce8f51). The approved technical specification and per-file plan remain independent editorial **v1.3**. Stage 0 OPEN; Stage 1 BLOCKED.

## Why this is needed

The earlier [installed-predecessor read-only checker](../../../scripts/stage0-installed-predecessor-readonly.py) was verified only with synthetic Python dictionaries. Its actual consuming commands — `pkg info -R --raw-format json`, `pkg which -q`, installed package script bodies and file modes — had **not** been executed against a native `pkg` database. This bounded increment exercises these assumptions before any actual OPNsense owner or installed old-service lifecycle test.

## Native scenario and strict isolation

[`stage0-installed-pkgdb-native.py`](../../../scripts/stage0-installed-pkgdb-native.py) first reads the **real immutable** published `0.6.2_1.pkg`, requiring SHA-256 `1e21fbcac847529b94fea940241b4da7f86a42d33c129b7003ad04a72f4e5a0f`, and extracts the archived service only for hashing. It **never installs or executes that original package**.

Inside a disposable root FreeBSD **15.1 amd64** VM, it then creates a separate *synthetic* `os-zapret2-restyle-0.6.2_1` package with exactly four inert `#!/bin/sh / exit 0` scripts and a harmless executable file under a newly created private `/tmp` path. It installs this fixture using real `pkg add` with **only** temporary `PKG_DBDIR`, `PKG_CACHEDIR`, isolated payload paths and disabled repository auto-update. It obtains the actual native installed JSON metadata with `pkg info -R --raw-format json`, the file owner with `pkg which -q`, and the installed file bytes/mode. It passes the result through the **unchanged** production `verify_data` consumer in the Stage 0.09 read-only checker. The product ABI string supplied to that function is **explicitly a synthetic input**, not observed OPNsense.

The VM test is selected using an explicit `--disposable-freebsd-vm` attestation and a native FreeBSD 15.1 root/amd64 gate. The test creates no OPNsense daemon, no original Zapret2 service, no configd action, no kernel/IPFW rule and no FreeBSD.conf change. All fixture files and the pkg database are under an auto-removed temporary directory. CI downloads the exact archived predecessor once inside the existing FreeBSD 15.1 historical-hook workflow.

## Proof levels

- **Local before PR:** Python byte-compilation and five offline unit tests pass; these cover isolation/refusal, inert hooks and rejection of an invalid archive digest before pkg operations. On Linux, invocation without VM attestation exits with refusal code 2.
- **Real native FreeBSD 15.1 CI:** **PASS** in [real FreeBSD15.1 CI #41296771422](https://github.com/Tolian82/os-zapret2-restyle/actions/runs/41296771422), which logs the fixture result `PASS_FREEBSD15_1_SYNTHETIC_PKGDB_FORMAT`; CI may expose a mismatch, which must be fixed in this same scope.
- **Real isolated OPNsense:** **NOT VERIFIED**. The `_29` verifier still requires actual installed `0.6.2_1` bytes/owner and an independently qualified disposable OPNsense guest.
- **Lifecycle:** real previous service FD9, package upgrade order, native `Mk/plugins.mk` successor, LH-01–LH-07 and Python-loss native Stop/Status are **NOT VERIFIED**. No `pkg add` or `pkg upgrade` of the real released package is performed here.

The published stable `v0.6.2` and immutable `0.6.2_1.pkg` are unchanged. No `0.6.2_30.pkg` is published, and owner appliance tests `_20`, `_23` and `_25` are not repeated.

**Native first-attempt finding (PR #794):** On a genuine FreeBSD15.1 VM, the original `_29` consumer refused `INSTALLED_PACKAGE_IDENTITY_MISMATCH` after `pkg info -R --raw-format json` returned a JSON root not representable as the previously assumed single dict. That run was **FAIL**, not a successful pkgdb qualification. The same-scope fix accepts only one manifest object or a JSON array of exactly one manifest object, refuses 0/2+ entries, and when installed raw metadata lacks archive-only `abi`, requires the installed `arch` token equal the SHA-verified archived `arch`, in addition to the independently checked target `pkg config ABI`. Five local tests cover the bounded parser and architecture mismatch; actual corrected native CI still requires fresh evidence.

**Second native attempt (PR #794):** The corrected JSON parser observed a **single-element list** with actual `name=os-zapret2-restyle`, `version=0.6.2_1`, `abi=FreeBSD:15:amd64`, `arch=freebsd:15:x86:64` and all four script keys from real `pkg info -R`. However, the synthetic roundtrip then refused `INSTALLED_HOOK_BODY_MISMATCH:pre-install`, because the test compared installed `pkg` metadata with the **authored pre-pkg-create fixture** rather than the exact synthetic package's actual `+MANIFEST`. The same-scope correction now reads the created synthetic archive's `+MANIFEST` and compares its four hook bodies against the installed JSON, mirroring the `_29` real archived-package logic. A bounded synthetic-script-only difference diagnostic records bytes and prefixes if a remaining mismatch exists. **The later corrected native run PASSED; preserve the earlier failures as diagnosis, not PASS.**

**Native acceptance result (CI #41296771422):** `STAGE0_NATIVE_PKGDB_OBSERVED` reports `root_type=list`, `items=1`, `name=os-zapret2-restyle`, `version=0.6.2_1`, `abi=FreeBSD:15:amd64`, `arch=freebsd:15:x86:64`, four hook names and expected manifest keys. `STAGE0_NATIVE_HOOK_DIFFERENCES={}` (no difference between **created .pkg +MANIFEST** and installed pkgdb hook bodies). `STAGE0_NATIVE_PKGDB.status=PASS_FREEBSD15_1_SYNTHETIC_PKGDB_FORMAT`, `native_installed_payload_mode=0o755`, `native_pkg_which_owner_matches=true`, `isolated_pkg_db_and_payload=true`. The immutable archived real service SHA is `b4f61f0622f908b06df41c0af1fb90f93d20d446a808af1fb16f82f770e42045`, but it was not installed. Explicit `actual_opnsense_installed_predecessor=false`, `actual_fd9_or_old_service=false`, `actual_package_replacement=false`, `stage0_closed=false`. This evidence closes ONLY the native pkgdb format qualification.
