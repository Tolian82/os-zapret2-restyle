Only then are those four **packaged hook bodies** decoded to a temporary private directory and passed via test-only path overrides to existing [lifecycle](../../../scripts/test-package-lifecycle-restart.sh) and [cold-kernel](../../../scripts/test-package-cold-kernel.py) regressions. **CI hookup:** [CI workflow](../../../.github/workflows/ci.yml) runs fast negative tests as part of the project validator, builds the real native Mk package inside isolated OPNsense 26.7, then invokes `python3 scripts/test-native-package-hook-regression.py dist/*.pkg` against the actual build output on the CI host. The output reports actual package SHA-256, exact four hook phases, both sandbox test outcomes and explicit `pre_pkg_admission_enforced=false` / `lh08_ac11_accepted=false`.
