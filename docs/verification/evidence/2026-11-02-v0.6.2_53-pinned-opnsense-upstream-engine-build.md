## Scenario and acceptance before implementation

The native CI boots a throwaway KVM guest, installs only build tools (`git`, GNU make, `pkgconf`, `lua54`) from **that guest's configured pkg repository**, without creating/changing `FreeBSD.conf` or otherwise touching the owner gateway. The script authenticates immutable genuine old archived `0.6.2_1.pkg`, original installed four hooks, installed service bytes/mode, original STOPPED/FD9 and unloaded IPFW. It requires the global `/usr/local/etc/zapret2/binaries/my/dvtws2` to be absent, checks out exact upstream commit `221d7dff24bfec0cd5ac0a5070b8acef2008af3d` by native `git fetch --depth 1`, verifies `HEAD`, compiles upstream official BSD target with `gmake bsd LUA_JIT=0 LUA_VER=5.4` **inside a temporary folder only**, then tests regular executable mode, 64-bit FreeBSD amd64 ELF, resolved Lua dependency and real `--help` parsing. It records built ELF SHA-256. It never moves the built file into the installed plugin path, invokes old service Start/Stop, enables IPFW, replaces packages or modifies target runtime. After compile, genuine installed old pkg and cold Status/IPFW must still match the original; temporary build is removed.
