## New test — two independent disposable fixtures

Use **only a disposable KVM OPNsense 26.7 FreeBSD:15:amd64 guest**. Install exact published immutable historical `os-zapret2-restyle-0.6.2_1.pkg` for *read-only authentication* of the original installed package, four hooks, genuine cold Status/FD9 and unloaded IPFW. Original installed package, service and firmware are **never** replaced, removed, stopped or started. All native `pkg add/lock/unlock/delete` operations target `zapret2-stage0-sidecar-only-fixture` in a fresh **private PKG_DBDIR**, temporary cache and temporary payload, separately for each of two cases.

Before every potential synthetic unlock, write an exact schema-1 `PENDING_PRIVATE_UNLOCK` record to a unique root-owned private file using `O_EXCL|O_NOFOLLOW`, mode 0600, file `fsync` plus directory `fsync`. The record binds **the synthetic package name**, expected original installed fixture version, SHA256 of old payload and private pkgdb path. This is a *durable diagnostic witness*, not a true exclusive pkg transaction, and a root attacker can alter it.

1. **Child killed; fixture unchanged:** Native old private fixture is installed and locked. A **specific subprocess created solely by this experiment** performs real private native `pkg unlock -y`, reports completion and stays alive. Parent sends `SIGKILL` to precisely that child PID, confirms death and observes native package remains **unlocked**. Independently read/validate the durable record, recheck exact original private pkgdb name/version/payload and fresh genuine cold owner snapshot. An external test harness may **manually** restore `pkg lock -y` on that original fixture and prove a subsequent direct delete is refused. No automatic restart/boot recovery is claimed.
2. **Direct privileged package mutation during unlocked window:** A separately installed and locked original private fixture is unlocked by another **owned test child**. Before killing it, the parent invokes actual uncoordinated native `pkg delete -y` against that same private fixture, proving that a privileged direct package operation can remove it **while the external controller still lives**. Parent then SIGKILLs its child; the validated durable record plus pkgdb/payload check must classify `REFUSE_MUTATED_OR_ABSENT_SYNTHETIC_PKG`, **never** mark restored state or attempt a synthetic `pkg lock` on an absent identity. The real published original plugin package must remain unchanged.

The standalone runner is [`scripts/stage0-opnsense-pkg-orphaned-unlock.py`](../../../scripts/stage0-opnsense-pkg-orphaned-unlock.py). The [dedicated CI workflow](https://github.com/Tolian82/os-zapret2-restyle/actions/workflows/stage0-opnsense-pkg-orphaned-unlock.yml) executes Python compilation, **15 offline safety contracts** for record identity/mode/ownership, exact old cold Status requirements, kill-target restriction, mutation vs re-lock classification, and a genuine disposable OPNsense run.
