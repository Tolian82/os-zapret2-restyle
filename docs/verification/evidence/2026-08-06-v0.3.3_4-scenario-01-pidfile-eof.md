# Live evidence — 0.3.3_4 scenario 1 PID-file EOF failure

Status: **FAILED ATTEMPT — NOT A SCENARIO PASS**

Date: `2026-08-06`

Package under test: `os-zapret2-restyle-0.3.3_4`

The normal service reported `RUNNING`, but Strategy Lab semantic evidence returned both process flags as false:

```json
{"schema":1,"source":"zapret_service","state":"RUNNING","child_running":false,"supervisor_running":false}
```

The process-inspector binding was correct in revision 4. The remaining defect was PID parsing. The semantic reader used this pattern:

```text
IFS= read -r _strategy_lab_semantic_pid ... || return 1
```

PID files written by FreeBSD `daemon(8)` may end at EOF without a trailing newline. In that format the PID text is available, but the shell read status is non-zero because no line delimiter was found. The semantic reader therefore rejected valid child and supervisor PIDs before process identity inspection.

Earlier appliance output also showed consecutive PID-file contents joined together, which is consistent with files that do not contain trailing newlines. The ordinary launcher and supervisor status paths remained functional because their PID parsers already accept EOF-terminated numeric text.

## Corrective requirement

Candidate `0.3.3_5` must accept numeric PID files ending with either newline or EOF, reject invalid values, preserve the FreeBSD process-inspection correction, add a no-newline regression fixture, and repeat scenario 1 on the owner appliance.

Scenario 1 remains pending.
