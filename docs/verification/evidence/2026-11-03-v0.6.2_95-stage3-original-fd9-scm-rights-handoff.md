## Why _94 is insufficient

[Prior _94 native witness](2026-11-03-v0.6.2_94-stage3-configd-detached-original-fd9.md) proved that a detached `daemon -f -P` child can acquire the authentic `/var/run/zapret2-lifecycle.lock` and preserve FD9 through actual `service configd restart`. However, the child **opened/locked FD9 after the configd launcher returned**, leaving an unverified initial dispatch-to-acquisition interval. Its PASS does **not** prove continuous pre-pkg admission.

## Exact new handoff protocol

1. Enter **one fixed, zero-parameter temporary root-owned configd action** in a disposable OPNsense 26.7 KVM guest. Authenticate exact current source SHA, root/FreeBSD amd64, CI opt-in, pinned `0.6.2_1.pkg` SHA and genuine installed STOPPED cold-owner baseline with original pkgdb/files/modes, Config, markers, processes and IPFW.
2. Create a single test directory `0700`, with root-only `0600` one-use nonce ticket. Verify no collision/symlink/foreign owner. Do not create an installable updater or alternate lifecycle lock path.
3. The **configd-invoked launcher** exclusively opens the existing authentic historical `/var/run/zapret2-lifecycle.lock` on FD9, verifies root-owned inode/device/link count, takes nonblocking BSD `flock`, and revalidates historical old STOPPED ownership under that FD9. If busy/incomplete/foreign, refuse **before** launching a worker, with no pkg invocation.
4. The launcher starts FreeBSD `daemon -f -P` with a separate root child and holds FD9 while waiting. The child binds exactly one Unix socket inside the root-only test directory. The launcher uses `sendmsg(SCM_RIGHTS)` to transfer the **already-open, already-locked original FD9 file description**, along with exact source SHA, nonce, original inode and created-vs-preexisting flag.
5. The child refuses missing/extra rights, wrong nonce/head/inode, symlink/foreign or unqualified original ownership. The child duplicates the received descriptor to **FD9**, executes genuine old cold-owner checks without reacquiring the lock, writes root-owned READY and returns an ACK containing the nonce and same PID **while the launcher still holds FD9**. The launcher validates ACK plus READY and independent `lockf` BUSY=75, and only then closes its FD9.
6. The controller validates independent BUSY=75 once the configd action returned, restarts **actual configd**, checks BUSY=75 again, requires unchanged READY PID/head/inode, releases the worker cooperatively and verifies DONE with same PID/nonce/inode. Any incomplete handshake, timeout or worker failure fails closed; on failure the disposable guest is destroyed, never deemed safely upgraded.
7. Verify exact installed old package/Config/process/IPFW state unchanged. Remove only root-authenticated temporary action/markers/socket/supervisor pidfile; if the historical original lock inode was initially absent, restore its absence **only after the worker exited and a separate exclusive lock attests the identical test-created inode**. Never unlink a foreign or busy lock.
