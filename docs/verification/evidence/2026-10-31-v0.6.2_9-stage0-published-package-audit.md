## Automatic archive inspection, provenance and hard stop

- `scripts/stage0-published-package-audit.py` accepts **existing local archives** and independent expected version/name/SHA-256, checks the full archive bytes before reading, then reads the `+MANIFEST` without extraction or executing any embedded scripts.
- The job downloads both **public exact historical packages** into a GitHub Actions runner's temporary directory, checks hashes with `sha256sum`, enumerates all archive member paths and their actual tar owner/mode/type, reads the real dependency metadata, and hashes each of the four package lifecycle scripts. Records private `curl-impersonate` ELF header, `e_machine` and binary SHA if included.
- JSON artifacts retain **all** archived paths/modes, symlinks, four hook hashes and observed private ELF metadata, not only highlighted findings. Source mode `100644` for `zapret_service.sh` from Stage 0's earlier scan can therefore be compared with actual historical archive mode.
- The analyzer rejects wrong SHA, package identity, missing lifecycle hooks, duplicates or inconsistent/malformed member listings; positive/negative fixture tests run without Internet and must pass before archive downloads.
- `tar` reads only the archive into memory and standard output; no `pkg install`, `pkg add`, kernel changes, host `/usr/local/etc/pkg/repos` edits or execution of historical package hook code occurs.

## Explicit remaining qualification boundaries

Source and published package archive proof is not the same as verified **installed** appliance content, OPNsense 26.7 package/repository provider identities, generic python3 package-provided link, private ELF dynamic library/loader compatibility on the qualified target or owned legacy `FreeBSD.conf` backup. Do not infer target ABI compatibility merely from the old tar manifest or private ELF machine number. Retain STOP gate for Stage 1 until these are established, or report a controlled qualification blocker. No new `.pkg` produced, existing release untouched.
