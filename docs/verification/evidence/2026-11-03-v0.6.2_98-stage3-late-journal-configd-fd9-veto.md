1. Guest identity, pinned original archive SHA and real installed old four hooks, Config, process/IPFW, STOPPED and old shared journal absence are independently verified. Save native installed `pkgdb` and every installed file digest/mode, Config bytes, service and hook SHA and owner/IPFW snapshots. Require exact GitHub head+root+disposable opt-in. The original historical `/var/run/zapret2-lifecycle.lock` is exclusively taken by the real one-use configd launcher before starting independent worker.
2. The same locked FD9 **open file description** is sent to an independent root `daemon -f -P` worker with `SCM_RIGHTS` plus exact SHA, nonce and original inode. Worker rechecks real old ownership under FD9, runs the *real installed native read-only* `/usr/sbin/pkg -o REPO_AUTOUPDATE=false query %n|%v os-zapret2-restyle`, checks original FD9 and old ownership again, then issues authenticated ACK. Controller verifies root-only query proof, independent FD9 BUSY and the same PID/inode across an actual configd restart.
3. **Only after** successful query+ACK+real configd restart, controller creates one known-invalid, strictly owned original shared transaction journal using the previously proven native _91 fixture. This is not old service mutation, does not change `pkgdb`, and is not installed on the owner's device. Controller verifies exact inode/mode/content and the still BUSY original FD9.
4. Controller releases its test-owned barrier. Still holding the same original FD9, **the same worker** calls the real historical old cold-owner validator again just before a *fixed nonmutating would-be pkg-dispatch tripwire*. It must receive the real exact `UNVERIFIED_JOURNAL_MARKER_OR_PIDFILE:` refusal; arbitrary exceptions, missing checks, changed inode, unexpected success (reaching the tripwire), a wrong nonce/PID or new package identity all fail the test. There is no `pkg add`, `pkg upgrade`, shell mutation or package replacement callable in the candidate final-gate helper.
5. Verify root-owned refusal record with same SHA, nonce, detached worker PID and original FD9 inode. The journal must still be present and byte-unchanged when refused. After worker exits, delete only the verified test-created invalid journal and, if newly created, its empty verified root parent; never remove unknown journal. Require unchanged original actual pkgdb/files/modes, Config, markers, owned process census, IPFW modules and rules. Restore original lock-file absence only after independently re-locking its exact test-created inode. Do not delete or repair a foreign/busy lock.
