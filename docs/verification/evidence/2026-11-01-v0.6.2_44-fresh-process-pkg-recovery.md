## What was established by earlier native experiments

## New narrowly bounded native experiment

The [Stage 0 fresh-process recovery runner](../../../scripts/stage0-opnsense-pkg-fresh-recovery.py) runs only on a fresh disposable OPNsense 26.7 KVM with FreeBSD 15 amd64; first install and independently authenticate the **exact immutable published old `os-zapret2-restyle-0.6.2_1.pkg`** (package SHA, actual installed service/hook/pkgdb modes) as a **read-only genuine predecessor**. It repeatedly invokes the old installed service Status through its own FD9 and requires an authenticated completely cold/unloaded-IPFW snapshot; real Zapret2 service/packages and firmware are never stopped, upgraded or removed.

All native `pkg add/lock/unlock/delete` effects use the distinct harmless `zapret2-stage0-sidecar-only-fixture` in **private per-scenario PKG_DBDIR**, temporary package cache and temporary payload. Each scope is confined under a new root-owned 0700 `stage0-fresh-process-recovery-*` directory. A precise durable `PENDING_PRIVATE_UNLOCK` record is written with mode 0600 and `fsync` for file and parent directory BEFORE synthetic unlock; it binds fixture identity/payload SHA and private pkgdb path, **not** a cryptographic signature or unbypassable protection. One exact test-owned subprocess runs native private `pkg unlock -y`, reports completion and is killed with SIGKILL. The parent verifies the synthetic package remains unlocked. Crucially, it then invokes the runner in a **new independent Python interpreter process** via its `recover` subcommand. The new interpreter gets only the exact archive path and private scope on disk, validates the private directory modes/owner and intent, independently rechecks genuine old cold owner and native package bytes, and can relock only the exact unchanged synthetic fixture.

Four independent temporary private scopes are mandatory:

1. **unchanged:** own-child SIGKILL leaves private original package unchanged and unlocked; a newly started interpreter must recheck exact durable intent + old published cold owner + private native pkgdb/payload, re-lock synthetic original and verify direct native delete is refused. Re-running another new interpreter is idempotent, with `ALREADY_LOCKED_UNCHANGED_PRIVATE_FIXTURE`.
2. **direct_delete:** after killing the own child, invoke direct root native `pkg delete -y` on only the unlocked private synthetic fixture. A fresh independent recovery process must refuse because package is now absent, **without attempting to re-lock an unproven identity**.
3. **tampered_intent:** after SIGKILL leave native synthetic package unchanged but alter only the synthetic pending-intent JSON package field. A fresh independent recovery process must refuse the untrusted record and leave the native fixture unlocked, not silently re-lock.
4. **unknown_owner:** after SIGKILL leave native synthetic package unchanged, inject only the already-qualified synthetic malformed genuine old common Apply journal, then invoke independent recovery. It must refuse **before native package mutation** because genuine old installed Status/owner evidence is unknown. Remove only the exact test-owned journal and recheck old service cold afterwards.

**Scope warning:** These are *new interpreter launches on the same live disposable KVM*, **NOT an OPNsense guest reboot, power loss, installed rc/configd startup reconciliation, root multi-process exclusion or product upgrade acceptance**. Even a successful `recover` command is a consciously invoked test-only repair, not an automatic service on boot. Direct root pkg operations remain possible during unlocked windows and can race between observations and lock. The unit tests cannot create product safety; their outcomes must be reported as bounded feasibility/hazard evidence only.
