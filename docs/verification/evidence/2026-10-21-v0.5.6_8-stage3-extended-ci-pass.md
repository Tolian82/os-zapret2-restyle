## Verified correction

Real candidate probe and IP-target/Host-SNI probe previously made Extended `tls12` and `http` depend on `curl exit_code == 0`, so genuine final 4xx/5xx HTTP after truncated body and verified TLS handshake without HTTP could fail despite transport reachability. A bare zero exit could also make a cleartext HTTP probe look positive without a valid final HTTP status.

- `tls12` now uses the existing pinned, CA-verified `chrome_https_evidence` classifier: verified TLS handshake **OR** genuine final HTTPS response. The private client still enforces `--tlsv1.2 --tls-max 1.2`; actual negotiated TLS version is not fabricated.
- `http` now uses `chrome_http_evidence`: accepted only with a genuine final HTTP 2xx–5xx, HTTP/1.x or HTTP/2, exact pinned IPv4; no TLS-only or exit-only success.
- Both paths **still require IPFW packet-counter increase and matching remote IP**. No changes to Standard, Model C, native FD9 or Stage 90.

Regression tests call **both actual probe functions** with positive pinned TLS1.2 handshake, genuine HTTPS 503 / HTTP 404 after transfer error 18, and negative certificate 60, incorrect IP, interim 100, missing final HTTP evidence and no IPFW interception. Exact HTTPS/443 and HTTP/80 request pinning, TLS max and no-redirect policy are checked. Project/Voice/FreeBSD15 CI PASS.

## Not accepted yet: target QUIC

Current `quic_target_request` uses OpenSSL against an intended UDP/443 target, but QUIC candidate code assigns `remote_ip=selected` instead of independently observing the socket endpoint and largely trusts process exit. Stage80 has no direct target QUIC baseline before dvtws2 and does not yet provide established QUIC 3/3 + exact finalist replay. Stage30's control probe is not target proof. These are explicit Stage 3 blockers, not a failed or successful owner-live QUIC test.

Next: isolated QUIC target identity/no-TCP-fallback evidence, direct baseline and 3/3 + exact replay work, with no changes to already accepted Standard/Model C.
