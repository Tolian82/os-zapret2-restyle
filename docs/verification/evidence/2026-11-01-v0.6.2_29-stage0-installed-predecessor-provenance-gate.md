# Stage 0.09 — Read-only installed predecessor provenance before real FD9 qualification

**Scope:** source-only `v0.6.2_29` from `main` `715b90f7f52ae89fe017b3b0090e96b4f6188a5e`. Approved native specification and plan remain editorial **v1.3**. No successor package or owner-appliance change.

## Observable scenario

On a **separately provisioned, disposable OPNsense 26.7 amd64 virtual guest** that already contains `os-zapret2-restyle-0.6.2_1`, establish whether the *actual installed predecessor* corresponds to the exact immutable published `0.6.2_1.pkg` **before** any package replacement or FD9/Stop experiment. This is a new, narrow prerequisite; it does not redo the completed owner `_20`, `_23` or `_25` probes.

The script [`stage0-installed-predecessor-readonly.py`](../../../scripts/stage0-installed-predecessor-readonly.py) verifies the archive SHA-256 `1e21fbcac847529b94fea940241b4da7f86a42d33c129b7003ad04a72f4e5a0f`; reads the original archive `+MANIFEST` and service bytes; queries the **installed** package raw JSON manifest using `pkg info -R --raw-format json`; compares all four original hook bodies byte-for-byte with the installed database, the installed service script bytes against the original archive, its exact `0755` executable mode, and its `pkg which -q` owner. It also requires actual OPNsense product ABI `26.7`, FreeBSD package ABI `FreeBSD:15:amd64`, root/amd64, an expected guest hostname and a reported virtual-guest environment.

The `--isolated-guest` flag is an explicit **operator attestation**, not proof of isolation; virtualization and hostname probes are defense-in-depth only. An administrator must independently establish that the guest is disposable, separate from the owner's working appliance, and has the approved exact predecessor. **Do not execute this workflow on the owner's working OPNsense gateway.**

## Non-mutating invocation — disposable guest only

First stage the already published immutable package archive and the matching script inside the disposable guest. After separately confirming isolation and hostname, the only script invocation is:

```sh
/usr/local/bin/python3 scripts/stage0-installed-predecessor-readonly.py --isolated-guest --expected-hostname '<disposable-guest-short-hostname>' --archive ./os-zapret2-restyle-0.6.2_1.pkg
```

The script issues read-only `hostname`, `opnsense-version`, `pkg config`, `sysctl`, `tar`, `pkg info` and `pkg which` calls and reads file metadata/bytes. No `pkg add`, `pkg upgrade`, `pkg delete`, `configctl`, service Status/Stop, FD9, IPFW, Config, watcher signal, repository changes or file writes occur. The JSON success result explicitly records `real_fd9_tested=false`, `actual_pkg_replacement=false`, `native_successor_package_tested=false` and `isolated_environment_independently_attested=false`. A refusal exits nonzero.

## Evidence and boundaries

**Locally executed before PR:** `python3 -m py_compile` both scripts; 7 deterministic offline unit tests passed, including 4 separate hook-body mismatches, identity/ABI errors, changed service bytes, wrong executable mode, unknown owner, unqualified virtual guest and archive digest mismatch; command without isolation attestation refuses. Tests use controlled data, **not installed OPNsense**.

**Not verified:** original and installed byte identity on a real isolated OPNsense guest, genuine old service FD9/Status/Stop, actual native pkg order, old PRE_DEINSTALL, new native `Mk/plugins.mk` successor and LH-01–LH-07. New source and CI can prove only preflight logic; qualified target execution remains a separate gate. Continue Stage 0 **OPEN / Stage 1 BLOCKED** until the guest and successor lifecycle evidence exists. Never infer old deinstall execution from `pkg add -f`; protect foreign/unproven `FreeBSD.conf` and do not repeat completed owner probes.

**Publication:** stable `v0.6.2` and its immutable `0.6.2_1.pkg` remain unchanged. `v0.6.2_29` is a source-only revision; **no `0.6.2_29.pkg`** is published.
