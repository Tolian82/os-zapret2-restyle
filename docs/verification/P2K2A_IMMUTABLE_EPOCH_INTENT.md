# #1052 P2k2a — root-private immutable generation epoch and pending intent

**Source candidate:** `v0.6.5_23`. This is a **real protected filesystem primitive** with actual fsync/open/no-follow/immutable-link operations, not an activated service. P2k2a intentionally does **not** implement the distinct authoritative destination commit/ack path (P2k2b), real installed FD9 hooks, raw collection or cron.

## User failure this prevents

After a crash/restart, `pending/<generation>-<id>.txt` survives. If its original debug reader position was only in memory, reprocessing the event from today's `dvtws2` or simply advancing the cursor can lose an event, misattribute its profile or remove source before a destination write. **Pinned upstream v1.0.7 logs “adding to” before raw append**, so matching debug isn't a commit. The P2k1 reader returns only an ephemeral candidate `Window`. A new live process cannot retroactively attest an old writer inode/process.

The pre-change source has **no durable root-only generation epoch or immutable prepared-pending receipt**. The focused test exercises the actual old P2k1 reader and real filesystem: create a P2c-typed original owner epoch from **its actual empty debug inode**, stage one fully rotated generation-tagged pending inode and candidate window, restart the Python store, recover the original metadata, and require that `ack_authorized=false` and `committed_cursor_offset=0` remain unchanged. No mock “success” callback is substituted for P2j commit.

## P2k2a exact implemented boundary

The import-only `backend/auto_detect_epoch_receipts.py` has a production-policy constant `/var/db/zapret2/auto-detect-epochs`, below the existing root-private `/var/db/zapret2` owner hierarchy, **not** in the group-traversable P2g producer root. The test injects a private temporary root; the module imports without creating an inode. The future original FD9 owner must **independently authenticate** the P2c `GenerationProof` before calling this API; passing a dataclass alone is never proof of live PID/FD ownership.

- `EpochReceipts.begin(proof, cursor)` re-reads the **actual zero-length protected native debug inode** via P2k1 `empty_epoch` and refuses a supplied forged dev/ino or inherited debug history. It writes a root-only `0700` per-generation directory and an immutable `0600 epoch.json`: original 32-hex operation/generation, SHA256 of sealed argv, original PID/birth/exec, exact native raw/debug path and profile ancestry, debug device/inode and **initial committed cursor offset 0**. Old PID/birth are historical provenance, not a running process proof.
- `stage(proof, cursor, window, pending)` requires the same stored original owner metadata, saved initial debug inode/offset, a **fully rotated single-link** root-owned pending file at the matching exact `<generation>-<128-bit-id>.txt` name, complete raw line(s), stable bounded no-follow inode read and exact group-mode opt-in. It independently re-runs the original P2k1 `propose_window` against the **real current debug inode and actual pending bytes**; caller-provided `Window` does not authorize an intent on its own.
- A single immutable `intent-<pending-name>.json` stores no user hostnames: pending device/inode/size/SHA256, debug source/start/end offsets and prefix hashes and candidate count. **Status is always `pending-debug-intent-not-commit`, `ack_authorized=false`**. It does not write destination lists, advance the committed debug cursor or delete pending. A second unrelated pending for the same generation refuses while the first is unresolved.
- Receipts are JSON bounded to 16 KiB; creation is new temp `0600` inode + fsync → **hardlink exactly once into final name** → unlink temp + directory fsync, never overwrite. A leftover temp, hardlink, foreign name, symlink, unsafe directory/file ownership/mode, conflicting replay or ambiguous multiple intents fails closed; no age purge.
- `historical(generation)` reconstructs an explicitly **non-authoritative** `HistoricalReceipt` from immutable root-only files. It can identify a pending inode from an old generation after restart **without** granting it today's P2c process, and without accepting current PID as the original.

## Tests and proof levels

The scoped `scripts/test-auto-detect-epoch-receipts.py` exercises real protected filesystem operations, not faked Python writes. It covers initial true inode, forged inode, pre-existing debug, restart/read idempotency, old/second intent retention, forged debug window, changed debug before staging, incomplete pending line, link-before-replace still-live inode, mismatched original sealed args SHA, unsafe file mode/hardlink/foreign interrupted temp and a refusing native entrypoint. Test runner `python3.13 scripts/test-auto-detect-epoch-receipts.py` is in the **existing** fast CI. P2j/P2k1 remain in that same gate. No additional FreeBSD/OPNsense engine VM is justified solely to test this **unwired private filesystem primitive**. Exact-head CI/package output is a separate factual gate.

## Still open before allowing production collection

This receipt is only a **prepared intent**. It is not an authenticated/committed debug checkpoint and cannot authorize `DurableInbox.acknowledge()`: the P2b true writer-FD drain, original FD9 process/generation seal and the idempotent P3 final auto-owned HOSTLIST write are absent. Crash after a real future destination commit but before advancing the cursor must replay the same pending idempotently; a durable commit/ack transaction (**P2k2b**) is required. Old-generation recovery must verify the original sealed provenance, not just trust this historic JSON or invent today's owner. The current worker remains **unconditionally disabled**, `dvtws.args` unchanged, no cron/configd, no GUI/list writes, no extra process, no installed package and no owner appliance actions. Existing full purge ownership of `/var/db/zapret2` is not extended to a newly provisioned live producer directory in this increment.

**Next action P2k2b:** design and qualify one durable idempotent destination commit for an attested pending inode, with independently persisted cursor/commit-receipt transition, replay after interrupted fsync, reboot and concurrent GUI edits; then original FD9 post-drop `nobody`→root reownership **before** IPFW, and only afterwards authorized running schema2/worker.
