# Stage 5 — real native TLS dvtws2 kernel argv and PID identity

**30 October 2026 · source/CI-only candidate `v0.6.1_20`, native PASS pending.** This is a **disposable FreeBSD 15.1** experiment, not an OPNsense installation or WAN test. The latest published and installed testing package remains `v0.6.1_12`; A07/A08, installed IPv6 and Voice are OPEN.

The existing production baseline controller's [`process_witness()`](../../scripts/stage5-wan-baseline-capture.py) already verifies the engine and monitor PID files, regular-file safety and native `ps -o lstart`. Alone, this does **not** establish which command-line options the running engine received. The new [guarded test](../../scripts/test-freebsd15-native-tls-process-identity.py) uses FreeBSD libc **`sysctlnametomib("kern.proc.args")`** to resolve the OS-provided parent MIB and appends the PID as an integer for direct read-only **`sysctl(3)`**. This yields a kernel-supplied **NUL-delimited argv vector**, not human-readable `ps command`, shell output or a guessed sysctl MIB number. FreeBSD 15.1's textual `sysctl -b kern.proc.args.<PID>` path returned `unknown oid` in [native CI #41125287883](https://github.com/Tolian82/os-zapret2-restyle/actions/runs/41125287883); the test now uses the native numeric kernel interface instead. It compares every token and its order with the exact configured argv for the **real pinned upstream `dvtws2 v1.0.6`** test process (commit `221d7dff24bfec0cd5ac0a5070b8acef2008af3d`), using the actual Lua `fake` profile generated by the production global Exclude compiler.

It observes two identical kernel argv reads **bracketed by** two identical production PID/start-time witnesses, refuses truncated/invalid bytes, missing/extra/reordered Lua options, changed expected values, terminated monitor and stale PID, and requires explicit re-attestation after monitor replacement. Every test process belongs to the temporary VM session and is cleaned up. No IPFW/WAN/capture/Config/GUI Apply, production service writes, or owner commands.

The only successful classification is `NATIVE_PROCESS_ARGS_MATCH_ONLY`, including a digest of raw kernel argv and immutable proof limits: `packet_specific_lua_action=UNVERIFIED`, `configured_profile_selected=UNVERIFIED`, `installed_a07=OPEN`, `installed_a08=OPEN`, `phase_b_permitted=false`. No raw user argv, TLS blob bytes, configuration, hostlist, or PCAP content is exported.

**Gate:** fast `--static` checks must pass locally and CI; the final exact-head FreeBSD 15.1 CI must *really start the pinned native engine* and log `NATIVE_TLS_PROCESS_ARGV_IDENTITY=PASS`. A missing `sysctl`, argv truncation, unsupported process title, failed engine, skipped native test or incomplete cleanup is **failure**. Linux preflight is not native proof.

**Limitations:** PID + FreeBSD `lstart` have coarse precision; process-title rewriting and racing PID reuse are not entirely eliminated. Exact observed argv proves **the process exposes the expected configured options at that moment**, not a packet-selected Lua function, loaded resource bytes, an actual WAN modification or Exclude effect. Any future real installed process identity collection needs separate owner approval, and installed Phase A/Phase B remain independent gates.
