# Stage 5 — consent-gated, single-phase WAN baseline capture

**29 October 2026 · source/CI candidate, NOT executed on owner OPNsense.** The existing installed `0.6.1_12` package, Config, WAN routes, IPFW and the stable `v0.6.0` release are unchanged. This is one increment toward the [installed A/B WAN evidence protocol](STAGE5_INSTALLED_WAN_AB_PROTOCOL.md), **not** an A07/A08/IPv6/Voice acceptance claim.

## User scenario and intentionally narrow scope

An owner *separately authorizes one diagnostic HTTPS request* against a known pinned IPv4 or IPv6 target after reviewing the generated [non-executing plan](STAGE5_WAN_ACQUISITION_PLAN.md). The source-only [baseline lifecycle controller](../../scripts/stage5-wan-baseline-capture.py) can then (and only then) capture **one baseline phase** to a local small PCAP. It does **not** perform an excluded phase, apply/change `Exclude IPSet`, call configd Apply, alter any IPFW rule/table, edit Config, change route, restart dvtws or install/update anything.

Even a successful baseline returns `BASELINE_CAPTURE_OBSERVED_ONLY`, `exclude_effect_proven=false`, `engine_strategy_modification_proven=false`, `wan_origin_proven=false`, `installed_a07=OPEN` and `installed_a08=OPEN`. Seeing TCP packets on the declared interface is not independent proof that a specific Lua DPI strategy modified them; a payload hash difference would not prove that either.

## Implemented boundaries

- **Offline validation:** `--check --plan <local-file>` validates that a bounded JSON plan **exactly** equals the output of its trusted adjacent plan-generator module. It performs no network operations and does not require OPNsense. Symlink/hardlink or malformed plans are refused.
- **Separate live-only authorization:** `--execute --plan <local-file>` is blocked unless root on FreeBSD installed OPNsense with both native filesystem indicators and the exact opt-in environment variable `ZAPRET2_ALLOW_ONE_BASELINE_WAN_CAPTURE=I_APPROVE_ONE_BASELINE_CAPTURE`. **The user has not provided that authorization. Do not invoke `--execute` from instructions, CI or any assistant action without a new owner-approved live trial.**
- **Existing native owner:** before any packet transmission, use only the already implemented `stage5-installed-evidence.py` bridge into production `voice_live_inspect.py`. It requires installed package `0.6.1_12`, ready committed runtime, verified process/supervisor and owned IPFW; do not recreate a second owner/strategy compiler.
- **Network safety:** verify source IP assigned to the declared WAN using read-only `ifconfig`, destination FIB route `route [-6] -n get`, available `tcpdump -i WAN -L` Ethernet DLT `EN10MB` and current TCP source-port bind availability. A free port at preflight is **not** proof of exclusive ownership later.
- **Single bounded process lifecycle:** start only the planned exact five-tuple `tcpdump` with unbuffered writing; require its observable `listening on` readiness marker **before** starting the pinned one-request curl command. Hard capture+probe upper bound 18 seconds, curl maximum 12 seconds, snaplen 4096, max 128 BPF-matched packets. No shell command interpretation; processes run in their own process groups, with SIGINT/SIGTERM then SIGKILL after a bounded wait. Fail closed and delete partial temporary artifacts on any error.
- **Local evidence only:** if the baseline request succeeds, the capture has an actual classic Ethernet PCAP header, bounded size and at least one unambiguous outbound TCP payload under the existing [offline five-tuple parser](STAGE5_WAN_OFFLINE_PCAP_ATTRIBUTION.md), compare a second verified native-owner snapshot using the existing bridge's comparison API. On success, retain raw PCAP only in a newly created `/tmp/zapret2-wan-one-*/baseline.pcap` directory with mode 0700; export a compact JSON with no raw payload, secrets or full Config.
- **Restoration/uncertainty:** on timeout, missing readiness, failed probe, wrong DLT, ambiguous capture or changed native-owner state, terminate the processes and remove partial capture. An uncertain owner state must never be called successful or repaired with blind IPFW/Config commands. No source-code branch can silently change Exclude, so there is no automatic GUI restoration path.

## Verification and remaining gates

[`scripts/test-stage5-wan-baseline-capture.py`](../../scripts/test-stage5-wan-baseline-capture.py) uses fake process instances and synthetic source/route/PCAP evidence. It tests both IP families, strict plan identity, symlink/hardlink refusal, opt-in guards, read-only preflight, readiness, bounded process ordering, cleanup on unsuccessful curl, and refusal on changed Config/owner. **No real capture is executed by tests; exact GitHub CI evidence is recorded only after it runs.**

The controller has **not** been launched on an actual OPNsense appliance. Exact readiness syntax and FreeBSD `tcpdump -L`/capture behavior need isolated FreeBSD execution or owner-safe read-only verification before live acceptance; mocks and Python syntax cannot validate this platform boundary. A single baseline capture would still need independent proof that real dvtws/Lua altered it; only after that and separate owner approval could the excluded A/B and GUI restoration be contemplated. Stage 5 installed A07/A08, native IPv6/Voice media/FD9 acceptance stay **OPEN**.

**No owner console command for live execution is authorized by this document.** The next step is to qualify these source and lifecycle tests in CI, then exercise an isolated native FreeBSD capture lifecycle without an Internet target and without OPNsense Config/IPFW mutation. Only then prepare a concise, explicitly reviewed owner checkpoint.
