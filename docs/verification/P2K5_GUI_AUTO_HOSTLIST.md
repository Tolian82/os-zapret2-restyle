# #1052 P2k5 — native Strategies Auto Hostlist, shared root lock and explicit-only target

**Source candidate:** `v0.6.5_27` (13 November 2026), no published `_27.pkg`; owner-installed stable `0.6.5_1.pkg` untouched. Not a P2 native observer/worker acceptance.

## Observable user problem

Before P2k5, the GUI had no independent editor for the final `auto-domains.txt`. A stale tab could not safely preserve native discoveries on saving an edited list. The original `target_mode.sh` still injected `<HOSTLIST:auto>` into auto-mode profiles, and `storage.sh` pointed `hostlist.auto` at the legacy `zapret-hosts-auto.txt`, contrary to the approved explicit-opt-in contract.

## Source change and real entrypoints

1. **One actual final path and explicit-only use:** `backend/storage.sh` resolves `hostlist.auto` to `/usr/local/etc/zapret2/ipset/auto-domains.txt`. `backend/target_mode.sh` keeps the known YouTube/User HOSTLIST and Telegram IPSET defaults in `auto`, but stops adding `<HOSTLIST:auto>` unless the source strategy explicitly contains it. `all` and `list` unchanged. The existing original profile pipeline test is updated, including an explicit `--new` source profile.
2. **Shared lock:** `backend/auto_detect_destination_commit.py` exports the same checked root-owned nonblocking `exclusive_destination_lock()` used by its P2k4 `exclusive_targets()` and the new GUI writer. The production lock path for this file is `/usr/local/etc/zapret2/ipset/.auto-domains.lock`. This does not grant Config/FD9 authority.
3. **Native root file I/O:** `backend/auto_detect_gui_hostlist.py` is invoked only by two new registered `configd` actions, `auto_hostlist_read` and `auto_hostlist_save`. A bounded authenticated POST envelope is transported as base64url, not used as shell syntax; the action validates FreeBSD root execution, exact paths and nofollow/owner/single-link snapshots. The existing canonical `domain_policy.normalize(..., 'user')` validates all positive/exclusion/exact modifiers, no second parser. Same-dir fsync plus link-once on first create or P2k2b's atomic CAS on replace. The root file changes without Config save, common Apply or restart.
4. **Stale form:** the returned 64-hex SHA256 revision distinguishes missing and empty, checks exact byte snapshot *inside the same lock* at save, and refuses a stale second tab with `result=conflict`, without touching either file or the user's unsaved draft. Missing, empty, populated and unreadable/error are distinct GUI states; failed or ambiguous saves require explicit reload before retry.
5. **Native view:** Strategies `general.volt` inserts a RU/EN multiline **«Найденные домены» / Auto Hostlist** row immediately after the User Domains row. Independent Save/Reload controls never enter `getFormData('frm_GeneralSettings')`, never write `config.xml` and never start the service. The existing Strategies form and Telegram baseline remain unchanged.
6. **Legacy safety:** if the new file is **absent**, native read/save under lock can atomically **copy** a bounded, root-owned legacy `zapret-hosts-auto.txt` byte-for-byte and retain the original. If the new file is **already present**, it is never overwritten with legacy data. A preexisting populated new file and a different populated legacy file remain separate: no automated union or destructive conflict resolution is claimed. Malformed, group-writable, oversized or symlink legacy sources refuse. Repeated GUI reads do not reimport data after the user deletes an entry in the new file. A full, conflict-aware two-present-file migration remains an explicit P3 gate before a stable release.
7. **No unrestricted GUI transport:** the configd-safe interactive editor explicitly bounds its payload to 40 KiB. A larger existing file is reported unavailable, not truncated or replaced; the full 4 MiB background engine data bound is separate. Future larger-file GUI transport must use an independently qualified mechanism, not weakening argv or escaping.

## Verification and deliberate boundary

`scripts/test-auto-detect-gui-hostlist.py` exercises actual protected native file read/create, revisions, stale-tab conflict, no-op, manual deletion not reimported, legacy copy, existing new file, root flock contention and symlink/invalid-domain refusal. `scripts/test-profile-pipeline.sh` checks the real Target Mode no-implicit-auto order and explicit source preservation; focused PHP lint, shell syntax and the existing fast affected CI run. No new full VM campaign is justified for a file-only GUI editor, but *changed native profile selection* still requires a qualified exact generated-profile/native witness before publishing or accepting a package. CI source tests/native artifact build are not owner-installed GUI acceptance.

**Remaining:** real P2k4 authoritative **full Config+all HOSTLIST** snapshot under correct shared locks, conflict-aware two-present-file legacy migration, protected known-list auto-owned records/relocation, original FD9 authorized schema-2 and post-nobody owner repair, old generation process/FD/drain proof, pending ack, 60-second configd/cron worker and owner-appliance testing. P2 partial; P3/P4 source partial, P5 open. The live Auto-detect collector is still disabled; the manual editor does **not** infer a bypass strategy. The stable installed package is unchanged.
