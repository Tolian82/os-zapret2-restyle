# Stage 5 — real upstream TLS fake packet/Exclude native attribution

**Scope (30 October 2026):** new source/CI-only experiment using pinned upstream Zapret2 `v1.0.6`, disposable **FreeBSD 15.1** VM, authentic OpenSSL TLS 1.2 ClientHello, `lo0` and test-owned IPFW divert. This is **NOT** the installed gateway's actual fake/split strategy, an approved WAN capture, A07/A08 PASS, or a published `v0.6.1_18` package. Only run from the existing guarded VM CI. All packets are local.

## Observable test

The [native test](../../scripts/test-freebsd15-native-tls-fake.py) uses the real production `global_exclusions.compose()/audit()` and six-list IPSET semantic compiler, the original native FreeBSD guest-only gate, and existing strict DLT_NULL/DLT_LOOP TCP PCAP parser. It uses a real upstream profile `--filter-l7=tls --payload=tls_client_hello --lua-desync=fake:blob=stage5_wire_fake:badsum` with a unique fixed hexadecimal blob and an unrelated out-of-profile control. The fake uses bad TCP checksum; its bytes must be seen in a bounded **native** outgoing PCAP, separately from the genuine original TLS ClientHello on the same attributed flow. **In a loopback VM, bad-checksum fakes can still disturb the TCP receiver:** the test does not claim intact peer delivery for the nonexcluded phases. For the **matching-Exclude** phase, where no fake should be injected, original peer delivery must be byte-identical.

For each family (`127.0.0.1` and `::1`), the same test captures exactly attributed TCP flows for one un-diverted baseline, one divert-owned active stream and one bypass-port control. The sender source port and original transmitted ClientHello are witnessed independently of receiver behavior; no fake may appear in the matching-Exclude phase. A native source-port/target-port+payload witness attributes the unique fake only to the intended active flow; no fake may appear on the baseline or bypass. Real IPFW rule owner, native process, rule counter, BPF capture readiness, bounded cleanup and default-allow restoration are mandatory.

| Phase | Global Exclude | Native captured fake on active flow |
|---|---|---|
| A | Empty | Must appear |
| N | Nonmatching `192.0.2.1/32` and `2001:db8::1/128` | Must still appear |
| B | Matching `127.0.0.1/32` and `::1/128` | Must not appear |

A forged blob observed on an unrelated TCP source port, an absent fake when allowed, a fake during the matched Exclude phase, missing genuine ClientHello in the outgoing PCAP, **non-identical peer delivery when Exclude matches**, incomplete PCAP, changed native IPFW ownership or unclean cleanup are **failures**, not partial success.

**Native follow-up (30 October 2026):** [CI #41113300888](https://github.com/Tolian82/os-zapret2-restyle/actions/runs/41113300888) isolated the next source-test defect: the existing native TLS PCAP decoder retained its original hardcoded destination-port filter `6541–6543`, while the new fake trial uses `6544–6545`. It therefore did not recognize authentic outgoing ClientHello or fake payloads even when present; the run is **FAILED**, not native evidence of either presence or absence. The decoder now accepts an explicit `ports` argument defaulting to its original `6541–6543`; the fake trial passes `6544–6545` and exercises a regression proving default-port filtering does not silently admit the new trial. Existing TLS `pktmod` proof remains unchanged and must still pass its own native job. The active peer receiver mismatch is a separate observed loopback effect and does not qualify the fake by itself. No owner WAN or A07/A08 evidence is claimed.

## Evidence and acceptance boundary

**Local preflight:** Python syntax plus negative/positive packet-attribution assertions can be tested off-target; synthetic PCAP frames never prove native behavior. Native qualification requires the **exact** `NATIVE_TLS_FAKE_PACKET=PASS` marker from a successfully completed FreeBSD15.1 job on the exact PR head. A failed/skipped native run is not success; retain and investigate its logs before any correction.

The original ClientHello remained attributable on the outgoing flow; the matching B phase also restored unchanged peer delivery. Native evidence is retained in [the exact trial record](evidence/2026-10-30-v0.6.1_18-native-tls-fake.md). Full PR acceptance still requires successful exact-head CI after these documentation updates.
