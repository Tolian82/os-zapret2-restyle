# #1052 P2k8i — original FD9 pre-IPFW observer handoff, fail-closed

**Candidate:** `v0.6.5_39` source, 14 November 2026. **No installed active Auto-detect or published .pkg.**

## User path and concrete defect

The original single Strategies/Voice shared Apply launches one `dvtws2` via `apply_runtime_activate()` (including restoration of the previous release), **before** `firewall_shared_runtime install`. P2k8h qualified an import-only, real FreeBSD helper that repairs the original protected `root:nobody-group 0660` raw/debug inodes after the original engine drops privileges. It had no installed original-FD9 caller, nor any way to preserve the exact **prelaunch** producer inode witness through the shell's original launcher without introducing a second daemon, lock or persistent witness.

P2k8i puts `apply_runtime_observer_preflight()` in the **real shared Apply preflight** before the journal/kernel and once again directly in `apply_runtime_original_launcher_once()` shared by activating and restoring a common engine. A normal release with only explicit `<HOSTLIST:auto>` materialized to ordinary `--hostlist` is unaffected. An actual `--hostlist-auto=` cannot launch without active generation metadata, and a forged/dangling generation file cannot authorize a collector. **Today the `authorize` CLI is absent and must refuse every live collector candidate**, until complete original same-generation schema-2, bounded cron/configd, safe pending drain/ACK and user data consumption are qualified.

## Original FD9 kernel and inode chain

The same installed `auto_detect_post_drop.py` module now exposes internal `capture` and `restore` commands for the *original held FD9 only*, reusing `voice_ipfw_adapter.require_lifecycle_lock()` instead of inventing a second lock. Under canonical `/var/run/zapret2-lifecycle.lock`, native FreeBSD EUID0 and original root-controlled producer root, `capture` prints a compact exact unsigned 6-integer tuple for both protected dev/inode/link identities. No extra file, cursor or database is written. After the original `launcher_start_once()`, `restore` receives that unchanged tuple, the original launcher-owned pidfile PID and its original absolute `dvtws2` binary; it rereads FreeBSD `ps` birth, uses P2b `OwnerToken` and `_owner_snapshot`, and invokes P2k8h's already-qualified `O_NOFOLLOW`/`fstat`/`fchown` on the **original same inodes**, refusing pid/args/owner drift. If the future authorized post-drop repair fails, the wrapper stops the just-launched engine and refuses **before IPFW install**. Existing single-engine rollback and journal retain their source contracts; the script does not start a second engine or write Config.

## Evidence and strict acceptance boundary

- Fast source tests `scripts/test-auto-detect-fd9-launch.sh` exercise a real shell invocation of the shared `apply_runtime_activate` with no observer: **one launcher → IPFW → supervisor**, and missing/forged/symlinked active generation or standalone `--hostlist-auto-debug=` refuses without launching. Two existing source-mounted Voice/cold-Apply fixtures were updated to include the real new `apply_runtime_observer_preflight()` rather than supplying a bypass stub. `scripts/test-auto-detect-post-drop.py` exercises numeric witness malformed and off-FreeBSD CLI refusal without changing files. Both join existing affected CI.
- The **existing one** disposable OPNsense 26.7 P2e/P2g/P2i VM now holds the original native FD9 over two *distinct* short Python processes, checks the missing FD9 refusal, captures the real P2g prelaunch inode identities, starts the original P2h pinned upstream `dvtws2 --user=nobody`, rejects a forged inode baton while raw remains nobody-owned, restores root ownership through the genuine original held-FD9 CLI, and only then installs its prior two scoped IPFW loopback rules and exercises known-first-match + unknown raw/debug append. No second VM/traffic program or unrelated long matrix.
- A green native packet run proves **qualified original-FD9 descriptor and protected original inode repair on disposable FreeBSD**, *not* that the installed product has an activated observer or that original FD9 is held across any new cron worker. The `authorize` command remains deliberately unimplemented, no real schema-2 owner map is written, and neither actual discovery, pending ACK nor cron/configd is registered. `commit_authorized=false`. Only explicit `<HOSTLIST:auto>` turns the final `auto-domains.txt` into a consumed list. Obsolete `zapret-hosts-auto.txt` content is never read/imported.
