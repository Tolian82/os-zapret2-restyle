# v0.3.3_21 — Migration Patch 4: Python request/probe execution

## Scope

This patch moves Strategy Lab finite request execution and stage-30/stage-40 probe parsing to Python 3.13 without moving candidate/family orchestration.

Python now owns:

- bounded DNS, TLS 1.3, TLS 1.2, HTTP, TCP and QUIC-control subprocess execution;
- separate command/arguments, return code, stdout, stderr, timeout/termination and duration evidence;
- DNS A/AAAA parsing restricted to the actual `ANSWER SECTION`;
- stage-30 IPv4/IPv6/QUIC capability probing;
- stage-40 clean-baseline execution and parsing;
- candidate DNS first-answer parsing through the same Python parser.

Compatibility boundaries:

- public `network.json` and `baseline.json` schemas remain unchanged;
- legacy combined text logs remain available to existing shell consumers;
- richer diagnostics are written to `network-evidence.json` and `baseline-evidence.json`;
- `strategy_lab/request.sh`, `extended_request.sh`, and `strategy_lab_probe_runner.sh` are thin adapters into Python;
- candidate runtime/family ordering, candidate lifecycle, expansion/stability and extended-protocol orchestration remain shell-owned until Migration Patches 5–6.

## Correctness fixes discovered during cutover

- the shell-global `_strategy_lab_type` collision is removed from the production baseline path because target type is now local Python state;
- DNS parser false positives from QUESTION/AUTHORITY/additional text are rejected;
- DNS timeout, subprocess failure and parser rejection remain distinct structured evidence;
- a terminal publication race exposed by the faster probe path was corrected: circular eligibility is persisted before the terminal `completed/error` state becomes visible, while all Patch-3 terminal semantics remain unchanged.
