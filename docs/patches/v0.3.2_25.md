# v0.3.2_25 — Strategy Lab hardening contract

## Purpose

Open the post-audit Strategy Lab hardening series and record the accepted implementation and publication order before runtime changes begin.

## Accepted decisions

- IPFW rules `19100–19131` are an exclusive Strategy Lab reservation. The implementation deliberately does not detect foreign occupancy, identify rule ownership, snapshot pre-existing rules, or restore rules found in that range.
- Every reported working result must include the tested domain or IP address and a complete profile ready to paste into **Traffic Strategy**.
- A result may not expose only a catalog fragment. It must include every profile-level filter, selector, range, payload, and desynchronization option used by the verified test.
- Domain profiles use the static Zapret2 selector `--hostlist-domains=`. IP profiles use `--ipset-ip=`. Global runtime parameters such as divert port, Lua initializers, daemon user, and socket arguments are not copied into Traffic Strategy.
- The exact displayed profile must pass a dedicated replay verification before entering the final shortlist.
- The series follows one logical change → one patch → one build → one verification.
- GitHub publication is strictly serialized: publish one commit, wait until all required checks complete successfully, verify the remote commit, and only then begin the next patch.
- A failed check is corrected within the current patch; no later patch may be stacked behind an unverified commit.

4. Complete Traffic Strategy profile construction and replay.
