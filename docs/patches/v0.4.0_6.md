# v0.4.0_6 — Strategy Lab timeout containment live candidate

Date: 2026-08-09
Status: testing candidate; `_32` is not closed until owner-live evidence is reviewed.

## Scope

This revision applies the smallest telemetry-backed correction needed to retest the
observed Stage-50 failure on OPNsense without mixing in `_33` validation changes or
warm-runtime experiments.

Measured `0.4.0_5` evidence showed seven reconnaissance candidates completing at roughly
5.11 seconds each while the single-candidate limit was 5 seconds and the enclosing Stage
50 limit was 45 seconds. The parent therefore could expire before the family result was
published. Stage 60 was also observed near its 60-second enclosing limit.

## Changes

- raise cold candidate execution defaults from 5 to 8 seconds for reconnaissance,
  expansion, stability and extended candidate runners;
- raise the current Stage-50 enclosing timeout from 45 to 60 seconds;
- raise Stage 60 from 60 to 70 seconds;
- keep the standard/extended search budgets at 150/270 seconds;
- after a forced Stage-50 candidate stop, run a separate bounded candidate cleanup so a
  killed Python child cannot leave temporary dvtws2/IPFW state behind;
- bump the plugin revision to `0.4.0_6`.

All defaults remain environment-overridable.

## Boundary

This testing candidate does **not** claim the complete `_32` hierarchy is finished. The
remaining acceptance work is to verify the live result and then finish/validate parent
admission and the bounded Stage-85/restoration containment model before `_32` is marked
complete. `_33` remains out of scope.
