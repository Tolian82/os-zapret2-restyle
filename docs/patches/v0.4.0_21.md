# v0.4.0_21 — Parallel Model B failed-probe attribution corrective

## Scope

This is a narrow experiment-only corrective for the `_20` controlled-parallel Model B
benchmark. Production Strategy Lab remains Model A. Worker width, parallel scheduling,
source-port-qualified IPFW rules, endpoint order, lifecycle ownership and restoration are
unchanged.

## Owner-live trigger

The first `_20` owner-live run against `job.tMYnFA` proved real three-candidate overlap and
reported a 32977 ms exhaustive parallel search, but rejected solely because
`route_attribution=false`. Every other required check, cleanup and restoration check passed.

Evidence:
`docs/verification/evidence/2026-08-11-v0.4.0_20-model-b-parallel-attribution-reject.md`.

## Defect

`_20` required curl write-out to report the connected remote IP and connected local source
port before route attribution could pass. A blocked/failed probe may never establish a
connected socket, so those write-out fields can be absent even though the exact IPFW rule
has already intercepted the packet.

The `_20` synthetic regression hid this boundary because its fake timeout output still
contained both `remote_ip` and `local_port`.

## Corrective contract

For a successful probe, PASS remains strict and unchanged:

- curl exit is zero;
- observed `remote_ip` equals the pinned selected IPv4;
- observed `local_port` equals the requested controlled source port;
- the exact IPFW rule counter grows.

For route attribution of a failed/blocked probe, `_21` requires:

1. execution evidence contains exactly one `--local-port` option with the requested source
   port;
2. execution evidence contains exactly one `--resolve` option equal to
   `endpoint:443:selected_ip`;
3. the source-port-qualified IPFW rule counter grows;
4. the temporary rule is removed successfully.

This does not infer success from a failed request. It proves ownership of the failed traffic
without demanding connected-socket metadata that may not exist.

## Regression coverage

A focused regression now covers three cases:

- blocked/failed curl with empty connected-socket write-out but exact command binding and
  exact IPFW counter growth: classification remains FAIL while attribution passes;
- wrong controlled source port in execution evidence: attribution must fail even if a test
  fixture reports counter growth;
- successful curl: exact connected remote IP and local port remain mandatory for PASS.

The existing `_20` concurrency, width, cleanup, result-equivalence and restoration matrix
continues unchanged.

## Live gate

`_21` must be installed and rerun against the same retained `job.tMYnFA` reference while its
resource inventory remains valid. Acceptance still requires all original parallel benchmark
checks plus semantic restoration. `production_approved=false` remains mandatory regardless
of the measured speed result.
