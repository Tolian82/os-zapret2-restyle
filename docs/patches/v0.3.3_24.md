# v0.3.3_24 — Migration Patch 7: Python final results and shell-owner retirement

## Scope

This patch completes the approved automated Strategy Lab Python migration before the
separate GUI/live reconciliation phase.

Python 3.13 becomes authoritative for:

- Stage 85 complete user-ready profile construction and validation;
- deterministic final source collection and ranking;
- exact three-attempt replay of the complete profile that will be published to the user;
- Standard and Extended unified shortlist selection;
- recommendation and circular-compatible TLS 1.3 subset publication;
- automated-job circular eligibility after verified Stage 90 restoration.

The patch also retires obsolete competing automated shell owners rather than keeping a
fallback orchestration engine.

## New owner

`src/opnsense/scripts/OPNsense/Zapret/strategy_lab_py/result.py` owns final automated
profile/result policy.

Supported profile contracts remain:

- TLS 1.3 — TCP/443 + TLS L7;
- TLS 1.2 — TCP/443 + TLS L7;
- HTTP — TCP/80 + HTTP L7;
- QUIC — UDP/443 + QUIC L7;
- generic UDP — validated configured UDP port with no L7 classifier.

A published profile contains the protocol filter, optional L7 filter, one validated target
selector, `--out-range=-d10`, and only the candidate desynchronization fragment. Runtime-
only dvtws2 arguments, nested filters, extra selectors, placeholders and `--new` are
rejected.

## Exact final replay

Every final source is replayed exactly three times. The replay input is the complete
published profile, not a hidden reconstruction of only its desynchronization fragment.
A source enters the shortlist only when all three attempts pass and the replay evidence
confirms exact profile identity.

Final replay reuses the existing Python `strategy_lab_py/candidate.py` owner. There is no
second readiness/interception/cleanup/protocol state machine.

`strategy_lab_profile_candidate_adapter.sh` is the only replay-specific system boundary.
For domain candidates it replaces exactly the already validated static
`--hostlist-domains=...` selector with the temporary runtime hostlist required by dvtws2;
all other candidate system actions are delegated to the canonical Patch-5/6 candidate
adapter.

## Unified shortlist

Standard mode publishes up to five replay-verified TLS 1.3 candidates.

Extended mode deterministically publishes the best replay-verified candidate per available
protocol in protocol order, up to five total. The TLS 1.3 subset remains separately
available as `circular_items` / `circular_count` for the private circular workflow.

Private circular session state remains shell-owned and consumes a frozen parent shortlist;
it does not gain ownership of automated job state or final result publication.

## Automated circular eligibility

Python evaluates automated-job circular eligibility only after final restoration evidence
is available. Eligibility requires:

- final state `completed`;
- final outcome `SUCCESS`;
- domain target;
- Stage 85 PASS;
- Stage 90 PASS;
- restoration verified;
- three to five valid replay-verified TLS 1.3 circular candidates.

The result is persisted through the Patch-2 Python state owner before terminal publication
becomes visible.

## Retired competing shell owners

The following automated shell owners are removed from the package source:

- `strategy_lab_profile_replay_runner.sh` — old parallel final profile replay engine;
- `strategy_lab/worker_result.sh` — old automated result/circular-eligibility owner;
- `strategy_lab/worker_stage_machine.sh` — old automated stage machine.

This does not remove shell code that still has a deliberate responsibility. In particular,
private circular-session state/worker logic and audited FreeBSD lifecycle, dvtws2 and IPFW
system adapters remain shell-owned.

Some older shell search/profile helper modules remain packaged where they are still sourced
by compatibility/system adapters, but they are not authoritative automated Stage-60/70/80/
85 owners. Physical cleanup beyond the competing owners must not be confused with this
ownership cutover.

## Production path

```text
zapret_service.sh
  -> strategy_lab_worker.sh
  -> strategy_lab_python.py orchestrate JOB_ID
  -> strategy_lab_py/orchestrator.py
  -> strategy_lab_python_stage_adapter.sh
       Stage 85 -> strategy_lab_py/result.py
       eligibility -> strategy_lab_py/result.py
       other OS-specific actions -> strategy_lab_stage_adapter.sh
```

Final replay inside `result.py` calls the same Python `candidate.py`; the narrow profile
adapter only prepares the exact profile for dvtws2 runtime execution.
