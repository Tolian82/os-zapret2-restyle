# v0.3.3_23 — Strategy Lab Migration Patch 6

## Purpose

Move Strategy Lab Stage-60 parameter expansion, Stage-70 stability/replay, and Stage-80 extended TLS 1.2 / HTTP / QUIC / configured generic-UDP orchestration from shell policy into Python 3.13 without pulling Stage-85 final shortlist/result ownership or GUI/status reconciliation forward.

## Ownership after this patch

`strategy_lab_py/search.py` is authoritative for:

- accepted-family expansion catalog selection;
- expansion candidate order, per-candidate timeout/cancellation, incremental result persistence, and early-stop policy;
- stability source collection, strategy de-duplication, deterministic complexity ranking, candidate limit, replay-attempt sequencing, and stable/unstable aggregation;
- forced sequential replay attempts and cleanup after timeout/cancellation.

`strategy_lab_py/extended.py` is authoritative for:

- TLS 1.2 and HTTP extended candidate catalog sequencing and first-working selection;
- QUIC capability skip policy, candidate sequencing, timeout/cancellation, and first-working/not-found result;
- configured generic-UDP input consumption, skip policy, candidate sequencing, timeout/cancellation, and first-working/not-found result.

The Patch-5 Python candidate owner is generalized rather than duplicated. TLS 1.3, TLS 1.2, HTTP, QUIC, and generic UDP share the same Python runtime/readiness/interception/cleanup policy. Candidate PASS still requires successful finite request execution, exact selected-endpoint identity, and IPFW counter growth.

`strategy_lab_py/request.py` additionally owns exact selected-endpoint QUIC and generic-UDP request/response execution while retaining the Patch-4 structured subprocess evidence contract.

`strategy_lab_candidate_adapter.sh` remains the narrow system boundary for audited FreeBSD/OPNsense mutations and observations. It now accepts explicit TCP/UDP transport, port, and optional L7 parameters for extended candidates, but it does not choose search order, timeout policy, candidate outcome, readiness verdict, or protocol result.

## Production launch boundaries

The following production runners are thin Python launchers after Patch 6:

- `strategy_lab_expansion_runner.sh` -> `search expand`;
- `strategy_lab_stability_runner.sh` -> `search stabilize`;
- `strategy_lab_extended_runner.sh` -> `extended tcp`;
- `strategy_lab_quic_runner.sh` -> `extended quic`;
- `strategy_lab_udp_runner.sh` -> `extended udp`.

QUIC and generic-UDP candidate compatibility runners only set protocol environment and delegate to the unified Python candidate runner. They no longer own shell candidate lifecycle/readiness/interception policy.

Older expansion/stability/extended shell modules remain packaged only as legacy compatibility source until the dedicated Patch-7 obsolete-orchestration retirement. They are not authoritative production owners after this patch.

## Compatibility invariants

- Stage numbers and Patch-3 whole-job budgets are unchanged.
- Expansion preserves `total_available`, `completed`, `candidates`, `working`, `failed`, and `stopped_reason`, including `no_accepted_family`, `enough_candidates`, and `catalog_exhausted`.
- Stability preserves deterministic strategy ranking, three-attempt replay by default, `candidates`, `stable`, `unstable`, and existing stop reasons.
- Extended TCP preserves independent TLS 1.2 and HTTP `tested`/`working` result objects and first-working behavior.
- QUIC preserves capability-derived skip reasons, sequential testing, first-working selection, and `not_found`.
- Generic UDP preserves validated job-local port/payload ownership, unconfigured skip behavior, sequential testing, first-working selection, and `not_found`.
- Candidate timeout/cancellation terminates the process group and requests audited candidate cleanup before orchestration continues or exits.
- Saved Traffic Strategy remains immutable.
- Stage 85 and final report/shortlist ownership are unchanged.

## Explicitly outside this patch

Migration Patch 6 does **not** migrate or redesign:

- Stage-85 final shortlist/profile/result assembly;
- remaining obsolete shell-orchestration retirement beyond production ownership cutover;
- circular-session private state ownership;
- GUI/status/progress/reload reconciliation;
- owner-assisted OPNsense live closure or stable publication.

Those remain assigned to Migration Patches 7 and 8.
