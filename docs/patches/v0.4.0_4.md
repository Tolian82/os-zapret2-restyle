# v0.4.0_4 — Native Zapret2 search graph

Status: **SOURCE-QUALIFIED / NOT PUBLISHED OR OWNER-TESTED**

## Purpose

Implement adaptive-search `_30` as one search-space ownership change. Stage 50 and Stage
60 must use a deterministic native-Zapret2 graph rather than treating flat TSV catalogs
as active search policy. The graph must preserve exact candidate ranges and resource
requirements, keep known working strategies reachable, and avoid meaningless Cartesian
products of installed resources and technique parameters.

## Graph contract

`strategy_lab_py/search_graph.py` owns one immutable TLS 1.3 DAG:

- seven low-cost Stage-50 reconnaissance seeds;
- sixteen Stage-60 expansion nodes connected by explicit parent edges;
- deterministic graph and candidate-spec identities;
- stable cost, complexity, provenance and target-binding metadata;
- Stage-50 accepted families as priority evidence only, never as a reachability gate.

The graph validates unique identities, known edges, stage direction and acyclicity before
it can produce a plan. Active Python Stage 50/60 no longer reads
`tls13-families.tsv` or `tls13-expansion.tsv`; those files remain compatibility fixtures
for retired shell paths only.

## Golden/reference corpus

The graph contains two exact regression candidates:

```text
--payload=tls_client_hello
--lua-desync=fake:blob=fake_default_tls
```

```text
--out-range=-d8
--blob=fake_tls_7
--payload=tls_client_hello
--lua-desync=multisplit:pos=2,midsld-2:seqovl=1:seqovl_pattern=fake_tls_7
```

Both remain graph-reachable when Stage 50 accepts no family or an unrelated family. The
second candidate is skipped with explicit evidence when `fake_tls_7.bin` is absent; that
does not remove BLOB-free, built-in or inline candidates. Unrelated installed resources,
including `wireguard*.bin`, never generate candidates.

## Exact candidate and range handoff

Every graph node carries a canonical `CandidateSpec`. Stage 50/60 serialize the exact spec
beside the generated strategy file and pass both to the candidate runner. The runtime
restores the spec, verifies identity/family/protocol/strategy/target binding, and rejects
drift before starting dvtws2. Stability attempts preserve the source spec and graph-node
evidence.

The active graph covers all four resource classes: BLOB-free, Zapret2 built-in, inline
`0x...`, and installed external `.bin`. Its candidates include `-d8`, `-d10`, and no
explicit output range. Final profile construction preserves zero or one candidate-defined
input/output range and no longer injects or requires `--out-range=-d10`.

Existing fixed extended/QUIC/generic-UDP and compatibility catalog fragments now state
their unchanged `-d10` choice explicitly, so removing the runtime default does not alter
those paths.

## Persisted evidence

Each job records:

- `family-search-graph.json` for Stage-50 reconnaissance planning;
- `search-graph.json` for Stage-60 ordering, scheduled nodes, semantic skips, golden ids
  and the graph identity;
- exact `candidate_spec`, `resource_inventory_id`, rendered runtime arguments and
  `graph_node` evidence on candidate results;
- `graph_exhausted` when Stage 60 reaches the end of its native plan.
