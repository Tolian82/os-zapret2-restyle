# v0.3.2_26 — Proof-based candidate runtime cleanup

## Purpose

Prevent Strategy Lab from declaring temporary candidate cleanup successful merely because its PID file was removed.

## Changes

- preserve candidate PID state until cleanup is proven;
- identify every Strategy Lab `dvtws2` process by executable and reserved divert port;
- recover lost or stale PID-file state by scanning the reserved runtime identity;
- send TERM, wait, then send KILL and wait again;
- require both process absence and divert-port release before deleting the PID file;
- require startup readiness evidence: expected process identity, occupied divert port, clean startup log, and survival through a readiness window;
- add the focused runtime-cleanup test to the mandatory domain-diagnostics CI suite.

## Verification

`test-strategy-lab-runtime-cleanup.sh` directly covers TERM/KILL cleanup, PID-file deletion only after proof, lost-PID recovery through runtime identity, and failure while the process or divert socket remains. The test is executed by `test-domain-diagnostics-contract.sh` in required CI.
