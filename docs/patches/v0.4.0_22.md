# v0.4.0_22 — Production Stage-60 controlled-parallel Model B

## Scope

Promote the owner-live accepted width-three controlled-parallel Model B execution semantics
into the real Strategy Lab Stage 60 while preserving cold Model A as the correctness and
runtime fallback.

This patch changes **Stage 60 only**. Stage 50 reconnaissance, Stage 70 stability, Stage 80
extended protocols, Stage 85 finalist validation and Stage 90 lifecycle restoration retain
their existing owners and contracts.

## Production execution model

The normal Stage-60 expansion runner now enters `stage60_parallel.py`.

The adaptive native search graph remains authoritative. A parallel batch contains only nodes
that are already on the currently resolved expansion frontier. The batch selector asks the
existing planner to score those ready nodes against the same Stage-50/current-job evidence;
it never marks an in-flight node resolved and therefore never unlocks a child speculatively.

Production boundaries:

- maximum resident/active candidate width: **3**;
- width is fixed by the accepted architecture decision and is **not CPU-count gated**;
- candidates inside one batch may probe concurrently;
- pinned endpoints inside one candidate remain sequential;
- when the winner target is partly satisfied, the next batch width is reduced to the number
  of winners still needed, so early-stop does not intentionally overshoot the winner target;
- batch outcomes are persisted in deterministic planner order, not thread completion order.

## Traffic ownership and PASS semantics

The production path reuses the exact `_21` owner-live attribution boundary:

- one unique controlled TCP source port per candidate/endpoint probe;
- one source-port-qualified temporary IPFW rule per active worker;
- exact pinned `--resolve endpoint:443:selected_ip` execution;
- exact rule counter growth and rule cleanup;
- a successful candidate endpoint still requires connected `remote_ip == selected_ip` and
  observed `local_port == requested_local_port`;
- a blocked/failed probe may prove route ownership through exact command binding plus exact
  matching IPFW counter growth and successful rule cleanup, but it remains a FAIL candidate
  result.

No parallel endpoint probing is introduced; only independent candidate tasks overlap.

## Budget and cancellation containment

Warm batch admission is performed before launch against the existing absolute Stage-60
operation deadline. The admission envelope includes:

- the bounded per-candidate discovery-probe envelope for all pinned endpoints;
- a conservative warm-pool startup reserve;
- the existing termination reserve;
- the existing cleanup reserve;
- the existing admission guard.

If that envelope no longer fits, Stage 60 persists the same honest
`insufficient_stage_budget` partial result and returns timeout rather than starting work that
cannot be cleaned within the parent boundary.

Cancellation is checked before batches and between sequential endpoints. The Stage-60 shell
owner also traps termination and unconditionally cleans the dedicated warm-worker rules,
ports and session.

## Cold Model A fallback

The existing `search.expand()` cold implementation is retained unchanged.

`STRATEGY_LAB_STAGE60_MODEL=cold` explicitly selects it for rollback/testing.

During normal parallel operation, any warm **infrastructure** failure (preflight, worker
readiness/identity, source-port ownership, route attribution, worker stability or cleanup)
disables warm execution for the rest of that Stage 60. The affected currently selected
candidates are then replayed through the existing cold candidate runner in deterministic
order, subject to the existing cold candidate admission check. Ordinary network FAIL/timeout
classification is evidence and does not itself trigger fallback.

The result records the fallback reason and execution model. This preserves correctness if the
warm optimization cannot be proven safe on a particular appliance.

## Stale-residue recovery

The shared Strategy Lab preflight now also removes dedicated width-three warm-worker process
residue. The normal Strategy Lab firewall-range cleanup already covers the dedicated rules;
the additional cleanup closes the dedicated dvtws2/divert-port residue boundary after a
hard-killed prior run.

## Verification

Automated coverage adds `test-strategy-lab-stage60-parallel-production.sh`, which verifies:

- width-three production routing;
- resolved-frontier batch selection without unresolved parent/child co-scheduling;
- deterministic winner-band width reduction;
- unique source-port planning;
- `_21` failed-probe attribution compatibility;
- explicit cold Model A fallback;
- budget admission and cancellation hooks;
- shell termination cleanup;
- next-job stale warm-worker cleanup.

The existing controlled-parallel Model B tests remain authoritative for synthetic concurrent
worker overlap, exact IPFW attribution, worker isolation and cleanup.

## Owner-live gate

Publication of `_22` does not by itself close the production migration. Owner-live testing
must prove both real production paths:

1. **No-candidate graph exhaustion** — `telegram.org`, Standard mode, normal production
   budget, complete Stage-60 result, no timeout caused by the former cold runtime cost, and
   clean Stage-90 restoration.
2. **Winner / adaptive early-stop** — `rutracker.org`, Standard mode, working candidates
   found through the normal adaptive search, deterministic early stop, unchanged Stage-70+
   behavior, and clean restoration.

Only after both gates pass can controlled-parallel Model B be marked production-verified.
