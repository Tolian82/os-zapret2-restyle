# v0.4.0_9 — adaptive validation depth

Package candidate: `os-zapret2-restyle-0.4.0_9.pkg`
Adaptive-search slice: `_33`

## Purpose

Separate inexpensive discovery evidence from finalist evidence without changing the
native-Zapret2 graph or promoting unmeasured warm-worker ideas. The patch implements the
approved `_33` contract: bounded lightweight discovery, fail-fast 3/3 stability, and cold
finalist depth validation.

## Source behavior

- Stage-50 reconnaissance, Stage-60 graph exploration and Stage-80 candidate discovery use
  a bounded GET limited to the first 4096 response bytes. The existing three-second curl
  network deadline is retained to avoid introducing a new live latency assumption.
- Stage 70 still requires 3/3 fresh-connection success, but the first failed attempt rejects
  the candidate immediately. Remaining repetitions are recorded as skipped/unnecessary,
  never fabricated as PASS.
- Candidate timeout, cancellation, cleanup and `_32` parent-budget admission remain intact.
- Stage 85 validates only the normal publication finalists (maximum three) with one cold,
  exact-profile replay using a larger bounded GET. The byte-depth target is 16 KiB and the
  request range permits up to 64 KiB.
- A valid cold replay that receives at least 16 KiB is `pass`.
- A required network/protocol/interception/HTTP failure is `fail`.
- A successful resource that ends before 16 KiB, or older fixture evidence that cannot
  prove byte depth, is `inconclusive`; it does not erase the independently proven 3/3
  connectivity/stability result.
- The Stage-85 child receives its own candidate envelope and is rejected before launch if
  the remaining parent budget cannot contain execution, termination and cleanup.
- Stage 85 preserves timeout status 124 through the shell stage adapter so the Python
  orchestrator reports a real timeout instead of converting budget exhaustion into a
  generic internal error.

## Deliberate non-goals

This patch does not add warm dvtws2 pools, preloaded buckets, Lua dispatchers, source-port
selectors, simultaneous candidate probes, a larger search graph, or new QUIC search
semantics. Those remain governed by the separate A/B/C experiment gate.

The total Standard/Extended search budgets remain 150/270 seconds. `_32` timeout
containment is retained rather than reopened.

## Verification

Focused regression:

`sh scripts/test-strategy-lab-adaptive-validation.sh`

The regression proves:

- discovery and deep GET ranges/deadlines are distinct;
- short successful responses classify as `inconclusive`, not false PASS/FAIL;
- HTTP failure classifies as `fail`;
- Stage 70 stops a PASS/FAIL candidate after two attempts and does not run the unnecessary
  third attempt;
- a 3/3 candidate still receives all three attempts and is stable;
- Stage 85 publishes a single cold deep replay with structured depth evidence while
  preserving the public shortlist/profile-replay shape.

The focused test is part of the existing search/extended continuity gate, so it runs on
both Linux validation and the FreeBSD 15 package job.

## Live gate

Source/CI/FreeBSD qualification is required before publication. After publication, owner
Standard and Extended testing against the current blocked target is required to validate
that discovery still finds any live winners available under the old probe and that
fail-fast/deep-finalist evidence behaves correctly when a winner is present.

The preceding `v0.4.0_8` timeout-containment live acceptance is preserved in
`docs/verification/evidence/2026-08-10-v0.4.0_8-timeout-containment-pass.md`.
