# v0.4.1_22 — Laboratory IPv4 targets with optional Host / SNI

## Scope

This patch implements the next owner-selected Strategy Lab task: Laboratory accepts a canonical IPv4 address as well as a domain target while preserving truthful protocol validation.

Package identity for this source patch is `VERSION=0.4.1`, `PLUGIN_REVISION=22`.

## Product contract

- The main Laboratory target field accepts either a domain or canonical IPv4 address.
- IPv4 support is deliberately first; IPv6 target support remains deferred because the current fixed search-epoch binding and production routing contract are IPv4-specific.
- An IPv4 target exposes an optional `Host / SNI` field.
- `Host / SNI` is a service identity, not a second destination: the connection remains pinned to the entered IPv4 address.
- When Host / SNI is supplied, TLS/HTTP/QUIC requests use that hostname identity while connecting to the fixed target IPv4 address.
- When Host / SNI is absent, a bare-IP request is validated only with semantics that remain truthful for an IP identity. In particular, a successful TCP connect is never accepted as proof that a TLS/DPI-bypass candidate works.
- Generic UDP uses the fixed destination IPv4 directly and does not require Host / SNI.
- Bare-IP QUIC without a hostname identity is unsupported rather than reported as a successful candidate because hostname verification cannot be performed.

## Runtime/search behavior

- Stage 00 classifies `domain` versus `ip` and persists the existing target contract.
- A per-job immutable `service-host` sidecar carries optional Host / SNI without changing the public status schema.
- Stage 40 skips DNS for an IPv4 target and performs an actual TLS 1.3 request against the fixed destination IP. With Host / SNI, curl preserves the service hostname through the fixed-IP binding.
- The search epoch keeps two identities separate for IP + Host/SNI jobs: `endpoint` is the service hostname and `selected_ip` is the user-entered destination IPv4.
- Native Stage-50/60 IP jobs do not add a hostlist target selector to the temporary dvtws2 candidate. Traffic isolation remains destination-IP/firewall scoped.
- Candidate TLS 1.3, TLS 1.2 and HTTP probes use protocol-aware requests against the fixed selected IP. The former IPv4 plain-TCP candidate shortcut is not used for these protocols.
- QUIC uses the fixed IP plus the explicit endpoint hostname when available; a bare IPv4 endpoint is rejected for QUIC hostname verification.
- Final profiles for an IP target continue to use the already-supported `--ipset-ip=<target>` selector and are replayed three times through the normal exact-profile verification path.
- Temporary circular browser validation remains domain-only in this patch; IP results are still subject to normal shortlist/profile replay verification.

## Preserved architecture

This patch does not change:

- Model C as the only normal production Stage-60 runtime;
- source-port attribution/lease ownership;
- adaptive search ordering or budgets;
- lifecycle lock ownership;
- normal-service stop/restore semantics;
- candidate cleanup, temporary firewall cleanup, or Stage-90 exact restoration;
- Generic UDP payload contract;
- Enable QUIC persistence/gating contract.

## Regression coverage

`tests/test-strategy-lab-ip-targets.sh` is intentionally not introduced; the repository's executable regression is `scripts/test-strategy-lab-ip-targets.sh`, automatically included by the existing Strategy Lab corrective matrix.

It checks:

- canonical IPv4 acceptance and domain regression;
- rejection of noncanonical IPv4 and IP literals as Host / SNI;
- optional Host / SNI endpoint identity;
- fixed-IP TLS 1.3 Stage-40 evidence using curl binding rather than a TCP-connect surrogate;
- search-epoch separation between service hostname and destination IPv4;
- IP search-graph target binding behavior;
- final `--ipset-ip=<target>` selector;
- API/configd/launcher/GUI handoff of Host / SNI;
- truthful Stage-40 IP presentation;
- package revision `_22`.

The complete project/Strategy-Lab corrective matrix and FreeBSD 15 package qualification remain mandatory before merge.
