# v0.4.1_8 — Correct Model-C lifecycle replay traversal

Status: **SOURCE CORRECTIVE / OWNER-LIVE PENDING**

## Root cause

The owner-live `_7` five-repeat Rutracker replay stopped before producing a measurement report. The isolated measurement tree was created with `0700` ancestors while the launched `dvtws2` workers drop privileges to `nobody`. The worker therefore could not traverse the measurement path to its generated runtime files. Model C failed closed to Model B, then the cold fallback surfaced `seqovl-host` status `1`.

This was a measurement-harness defect. The failed `_7` attempt produced no lifecycle-cost data and does not establish a production Model-C regression.

## Corrective

Before `model-c-lifecycle-measure run` starts Stage 60, the packaged Python entry point now validates the exact expected `model-c-lifecycle-measurement/session.*/runs` layout and changes only those three ancestor directories to `0711`. The private cleanup directory remains `0700`; unexpected layouts or permission errors fail closed.

The focused regression reproduces the `_7` `0700` layout, verifies the three required `0711` ancestors, verifies `cleanup-runtime` remains private, and rejects an unexpected layout.

The FreeBSD package CI contract now derives package identity from `VERSION` and `PLUGIN_REVISION` instead of hard-coding the previous source revision. It remains focused on FreeBSD 15 ABI/package inspection, packaged corrective paths, and unchanged production Model C/B contracts.

## Production boundary

Production Model C, Model B fallback, cold Model A, adaptive search, source-port leasing, candidate width, CandidateSpec semantics and discovery GET-4K are unchanged. `_8` only repairs the measurement replay boundary.
