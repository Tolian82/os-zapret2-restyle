# v0.3.3_22 — Strategy Lab Migration Patch 5

## Purpose

Move the standard TLS 1.3 candidate runtime and Stage-50 family screening policy from shell to Python 3.13 without pulling Migration Patch 6 expansion/stability or extended-protocol orchestration forward.

## Ownership after this patch

Python 3.13 is authoritative for the standard candidate path:

- endpoint-to-IPv4 binding using the Patch-4 ANSWER-section-aware DNS parser;
- candidate runtime preparation sequence and readiness decision;
- stable readiness qualification from process identity, divert-socket availability and startup-log classification;
- fatal candidate startup-log rejection;
- endpoint-bound TLS 1.3/TCP probing through the Patch-4 request owner;
- IPFW before/after interception evidence and endpoint identity matching;
- candidate success/error evidence;
- ordered seven-family TLS 1.3 screening;
- per-candidate timeout/cancellation handling;
- `family.json` completed/accepted/rejected aggregation.

`strategy_lab_candidate_adapter.sh` is intentionally a narrow shell system adapter. It retains audited FreeBSD/OPNsense mutations and observations only: WAN lookup, candidate files, IPFW rule installation/removal/counters, job-directory access mode, daemon launch/stop, pid/process identity and divert-socket snapshots. It does not choose family order, readiness verdict, probe success, timeout policy or candidate outcome.

`strategy_lab_candidate_runner.sh` and `strategy_lab_family_runner.sh` are Python launch boundaries. The candidate runner preserves the existing 3–7 argument compatibility contract and smoke defaults so Stage 60/70 callers can reuse the Python candidate without migrating expansion/stability policy early.

The old shell `strategy_lab_family_screen()` owner is retired; `strategy_lab/family.sh` contains no fallback implementation.

## Compatibility invariants

- Stage 50 remains the same numbered stage and preserves its external status/result contract.
- Candidate result evidence retains `id`, `family`, `strategy`, `endpoints`, `all_pass` and runtime evidence.
- Family result evidence retains `total`, `completed`, `families`, `accepted`, `rejected`, `all_pass` and timeout records.
- Standard candidate infrastructure/runtime failure remains non-zero at the compatibility runner boundary while preserving diagnostic JSON.
- Candidate cleanup remains mandatory on success and failure and still proves the reserved IPFW range empty.
- The inherited Strategy Lab lifecycle lock and Patch-3 orchestration remain unchanged.
- Patch-4 finite request/probe ownership remains unchanged.

## Defect-backlog treatment

The standard candidate fatal-log readiness mechanism is replaced by Python and covered by focused regression. This is source/CI correction evidence only. The exact `_17` Stage-50 failure is still not claimed, and the live defect remains open until owner-assisted replacement evidence exists.

## Explicitly outside this patch

Migration Patch 5 does **not** migrate:

- parameter expansion orchestration;
- stability/replay orchestration;
- TLS 1.2 / HTTP extended candidate orchestration;
- QUIC candidate orchestration;
- generic UDP candidate orchestration;
- final shortlist/result ownership;
- GUI/status reconciliation.

Those remain assigned to Migration Patches 6–8.
