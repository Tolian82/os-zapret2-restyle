# v0.3.3_18 — Strategy Lab Python platform and compatibility foundation

## Scope

Implement Migration Patch 1 from `docs/architecture/STRATEGY_LAB_PYTHON_MIGRATION.md`
without changing the active Strategy Lab state machine or product behavior.

## Verified platform contract

For the supported OPNsense 26.7 / FreeBSD 15 target:

- OPNsense 26.7 build configuration uses FreeBSD 15.1 and `PYTHON=313`;
- OPNsense core provides `/usr/local/bin/python3` as the stable link to the selected
  `python${CORE_PYTHON}` interpreter;
- this plugin declares `python313` explicitly because the new packaged code directly
  depends on that runtime;
- the custom package manifest maps that dependency to `lang/python313`;
- no third-party `pip` dependency is introduced.

The compatibility launcher uses `/usr/local/bin/python3` on OPNsense. FreeBSD 15 CI uses
`/usr/local/bin/python3.13` explicitly because the stock FreeBSD VM does not install the
OPNsense-managed compatibility link.

## Changes

- add packaged `strategy_lab_python.py` and `strategy_lab_py` foundation module;
- add `strategy_lab_python_launcher.sh` with Python 3.13 validation and deterministic
  `EX_SOFTWARE=70` startup errors;
- provide a compatibility delegation path to the existing shell worker while leaving it
  disconnected from the production service path in this patch;
- add focused Python 3.13 syntax, import, launcher, error, and delegation regressions;
- extend Linux and FreeBSD 15 CI to execute the foundation on Python 3.13;
- verify the generated package contains the Python sources and declares
  `python313 -> lang/python313`;
- advance `PLUGIN_REVISION` from `17` to `18`.

## Runtime boundary

`zapret_service.sh` still launches
`/usr/local/opnsense/scripts/OPNsense/Zapret/strategy_lab_worker.sh` directly.
No job state, stage, probe, persistence, candidate, lifecycle, or result responsibility
moves to Python in Migration Patch 1.
