# v0.4.0_11 — propagate candidate RSS into Model A evidence

## Purpose

This packaged corrective patch fixes the single live defect exposed by the first
`v0.4.0_10` Model A appliance report: the FreeBSD system adapter measured candidate RSS,
but Python readiness evidence discarded that field before candidate results were
persisted.

No search policy, timeout, lifecycle ownership, Model A coverage rule, or warm-runtime
architecture changes in this patch.

## Runtime correction

`strategy_lab_py/candidate.py` now preserves `rss_kb` from the validated runtime snapshot
inside the readiness object that is written to `candidate-runtime/readiness.json` and
embedded as `runtime` in each candidate result.

When no runtime snapshot exists, the fallback readiness object explicitly exposes
`rss_kb=null`. This keeps unavailable measurement distinct from zero RSS and preserves the
existing Model A truthfulness contract.

The FreeBSD shell adapter itself is unchanged: `v0.4.0_10` already reads RSS with the
configured `ps` binary only after candidate PID identity is validated.

## Regression

`scripts/test-strategy-lab-python-candidate-family.sh` now makes the mock runtime snapshot
return `rss_kb=12345` and requires the persisted successful candidate result to contain
exactly that value.

The existing Model A measurement test continues to require `rss_observed=true` before a
complete fixture can return `reference_collected`.

## Live evidence basis

Owner Standard job `job.Oeq7Rc` on `v0.4.0_10` / `rutracker.org` produced 25 cold samples
and passed every Model A coverage check except RSS. Its summary reported:

- PASS and FAIL candidates observed;
- repeated candidates observed;
- `blob-free`, `builtin`, and `external` resource classes observed;
- `-d8` observed;
- 16 overlapping TLS/443 specs;
- verified clean restoration;
- `rss_observed=false` and all candidate RSS values null.

The exact evidence summary is preserved in
`docs/verification/evidence/2026-08-10-v0.4.0_10-model-a-rss-gap.md`.

## Acceptance boundary

After FreeBSD 15 CI/package qualification and testing-prerelease publication, run one
comparable Standard `rutracker.org` job on `v0.4.0_11`, then summarize that job with the
existing `model-a summarize` command.

Change-specific live PASS requires numeric RSS in candidate samples and
`coverage.checks.rss_observed=true`. If the remaining coverage conditions are again
present, the report should reach `conclusion=reference_collected`.

`v0.4.0_11` still does not approve Model B/C, a warm pool, dispatcher, source-port
selector, preload policy, or parallel candidate probing.
