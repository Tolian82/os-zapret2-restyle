# v0.4.0_26 — Adaptive Strategy Lab workload budget

Status: **SOURCE/CI/PUBLICATION/OWNER-LIVE PASS**

## Scope

This packaged patch changes **Strategy Lab parent-budget calculation only**. It does not
change the native candidate graph, Model-C/Model-B/cold-Model-A execution order, candidate
classification, source-port leasing, endpoint attribution, cancellation semantics, or
semantic restoration.

The accepted `_25` topology remains the calibrated floor:

- base Standard budget: `150 s`;
- base Extended increment: `120 s`;
- base Stage-80 parent: `120 s`;
- reference endpoint count: `2`.

After Stage 30 has measured the network, `_26` derives one deterministic
`eligible-work-v1` plan from the actual eligible work matrix rather than replacing the
known-good floor with one oversized guessed timeout.

## Workload inputs

The plan records:

`number of endpoints × IPv4/IPv6 × TLS/QUIC × Generic UDP × Standard/Extended mode`.

Current production semantics are respected exactly:

- IPv4 is mandatory for a Stage-30 PASS and remains the native search epoch;
- IPv6 availability adds real clean-baseline DNS/TLS work but does not pretend that the
  current TLS 1.3 candidate graph has become IPv6-owned;
- QUIC is charged only in Extended mode when Stage 30 reports `quic_ipv4=available`;
- Generic UDP is charged only in Extended mode when the validated job-local UDP request is
  configured;
- Extended TCP remains covered by the existing `120 s` Extended floor;
- endpoint growth beyond the currently calibrated two-endpoint topology adds bounded linear
  headroom rather than a multiplicative unlimited timeout.

## Deterministic weights

The additional finite headroom is:

- each endpoint beyond the calibrated first two: `+30 s` to the Standard parent and, in
  Extended mode, `+15 s` to the Extended/Stage-80 parent;
- available IPv6: `+5 s` per resolved endpoint to the Standard parent for the extra
  AAAA/TLSv6 baseline work;
- available Extended QUIC: `+20 s`, matching the four-entry QUIC catalog at the existing
  `5 s` optional-candidate envelope;
- configured Generic UDP: `+15 s`, matching the three-entry UDP catalog at the existing
  `5 s` optional-candidate envelope.

The algorithm never reduces the configured base budgets. Environment overrides for the
existing base budget variables remain the floor and are extended by the same measured-work
policy.

For the accepted two-endpoint IPv4-only/QUIC-closed/no-UDP topology, the effective budget is
exactly `150 + 120 = 270 s`, with Stage 80 `120 s`. Owner-live `_26` `job.xhdgCU` confirmed
this exact production behavior.

For a two-endpoint Extended job with IPv6, QUIC and Generic UDP all eligible, the deterministic
plan is:

- Standard `160 s`;
- Extended increment `155 s`;
- total search/job deadline `315 s`;
- Stage-80 parent `155 s`.

All absolute deadlines remain anchored to the original job start epoch. Stage 30 does not
restart the clock.

## Persistence and telemetry

After a successful Stage 30, production orchestration writes
`adaptive-budget.json` in the job directory and records a `budget_adaptation` event in
`timing-telemetry.json`. The existing public numeric budget/deadline fields in `status.json`
are rewritten to the effective values through the established atomic state owner.

The persisted plan includes:

- `policy=eligible-work-v1`;
- measured work matrix;
- explicit weights;
- per-source additions;
- base and effective Standard/Extended/search/Stage-80 seconds.

This makes owner-live evidence able to distinguish a real adaptive extension from a fallback,
timeout or arbitrary environment override.

## Implementation

- `strategy_lab_py/adaptive_budget.py` owns calculation, durable plan evidence, telemetry and
  the production `AdaptiveBudgetOrchestrator`;
- `strategy_lab_py/compat.py` routes automated orchestration through that owner;
- the existing `Budget` implementation remains the absolute deadline primitive;
- `late_containment.ContainedOrchestrator` remains the Stage-85/restoration containment base;
- Stage 60 remains `C-warm-bucket-source-port-dispatch -> B-warm-worker-parallel-batched ->
  A-cold-fallback` with `_25` free-port leasing unchanged.
