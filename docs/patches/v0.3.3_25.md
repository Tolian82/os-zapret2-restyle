# v0.3.3_25 — Migration Patch 8: GUI/status reconciliation and live-gate candidate

## Scope

This patch begins the final Strategy Lab migration phase after automated backend ownership
was completed in `_24`. It reconciles the Diagnostics presentation and status-read path
with the persisted Python job-state model and prepares the first post-migration package
candidate for owner-assisted OPNsense verification.

The patch does **not** move any automated backend policy out of Python and does not mark
frozen `_17` live defects fixed without new appliance evidence.

## Launcher lock isolation

The ordinary automated launcher held `STRATEGY_LAB_LOCK_FILE` on file descriptor 9 while
calling `daemon(8)`. Unlike the already corrected private circular launcher, the automated
path did not explicitly close FD 9 for the background lifecycle process.

That allowed the long-lived worker tree to inherit the launcher serialization lock. While
the worker was active, a status request could fail the nonblocking launcher lock and
configd could surface an empty response. This is consistent with the frozen `_17` GUI
symptoms: immediate visible ERROR, `Strategy Lab returned no output.`, and progress staying
at 0% until the worker terminated.

`strategy_lab/launch.sh` now starts the background lifecycle transaction with `9>&-`.
The launcher lock remains held by the short start transaction itself but is not inherited
by the worker.

## Transport status is not job state

`StrategyLabController::backendResponse()` now marks empty and invalid configd output with
`transient=true`. Browser/AJAX transport failures use the same transient channel.

Diagnostics now treats a Strategy Lab job snapshot as authoritative only when it contains:

- a validated `job.*` identifier; and
- one persisted automated job state: `queued`, `running`, `cancel_requested`, `completed`,
  or `error`.

The visible job state is derived only from `data.state`. `data.status` is never used as a
fallback job state, so a transport reply such as `{status:"error"}` cannot masquerade as a
terminal Strategy Lab ERROR.

## Polling, progress and reload

For an active job:

- transient status reads preserve the last valid rendered job state/progress;
- the GUI shows a localized temporary-status message and retries polling;
- non-transient backend errors stop polling without fabricating a persisted terminal state;
- an accepted start is rendered immediately as `QUEUED` at Stage 00 while the first
  persisted snapshot is being read;
- persisted `progress.percent` remains authoritative, with the historical stage map only
  as fallback.

Diagnostics initialization uses an explicit active-job discovery routine. A transient
initial read is retried; explicit `{status:"idle"}` still opens the idle view and does not
resurrect retained terminal history. An actual active snapshot resumes polling.

Private circular polling also preserves its last valid state across transient/busy reads.

## Focused regression

`scripts/test-strategy-lab-gui-status-reconciliation.sh` requires:

- automated `daemon(8)` launch closes FD 9;
- empty/invalid backend output is classified transient;
- AJAX failures use the transient channel;
- GUI job rendering accepts only validated persisted snapshots;
- transport `status` cannot fall back into visible job `state`;
- active polling retries transient reads without clearing persisted progress;
- reload discovery retries transient reads and accepts explicit idle;
- start renders a queued Stage-00 snapshot before polling;
- RU/EN transient status messaging remains deliberate.

The canonical Strategy Lab corrective matrix discovers this regression automatically.
