# Patch candidate `v0.3.2_17` — Cancel active Strategy Lab runners

## Scope

Corrective Patch 3 makes active stage 60, 70, and 80 runner processes responsive to the persisted cancel control. It deliberately leaves stage ordering, terminal-outcome classification, and shared time budgets to later corrective patches.

## Changes

- Added one common cancellation-aware runner boundary.
- Added production wrappers for parameter expansion, stability, extended TCP, QUIC, and configured UDP.
- Exported the worker PID and job cancel-file path to controlled runner descendants.
- On cancellation, the boundary captures and terminates the active process tree, waits a bounded grace interval, escalates remaining processes to `KILL`, reaps the root runner, and signals the worker.
- The existing worker `TERM` trap then marks unfinished work skipped and performs mandatory candidate cleanup and semantic service restoration.
- Normal runner exit status is preserved when no cancellation exists.

## Regression coverage

`scripts/test-strategy-lab-active-cancel.sh` exercises cancellation while representative stage 60, stage 70, extended TCP, QUIC, and UDP work is active. Every case verifies:

- the worker cancellation trap is invoked;
- the runner and its child are no longer alive;
- completion occurs within a bounded interval;
- normal non-zero status propagation still works;
- production runner variables point to the cancellation wrappers;
- every wrapper uses the common process-tree implementation.
