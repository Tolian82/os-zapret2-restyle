# v0.4.0_10 — Model A cold-reference measurement harness

## Purpose

This packaged patch starts the post-`_33` experiment phase without promoting a warm
runtime model. It adds a read-only Model A evidence summarizer for completed cold Strategy
Lab jobs and adds RSS evidence to future candidate readiness snapshots.

The production candidate lifecycle remains cold and serial. No Model B/C worker pool,
dispatcher, source-port selector, warm preload policy or parallel probing is enabled.

## Runtime changes

- `strategy_lab_py/model_a.py` adds:
  `model-a summarize OUTPUT JOB_ID [JOB_ID ...]`;
- the command consumes only retained completed-job evidence and does not acquire lifecycle
  ownership, stop/start Zapret2, launch a candidate, alter a job, or delete evidence;
- candidate samples are collected from Stage 50, Stage 60, Stage 70 attempt evidence and
  Stage 85 cold deep replay evidence;
- the report preserves candidate/spec identity, stage/path, result classification,
  endpoint/interception identity, resource class, output range, search epoch and resource
  inventory identity;
- per-phase statistics include count, median, nearest-rank p90 and max for preparation,
  launch, readiness, probe, combined bounded stop/cleanup and total cold wall time;
- per-candidate statistics group repetitions by immutable `spec_id`;
- the report evaluates the experiment-plan corpus/coverage conditions and returns
  `reference_collected` only when the currently machine-checkable Model A coverage is
  complete; otherwise it reports `inconclusive` and the missing checks;
- future candidate readiness snapshots now include `rss_kb` when FreeBSD `ps` can read it;
- appliance/package identity is included when the summarizer runs on FreeBSD/OPNsense.

## Explicit measurement limits

Two phase boundaries remain intentionally truthful rather than fabricated:

- `resource_init_ms` remains `null` while resource initialization cannot be separated from
  launch/readiness without changing the runtime model;
- current production cleanup exposes one bounded `cleanup_ms`; the report therefore names
  it `stop_cleanup_ms` and does not claim a separate `stop_ms` value.

The harness is designed to show these gaps explicitly. A later instrumentation change is
justified only if live Model A data shows that the combined phase must be decomposed before
a warm-model decision.

## Experiment workflow

After installing the candidate, run normal Strategy Lab tests under identical appliance,
Zapret2 runtime, target and search-epoch conditions. Retain enough completed jobs to give
repeated samples, then summarize them, for example:

```text
/usr/local/opnsense/scripts/OPNsense/Zapret/strategy_lab_python_launcher.sh \
  model-a summarize /root/strategy-lab-model-a.json \
  job.AAAAAA job.BBBBBB job.CCCCCC
```

The resulting JSON is the portable raw/summary evidence record to preserve under
`docs/verification/evidence/` after owner-assisted execution.

## Verification

Focused regression:

`sh scripts/test-strategy-lab-model-a-measurement.sh`

The normal corrective matrix discovers this test automatically because it matches the
`test-strategy-lab-*.sh` contract. Packaged-source changes also require the normal Python
3.13/Linux and FreeBSD 15 package gates.

## Acceptance boundary

`v0.4.0_10` does **not** approve Model B or Model C. Its live acceptance condition is that
real OPNsense jobs produce a truthful Model A report with usable timing/RSS distributions,
exact candidate/interception identity and verified restoration/cleanup evidence. Any
coverage gap remains `inconclusive` rather than being filled by assumption.
