# v0.4.0_12 — Model B warm-worker coexistence experiment harness

## Purpose

This packaged patch adds the **experiment-only** Model B measurement harness selected by
the accepted Model A cold reference. It does not change normal Strategy Lab search,
shortlisting, candidate execution or GUI behavior.

The question for `_12` is narrow: can several exact Model-A reference candidates remain
alive as distinct warm `dvtws2` workers while sequential probes are routed to one intended
worker at a time with deterministic attribution, cold-result equivalence and complete
lifecycle restoration?

## Experiment corpus

The harness consumes one completed successful Model A Standard/domain job. For the current
owner reference `job.TtZeaH`, it deterministically selects three compatible TLS 1.3 / TCP
443 candidates from the retained evidence:

- one repeated known-PASS `blob-free` candidate;
- one known-FAIL `builtin` candidate;
- one known-FAIL `external` candidate using `-d8`.

The retained `CandidateSpec`, pinned search epoch and `ResourceInventory` are the source of
truth. The currently installed Lua/fake-file inventory must have the same inventory
identity as the reference job or the experiment rejects before worker launch.

## Warm-worker isolation

Model B uses three dedicated experimental worker slots only:

| Slot | Divert port | IPFW rule |
|---|---:|---:|
| pass | 9990 | 19128 |
| builtin | 9991 | 19129 |
| external | 9992 | 19130 |

Each worker has its own runtime directory, PID file, log, rendered exact candidate
arguments and divert port. PID identity validation includes the exact `dvtws2` executable
and assigned `--port=` value.

The FreeBSD adapter can touch only those three ports/rules. It does not call the normal
Strategy Lab whole-range firewall cleanup and does not change the production candidate
runtime contract.

## Sequential routing contract

All three workers are launched before the first probe and must reach readiness. Probes are
then run strictly sequentially.

For one selected probe the harness installs only that worker's dedicated divert rule. The
two inactive Model B rules must be absent. The selected rule's packet counter must grow,
the pinned endpoint identity is recorded, and the resulting PASS/FAIL classification must
match the same candidate's Model A reference classification. The route is removed before
the next candidate is selected.

The initial sequence is `PASS -> builtin FAIL -> external -d8 FAIL -> PASS`, which checks
that repeated selection remains stable while all workers coexist.

No source-port selector, Model C dispatcher or simultaneous candidate probing is used.

## Failure/cleanup measurements

After the coexistence sequence the harness:

1. stops the builtin worker and verifies the other workers remain ready and the known-PASS
   worker still matches Model A;
2. deliberately kills the external worker, verifies its process/socket are absent, and
   confirms the remaining PASS worker still behaves identically;
3. records per-worker and aggregate RSS plus pool startup, dispatch and probe timing;
4. removes all dedicated Model B rules/processes.

A mismatch in result, worker identity, routing attribution, survivor behavior, controlled
worker-death cleanup or RSS evidence prevents preliminary acceptance.

## Lifecycle ownership

`strategy_lab_model_b.sh` acquires the same `/var/run/zapret2-lifecycle.lock` used by
normal Zapret2/Strategy Lab lifecycle operations. The experiment worker inherits lock FD 9
and the existing internal service ownership token.

Before Model B starts, semantic Zapret2 evidence is captured and the current normal
service state must match the Model A reference. The normal service is stopped under the
shared lock, the experiment runs, all dedicated Model B state is removed, and the original
service state is restored.

Final acceptance additionally requires the final semantic service state, effective config
hash, runtime-arguments hash and normal-firewall hash to match the initial evidence.

The wrapper has terminal cleanup/restoration handling so a normal error, cancellation or
signal path cannot intentionally bypass restoration.

## Result contract

The output JSON is an experiment record, not a Strategy Lab user result.

`conclusion=accept` means only that the Model B **coexistence experiment** passed its
measurement contract on that appliance/run. The report always retains:

- `experiment_only=true`;
- `parallel_probes=false`;
- `production_approved=false`.

A successful `_12` live run therefore permits an evidence/decision review; it does not by
itself switch production Strategy Lab to warm workers.

## Invocation after testing-prerelease publication

Use the accepted `_11` reference job and an explicit report path:

```text
/usr/local/opnsense/scripts/OPNsense/Zapret/strategy_lab_model_b.sh \
  job.TtZeaH /root/strategy-lab-model-b-v0.4.0_12.json
```

The command prints the report path and experiment conclusion after restoration. Upload the
JSON for the evidence review.

## Regression

`scripts/test-strategy-lab-model-b-experiment.sh` uses a deterministic mock system adapter
and reference corpus to verify:

- three simultaneous warm worker identities and numeric RSS;
- sequential A/B/C/A routing with inactive rules absent;
- exact Model-A PASS/FAIL equivalence;
- independent worker stop;
- controlled worker-death cleanup;
- remaining-worker equivalence after stop/death;
- semantic restoration as a hard final gate;
- rejection if normal-firewall restoration evidence changes;
- the explicit non-production/non-parallel boundary.

## Out of scope

`v0.4.0_12` does not implement or approve:

- production warm-worker reuse;
- Model C or candidate buckets;
- source-port dispatch;
- simultaneous/parallel candidate probes;
- Lua/BLOB preload-policy changes;
- new search ordering or timeout constants;
- GUI controls for Model B.
