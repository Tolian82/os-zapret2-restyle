# Patch v0.3.2_5

Date: 2026-08-04

Package candidate:
`os-zapret2-restyle-0.3.2_5.pkg`

Project version:
`0.3.2` unchanged

==================================================
TYPE
==================================================

This is Strategy Lab Patch 3 and an ordinary package patch. It is not a project
release and creates no tag, GitHub Release, release asset, or pkg-repository
publication.

==================================================
OBJECTIVE
==================================================

Implement Strategy Lab stages 10, 20, and 90 as one lifecycle transaction:

- capture the complete initial Zapret2 service state;
- stop a running normal service before testing;
- verify that the normal service is stopped;
- perform mandatory cleanup on every exit path;
- restore exactly RUNNING to RUNNING or STOPPED to STOPPED;
- report `RESTORE_FAILED` when exact restoration is impossible.

==================================================
IMPLEMENTATION
==================================================

- Added `strategy_lab/lifecycle.sh` as the lifecycle adapter used by the worker.
- Routed the whole worker through the existing
  `/var/run/zapret2-lifecycle.lock` boundary owned by `zapret_service.sh`.
- Added internal owner-only service actions for status, stop, and start while the
  Strategy Lab worker retains lifecycle-lock descriptor 9.
- Reject incomplete or unknown initial service state before normal runtime mutation.
- Added bounded stop and restore operations.
- Kept stage 90 executable after normal completion, cancellation, signal, or error.
- Preserved completed results and skipped only unexecuted work after cancellation.
- Added exact bilingual service-stop and service-restoration messages.
- Added explicit stage-90 failure and final `RESTORE_FAILED` outcome.

==================================================
BOUNDARIES
==================================================

Patch 3 does not:

- perform DNS, TLS, HTTP, IPv4, IPv6, QUIC, or UDP probes;
- launch a temporary candidate dvtws2;
- install candidate firewall rules;
- connect the dormant Strategy Lab GUI partial to the active Diagnostics page;
- replace the synchronous Blockcheck path.

==================================================
AUTOMATED VERIFICATION
==================================================

Mocked lifecycle coverage verifies:

- RUNNING → stopped during the job → RUNNING;
- STOPPED → remains STOPPED;
- cancellation after service stop still executes stage 90;
- exact `SKIPPED — отменено` and `SKIPPED — canseled` output;
- second-job busy behavior;
- incomplete initial state fails closed without service mutation;
- injected restore-start failure produces `RESTORE_FAILED`;
- internal lifecycle actions reject callers outside the Strategy Lab lock owner;
- shell syntax and legacy Blockcheck-path preservation.

Owner-assisted OPNsense verification remains deferred until all 13 Strategy Lab
patches have completed the serial GitHub gate.
