# v0.3.3_5 — Accept FreeBSD daemon PID files ending at EOF

## Scope

Correct the remaining Strategy Lab stage 10 failure after revision `0.3.3_4`.

## Root cause

The process-inspector binding was correct, but `strategy_lab_semantic_pid_matches()` read PID files with a shell `read` command followed by immediate failure on a non-zero read status. FreeBSD `daemon(8)` PID files may contain a valid numeric PID without a trailing newline. In that case the variable is populated, but `read` returns non-zero at EOF and the semantic check rejects the valid process.

## Changes

- add shared `common_pidfile_read` parsing for newline-terminated and EOF-terminated numeric PID files;
- reject empty, malformed, PID 0, and PID 1 values;
- use the shared reader in Strategy Lab semantic lifecycle evidence;
- retain the FreeBSD-safe `ps -xww` process identity path;
- add regression coverage with `printf '%s'` PID fixtures;
- record the failed `0.3.3_4` live attempt;
- advance the package candidate to `0.3.3_5`.
