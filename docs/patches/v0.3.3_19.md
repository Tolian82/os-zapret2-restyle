# v0.3.3_19 — Strategy Lab Python state, progress, and structured persistence

## Scope

Implement Migration Patch 2 from `docs/architecture/STRATEGY_LAB_PYTHON_MIGRATION.md`:
move authoritative automated-job state/progress/event persistence to Python while keeping
the numbered stage machine, budgets, lifecycle decisions, probes, candidate search, and
finalization policy in the existing shell orchestration.

## Changes

- add `strategy_lab_py/state.py` as the sole authoritative writer for automated-job
  `status.json` and `events.ndjson`;
- preserve schema 2, stage numbers/keys, progress percentages, cancellation fields,
  terminal-state guards, and revision semantics;
- serialize concurrent automated-job state mutations through the Python state lock;
- use same-directory temporary files, fsync, atomic replace, and mode `0644` for persisted
  automated-job JSON/NDJSON;
- keep shell `strategy_lab/state.sh` function names as thin compatibility adapters;
- route automated-job target/network/baseline/family/expansion/stability/shortlist/
  extended/QUIC/UDP, lifecycle snapshot/restoration, stale recovery, and terminal
  circular-eligibility fields through Python;
- remove the old shell `strategy_lab_state_transform` and private jq/temp/mv writers from
  the migrated automated-job paths;
- preserve private circular-session `state.json` on its existing shell writer until a
  separately scoped circular-state cutover, avoiding two concurrent owners of that file;
- keep Python state-path validation capable of handling a future private `state.json`
  cutover without making it the production circular owner in Patch 2;
- add focused concurrency, atomic-write, public-schema, progress, revision, cancellation,
  event, stale-recovery, and state-path regressions;
- advance `PLUGIN_REVISION` from `18` to `19`.

## Deliberate non-changes

- `zapret_service.sh` still invokes `strategy_lab_worker.sh` as the production worker;
- shell still decides stage order, stage outcomes, budgets, cancellation/finalization
  policy, candidate search, and lifecycle actions;
- private circular-session state transitions remain on the pre-existing shell writer;
- no probe parser or Stage-50 algorithm is moved;
- no GUI behavior is changed or declared fixed;
- no confirmed live defect is closed by source migration alone.
