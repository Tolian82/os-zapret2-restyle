# v0.4.1_12 — Documentation consistency corrective

Status: **DOCS / GOVERNANCE ONLY**

## 1. What changes and why

A cold-start audit of the newly introduced operational-memory architecture showed that the main
startup path was already effective, but several older specialist/process documents could still send a
new session back into historical analysis:

- `STRATEGY_LAB_MODEL_C.md` still described `C -> B -> A` as the accepted current architecture and
  retained the old `_23` live-pending boundary;
- `STRATEGY_LAB_ADAPTIVE_SEARCH.md` still described A/B/C as future competing experiments and old
  `_32/_33` work as pending;
- `STRATEGY_LAB_ADAPTIVE_BUDGET.md` bound budget policy to preserving the old C/B/A ordering;
- `DEVELOPMENT_GUIDE.md` still used the pre-handoff startup order and made audit/Finding work appear
  mandatory before every code change;
- current-task specialist reading was not explicitly named in `START_HERE`;
- source-code authority versus documentation authority could be read ambiguously;
- `START_HERE`, `PROJECT_STATE` and `ROADMAP` repeated too much of the same material;
- `INDEX` still made several decision/workflow documents look mandatory for every GitHub mutation;
- the old 2026-07-28 document-role map did not include `PROJECT_PRINCIPLES` / `START_HERE`;
- GitHub publication wording did not cleanly distinguish unchanged task-branch creation from the
  documentation gate on the first substantive published change.

This corrective:

- explicitly separates source authority (actual implementation) from documentation authority
  (approved decisions/state/plan) and defines mismatch as a synchronization defect;
- makes `START_HERE` explicitly name the required specialist reading for `_13`;
- reduces duplication among `START_HERE`, `PROJECT_STATE` and `ROADMAP`;
- rewrites Model-C/adaptive-search/adaptive-budget architecture docs to current `_12 -> _13` truth;
- rewrites `DEVELOPMENT_GUIDE` as a compact procedure with audit as a conditional branch;
- simplifies `INDEX` GitHub reading to one always-required publication procedure plus conditional
  decisions;
- clarifies the GitHub documentation gate timing;
- records that the old one-document/one-question role map is superseded only in its mapping while its
  single-responsibility principle remains active.

Non-goals:

- no runtime/package source change;
- no package revision change;
- no Model-C behavior change;
- no prohibition on audits;
- no deletion of historical evidence/patch records;
- no weakening of evidence-first, GitHub-plugin-first, cleanup/restoration or release boundaries.
