# v0.4.0_14 — Model B post-drop worker access corrective

## Scope

One live-proven defect only: the Model B experiment creates its active session ancestors as
private `0700` directories even though every warm dvtws2 candidate is hostlist-backed and
runs with `--user=nobody`.

The `_13` owner run advanced past clean preflight but all three workers disappeared before
readiness: every snapshot had `pid=null`, `process_identity=false`, `socket_ready=false`
and `rss_kb=null`. Selected IPFW counters still moved, so later probes were diverted to
ports without qualifying workers and timed out. Restoration remained fully verified.

Exact owner evidence:
`docs/verification/evidence/2026-08-10-v0.4.0_13-model-b-worker-access-reject.md`.

## Root cause

This is the same FreeBSD/dvtws2 privilege-drop boundary already proved by the normal
Strategy Lab `_16`/`_17` correction series. dvtws2 initially loads its hostlist, switches
to UID/GID 65534, and then checks/reopens the hostlist after the drop. A readable file is
still inaccessible when a private ancestor directory denies search permission.

The Model B path introduced a new private ancestor pair:

`.../strategy-lab/model-b/session.<pid>/workers/<slot>/hostlist.txt`

The hostlist itself is mode `0644`, but `_13` changed both `model-b` and `session.<pid>` to
`0700`, recreating the already solved traversal defect.

## Change

- advance `PLUGIN_REVISION` from `13` to `14`;
- while the lifecycle-owned Model B experiment is active, set the retained `model-b` root
  and the current session directory to search-only-for-others mode `0711`;
- keep the tree non-listable and keep worker hostlists read-only;
- on every worker-wrapper exit path, restore the retained Model B root to private `0700`
  and restore the active session to private `0700` before deleting the per-run session;
- extend the Model B focused regression to require both sides of that bounded access lease
  and the existing hostlist/worker traversal modes;
- record `_13` as a real owner-live Model B reject with complete semantic restoration.

## Explicit non-scope

This patch does not change:

- Model B candidate selection or the exact Model A reference corpus;
- ports `9990–9992` or rules `19128–19130`;
- probe classification, routing, timing or A/B/C/A ordering;
- normal Strategy Lab candidate lifecycle;
- Model C, source-port dispatch or true parallel probing;
- production approval of any warm-worker architecture.

The `_13` run separately proved that the experiment continues after a failed pool-readiness
check and later reports a downstream `kill-owned` error. That fail-fast/control defect is
retained for a separate logical corrective after this worker-access blocker is isolated.

1. the Model B wrapper grants `0711` only to the two active session ancestors needed by

2. private `0700` mode is restored during wrapper cleanup;
3. hostlists remain read-only and worker directories remain traversable;
4. Model B experiment isolation, sequential-probe, RSS, independent stop/death and
   semantic-restoration fixtures remain unchanged;
5. the FreeBSD 15 package still contains the complete Model B harness;
6. live acceptance remains pending until the owner installs `_14` and repeats the same
   `job.TtZeaH` experiment.
