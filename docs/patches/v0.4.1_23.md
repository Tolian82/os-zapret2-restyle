# v0.4.1_23 — truthful Strategy Lab protocol/result classification

## Scope

Correct three owner-live false-result cases found while qualifying `v0.4.1_22`, without changing the accepted Model C runtime, lifecycle/restoration contract, fixed search epoch, candidate catalogs, or search budgets.

## Owner-live evidence that triggered the patch

1. `rutracker.net` reached Stage 70 with three independently stable TLS 1.3 candidates, but Stage 85 discarded them because the authenticated/intercepted HTTP response was `502`. The same jobs already proved `curl` exit `0`, the expected fixed IPv4 endpoint, successful TLS, and firewall interception. An HTTP application error is not evidence that the DPI bypass path failed.
2. Bare-IPv4 QUIC correctly refused hostname verification without Host/SNI at the request layer, but Stage 80 presented four non-executed candidates as “tested”.
3. Bare-IPv4 TLS can fail certificate verification (`curl` exit `60`) solely because no service identity was supplied. Reporting a final `NO_CANDIDATE` in that case is misleading; the user needs Host/SNI for a meaningful HTTPS/TLS test.

## Production behavior

- Finalist deep validation keeps the existing strong requirements: exact profile replay, endpoint PASS, fixed search epoch, and confirmed firewall interception. When those requirements are satisfied and curl returns a real HTTP status, HTTP `4xx`/`5xx` is retained as `reachable_application_error` and remains an accepted DPI-path result. `502` is not special-cased.
- Missing interception, failed replay, missing/invalid HTTP evidence, timeout/reset/TLS failure, or another transport failure still rejects the finalist.
- Enabled QUIC on a bare IPv4 target is short-circuited before candidate execution with `status=skipped`, `reason=host_sni_required`, `tested=[]`. RU/EN Stage-80 presentation explicitly says Host/SNI is required.
- A bare-IPv4 baseline certificate verification failure (`curl` exit `60`) writes job-local evidence that the HTTPS identity is incomplete. If the job would otherwise end as `NO_CANDIDATE`, the terminal result becomes `PARTIAL` with explicit RU/EN guidance to provide Host/SNI and retry. A later run with Host/SNI clears that condition.
- Generic UDP remains valid for bare IPv4 targets. Bare IPv4 itself remains a supported target form.

## Regression coverage

- `scripts/test-strategy-lab-truthful-results.sh` covers accepted intercepted HTTP `502`, rejection without interception, bare-IP TLS identity marking/clearing, truthful bare-IP QUIC skip, RU/EN presentation, packaged entry-point installation, and revision identity.
- Existing IPv4 target contract advances to `PLUGIN_REVISION=23`.
- Existing adaptive-validation tests remain a test of the underlying unpatched classifier; the packaged production entry point explicitly installs the corrective compatibility layer, matching the established `ip_target_support` pattern.
