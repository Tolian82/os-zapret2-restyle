# v0.3.3_27 — Stage-40 DNS deadline correction

Status: **SOURCE CORRECTION / LIVE RETEST REQUIRED**

## Purpose

Correct the repeated Stage-40 DNS prerequisite failure observed on published/installed
`v0.3.3_26` without changing resolver choice, DNS parsing semantics or Strategy Lab
ownership.

## Live evidence

Authoritative evidence:
`docs/verification/evidence/2026-08-08-v0.3.3_26-scenario-01-stage40-dns-deadline.md`.

Job `job.Cs5ryG` shows `/usr/bin/drill rutracker.org A` being terminated after
`duration_ms=2024` and classified as `timeout`. The owner can obtain valid answers from
the same local resolver immediately or, intermittently, only after about 8–10 seconds.
Five additional Strategy Lab attempts stopped at the same Stage-40 prerequisite.

## Root cause

`strategy_lab_py/request.py` limited every DNS subprocess to 2 seconds. In addition,
`strategy_lab_py/orchestrator.py` limited the complete Stage-40 adapter to 5 seconds.

The first limit explains the `_26` evidence directly. Raising only that first limit would
leave the outer Stage-40 watchdog able to terminate a still-valid 8–10-second resolver
request, so both bounds must be corrected together.

## Correction

- keep `/usr/bin/drill` and the local OPNsense resolver path;
- set the Python-owned DNS subprocess deadline to 15 seconds;
- set the enclosing Stage-40 operation limit to 20 seconds;
- keep DNS `timeout`, `command_error` and `parser_rejected` evidence distinct;
- keep ANSWER-section-only A/AAAA parsing unchanged;
- keep the Standard overall budget at 150 seconds;
- apply the same DNS deadline to the Python compatibility `request dns` entry point so
  there is not a second 2-second DNS policy.

These values are upper bounds. A DNS answer returned in milliseconds still completes in
milliseconds.

## Regression

`scripts/test-strategy-lab-python-probes.sh` now requires a valid DNS response delayed
past the old 2-second cutoff to remain PASS and verifies the 15-second request limit.

`scripts/test-strategy-lab-python-orchestration.sh` verifies the 20-second Stage-40
envelope. The existing FreeBSD DNS timeout regression moves its deliberately hung mock
beyond the new deadline and must still terminate with timeout evidence.
