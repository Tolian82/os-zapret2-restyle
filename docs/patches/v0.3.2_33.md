# v0.3.2_33 — Bind candidate endpoints and prove interception

## Purpose

Prevent Strategy Lab from reporting a working candidate when DNS resolution, the temporary firewall rule, and the actual request refer to different remote addresses or when the successful request did not traverse the assigned Strategy Lab rule.

## Changes

- select one IPv4 address for every endpoint and persist endpoint, selected address, and assigned IPFW rule in a binding table;
- deduplicate identical selected addresses while retaining the correct rule mapping for every endpoint;
- use curl `--resolve` for TLS 1.3, TLS 1.2, and HTTP candidate requests;
- connect QUIC and configured UDP probes directly to the selected address while preserving the domain for SNI and certificate verification where applicable;
- disable redirect following for endpoint-bound HTTP requests;
- record IPFW packet and byte counters immediately before and after each candidate request;
- run endpoint probes sequentially so counter growth belongs to the tested request;
- persist selected and remote addresses, rule number, counters, endpoint-match state, and interception state in each endpoint result;
- require successful request status, exact selected/remote address equality, and positive packet-counter growth before reporting PASS;
- apply the same evidence contract to standard TCP/TLS, extended TLS/HTTP, QUIC, and configured UDP candidates.

## Verification

`test-strategy-lab-interception-evidence.sh` verifies deterministic binding and rule reuse, successful evidence publication, rejection of a mismatched remote address, rejection without counter growth, strict redirect handling, selected-IP QUIC connection, and integration in every candidate runner.
