# v0.3.2_32 — Persist candidate runtime readiness

## Purpose

Make a working candidate depend on explicit, reviewable evidence that the intended temporary Strategy Lab runtime was ready before probes were accepted.

## Changes

- persist a per-candidate readiness record containing the Strategy Lab job, PID, executable, command line, reserved divert port, process-identity result, socket readiness, startup-log validation, and readiness-window stability;
- require the exact `dvtws2` executable and reserved port identity;
- require the divert socket to be open and the startup log to contain no fatal, parse, option, bind, or load errors;
- attach the readiness record to TCP/TLS/HTTP, QUIC, and configured UDP candidate results;
- force `all_pass=false` when readiness evidence is missing or not fully successful;
- preserve the evidence file after candidate cleanup for later shortlist and audit use;
- add the focused runtime-readiness test to mandatory CI.

## Verification

`test-strategy-lab-runtime-readiness.sh` verifies the complete positive evidence record, result attachment, rejection of a dirty startup log, and readiness integration in every candidate runner.
