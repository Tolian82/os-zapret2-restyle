# v0.4.0_17 — Model B failed-readiness fail-fast

Date: 2026-08-11
Package candidate: `os-zapret2-restyle-0.4.0_17.pkg`

## Problem

The owner-live `_13` Model B reject proved a control-flow defect independent of the worker-startup causes later closed by `_14` and `_16`: when the warm pool ended readiness with `all_workers_ready=false`, the experiment still entered route/probe and controlled stop/death work. That produced avoidable network timeouts and allowed a downstream `kill-owned` failure to obscure the first causal failure.

The `_16` owner-live rerun later reached `conclusion=accept`, proving that the normal ready-pool path is correct, isolated and restorable. It does not exercise the failed-readiness branch, so that negative-path defect remains valid and separate.

## Correction

`strategy_lab_py/model_b.py` now treats failed pool readiness as a hard experiment boundary.

After all worker snapshots and the three readiness/identity/RSS checks are persisted:

1. if every worker is ready, the existing Model B coexistence sequence is unchanged;
2. if any worker is not ready, the report records the exact failed slots and `downstream_actions_skipped=true`;
3. the experiment immediately becomes a truthful `reject` with error `Model B worker pool did not reach readiness`;
4. no route-add, probe, independent-stop, survivor check, controlled-death or `kill-owned` action is attempted;
5. the existing `finally` cleanup request still runs, after which the shell lifecycle owner performs the existing exact service restoration/finalization transaction.

This patch does not change worker startup, readiness criteria, candidate selection, route ownership, probe semantics, successful Model B behavior or normal Strategy Lab execution.

## Regression contract

New focused regression `scripts/test-strategy-lab-model-b-failed-readiness.sh` injects one non-ready worker and proves:

- final pre-restoration experiment result is `reject`;
- `all_workers_ready=false`, `unique_worker_identity=false`, and missing RSS remain truthful evidence;
- the failed slot is preserved;
- `probes`, `independent_stop`, `controlled_worker_death`, and timing derived from those actions are absent;
- no downstream `route-add`, `route-del`, counter, rule-present, stop or `kill-owned` adapter action occurs;
- bounded `cleanup-all` is still requested.

The existing Model B success regression remains responsible for proving that a fully ready pool still executes the complete sequential coexistence, independent-stop/death and restoration contract.

## Scope boundary

Model B remains an experiment only:

- `experiment_only=true`;
- `parallel_probes=false`;
- `production_approved=false`.

This patch does **not** add Model C, a dispatcher, source-port selection, preload-policy changes, production warm reuse or parallel candidate probing. It also does not convert the promising `_16` latency measurements into a production architecture decision.

## Live boundary

Latest published and owner-tested candidate remains `_16`, whose retained Model B run is `accept` with complete semantic restoration. `_17` is the source candidate for the negative failed-readiness control correction and requires normal CI/FreeBSD 15 qualification before testing publication. A future live negative-path run is useful only if a naturally or deliberately controlled non-ready worker can be induced without weakening lifecycle safety; source regression is the direct change-specific gate.
