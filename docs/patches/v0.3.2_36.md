# v0.3.2_36 — Expose validated generic UDP input

## Purpose

Make the existing generic UDP Strategy Lab branch usable through the supported
Diagnostics GUI/API while preventing arbitrary server-path access and payload retention.

## Changes

- add optional generic UDP port and payload-file controls to extended mode;
- read the selected browser file as Base64 without sending a local path;
- validate the port, canonical Base64, and decoded size in the API;
- limit payloads to `1..4096` bytes;
- extend the configd start action with explicit UDP port and payload parameters;
- preserve backward compatibility for start calls without generic UDP input;
- decode accepted data into fixed `0600` files inside the new job directory;
- expose only port and payload-size metadata in job status;
- export the fixed job-local file to the existing UDP runner;
- remove the payload on success, cancel, timeout, error, failed launch, and stale-worker
  recovery;
- add the focused contract test to mandatory Strategy Lab validation.

## Security boundary

The client cannot provide a server filesystem path. The only accepted payload source is
the uploaded byte content, and the worker can read it only from the fixed current-job
location.
