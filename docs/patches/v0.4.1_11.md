# v0.4.1_11 — Keep Model-C buckets profile-compatible

Status: **SOURCE CORRECTIVE / OWNER-LIVE PENDING**

## Trigger

Published `v0.4.1_10` owner-live lifecycle measurement reached the real production Model-C path. Repeats 1-2 completed through Model C, while repeat 3 produced `Model C bucket candidates are not profile-compatible` and fell back to Model B.

## Root cause

Stage 60 chooses a ready batch width from the remaining winner target. When early winners reduce the target, later batches can shrink to width one and hide profile incompatibility. When no early winners exist, width remains three. The generic adaptive chooser preserves candidate order but can return adjacent ready candidates with different Model-C profile keys.

Model C already validates compatibility using `(l3, transport, port, l7, target_binding)` and correctly refuses a mixed bucket. The defect is therefore the Model-C batching boundary, not rendering, attribution, source-port leasing, measurement, or fallback.

## Corrective

`_11` keeps the native ready order and maximum width three, but while Model C is enabled it selects only the largest contiguous prefix whose candidates share the existing Model-C profile key. The first incompatible candidate remains next in the native order and is not skipped or reordered.

If Model C later disables for any infrastructure reason, the original generic batch chooser is restored before Model B/A fallback continues.

Focused regression proves a mixed ordered ready set is split at the profile boundary and that the next incompatible candidate remains next.

## Unchanged production behavior

- native search graph and candidate priority/order;
- winner target and width-three maximum;
- CandidateSpec identities and rendered strategy semantics;
- source-port lease/allocation and attribution;
- bounded GET-4K discovery;
- Model C -> Model B -> cold Model A fallback;
- cleanup/restoration and lifecycle ownership.

Owner-live must repeat the same five-run lifecycle measurement. Lifecycle reuse/startup optimization remains unselected until a complete fallback-free measurement is accepted.
