# v0.4.1_10 — Align lifecycle replay with the production Stage-60 adapter

Status: **SOURCE CORRECTIVE / OWNER-LIVE PENDING**

## Trigger

Owner-live testing of published `v0.4.1_9` correctly produced an inspectable rejected
report for retained Rutracker reference `job.lWLjqL`. The first replay batch reported:

`Model C unavailable (Stage-60 controlled source-port alternate pool is exhausted); Model B fallback failed (Stage-60 controlled source-port alternate pool is exhausted)`

The report then failed fast after repeat 1, retained all fourteen persisted cold-fallback
batches, and proved cleanup/lifecycle restoration.

## Root cause

The `_9` diagnostic was truthful, but the observed source-port exhaustion was introduced by
the measurement worker rather than by production Stage 60.

Production `strategy_lab_stage60_parallel_runner.sh` selects
`strategy_lab_model_b_parallel_adapter.sh` and exports it through
`STRATEGY_LAB_MODEL_B_SYSTEM_ADAPTER`. That adapter implements the controlled-parallel
`source-port-free` and `route-add-source` actions and delegates the accepted base worker,
cleanup and counter actions unchanged.

The lifecycle measurement worker instead defaulted to `strategy_lab_model_b_adapter.sh`
and did not export a matching `STRATEGY_LAB_MODEL_B_SYSTEM_ADAPTER` for the Python replay.
The base adapter has no `source-port-free` action, so every availability probe returned a
non-zero status. `stage60_source_port_lease.py` therefore treated every preferred and
alternate port as unavailable until its bounded 2048-port scan failed closed. Model C and
its independently leased Model B fallback both observed the same artificial exhaustion and
Stage 60 correctly fell back to cold Model A.

This explains the `_9` owner-live result without establishing a production Model-C or
source-port-leasing regression.

## Corrective

`_10` changes only the lifecycle measurement owner:

- default its Model-B system adapter to the same
  `strategy_lab_model_b_parallel_adapter.sh` used by production Stage 60;
- export the resolved adapter through `STRATEGY_LAB_MODEL_B_SYSTEM_ADAPTER` before invoking
  the Python replay so `model_b._try_adapter()` reaches the production controlled-parallel
  adapter contract;
- keep cleanup on that same adapter, which delegates `cleanup-all` to the accepted base
  adapter;
- extend the focused lifecycle regression to prove production owner and measurement owner
  select/export the same parallel adapter;
- prove the real shell parallel adapter recognizes `source-port-free` on a synthetic free
  port and retains `route-add-source`.

## Production boundary

Production Model C, Model B, cold Model A, source-port lease allocation, adaptive search,
CandidateSpec, width three, discovery GET-4K and all production adapter implementations are
unchanged.

Owner-live repeats the same five-run Rutracker lifecycle command. A valid run must now
exercise production Model C rather than a measurement-induced fallback; only then may the
lifecycle amortization data be interpreted.
