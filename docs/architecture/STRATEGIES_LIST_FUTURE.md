# Future: каталог текстовых списков и переносимость

**Статус: будущие направления, не активная работа в ТЗ_6v3.** Полная дискуссия и границы задач — [Features / Future #1192](https://github.com/Tolian82/os-zapret2-restyle/issues/1192). Активное ТЗ — [ТЗ_6v3](TZ_6v3.md); текущий transport API — [Strategies List API v1](STRATEGIES_LIST_API_V1.md).

1. **Дополнительные HOSTLIST:** от пяти текущих до **6–8 источников всего**, при незначительном росте общего числа доменов. Каждый реальный новый target/происхождение Auto/профиль Zapret2 требует отдельной регистрации и проверки; не добавлять запасные поля сейчас.
2. **Типизированный реестр:** в дальнейшем при необходимости включить IPSET, Telegram IPSET, `domain_exclusion` и `ipset_exclusion` в общий транспорт. У них отдельные валидаторы, семантика и собственное сохранение. В ТЗ_6v3 эти поля работают по-старому и не становятся HOSTLIST.
3. **Полная унификация пользовательских изменений:** общий отслеживатель всех форм, ревизий и конфликтов, если станет оправданным. Сейчас — лишь минимальные необходимые CAS/черновики пяти списков.
4. **pfSense:** самостоятельный будущий порт с платформенным GUI/Config API, сохранением/backup/locking/rollback и сервисным adapter. Повторно использовать общий валидатор и контракт списков; сегодня код pfSense не писать.
5. **Хранение:** ручные YouTube/User пока в OPNsense `config.xml`, найденные — защищённые `.txt`; возможность отдельных файлов для будущих ручных списков и миграции существующих рассматривать только с гарантией backup/restore и обоснованной потребностью. Не делать SQLite/другой database.
6. **Размеры и транспорт:** multipart/JSON в рамках одного Apply уже целевой стандарт ТЗ_6v3. Сложный chunked upload/staging и системная перенастройка PHP — не часть нынешнего scope, обсуждать только при измеренном ограничении.
7. **Другие разделы:** Voice/«Передача голоса», лаборатория, WAN, глобальные исключения — возможные отдельные планы при самостоятельном согласовании, без побочного изменения в текущем ТЗ.

Выпуск ТЗ_6v3 и нового тестового `.pkg` **не закрывает Future #1192**.
