## Original producer trace and observed gap

The actual original implementation is `setup_transaction.sh::install_transaction` (original setup.lock + inherited FD9) → `install_first_runtime` → `setup.sh::install_runtime` (Git clone, native `make`, original resources/ELF checks) → `first_install_validate` (Git HEAD, exact tag commit and executable, compiler-link policy) → staged checkout publication → `first_install_finish` → **single** `write_active_release` and cleanup. The original `first-install.intent` is an atomically written, synced two-line `version=...` / `original=0|1` recovery control, and stage `runtime` / `original` preserves the three package-generated native template files when present.

For an upgrade/reinstall, the original parent already sees genuine child successful make and writes the exact three-line `vTAG / commit=OID / engine_sha256=SHA` through the sole `write_active_release ... bound`, with original rollback evidence. First install lacks that **durable producer correlation**. A crash after publication can leave `ZAPRET_DIR` with correct Git/tag/ELF and the old two-line intent; the recovery branch calls `first_install_finish` without a new successful build. Its intentional one-line legacy marker is display-only. Existing `first_install_validate` proves identity and shape, **not** that the current transaction's make completed or that its exact produced ELF remains unchanged across interruption.

## Required bounded first-install handoff

1. Preserve exactly one parent owning the existing setup.lock and inherited original native FD9 across build, seal, publication, restart and recovery. No detached witness can authorize, no second journal or Config writer, no independent runtime publisher, and no implicit native Start/Stop or IPFW transition. The first-install path remains intentionally STOPPED.
2. Begin with the existing two-line prepared intent. Only **after** the actual original `setup.sh` child succeeds and the parent verifies the exact staged tree, Git/tag→HEAD, safe resource/link policy and FreeBSD compiled `dvtws2` may the parent durably advance that **same** existing intent to a strict, fixed-format built state binding exact release, commit OID, ELF digest and original-template flag. The transition must be atomic and durable *before* renaming staged runtime to its active path. The witness must be coupled to a genuine successful original child, never minted from a recovered tree or from merely reading a binary.
3. On a clean original first-install attempt, require absence of prior active marker and foreign/pending state. Before any bound marker publication, read back the built intent and re-attest the unchanged exact staged-or-promoted Git/tag/ELF bytes, canonical regular files, ownership/link boundaries and the original package templates. The already-existing `write_active_release` is the **only** active-record writer; either extend its original bound path with the first-install-specific verified evidence or refuse. Do not reuse an upgrade backup guard that requires a nonexistent previous runtime, and do not add a second write path.
4. For power-cut/reentry, distinguish at least: prepared without built proof; complete original built proof with staged runtime; complete original built proof after publication; exact marker already committed before cleanup; missing/partial/foreign intent; changed live/stage Git or ELF; changed original templates; unexplained service/IPFW owner. A two-line legacy intent or an already published checkout must **never** be silently upgraded to a bound receipt. Ambiguous or mutated state returns a fixed recovery-required refusal with original bytes retained; success cannot be inferred from matching tag or rc0 alone.
5. Check durability and ordering at both interruptions: producer-built intent `sync` before any original `mv`; exact single active-record `mv` plus durable barrier before retiring original template backup or removing intent. If a resumed operation observes its existing exact record, verify it byte-for-byte rather than blindly rewriting or removing foreign state. Preserve the existing unbound first-install compatibility and GUI first-line display contract.
6. Any future physical runtime adoption remains guarded by S10 original immutable root/journal/seal/Config/Found P1 ownership and then ordered S11–S14. A first-install Git/ELF record is necessary build provenance, **not** authority for immediate Apply, auto-learning, IPFW or engine activation.

## S10c2b3h original producer implementation candidate (_223)

Old two-line interrupted intents remain legacy/unbound. Check the original G03 fast suite and real FreeBSD 15 native G03 before treating these source changes as accepted.
