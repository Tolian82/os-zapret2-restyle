## 3. Прежние reconfigure / restart и различие Reload

- `configd [restart]` → `service_dispatch restart` → `reconfigure_service` → `orchestrator_native_reconfigure` для Legacy; для committed Common outer owner branch в `service_with_lifecycle_lock:3593–3609` выполняет `shared_apply_stop_service` + `shared_apply_boot_service`. Это *два механизма* при одинаковом публичном имени.
- `configd [reconfigure]` → аналогичный Legacy `reconfigure_service`, а Common `service_with_lifecycle_lock:3510–3530` может сразу вызвать `shared_apply_boot_service`, то есть нет гарантии отдельного физического Stop→Start в этом alias. `ServiceController.reconfigureAction` существует, но его текущая GUI reachability не подтверждена.
- `Strategies/Voice Apply` сейчас строит candidate и входит в full activation `backend/apply_runtime.sh`; **pure diff classifier NO_CHANGE/RELOAD/RESTART/START/STOP/SAVE_ONLY/REFUSE и отдельная публичная команда `reload` в текущем dispatcher отсутствуют**. Не считать неизменный Apply доказательством no-op или live reload.
- Исключение, которое нельзя сломать: WAN-only stopped save `shared_apply_wan_save_service` и нетребовательная к active manifest Standard/Extended Lab before first ordinary Start (`V5-11 / G05→G08`). Исторический native PASS предыдущих версий не равен future manifest refactor PASS.
- `backend/auto_detect_minute.py` / Found/managed hot-writers P1/CAS/ACK работают вне foreground Apply; при этом обход reconfigure ради Auto запрещён. Указанное в upstream `manual.en.md` автоматическое перечитывание HOSTLIST/IPSET и SIGHUP — **канон**, его экспериментально не перепроверять; S03 проверяет только наши writes/PID signal/FD9/receipt.

## 6. S02 отрицательные зоны и handoff → S03

1. **Реальные физические decision trees дублируются**: public Common/Legacy selector, Lab internal, pkg prepare/finish, Auto Restart, setup resource recovery, и отдельный `backend/apply_runtime.sh`. Единый FD9 защищает многие из них, но не выполняет строгий DEV-065 «менять Start/Stop только в одном исходном файле». Новому canonical physical owner предшествуют S04–S10 — немедленно переносить функции нельзя.
