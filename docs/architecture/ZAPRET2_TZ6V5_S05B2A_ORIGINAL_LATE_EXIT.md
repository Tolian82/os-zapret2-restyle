# TZ6v5 S05b2a — original delayed engine-exit receipt under FD9

**23 November 2026.** Candidate source `v0.6.5_157` based on merged `main _156 ddfa341b` (S05b1). This is a narrow **S05b2a** acceptance slice, not full S05b/S05. See [TZ_6v5](TZ_6v5.md) and [S05 tracking #1269](https://github.com/Tolian82/os-zapret2-restyle/issues/1269).

## Actual verified producer

Existing `supervisor_loop.sh` detects disappearance of the real native `dvtws2` after ready. [Native RED #45240400594](https://github.com/Tolian82/os-zapret2-restyle/actions/runs/45240400594) proved `daemon -p` had removed the engine PIDfile by the later callback inspection; the original Stop correctly refused without trusted process provenance. The candidate fix pins the **original real engine PID into the live supervisor's immutable OS argv at launch**, before releasing original FD9. The supervisor synchronously calls the existing `zapret_service.sh runtime-failure <fixed-message> <original-child-pid> <own-monitor-pid>`. The current Common FD9 route verifies the **current original live monitor PIDfile, exact executable/path/child-PID argv and stable kernel process birth (lstart)** twice, then the existing sealed Common journal, exact engine census, saved Config, installed tree and scoped IPFW. Stale, replaced, unsigned or dead monitors refuse **before** any kernel change. `shared_apply_stop_service` remains the one original transaction (not legacy broad `orchestrator_runtime_failure`). That Stop checks the original sealed bundle, native saved Config, exact process census and scoped original IPFW ownership before any cleanup, then verifies the physical STOPPED terminal state.

**New S05b2a producer boundary:** Only after this original Stop returns verified success does the same FD9 owner call the **existing** `shared_apply_operation.py` writer with the original committed operation ID. The original schema-1 `/var/db/zapret2/shared-apply/operation.json` accepts one optional `failure` field **only** in `committed`, with exact keys/schema, id equal to original owner, canonical UTC recording time, code `ENGINE_EXIT_AFTER_READY`, action `runtime-failure`, and `exit_status=null`. The protected writer also re-runs the original `voice_live_inspect.examine_shared` to verify an actually stopped Common owner before writing. Duplicate callback keeps the original first event (no overwrite, no new event). Invalid/stale/racing ID, phase, foreign/runtime mismatch and all failures refuse without second journal, Config writer, IPFW handler or arbitrary process kill.

The read-only `status --json` reader reuses the original root-only validator and compares the journal twice. It projects that event **only if** S04 independently classifies `manifest=valid`, `runtime=STOPPED`, the validated current original committed owner has the same ID and the record is stable. `last_error` gives fixed `ENGINE_EXIT_AFTER_READY`/engine-stop, original operation ID, qualified **recorded-at** UTC (not exact exit time), `runtime_before=RUNNING`, `runtime_after=STOPPED`, and `verification=uncertain` for unknown exit cause. Top-level physical Status rc remains 1 for stopped. Source code does **not** claim an OS wait status, signal cause, native stderr excerpt or sealed generation: `exit_status,stderr_excerpt,log_ref,generation=null`. No raw dvtws2 logs, Config, IP/domain, tokens or argv enter public output.

**Expiry:** A successful original `shared_apply_boot_service`, after re-attesting the sealed RUNNING engine/supervisor/IPFW, clears this error field using the same original journal writer, checked against the same live owner; failed activation may not erase it. Applying a new committed candidate creates a new original operation ID and no inherited old failure. No extra persistent file is introduced.

**Important:** The verified live supervisor becomes the only post-ready witness if the original engine PIDfile disappears. A manual replay without its exact live PID, kernel birth and pinned monitored engine ID must remain refused. This does not grant authority to a naked PID, prior log, stale monitor or ordinary `status`. See [blocker #1272](https://github.com/Tolian82/os-zapret2-restyle/issues/1272); the candidate is NOT GO without genuine real callback native GREEN.

## Exact-head gates

Source unit tests exercise the actual SharedApplyOperation durable writer in isolated temp dirs: optional exact schema/backward compatibility, committed-only events, duplicate idempotency, cross-owner refusal, strict UTC/cause/exit-code validation, interrupted/racing records, secure Status projection and clearing by verified success. Original S05a five-state native JSON no-write regression remains required.

A **new dedicated disposable native OPNsense 26.7 VM** installs the exact PR package, initializes real upstream `dvtws2`, creates a genuine healthy Common owner, checks stale wrong-PID `runtime-failure` refuses without changes to owner/Config/kernel (only the existing FD9 lockfile metadata may change), then **intentionally sends SIGTERM to the actual engine solely inside this isolated CI VM**. The genuine original supervisor callback must complete original FD9 Stop, persist the same-owner durable error, and expose precisely one safe read-only JSON event. A genuine original start must re-attest RUNNING and clear the old event. No such signal is permitted for Auto-detect traffic maintenance or the operator appliance. Foreign IPFW rules are never deleted.

## Still outside this bounded step

An engine killed by a deliberate signal is a genuine exit **after ready**, but the original daemon/supervisor wrapper does not return the upstream process's actual exit code. Consequently S05b2a cannot claim `ENGINE_EXIT_EARLY`, a precise native exit rc or causal raw stderr. These remain **NO-GO** until an authentic original producer/attestation can carry them. Setup/pkg/Lab and general Start/Stop/Restart errors, original plain Status historical FD9 side effect, GUI RU/EN and full S05 native acceptance remain later S05b2b/S05c work. No public `_157.pkg`, no operator-device change and no full S05 GO.
