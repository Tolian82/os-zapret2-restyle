## Наблюдение установленного 0.5.3_3

Владелец 17.10.2026 подтвердил установку проверочного `0.5.3_3` с точным SHA-256 `f3fc9e09d5713587c8381d5d44e86192e6908c3c623d434ebb80e618bd7db40d`. Снимок GUI подтверждает русские native help, отсутствие селектора релизов и работу выбора WAN/кнопки «Проверить» без прежней нормализационной ошибки. Однако общий статус UI ошибочно показывает «Неизвестно»: `configctl zapret setup_status` сообщил `installed=1; service=started; version=v1.0.5.2; setup=ready; busy=0`. Независимый `voice_inspect` сообщил `state=uninitialized; remedy=common-apply-required`, то есть Voice runtime/IPFW пока не активирован. Отдельный read-only `configctl zapret voice_lifecycle_inspect` вернул `Execute error`. Последующий штатно заблокированный read-only вызов показал `VoiceLifecycleRouteError: unsafe or replaced native Config inode`: OPNsense 26.7 использует `wwwonly:wheel` для `/conf/config.xml`, а скрипт ожидал `root:wheel`. Это ошибка проверки владельца в плагине, не доказательство повреждения Config.

Кандидат `_4` исправляет правдивое отображение общего Zapret2/неподтверждённого Voice и дефект точного владельца Config в read-only lifecycle inspector и соседнем saved-draft preview. Сохраняются точные inode/device/nlink, root-сервисная FD9-блокировка, строгий именованный владелец `wwwonly:wheel` и Config flock, без разблокирования Start/Stop или Apply. [CI #39038290885](https://github.com/Tolian82/os-zapret2-restyle/actions/runs/39038290885) (Voice/Project/FreeBSD 15 pkg) успешно. [Тестовый пакет `_4`](https://github.com/Tolian82/os-zapret2-restyle/releases/download/v0.5.3_4/os-zapret2-restyle-0.5.3_4.pkg) опубликован, SHA-256 `cba1c1a68a36a4d0cfbe61312157da338c386f9cde20e1395ada5e9393a0f37d` подтверждён; установленная `_4` ещё не проверена.

## Наблюдение установленного 0.5.3_4

17.10.2026 владелец подтвердил установку `0.5.3_4` на OPNsense 26.7.7. `setup_status` сообщает `service=started` и `v1.0.5.2`; GUI корректно показывает «Запущена · Voice не подтверждён». `configctl zapret voice_lifecycle_inspect` теперь успешно отвечает `state=voice-saved-off-common-apply-available`, `saved_voice_on=false`, все пять сохранённых профилей OFF. Отдельный `voice_inspect` сообщает `state=uninitialized`: Voice/IPFW ещё не подтверждён. На скриншоте Telegram выбран ON в форме, однако backend сообщает saved OFF, поэтому успешного сохранения/применения нет.

Новый блокер: Voice GUI показывает на WAN обобщённую ошибку проверки, внизу «Результат применения неизвестен». Аудит `VoiceController::applyAction()` обнаружил ложную неопределённость: `catch (Throwable)` помечает `requires_review=true` даже ДО dispatch `zapret shared_apply`. В `_5` ошибки до границы FD9 классифицируются как безопасный отказ `applied=false`, `requires_review=false`, с фиксированным кодом стадии и записью типа исключения в PHP error_log без входных данных, а post-dispatch остаётся неизвестным результатом и блокирует повторный Apply. Конкретная первопричина ошибки подготовки XML/модели на устройстве ещё **не доказана**. Есть PHP-регрессия для Throwable в guard до dispatch и для dropdown+ON модели. [CI #39042954730](https://github.com/Tolian82/os-zapret2-restyle/actions/runs/39042954730) (Voice/Project/FreeBSD15 pkg) успешен; исправление включено в `main` [d91c8cb](https://github.com/Tolian82/os-zapret2-restyle/commit/d91c8cb9ff957ef71545cb8d8bcca26638101f77), [проверочный пакет `_5`](https://github.com/Tolian82/os-zapret2-restyle/releases/download/v0.5.3_5/os-zapret2-restyle-0.5.3_5.pkg) опубликован, SHA-256 `3c4ca5acf76e22f0d0fc16c823849bc363030f137e36d1bea8c2bc2e1613b7da` подтверждён. Установка `_5` ещё не наблюдалась.

## Точное следующее действие

Владелец может установить [тестовый `0.5.3_5.pkg`](https://github.com/Tolian82/os-zapret2-restyle/releases/download/v0.5.3_5/os-zapret2-restyle-0.5.3_5.pkg) как при предыдущих проверочных релизах. Проверить SHA-256: `3c4ca5acf76e22f0d0fc16c823849bc363030f137e36d1bea8c2bc2e1613b7da`. После установки `pkg info os-zapret2-restyle`, `Ctrl+F5` на Voice и **только «Проверить»** (read-only), без повторного «Применить», «Сохранить черновик» или рестартов. Если ошибка есть, новый GUI возвращает локализованный **этап** `model` или `candidate-xml`; сообщение следует зафиксировать. Для точной PHP-причины использовать соответствующую запись `error_log` по классу и стадии, без запроса приватного Config XML. Если «Проверить» проходит, дальше отдельный согласованный тест сохранения/Apply; не объявлять голос работающим автоматически.

[Текущая приёмка](VOICE_CODE_COMPLETION_GATE.md). Стабильный GUI/pkg репозиторий остаётся на опубликованном `v0.5.3_2`, а `_5` существует только как GitHub testing prerelease.
