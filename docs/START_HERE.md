## Established implementation boundary

Feature [#1052](https://github.com/Tolian82/os-zapret2-restyle/issues/1052) is active. P0/P1 are complete; P2a–P2d contribute protected queue, FreeBSD writer-FD observation, common-owner attestation and original-generator ancestry. P2e's actual `orchestrator_build_release()` offline shared-generator witness passed on disposable OPNsense/FreeBSD [native run #43392107224](https://github.com/Tolian82/os-zapret2-restyle/actions/runs/43392107224).

The P2f source-only proposal plans the P0-qualified trailing no-action observer from the true P2d same-build map and final args. Source `_17` additionally calls a **read-only check inside the existing original FD9 shared Apply** immediately after authoritative native PHP candidate preflight and before any runtime/kernel or Config mutation. It correlates the original workspace, sealed source map and `dvtws.args`, original TCP ports (including ranges), and the already-attested candidate digest; failed/missing proof cannot block ordinary Apply or authorize an observer. The proposed schema-2-shaped record remains **deliberately unauthorized** (`P2F_OFFLINE_PLAN_ONLY`). [P2f proof contract](verification/P2F_OFFLINE_OBSERVER_PLAN.md).

Source `_18` resolves a demonstrated path/permission incompatibility: the real shared Apply parent `/var/db/zapret2` must stay `0700` and is nontraversable by the native `nobody` engine. The dormant P2g storage primitive instead fixes an independently rooted, checked `root:nobody` producer location `/var/db/zapret2-auto-detect`, with root-private pending and precise group file modes; queue/FD checks remain strict by default. [P2g contract](verification/P2G_NATIVE_WRITER_STORAGE.md).

Source `_19` also writes only a **sealed, nonactivating** observer preview plus refusal-marked metadata in the original FD9 release after native PHP preflight, revalidating them before kernel/Config actions. It intentionally does not create real raw/debug files or change live engine argv: without a running durable worker, early native discovery could grow without bound. [P2h exact scope](verification/P2H_ORIGINAL_FD9_SEALED_PREVIEW.md).

Source `_20` adds the targeted [P2i original-preview native loopback witness](verification/P2I_NATIVE_ORIGINAL_PREVIEW_LOOPBACK.md) to the **existing disposable** P2e/P2g OPNsense VM. It uses the genuine P2h preview and pinned upstream engine rather than a constructed second profile. Native P2i exposed an upstream startup ownership change: pinned `dvtws2 --user=nobody` chowns its raw inbox to nobody. The scoped test must demonstrate exact root reownership **after process drop, before packet diversion**, and prove actual later append, without relaxing queue safety. This is only guest feasibility, not a deployed FD9 startup solution. The native result remains a **separate gate**, not source-only evidence. Product native recording stays switched off.

Source `_21` adds the [P2j dormant pending-cycle bridge](verification/P2J_SAME_GENERATION_DURABLE_CYCLE.md): each saved inode is tagged with its authentic 32-hex shared-Apply generation, stale/unknown pending is never silently reassigned to another process, and a same-generation crash after hardlink is recoverable before FD/debug/commit acknowledgment. Source-only injected adapter tests are not live FD/debug/destination proof; its public worker entry refuses unconditionally. Existing P2i native first-match and upstream chown evidence remain valid.

This is **not** an implemented or accepted live observer, changed release argv, actual native writer event, sealed authorized schema-2 generation, real process/FD drain correlation, durable destination writes or active cron worker. P2 remains open; P3–P5 remain open. Exact-head source/CI checks must be recorded separately from P2e's prior native success.
