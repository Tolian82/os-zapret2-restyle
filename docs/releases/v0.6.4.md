# os-zapret2-restyle v0.6.4 — native OPNsense full release

**Release candidate:** `v0.6.4_1` (`VERSION=0.6.4`, `PLUGIN_REVISION=1`), built for OPNsense 26.7 / FreeBSD 15 amd64. **Full publication is pending final exact-head gates.** This file describes the proposed stable release; it does not claim an immutable `v0.6.4` tag, `0.6.4_1.pkg`, SHA-256 or Pages repository is already available. The existing stable `v0.6.3` tag is immutable.

## What's new since v0.6.3

- **Full native install/uninstall lifecycle:** OPNsense's stock package system, GUI setup of the separately managed bol-van/zapret2 runtime, normal package removal/reinstallation without destroying user Config/upstream/custom Lua/BIN, and separately confirmed full purge with private Config backup and self-removal.
- **Initial configuration and WAN-first behavior:** clean-only defaults (ten ordered YouTube Domains and the validated TCP HTTP/TLS plus UDP QUIC strategy); unchanged saved settings after ordinary reinstall; independent WAN-only Save even with no running engine; explicit errors for missing/invalid WAN and missing upstream.
- **Service and shared Voice:** original FD9 serialization, one owned `dvtws2` for ordinary and selected Voice profiles, no-action/empty ordinary strategy support, transactional Start/Apply/Stop/Restart and scoped IPFW rules. The owner explicitly accepted Voice Transmission service tests on the installed testing candidate.
- **Strategy Lab restored:** Standard/Extended pre-start and running-service checks with truthfully classified no-candidate results and Stage90 restoration. Stage50 and Stage60 temporary hostlists remain readable **after the candidate process drops privileges to `nobody`**, through isolated `root:nobody` staging rather than opening private job directories. Diagnostics retain process/socket/log/RSS readiness signals; Model C remains fail-closed without bypass fallbacks.
- **Native resource management:** GUI-managed Extra Lua/BIN resources, read-only help inventory and guarded remove/reinstall; no new external installer or update manager.

## Installation and updates

Use the official project package repository for OPNsense 26.7 / FreeBSD 15 amd64. When not yet registered, add it from a root shell:

```sh
fetch -o /usr/local/etc/pkg/repos/zapret2-restyle.conf https://tolian82.github.io/os-zapret2-restyle/zapret2-restyle.conf
pkg update -f
```

Then install/update **`os-zapret2-restyle`** from **System → Firmware → Plugins**. Review any dependency transaction. The Zapret2 runtime is separately installed/selected via **Services → Zapret2 → Zapret2 Service**, not bundled into the plugin package. Do not bypass `pkg` hooks, enable stock FreeBSD repositories or disable PF.

### Upstream runtime management and safe full purge

```sh
# Install/reinstall/upgrade/downgrade to an exact release.
/usr/local/opnsense/scripts/OPNsense/Zapret/setup.sh install v1.0.3

# Uninsatll Purge.
/usr/local/opnsense/scripts/OPNsense/Zapret/purge-os-zapret2-restyle.sh --purge
/usr/local/opnsense/scripts/OPNsense/Zapret/purge-os-zapret2-restyle.sh --dry-run
```

**Run `--dry-run` first** to inspect the targeted resources. **`--purge` is destructive**: it removes the plugin and owned settings/runtime/resources after interactive confirmation `PURGE OS-ZAPRET2-RESTYLE` and private `/conf/config.xml` backup. Ordinary GUI uninstall is deliberately non-destructive and retains that independent purge CLI for later use.

## Release deliverables and verification

The **v0.6.4** full-release workflow must publish and verify the immutable `v0.6.4` tag, GitHub Release with native `os-zapret2-restyle-0.6.4_1.pkg` and `SHA256SUMS`, and matching OPNsense Pages/pkg repository with `FreeBSD:15:amd64` metadata (`meta.conf`, `packagesite.pkg`, `data.pkg`). It must validate the exact release-preparation source commit, compile with the official OPNsense Mk, inspect the actual package manifest and digest and confirm the Web/pkg delivery path. This document contains no guessed final SHA.

**Known limits:** a positive endpoint probe can mean an unblocked network rather than a successful DPI bypass. Voice service acceptance does not guarantee universal media success. Physical IPv6 WAN, arbitrary provider behavior, sudden power-loss recovery, and unrelated external network failures are not silently marked PASS. Known genuine `RESTORE_FAILED`, leaked plugin-owned resources or unverified restoration in a mandatory release check block promotion.
