# os-zapret2-restyle v0.5.2

**Этап разработки, без релиза.** Открыт владельцем 13.10.2026: `VERSION=0.5.2`, `PLUGIN_REVISION=60`, candidate `v0.5.2_60`, имя пакета-кандидата `os-zapret2-restyle-0.5.2_60.pkg`. Пакет не опубликован; Draft PR #328 не merged/ready.

## Назначение

Завершить страницу «Передача голоса» по неизменному ТЗ через общий backend «Стратегий»: одна модель, полный generator, сериализованный Apply/rollback, scoped Voice IPFW и штатный lifecycle/boot. [Утверждённая архитектура](../architecture/VOICE_TRANSMISSION_GUI.md#12-общий-backend-со-стратегиями-утверждено-13102026).

- Краткие START_HERE/PROJECT_STATE/ROADMAP/INDEX и ТЗ без повторённых старых отчётов.
- [Восемь полных исторических снимков v0.5.1](../history/stages/v0.5.1/README.md), загружаемые по необходимости.

GUI/CONFIG/BOOT и media qualification не объявляются принятыми. Stable Web/pkg остаётся v0.5.0, опубликованный testing — v0.5.0_3. Новый tag/release, testing publication и Pages/pkg deployment не выполняются.

В `_49` добавлено строго подтверждённое no-mutation восстановление фазы `activating` (только с previous common owner) и однозначная обработка шести старых SHA с неверными заголовками в CI. Активный `activated` и частично изменённый runtime по-прежнему блокируются. В `_48` исправлена PID-парковка отката и дополнена регрессия; активная документация очищена от ошибочных вставок. Это ещё не приёмка power-cut recovery и running-legacy migration; выпуск не выполняется.

В `_50` реализован холодный rollback прерванной `activated` из нового sealed release в предыдущий committed common runtime и добавлены fault-injection tests, без изменения frontend или релиза. Не является универсальным восстановлением после power-cut.

В `_51` устранено уничтожение неизвестных `.stage.$$`/`.old.$$` и конфликтующих backup при atomic runtime install; добавлены отрицательные тесты существующего helper. Это не автоматическое восстановление частично перезаписанного runtime, без релиза и изменений frontend.

В `_52` добавлен холодный rollback stale `activating`, если atomic rename нового release уже полностью завершился; использован прежний общий backend/FD9/Config/kernel attest и phase-bound `finish-activating`. Mixed/missing runtime и live owner не восстанавливаются автоматически. Frontend не изменён, релиз не выпускается.

В `_53` atomic stage/park/backup нового общего Apply привязаны к его уже записанному ID; при двух строго аттестованных missed rename layouts old runtime можно восстановить, сохраняя crash evidence. Старые PID-only остатки не подхватываются. Без нового writer/WAL, изменения frontend и релиза.

`_54` добавил только read-only проверку живого legacy владельца под штатным FD9. Это не разрешение на live cutover, фронтенд и релиз не изменяются.

В `_55` существующий full legacy PoC kernel/argv/IPFW witness подключён к read-only `shared-apply-legacy-audit` общего backend; output по-прежнему прямо запрещает handoff до обратимого переключения. Без новых WAL, Config writer, GUI и релиза.

В `_56` исправлена root FD9 маршрутизация old legacy audit, добавлена candidate-bound read-only квалификация (sealed Voice ON candidate, Config, merged runtime, exact old IPFW/argv) без права mutating cutover. GUI и релиз не меняются.

В `_57` подтверждённый running legacy candidate получает полный sealed five-domain predecessor + rollback plan в своей private shared-work директории. Это не второй WAL и не live cutover: old process/kernel/Config сохраняются неизменными, GUI не меняется, релиз не выпускается.

`_58` устранил регрессию CI на изменившемся production FD9 route и добавил проверки привязки immutable previous-five backup к sealed candidate и сохранения evidence при послеоперационном drift. Процесс и IPFW ещё не переключаются; релиз не выпускается.

`_59–_60` записывают candidate-scoped старый full previous-five digest в существующий общий `prepared` journal через FD9 и блокируют преждевременное `activating` и автоматическое закрытие при reboot. Это не разрешённая live миграция; arming блокирует штатный boot до появления единого rollback executor, поэтому на production не запускать. Без release/frontend изменений.
