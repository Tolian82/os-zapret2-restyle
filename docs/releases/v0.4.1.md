# os-zapret2-restyle v0.4.1

Release date: 2026-08-12

Package:
`os-zapret2-restyle-0.4.1_1.pkg`

Target:
OPNsense 26.7 / FreeBSD 15 amd64

==================================================
SUMMARY
==================================================

v0.4.1 promotes the owner-tested `0.4.0_26` runtime line to the next stable project
version. The release-preparation patch changes release metadata and synchronized
engineering documentation only; it does not introduce new runtime behavior beyond the
already published and owner-live accepted `_26` candidate.

The release consolidates the completed adaptive Strategy Lab search/runtime work after
v0.4.0: deterministic native Zapret2 candidate planning, warm execution Models B and C,
controlled source-port ownership, and workload-derived finite parent budgets.

==================================================
HIGHLIGHTS
==================================================

- Strategy Lab uses immutable Python `CandidateSpec` and job-scoped `ResourceInventory`
  evidence with a deterministic native Zapret2 search graph and fixed endpoint epoch.
- Stage 50 is prioritization evidence rather than a Stage-60 reachability gate; candidate
  ranges/resources are preserved from the candidate definition through validation and
  profile output.
- Stage 60 normally uses one warm Model-C bucket with deterministic source-port Lua
  dispatch, while accepted width-three Model B and cold Model A remain fail-closed
  fallbacks.
- Controlled source ports are leased with `preferred-free-else-alternate`; a fallback
  obtains a fresh independent lease rather than inheriting a failed concrete allocation.
- Parent deadlines use `eligible-work-v1`, deriving bounded extra headroom after Stage 30
  from the measured endpoint/network/protocol work matrix instead of increasing one global
  timeout blindly.
- Stage 70/80/85 result semantics, cancellation, cleanup and exact Stage-90 restoration
  remain preserved by the accepted runtime architecture.

==================================================
LIVE VERIFICATION
==================================================

Published candidate `v0.4.0_26` is the exact owner-tested runtime basis for v0.4.1.
Extended `telegram.org` job `job.xhdgCU` proved production `eligible-work-v1` wiring on the
owner appliance: two endpoints, IPv4 available, IPv6 unavailable, QUIC/IPv4 closed and no
Generic UDP produced the exact finite `150/120/270/120` second budget plan.

Stage 60 genuinely used `C-warm-bucket-source-port-dispatch`, completed all 16 candidates,
ended truthfully with `graph_exhausted`, and recorded `.parallel.fallbacks=[]`. Stage 60
took `34209 ms`; the complete job took `114644 ms` and ended `NO_CANDIDATE`. Stage 90
restored the initially running Zapret2 service; post-job rules `19128-19130` were absent.

Earlier accepted owner-live evidence also retains the Model-C working-candidate path and
the Model-B fallback/reference baseline. No new runtime behavior is introduced by the
0.4.1 release-preparation change, so the risk-based release policy uses the accepted `_26`
owner-live result as the selected live basis instead of requiring unrelated pending matrix
rows to be fabricated or rerun.
