## What's new since v0.6.2

- **Native OPNsense packaging and lifecycle:** official `Mk/plugins.mk` package, dynamic native Python/provider dependencies, ordinary OPNsense package hooks and `configd` service paths. The plugin and upstream `bol-van/zapret2` engine remain separately managed.
- **Shared live service:** one native `dvtws2` for Traffic Strategies and optional Voice, serialized apply/rollback under original FD9, scoped IPFW rules (`19000–19010`; Strategy Lab `19100–19131`). Real native clean installation, old RUNNING replacement, shared Voice/HTTPS, reboot and package/resource scenarios were qualified on disposable OPNsense guests.
- **GUI and Strategy Lab reliability:** restore correct WAN↔LAN interface selection; repair Stage-85 shell-adapter preflight to accept the readable `/bin/sh`-invoked `0644` file while retaining strict cleanup. On the owner's installed immutable testing `v0.6.2_188`, Standard and Extended Strategy Lab both completed Stage 99 with three verified deep-replayed candidates and `RUNNING→RUNNING` restoration.
- **Reliability of release inputs:** one root `VERSION` is authoritative; new/changed production code is scanned for unsupported version/platform assumptions before long CI. A fixed SHA-256-verified private `curl-impersonate` input is retained where reproducibility requires exact bytes.
- **Release workflow cleanup:** retired the old never-materialized `native-product-installed-acceptance.json` switch, which checked three arbitrary booleans but did not validate an installed final package. Actual native CI and package checks, release notes, generated pkg repository and published assets remain mandatory. The release notes are read directly from this document by the GitHub Release publisher.

Already shipped in `v0.6.2`: IPv4/IPv6 managed targets, global Exclude IPSet, dual-stack Strategy Lab and configurable Voice/STUN; they remain supported, not newly presented as verified ISP bypass.

## Installation and update

The full release is distributed through the project OPNsense pkg repository for `FreeBSD:15:amd64`. On an OPNsense 26.7 root shell, register the repository if not already configured:

```sh
fetch -o /usr/local/etc/pkg/repos/zapret2-restyle.conf https://tolian82.github.io/os-zapret2-restyle/zapret2-restyle.conf
pkg update -f
```

Then use **System → Firmware → Plugins** to install or upgrade **`os-zapret2-restyle`**. Review native dependency transactions; do not add a stock FreeBSD repository, ignore dependencies, bypass package hooks or disable PF. The upstream `dvtws2` runtime is installed/selected separately in **Services → Zapret2 → Zapret2 Service**.

**Release artifacts:** [GitHub Release v0.6.3](https://github.com/Tolian82/os-zapret2-restyle/releases/tag/v0.6.3) should contain `os-zapret2-restyle-0.6.3_1.pkg` and `SHA256SUMS`. The matching public pkg repository must contain `FreeBSD:15:amd64/os-zapret2-restyle-0.6.3_1.pkg`, `meta.conf`, `packagesite.pkg`, `data.pkg` and checksum metadata. The release job must report actual SHA-256 from published bytes; this document does not guess a digest before the build.

## Acceptance and limitations

**Qualified prior to the release-preparation merge:** historical Stage 5 native same-physical-archive OPNsense clean/RUNNING/shared Voice/reboot/HTTPS checks and owner-live `v0.6.2_188` Standard/Extended Strategy Lab Stage85/90/99 with verified restoration. The earlier testing package and final `0.6.3_1.pkg` are **different physical artifacts**. The final release requires latest-head CI, exact tag/commit identity, native package validation, published `SHA256SUMS` and Pages/pkg deployment; a failed/skipped/old-head check is not PASS.

**Not asserted:** DPI bypass on a genuinely blocked ISP WAN path, actual installed IPv6 WAN packet tests on the owner's IPv4-only stand, Telegram/Discord MEDIA/CALL success, sudden power-loss recovery or an unperformed physical owner Web firmware upgrade. A positive laboratory endpoint can mean the target was already reachable. [Intermittent Guest B investigation #954](https://github.com/Tolian82/os-zapret2-restyle/issues/954) is open; any reproduced genuine `RESTORE_FAILED` or unverified restoration in a mandatory final-candidate scenario is a release blocker, never silently accepted.
