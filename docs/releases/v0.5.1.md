Further draft protection: shared atomic runtime rollback now parks the current release during a valid-backup restoration; on failed backup rename it attempts to put the candidate back, preserving both copies if successful. Unknown pre-existing parking path aborts safely. Automated fault-injection tests were added. No claim of power-loss atomicity or production Voice activation.


Draft includes a shared runtime rollback safety fix: when an expected previous release backup is absent or symlinked, `atomic_restore_tree` leaves the current active dvtws2 tree untouched instead of deleting it first. Added portable Linux/FreeBSD regression. Full Voice Save/Apply remains disabled.


Draft native lifecycle safety: a read-only boot gate under existing lockf protects interrupted whole-runtime/IPFW intents, corrupted journal paths and active native Voice ownership from legacy start/stop/reconfigure/PoC mutations; empty/missing journals retain previous behavior. Gate is tested and packaged; real native Apply, migration and reboot recovery remain unimplemented.


Read-only configd Voice inspection now prioritizes the full-runtime persistent cutover journal over apparently healthy IPFW rules, reporting interrupted phases in localized GUI text. It never repairs or activates runtime, and native Apply remains unavailable.


Draft adds a non-executable adapter-injected whole-runtime Voice cutover coordinator and a separate private durable prepared/mutating/committed journal, with independent rollback/crash tests covering Config, one engine, owned IPFW and supervisor. These are test-only contracts; there is still **no GUI Voice Apply or production cutover**, no safe legacy PoC migration, no installed engine acceptance and no reboot recovery.


Development-only bundle integrity preflight now validates Voice profile/target hashes, ordinary Strategies, generated dvtws2 arguments and derived IPFW capture scopes, including production ports.sh parity. FreeBSD CI uses a temporary test-interpreter alias to execute shared IPSET normalizer. No native Voice Save/Apply, legacy removal or router-live verification is delivered by this draft.


Draft validation additionally covers all five Voice IPSETs through the actual shared `targets_prepare_managed()` normalizer, then the candidate compiler, with a negative malformed CIDR fixture. No production runtime activation is implied.

Development safety update: persisted native Voice ON is blocked at the service entry before any IPFW initialization and before the START cleanup path; global Zapret OFF remains supported. A CI regression bridges the offline Voice candidate through the production dvtws2 argument generator and scopes IPFW separately for Voice and normal TCP/UDP. Stage inputs are rechecked against source XML/IPSET/ordinary changes and symlinks, with directory fsync. These are pre-activation controls, not a released, installed or verified voice-call runtime.


Additional Draft safeguards: a pure PHP VoiceApplyCandidate computes field differences and normalizes enabled IPv4 IPSETs without touching persistent settings or the kernel; invalid/mismatched WAN is rejected. Generated configuration now reflects five saved Voice ON/OFF values and the existing native orchestrator refuses to build the old PoC on unsupported native Voice ON instead of silently ignoring it. This is a transitional fail-closed safeguard, not a production Voice activation or a released package.


Native Voice GUI model loading now supplies an atomic configuration snapshot and the Validate-only endpoint requires the same digest; stale Strategies/Voice/shared IPSET edits are rejected. The snapshot covers general, strategy, voice and hostlist groups, but excludes unrelated Laboratory. This is a concurrency preflight, not a save or runtime activation. Unit/GUI contract tests were added; owner-live Apply/boot remains open.

Russian and English field diagnostics are provided; CI cross-checks Python/PHP parser acceptance. Apply remains disabled; test success does not modify OPNsense, prove Telegram media transfer or qualify an installed production runtime.


The old transient Telegram Voice helper migration is now modeled read-only, with distinct explicit ON/OFF, missing marker, ambiguous still-active PoC and clean-install cases. This does not remove the old PoC or activate new profiles; the one-way handoff and reboot/rollback remain open.


Additional development-only components: read-only-by-default FreeBSD IPFW adapter, strict native argv/table parsing, read-only Voice configd/API inspector visible in Russian/English, unordered table consistency checks and bounded fake TTL/checksum/ipfrag/out-range parser. No real Voice apply path, live rule replacement or reboot restore is delivered by this draft. Tests and package build do not imply media connectivity.

## Scope

Native **Voice Transmission / Передача голоса** settings between Strategy and Laboratory, with five STUN service profiles (Telegram, Discord, X (Twitter), SIP (VoIP), Custom), one WAN selector, reusable IPv4 target IPSETs, bilingual guidance, and the existing shared Zapret2 process.

## Current implementation boundary

The model/form/navigation/help, named target normalization, and standalone fail-closed STUN profile compiler and declarative Voice IPFW capture plan and read-only persisted OPNsense Voice model export, private inert candidate-bundle preflight and one-engine traffic-merging helper are staged. An adapter-injected ownership/rollback IPFW algorithm, retryable cleanup and durable owner-private intent journal and mock-only activation ordering with read-only restart triage are tested but not connected to the router in Draft PR #328. Its initial allowlist is deliberately narrower than the final approved native parameter surface pending engine-specific verification. Strategies Apply now preserves other Voice/IPSET fields and rejects stale Telegram IPSET snapshots. A Voice-specific payload whitelist/freshness helper is staged, but no Voice Apply endpoint is active. Voice Apply remains disabled: none of the intended new persistent enabled-state/live integration of staged generated profiles, transaction, multi-service destination-scoped firewall rules, independent WAN isolation, compatible CLI migration, rollback, or boot recovery are complete. The previous `telegram_voice` PoC remains the implementation currently present on the stable installed product.

The known Telegram STUN fake template is a migration example, **not a qualified working voice strategy**. Non-STUN Telegram traffic stays in ordinary Strategies. No change to the user’s Squid/sing-box/PF/TNAS laboratory is included.
