# os-zapret2-restyle v0.5.1

**Status: DEVELOPMENT DRAFT — not released.** Source branch `feature/v0.5.1_1-voice-transmission`, [PR #328](https://github.com/Tolian82/os-zapret2-restyle/pull/328).

Proposed development candidate: `os-zapret2-restyle-0.5.1_1.pkg`. **No package has been published or approved for installation.**

## Scope

Native **Voice Transmission / Передача голоса** settings between Strategy and Laboratory, with five STUN service profiles (Telegram, Discord, X (Twitter), SIP (VoIP), Custom), one WAN selector, reusable IPv4 target IPSETs, bilingual guidance, and the existing shared Zapret2 process.

## Current implementation boundary

The model/form/navigation/help, named target normalization, and standalone fail-closed STUN profile compiler and declarative Voice IPFW capture plan and read-only persisted OPNsense Voice model export are staged in Draft PR #328. Its initial allowlist is deliberately narrower than the final approved native parameter surface pending engine-specific verification. Strategies Apply now preserves other Voice/IPSET fields and rejects stale Telegram IPSET snapshots. Voice Apply remains disabled: none of the intended new persistent enabled-state/runtime profile generation, transaction, multi-service destination-scoped firewall rules, independent WAN isolation, compatible CLI migration, rollback, or boot recovery are complete. The previous `telegram_voice` PoC remains the implementation currently present on the stable installed product.

The known Telegram STUN fake template is a migration example, **not a qualified working voice strategy**. Non-STUN Telegram traffic stays in ordinary Strategies. No change to the user’s Squid/sing-box/PF/TNAS laboratory is included.
