# Проверка реального Voice STUN/MEDIA/CALL на OPNsense (без изменения трафика)

**Статус:** приёмка на реальном оборудовании ещё не выполнена. Этот инструмент не доказывает установление вызова сам по себе. Запускать только на FreeBSD OPNsense с установленным тестовым пакетом и полностью применённым общим Voice/Strategies runtime.

Цель — минимальными командами отличить три разных факта: (1) активный общий `dvtws2` и его точные правила IPFW, (2) реальный проход исходящих UDP-пакетов по правилам Voice, (3) успешный STUN, двусторонний медиатрафик и слышимость — последние два пункта должны быть подтверждены **отдельным реальным звонком и сетевой диагностикой**. Никакая величина счётчика IPFW сама по себе не подтверждает ответ STUN, медиа или успех вызова.

## До звонка

Проверить, что используется `v0.5.2_121` или более новый тестовый пакет в Draft PR #328, страница «Передача голоса» уже применена штатной кнопкой «Применить», хотя бы один Voice-профиль включён. Не запускать тест на старом Telegram PoC, на legacy-движке без общего журнала, при незавершённом Apply или при состоянии `requires-review`.

Все команды выполняются по SSH от `root` на OPNsense. `voice_live_trial.py` запускает только **read-only** проверку установленного общего runtime и `/sbin/ipfw -a list`; он не меняет Config, IPFW, счётчики, маршруты или процессы. Файлы в `/tmp` создаются перенаправлением вывода shell для сравнения, а не через механизм Zapret2.

```sh
PY=/usr/local/bin/python3.13
PROBE=/usr/local/opnsense/scripts/OPNsense/Zapret/backend/voice_live_trial.py
"$PY" "$PROBE" snapshot > /tmp/zapret-voice-before.json
cat /tmp/zapret-voice-before.json
```

Если первый снимок завершился отказом, **не проводить принудительную миграцию** и не запускать обходной `ipfw add/zero/delete`. Сообщение означает, что не подтверждён единственный текущий владелец Voice/Strategies, его release, процессы либо IPFW. В таком состоянии надо сначала исследовать общий Apply, но не имитировать успешную работу.

## После начала реального звонка

Выполнить исходящий голосовой звонок Telegram и дать передаче голоса некоторое время. Затем, **не перезагружая** OPNsense, не нажимая повторно Apply и не сбрасывая счётчики, выполнить:

```sh
"$PY" "$PROBE" snapshot > /tmp/zapret-voice-after.json
"$PY" "$PROBE" compare /tmp/zapret-voice-before.json /tmp/zapret-voice-after.json
```

Результат содержит `packet_delta` и `byte_delta` для каждого *включённого* Voice-профиля и `ipfw_packets_observed`. Положительное значение доказывает только то, что исходящие пакеты соответствовали нужному IPFW-правилу в выбранном интервале. Значение `0` само по себе не устанавливает причину — звонок мог не попасть в диапазон назначения, маршрутизироваться через иной WAN или не начаться.

Поля `stun_verified`, `media_verified` и `call_verified` всегда равны `false`. После реального вызова отдельно документировать: успешный/неуспешный STUN, удалось ли установить звонок, слышна ли речь в обе стороны, версии OPNsense/плагина, используемый интерфейс WAN, а также редакцию профиля STUN. Для STUN/MEDIA доказательств использовать согласованную сетевую диагностику в лаборатории, без публикации чужого содержимого разговоров или ключей.

## Отказы и границы

Утилита отказывается работать, если нет подтверждённого `committed` native общего владельца, если процесс/IPFW не готов, включённые Voice правила отсутствуют, операция изменилась между снимками, обнаружены дубликаты IPFW счётчиков либо их сброс. Для `compare` запрещено смешивать разные `owner`, разные составы правил и снимки с отрицательными дельтами. При ошибке **ничего не восстанавливается автоматически**.

Этот тест — шаг приёмки, а не замена исправления найденных проблем. PR остаётся Draft; релиз и merge запрещены до настоящих GUI/CONFIG/BOOT и STUN/MEDIA/CALL испытаний.
