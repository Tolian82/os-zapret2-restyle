# os-zapret2-restyle — текущее состояние v0.5.x

**`v0.5.2_74` — завершение pristine `activating` с оставшимся atomic stage.** В штатном FD9 recovery предыдущий полностью проверенный common owner больше не объявляется восстановленным при неизвестном operation-ID stage/park/backup. Если прежний sealed runtime, Config, процессы и IPFW нетронуты, а stage равен полному sealed новому release, удаляется только этот проверенный stage, затем повторно проверяется прежний владелец и фиксируется существующее `recover-activating`. Частичный/чужой stage, parked/backup collision или отказ удаления оставляют journal незавершённым. Новых WAL, процессов, frontend и legacy actuator нет; работающий old Telegram PoC ещё не мигрирован.

**`v0.5.2_73` — общий runtime-failure без старого IPFW sweep.** Callback supervisor передаёт исходный PID отслеживаемого `dvtws2`. Под original FD9 committed common owner обрабатывает сбой через уже существующий проверяемый common Stop: требуется тот же PID-файл, отсутствие работающего движка и orphan census, точный sealed runtime/native Config и принадлежащие common IPFW. Запоздалый callback от прошлой генерации, partial journal или чужие объекты отвергаются. Старый PoC без common owner продолжает использовать прежний обработчик. Это исправление общего lifecycle на пути к миграции, но не сам исполняемый legacy→common handoff; live FreeBSD ещё не проверен.

**`v0.5.2_72`:** устранена устаревшая OFF-only семантика на уже существующей странице Voice. Подтверждённая нативная кнопка ON/OFF Apply, правильные RU/EN подсказки, запрет слепого повтора после `requires_review`/браузерного таймаута и согласованный с 600-секундным backend лимит ожидания. Ни компоновка UI, ни структура пяти профилей не изменены. Старый живой PoC всё ещё требует отдельного перехода.

**`v0.5.2_71`:** закрыт ограниченный cold recovery из `activating`, когда новый полный sealed release и staged-IPFW реально установлены, но запись `activated` прервана. Тот же общий возврат `_70` требует точного previous owner/Config, пустых PID и независимого engine census. Реальная квалификация FreeBSD power-cut, old PoC migration и Telegram voice остаются открыты.

**`v0.5.2_70` — возврат после прерванного общего Apply с временными IPFW.** В существующем `shared_apply_recover_activated_cold_service` фаза `activated` теперь восстанавливает предыдущего подтверждённого common owner из полностью проверенного нового runtime и прежнего native Config, когда движок/монитор отсутствуют, а kernel точно соответствует либо новому uncommitted IPFW+stage, либо старому IPFW после rollback, либо ожидаемой очистке. Используются только существующие `verify-staged`/`rollback`/`install`/`commit` и старый атомарный runtime installer; после отключения IPFW применяется прежний cold-restoration путь. Любая неизвестная стадия, чужие правила/процесс или сбой оставляют journal незакрытым. Добавлена направленная shell-проверка последовательности и повторов. Реальная FreeBSD/power-cut и STUN/MEDIA/CALL приёмка ещё не выполнена.

**`v0.5.2_69` — честный общий Stop при потерянном PID.** Штатный Stop теперь использует существующий независимый census точного исполняемого файла dvtws2 перед решением «уже остановлено» и перед остановкой собственного процесса. После остановки PID-владельца census повторяется до изменения IPFW: посторонний/осиротевший/дублирующий процесс приводит к отказу, а не к успешному `native-common-stopped`. Регрессии выполняют настоящий Stop-функционал с подставными process/kernel адаптерами, включая нормальный повторный Stop. Нет нового backend, WAL, frontend или автоматического legacy STOP; FreeBSD live и STUN/MEDIA/CALL остаются не подтверждены.

**`v0.5.2_68` — исправление blocker в live predecessor attestation.** Функции операторского `legacy-begin`/`legacy-cancel` раньше пытались читать `marker`, `process_instances`, `managed_ipv4_sha256`, `active_argument_sha256` и `legacy_ipfw_previous` из сокращённого результата `inspect_legacy_previous`, в котором этих полей **нет**; production FreeBSD route отказывал без нужной проверки. Новый `inspect_legacy_previous_live_identity` извлекает точные поля только из полностью проверенного sealed `legacy.json`, повторно сверяет его checksum, previous-five binding и manifest перед использованием. Добавлен regression-test на сравнение прежнего PID/argv/IPFW/marker с реальным live inspector и на отказ при изменении manifest. Не создано нового движка, WAL, независимого backend или unsafe actuator. Команды остаются operator-only; живой reversible cutover и FreeBSD STUN/MEDIA/CALL приёмка ещё не готовы.

**`v0.5.2_67` — корректировка test-harness.** Новая проверка production outer FD9 dispatch проверяет членство каждой legacy operator-команды без зависимости от того, какая команда последняя в shell `case`. Алгоритм `legacy-quiescing` из `_66` не менялся: он атомарно сохраняет intent до реального STOP, отменяется только при неизменённом старом владельце, и не выдаёт разрешение на live migration или Telegram call. CI последнего HEAD проверяется, frontend/ТЗ и релиз не меняются.

**Текущая ревизия: v0.5.2_66 (без релиза).** В единственном durable journal `shared-apply/operation.json` теперь фиксируется `legacy-quiescing` — первый защищённый барьер непосредственно перед будущей остановкой старого Telegram PoC. Операторский `shared-apply-legacy-begin ID` через штатный FD9 и оригинальный Config flock повторно сверяет sealed previous-five snapshot, прежние Config/runtime/marker, точные FreeBSD процессы/argv и IPFW, затем атомарно записывает фазу без остановки процесса. После reboot обычные Apply/boot-recover не переходят через `legacy-quiescing`; ручной `legacy-cancel` допустим только если прежний PoC полностью неизменён. Нет нового backend/WAL/движка, GUI/ТЗ сохранены. **Это ещё не рабочая миграция; operator arm/begin на production не выполнять.** Следом нужен один исполнитель для настоящего STOP + restore-on-failure + restart/cutover и FreeBSD owner-live/STUN/CALL тесты.

**`_57`:** новый операторский маршрут `shared-apply-legacy-capture <32-hex-id>` через штатный FD9 сохраняет полный recoverable предыдущий PoC в том же `shared-work/<ID>/legacy-backup`, который принадлежит sealed Voice candidate. **`v0.5.2_41` — read-only native common IPFW inspection:** существующая `voice/inspect` теперь различает legacy IPFW ledger и новый подтверждённый common owner из единого durable journal. Когда owner committed (либо у `restored` есть предыдущий committed owner), инспектор подтверждает целостность source bundle, совпадение page/dependencies/changed_fields с sealed plan и фактические kernel IPFW правила/таблицы по manifest общего release; при совпадении возвращает `state=ready`, `source=native-common`, `condition=common-ipfw-verified-only`, **`can_activate=false`**. Все pending-фазы немедленно возвращают `interrupted`, без обращения к IPFW. Чужие или частичные правила остаются blocked; если common owner отсутствует, сохраняется legacy inspection. Это статус только IPFW, НЕ подтверждение живых dvtws2, успешного STUN или звонка. GUI, ТЗ, FD9 runtime и native Config не изменены. Запрошена проверка CI ревизии `_41`, живые FreeBSD tests отдельно.

**`v0.5.2_42` — read-only свидетельства процессов общего движка и пяти Voice-профилей.** Единственный существующий endpoint `voice/inspect` после подтверждения общего sealed owner и kernel IPFW дополнительно проверяет PID `dvtws2`, PID supervisor и точное совпадение установленного `runtime-v2/voice-plan.json` и `dvtws.args` с тем же sealed release. Имена включённых профилей сопоставляются одновременно с `voice-plan.profiles`, `capture.voice` и фактическими IPFW таблицами. Для всех пяти служб возвращаются отдельные `configured`, `capture_verified`, `runtime_state`, `media_verified=false`; для всей операции — `runtime.state`, `engine_verified`, `supervisor_verified`, `source_verified`, `call_verified=false`. Это НЕ пять независимых демонов и не подтверждение прохождения STUN, медиа или звонков. Нет новых писателей, WAL или изменений GUI. После контрольных тестов требуется FreeBSD owner-live/call acceptance.

**`v0.5.2_43` — предотвращение ложного `requires-review` при обычном legacy/foreign runtime.** В общем `backend/apply_runtime.sh` read-only `apply_runtime_probe` отделён от мутирующего `apply_runtime_preflight`. Под исходным FD9, после detached Config preflight и до durable фаз `prepared/activating`, `shared_apply_execute_service` проверяет полноту candidate, engine/supervisor, соответствие common active release и фактический IPFW. Запущенная legacy-установка без `voice-plan.json`, частичный monitor и чужой kernel/IPFW отвергаются кодом 69 **без записи** новой транзакции и без firewall_prepare. Когда проверки пройдены, тот же probe повторяется внутри runtime activation после durable intent, чтобы отказать при гонке внешних изменений. В тестах отдельно проверено, что негативные случаи не вызывают `record:prepared`, `record:requires-review`, Config::save или изменение firewall. Это только безопасное предотвращение ложного зависания; автоматическая live migration legacy→common и FreeBSD owner-live ещё требуют проверки.

**`_44`–`_45`:** первоначальная попытка PID-парковки отката сохранила буквальный `$` в исходнике и тесте. `_48` исправляет имя на `$$` и доказывает, что текущая парковка конфликтует безопасно, а чужие следы не перезаписываются. Защита census процессов `dvtws2` из `_45` сохраняется.

**`_47` — тестируемый quiescent legacy→common migration.** Добавлен интеграционный shell-сценарий на существующем `apply_runtime.sh`: при полностью остановленных dvtws2/supervisor и пустом owned IPFW прежняя legacy-директория (без нового `voice-plan.json`) сохраняется штатным atomic backup, запускается общий runtime, а отказ до Config save восстанавливает именно прежнюю директорию и пустой kernel. Успешный повторный Apply оставляет старый backup доступным; работающий legacy-процесс по-прежнему отвергается. Это **не** автоматическая остановка и не эксперимент над живым OPNsense; API GUI и утверждённое ТЗ не менялись. Переход с running legacy требует отдельного доказанного live-owner handoff; FreeBSD owner-live и реальный STUN/call acceptance всё ещё не завершены.

State-line scope: **`v0.5.x`**. Текущий этап — **`v0.5.2_74`**, открыт владельцем 13.10.2026 без релиза. Поток состояния: `START_HERE -> PROJECT_STATE -> version-line archive`; смена третьего компонента не закрывает линию `v0.5.x`.

## Сохраняемая продуктовая база

- DNS считается исправным; старое расследование закрыто до нового воспроизводимого отказа.
- Model C — единственный normal production Stage 60; автоматический A/B fallback удалён. Закрытые измерения Lua/BLOB/discovery/readiness не повторяются без нового основания.
- Strategy Lab поддерживает domain и canonical IPv4 с optional Host/SNI; трафик остаётся привязан к введённому IP, итоговый fixed-IP replay сохраняется. Bare-IP TLS даёт PARTIAL с guidance, bare-IP QUIC без Host/SNI пропускается; Generic UDP независим от Host/SNI/QUIC.
