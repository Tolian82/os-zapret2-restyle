**Подтверждённая исходниками граница Config (решение владельца 26.10.2026):** Для обычного Strategies/Voice Apply единственный writer — штатный OPNsense Config через `SharedConfigCommit::persist`: изменённые модельные поля → `serializeToConfig(false, true)` → `Config::save()`; при `changed_fields=[]` сохранение пропускается. Для Remove сохранённые параметры остаются без изменений, `config-saved` означает только повторную аттестацию уже сохранённого snapshot. Утверждено использовать существующие `preflight`/`saved`, оба журнала и штатный common runtime/IPFW restore; общий `recover-saved` не следует вызывать как откат к прежнему владельцу, поскольку он может активировать новый release. **В `_34` в source добавлена узкая cold-recovery Remove на `config-saved`: при неизменном Config и двух исходных журналах прежний runtime/IPFW возвращает существующий common cold actuator, а отдельное окончание того же shared journal записывает `restored` только после полной аттестации прежнего владельца. Обычный `recover-saved` и универсальные переходы `config-saved` не расширены. CI и натурная проверка ещё не подтверждены на момент фиксации исходного кандидата; GUI/API Remove остаётся read-only.** [Решение](DECISIONS.md).


**Текущая граница `_35` (исходный код; испытания OPNsense ещё не выполнены):** внутренний Remove журнал фиксирует идентичность каждого исходного inode Lua/BIN (device/inode/mode/uid/gid/mtime/flags). При ошибке или прерывании `_restore_remove` переподключает исходный inode из карантина через `os.replace`, сохраняя реальные метаданные, включая ACL/flags; не пересоздаёт прежние файлы через байтовую запись с режимом `0644`. Отсутствующий/подменённый inode, совпадение одних SHA-256 при чужом inode или отсутствие свидетельства оставляет восстановление неподтверждённым (`RESTORE_FAILED`) и сохраняет журнал. Подтверждение через CI, установленную OPNsense и разрешение Remove в API/GUI пока отсутствуют. Релиз и пакет не публикуются.

## Strategy Lab — текущий код и согласованное направление

[Integration map](architecture/STRATEGY_LAB_BROWSER_HTTP_PLAN.md).

## Telegram Voice — закрытый результат исследований

Владелец завершил кампанию 20.10.2026. Через прямой тракт OPNsense доказаны исходящие original/fake UDP, но ответы рефлектора и рабочая медиасессия не получены: `MEDIA_PASS=false`, `CALL_PASS=false`. Контроли fake OFF и TTL7 не дали положительного результата; исходная Strategy #4 и проверенные временные маршруты восстановлены.

Положительный опыт через pfSense `.1.140` не является доказательством Zapret2-обхода того же прямого провайдера: обнаружены Telegram route через `ovpnc6`, NAT на VPN-адрес и первый traceroute hop `10.1.11.1`. Точный путь конкретной переадресованной сессии не подтверждён PCAP. GOST SOCKS UDP и OpenWrt STUN fake egress подтверждены отдельно, без доказанной Telegram-медиасессии. Точная причина отсутствия ответов на прямом OPNsense тракте не установлена.

GUI Voice, сохранённые параметры STUN и общий Apply остаются частью продукта. Закрытие исследования не означает удаления этих функций и не даёт им недоказанный статус рабочего Telegram preset. Старые предложения звонков, STUN, PF/NAT, захватов, TTL/fake и маршрутов не являются текущими задачами. [Заключительное доказательство](verification/evidence/2026-10-20-telegram-native-voice-provider-blocked-final-closure.md).
