Дубли между путями позднее нужно разбирать идемпотентно тем же P1/WAL. Рекорд хранит полные SHA/size preimage/postimage отдельно от курсоров; `cursor_advanced=false`, `ack_authorized=false`. **ТЗ_6v4 STEP 5 — read-only post-physical rebind inspector (SOURCE-ONLY):** `inspect_original_learning_native_rebind_locked()` проверяет **все N** в той же исходной P2a+GUI/унаследованной Config FD4 и FD9 generation, но не вызывает `prepare_learning_first_slot()` после rename: прежний исходный dev/inode **обязан** перестать совпадать с рабочим именем. Возвращаются только фаза и ограниченные размеры/хеши, без очистки. **`physical_rotation_authorized=false`, `ack_authorized=false`.** Не считать это native hot-reload PASS: для этого потребуются отдельные штатные PID/argv/FD9 и установленные условия реального двигателя. **ТЗ_6v4 STEP 5 — оригинальный checkpoint → native compaction preflight (только исходники):** import-only `preview_learning_checkpoint_native_compaction_locked()` под исходным P2a+GUI и текущим FD9/P2b сверяет write-once slot, завершённый WAL/checkpoint, постоянный Found, оба active managed и текущий единый P1/Exclude; создаёт точный per-N список строк из уже запечатанного native-префикса, дописанный позднее suffix оставляет без изменений.
