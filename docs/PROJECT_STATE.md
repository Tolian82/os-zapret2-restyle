## Strategy Lab — текущий код и согласованное направление

Audit was based on restyle `8b31fa49cfcf00617f3137b8eb7bc80427d1f19f` and recorded upstream snapshots. On 21 October 2026, the owner approved **three independent sufficient reachability signals: verified target TLS handshake, verified target QUIC handshake, OR genuine final target HTTP response (including 4xx/5xx, without requiring a body)**. The available FreeBSD `latest` client is fetched anew per build without upstream version pin; one supported Chrome profile is selected. [Integration map](architecture/STRATEGY_LAB_BROWSER_HTTP_PLAN.md).

**Реализовано в текущем исходном коде:** Python-планировщик, Model C как единственный нормальный production-путь, CandidateSpec/ResourceInventory, фиксированный endpoint epoch и source-port атрибуция, конечные бюджеты, отмена, Stage 90. Source candidate `_5` changes default Standard HTTPS execution to the private Chrome launcher (not system curl), removes forced TLS1.3 and HTTP1.1, and introduces a single authenticated handshake-or-real-HTTP-response classifier with pinned remote IP for baseline and Model C. Installed `v0.5.6_6` Strategy Lab Standard `github.com` accessible-target and Stage 90 restoration **GUI PASS**; blocked-target candidate search and Model C are unverified. Extended QUIC still uses the old OpenSSL handshake and remains Stage 3. В Stage 80 есть четыре QUIC-кандидата; QUIC уже может быть источником Stage-85 результата. Ранний `TARGET_ACCESSIBLE` уже завершает задание до поиска/Extended.

**Approved requirements and implementation boundary:** `BH-01`–`BH-12` and six stages of the [English plan](architecture/STRATEGY_LAB_BROWSER_HTTP_PLAN.md). Stage 1 FreeBSD15 package build and testing asset publication passed; owner confirmed installation and client readiness. Actual TLS and HTTP3-only QUIC network success observed on installed `_3` with selected `chrome150`; `CERT=0` and `EXIT=0` for all five checks, including Google HTTP/3 204. Explicit TLS1.2-only check PASS on GitHub: observed TLSv1.2 and valid certificate, HTTP2 200 and `TLS12_EXIT=0`. Stage 1 V1 accepted. [Owner evidence](verification/evidence/2026-10-21-v0.5.6_3-owner-live-chrome-tls-quic.md). Stages 2–6 are not implemented. Reachability will use the handshake-or-HTTP-response rule and unpinned FreeBSD `latest` acquisition. An authentic HTTP response is affirmative evidence (not merely diagnostics); HTTP/ALPN/body fields not actually observed stay unknown. Direct HTTPS success by TLS **or** HTTP response skips QUIC. No Firefox, ordinary curl fallback, replacement Python scheduler or new recovery architecture.

## Telegram Voice — закрытый результат исследований

Владелец завершил кампанию 20.10.2026. Через прямой тракт OPNsense доказаны исходящие original/fake UDP, но ответы рефлектора и рабочая медиасессия не получены: `MEDIA_PASS=false`, `CALL_PASS=false`. Контроли fake OFF и TTL7 не дали положительного результата; исходная Strategy #4 и проверенные временные маршруты восстановлены.

Положительный опыт через pfSense `.1.140` не является доказательством Zapret2-обхода того же прямого провайдера: обнаружены Telegram route через `ovpnc6`, NAT на VPN-адрес и первый traceroute hop `10.1.11.1`. Точный путь конкретной переадресованной сессии не подтверждён PCAP. GOST SOCKS UDP и OpenWrt STUN fake egress подтверждены отдельно, без доказанной Telegram-медиасессии. Точная причина отсутствия ответов на прямом OPNsense тракте не установлена.

GUI Voice, сохранённые параметры STUN и общий Apply остаются частью продукта. Закрытие исследования не означает удаления этих функций и не даёт им недоказанный статус рабочего Telegram preset. Старые предложения звонков, STUN, PF/NAT, захватов, TTL/fake и маршрутов не являются текущими задачами. [Заключительное доказательство](verification/evidence/2026-10-20-telegram-native-voice-provider-blocked-final-closure.md).
