## `v0.4.1_16` — Generic UDP browser staging and owner-live PASS

End-to-end source tracing resolved an important boundary distinction: Generic UDP does not upload a multipart file into an OPNsense upload directory. The selected file is read in the browser and sent as Base64 in the ordinary start POST; private server files are created only after API/configd/launcher acceptance.

`_16` implementation:

- stages the selected `File` immediately on `change`;
- reads/validates exact bytes and retains filename, byte count and Base64 in application-owned state;
- shows localized ready-to-send filename/byte evidence before Run;
- starts from the staged Base64 even if native selection is later lost;
- retains a bounded native-file fallback at Run;
- removes realm-specific `instanceof ArrayBuffer` dependency;
- keeps strict `1..4096` decoded-byte/API validation;
- adds explicit job-local preparation failure classes, including unavailable/not-writable job directory, temp creation, decode, write/chmod/move and state-record failures;
- preserves selected-port/payload control observation, UDP no-reply semantics, candidate enumeration and Stage-90 cleanup.
