- every GitHub scope performs a documentation-impact check;
- cold start is context-first and permits exact-repository-state reuse of unchanged Level 1;
- local tracked Markdown paths and heading fragments are validated so file deletion/rename cannot strand links;
- current/new documentation uses clean Markdown without destructively restyling historical Level-3 bodies.

### Rule clarity and scoped validation

The next audit refined ambiguity and efficiency without changing `DEV-001`, `DEV-002`, `GH-014`, or `GH-015`:

- `CHAT-001` requires owner-facing explanations to be Russian sentences and treats English check/file/command names only as literal object names when useful;
- `DOC-024` explicitly defines the current-state conveyor `START_HERE -> PROJECT_STATE -> version-line archive`;
- `DOC-054` defines when to create, refine, cancel, or replace a canonical rule and excludes one-off/current work from rule creation;
- `DOC-031` limits roadmap commitments to accepted future directions rather than every mentioned idea;
- `DOC-036` makes the reconciliation decision mandatory while allowing a justified no-document-change result;
- the former mandatory broad GitHub reconciliation rule is cancelled without ID deletion because targeted dependency/link reconciliation plus scope/risk inspection supersedes its repository-wide audit requirement;
- `GH-016` makes CI proportional to the changed scope;
- `GH-027` keeps release identity/tag/assets immutable while allowing transparent correction of human-facing release notes;
- pure Markdown documentation PRs receive focused governance/integrity validation; product/package or general CI changes retain full validation as applicable.

### Direct GitHub patch/package delivery

Owner-approved delivery semantics were hardened after the `_13` testing publication exposed a gap between source-PR reconciliation and facts that only exist after immutable publication:

- `CHAT-015` now treats `сделай патч`, `сделай пакет`, and `выложи пакет` as GitHub-delivery commands rather than chat-file requests;
- `CHAT-027` forbids chat/sandbox `.pkg`, `.zip`, `.tar.*`, `.patch`, `.diff`, or equivalent transport artifacts as project patch/package delivery;
- `DEV-040` makes persistent GitHub publication the testing-package completion boundary while preserving the distinction from a full release;
- `DOC-037` defines the single bounded exception to same-source-PR documentation reconciliation for immutable facts that do not exist until after publication;
- `GH-035` requires the testing source SHA to be both an ancestor of `main` and the commit whose parent has a different package identity, preventing accidental publication from a later docs/governance commit with the same `_N`;
- `GH-060` makes package publication automatic after an authorized source patch creates a new package candidate and forbids a second publication-confirmation stop;
- `GH-061` requires the publisher to create a Draft publication-record PR with machine-generated evidence, after which the assistant completes bounded documentation reconciliation, exact-head validation/merge, main verification, and cleanup without new owner permission;
- `publish-prerelease.yml` implements the source-identity guard, persistent release verification, SHA-256 capture, direct asset URL, automatic Draft record PR, and idempotent recognition of an already-correct immutable release;
- `test-github-branch-hygiene.sh` makes these publisher/rule properties part of CI so the contract cannot be silently weakened.
