# v0.5.x — current working ledger

## 2026-10-13 — v0.5.2_23–_24: Common predecessor + native cold recovery

Ревизия _23: в том же durable operation.json сохраняется `previous` — идентификатор предшествующего committed common owner. Теперь новый Apply и его откат не превращают общий runtime в legacy Telegram Voice: `inspect` возвращает старого владельца, FD9 boot пересматривает восстановленную операцию и выбирает общий release. Результат покрыт regressions на pending, rollback, invalid predecessor и обычный start.

Ревизия _24: отдельный cold restart для уже сохранённого `config-saved`. Под FD9 повторно подтверждаются источник (bundle seal), native saved Config, отсутствие процессов и kernel IPFW и только затем выполняются тот же `apply_runtime_activate/commit` и долговечная запись `committed`. При любом сомнении операция остаётся pending; `activating/activated` не разблокируются. Native stop/restart, public кнопки двух страниц и FreeBSD owner-live остаются недоделанными.

CI последнего HEAD и реальное FreeBSD тестирование ещё не подтверждены. Незавершённые фазы `activating/activated` не могут перейти в `committed` без независимых evidence.

После `_21` проверка выявила неверную ссылку на `ID` вместо уже существующей регулярки `OP_ID` в команде `recover-prepared`. Требуется завершённый CI последнего HEAD и FreeBSD appliance acceptance; непроверенные `activating/activated/config-saved` не могут автоматически размечаться restored.


## 2026-10-13 — v0.5.2_21: bounded recovery of untouched PREPARED state

Подтверждённая `prepared` — единственная фаза, которую можно доказуемо завершить без чтения живых kernel/Config witnesses: общий исполнитель не мутирует ничего до fsync-записи `activating`. Добавлен read-only `inspect` возврат `prepared ID page`, а под штатным root FD9 `recover-prepared` проверяет seal исходного bundle, повторно сверяет журнал и атомарно записывает `restored`. Обычный `start/reconfigure` автоматически разрешает этот точный случай перед guard; при неудаче или фазе начиная с `activating` блокируется без legacy fallback. CI моделирует успешное восстановление, провал attestation и отказ на постмутационной фазе. Pending после kernel/runtime/Config изменения требует дальнейшей разработки точного recovery, а public Voice ON пока не подключён.


## 2026-10-13 — v0.5.2_18–_20: sealed candidate и native common boot

В `_18` общий detached candidate.xml/plan.json/release получает один атомарно записанный, fsync-проверенный SHA-256 seal внутри existing shared-work ID; перед kernel activation и непосредственно перед native Config::save он проверяется заново. Изменение выпуска вызывает отказ или проверяемый rollback, а не незаметную запись другой конфигурации. В `_19` added root FD9 read-only journal `inspect`, PHP saved Config witness и штатный common boot от `committed` journal через прежний `apply_runtime_activate/commit`. В `_20` fault-injection тест действительно исполняет оригинальный `service_with_lifecycle_lock` и доказывает, что committed owner start/reconfigure не падает в legacy, pending/malformed owner блокирует запуск, отсутствие owner сохраняет legacy route. Это не завершает powercut recovery после `activating/activated/config-saved`, публичное GUI Apply, stop/restart или FreeBSD live acceptance.

В `_17` shell fault-injection запускает сам сервисный исполнитель с инжектированными native Config, IPFW и journal операциями, покрывая успешный ON, ошибку до Config, uncertain save, сбой activation, journal и commit. Следующие ещё обязательные пункты: actual on-appliance FreeBSD verification, crash-restart recovery, native boot и одна штатная кнопка Apply на каждой странице без изменения frontend. ## 2026-10-13 — v0.5.2_11: native Config/runtime transaction ordering

## 2026-10-13 — v0.5.2_3: общий firewall полного release

`firewall_shared_runtime` использует существующие bounded IPFW adapter/transaction функции и производное владение из предыдущего/кандидатного общего release, без `VoiceOwnershipStore` или новой persistent схемы. Install сохраняет prior table contents до общего commit, rollback возвращает их при отказе runtime/Config, commit удаляет проверенные stage/retired таблицы. First start и Stop выражаются пустым observed/desired manifest. Native CLI требует FreeBSD root и исходный удерживаемый FD9; общая attestation вынесена в adapter с compatibility wrapper прежнего executor.

Сквозной full generator → injected IPFW прошёл all-five/update/repeat/all-OFF/Stop/rollback и сохранение чужих объектов. Семантическая сверка обнаруживает команды, вернувшие успех без нужного изменения, в install/restore/cleanup. В runtime/GUI новый путь подключается этапом 3; reboot/crash/live capture не объявляются пройденными. Frontend и разделы 1–11 ТЗ сохранены.

В этой же поставке исправлена конкретная FreeBSD CI ошибка `_2`: common-runtime fixture теперь даёт generic `python3` и `python3.13` одному установленному интерпретатору, поскольку строгий existing IPSET normalizer вызывает `python3`. Повтор изолированного сценария с ограниченным PATH проходит локально; FreeBSD 3.13 подтверждает CI. Локальные Python проверки выполнены на 3.12; PHP parity здесь не запускалась успешно из-за отсутствующего PHP и проверяется обязательным GitHub CI.
