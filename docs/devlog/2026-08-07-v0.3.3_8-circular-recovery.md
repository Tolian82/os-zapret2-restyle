# 2026-08-07 — v0.3.3_8 circular stale recovery ownership

## Scope

Patch 3 of the third-audit corrective series implements `SL3-002`.

## Root cause

`strategy_lab_circular_recover_stale_session()` performed semantic service restoration directly from the circular launcher context after owner loss. The lifecycle helpers it called use protected `strategy-lab-status/evidence/start/stop` actions, while `zapret_service.sh` deliberately rejects those actions without the Strategy Lab lifecycle lock owner environment. The focused circular-owner test hid the defect by replacing the whole restore function with a successful mock.

## Implementation

- Reused the lifecycle-owned `strategy-lab-recover` service transaction introduced by Patch 2 rather than creating another lifecycle entry point.
- Extended `strategy_lab_recovery_worker.sh` to prefer ordinary job state and, when absent, bind generic runtime/lifecycle helpers to a private circular session under `circular/sessions/job.*`.
- Removed direct protected restoration from `circular_owner.sh` when a lifecycle snapshot exists.
- Circular stale recovery now delegates to `strategy-lab-recover` and accepts success only when persisted restoration proves semantic equality, unchanged strategy evidence, and clean temporary runtime.
- Invalid or failed proof is explicitly forced unverified and persisted as `restore_failed/RESTORE_FAILED`; the active session remains present so automatic retry stays blocked.
- A stale queued session with no lifecycle snapshot retains the safe pre-mutation residue-cleanup path because no normal service mutation has occurred.
- Circular configd start/status/stop actions use 180 seconds, `CircularController` uses 190 seconds, and the shared browser AJAX envelope remains 200 seconds so synchronous stale restoration is not wrapped by a shorter caller.

## Regression coverage

- `test-strategy-lab-circular-owner.sh` now verifies delegation to the lifecycle-owned recovery action, owner-token mismatch handling, successful semantic proof, rejection of contradictory proof, and retry blocking. It no longer mocks `strategy_lab_restore_initial_service_state()` inside the circular owner module.
- `test-strategy-lab-circular-recovery-contract.sh` verifies the service-owner route, circular namespace binding in the shared recovery worker, absence of direct protected restoration in `circular_owner.sh`, and the 180/190/200 response envelope.
- Existing semantic restoration and full corrective-matrix tests remain mandatory.
