# 2026-08-08 — v0.3.3_26 Stage-50 candidate isolation

## Trigger

The first post-migration owner-assisted Scenario-1 run used published testing candidate
`v0.3.3_25` on OPNsense against `rutracker.org` in Standard mode.

Job `job.c0oydv` reached Stage 40 with visible 36% persisted progress, then ended Stage 50
with the generic message `Temporary candidate runtime failed internally.`. Stage 90 restored
Zapret2 successfully.

## Live diagnosis

The preserved job bundle changed the diagnosis materially:

- candidate runtimes started, bound divert port 9989 and became stable/ready;
- IPFW interception counters increased;
- the first four families were actually executed;
- `seqovl` reached `rutracker.org` successfully with curl exit 0, matching selected remote
  IP and HTTP 301;
- the family aggregate already contained `accepted=["seqovl"]` and `all_pass=true`;
- the aggregate stopped at `completed=4` of `total=7`.

This proves that the Stage-50 terminal ERROR was not a global temporary-runtime startup
failure.

## Source trace

The Python candidate owner intentionally converts candidate-local exceptions into a
structured JSON result with `error:true`. The shell compatibility runner maps such a result
to exit status 1.

The Python family owner then treated any nonzero runner status as a fatal screening error
before loading the JSON. That control-flow mismatch converted a local rejected candidate
into a terminal Stage-50 error and prevented candidates 5–7 from completing.

## Corrective implementation

Created candidate `_26` and changed only the Stage-50 aggregation boundary:

- delete any stale per-candidate JSON before launch;
- read fresh structured result after every non-timeout candidate invocation;
- nonzero + structured `error:true` becomes a rejected entry and screening continues;
- `runner_status` is preserved for diagnostics;
- nonzero without valid structured error evidence remains fatal;
- timeout and cancellation contracts remain unchanged.

Added `scripts/test-strategy-lab-stage50-candidate-isolation.sh` to reproduce the exact
control-flow class: success → structured error/exit 1 → later candidate, with full screening
completion required.
