three stable 3/3 `rutracker.org` finalists reached cold Stage-85 validation, while Standard

## Scope selected

This cycle implements the Model A measurement harness only.

The implementation deliberately does not:

- keep dvtws2 warm;
- start more than one candidate runtime;
- introduce a dispatcher or source-port selector;
- run candidate probes in parallel;
- change search ordering, timeout budgets or validation classification;
- mutate retained job evidence while measuring it.

## Implementation

A new Python module, `strategy_lab_py/model_a.py`, summarizes one or more retained completed
jobs. It discovers leaf cold candidate evidence from family screening, parameter expansion,
stability attempts and finalist deep replay. Aggregate stage JSON and `*.spec.json` files
are ignored because they are not independent candidate executions.

Each sample records:

- job/stage/path;
- candidate/spec/family/protocol identity;
- resource classes and output range;
- PASS/FAIL/TIMEOUT/ERROR classification;
- selected and remote endpoint identity plus IPFW interception evidence;
- search epoch and resource inventory identity;
- existing cold lifecycle phase timings;
- candidate RSS when present in the readiness snapshot.

The summarizer emits median, nearest-rank p90 and max distributions globally and by
immutable candidate `spec_id`. It also evaluates the experiment-plan coverage conditions:
PASS and FAIL observations, a candidate with at least three samples, required resource
classes, `-d8`, at least two overlapping TLS/443 specs, RSS evidence and verified clean
restoration for every input job.

Because current production evidence does not separate stop from the remainder of cleanup,
the field is explicitly named `stop_cleanup_ms`. Likewise `resource_init_ms` remains null
when it is included in launch/readiness. The report never invents those values.

The candidate system adapter now records `rss_kb` in its normal readiness snapshot using
the already validated candidate PID and the configured `ps` binary. This is read-only
instrumentation and does not alter runtime ownership or readiness criteria.

## Verification contract

`scripts/test-strategy-lab-model-a-measurement.sh` builds a deterministic completed-job
fixture with repeated passing cold samples, failing built-in/external-resource samples,
`-d8`, endpoint/interception evidence, RSS and verified restoration. It proves:

- the packaged launcher exposes `model-a summarize`;
- the report groups immutable candidate repetitions correctly;
- median/p90/max phase statistics are produced;
- resource/range/overlap/RSS/restoration coverage is machine checked;
- a complete fixture returns `reference_collected`;
- a missing job fails through the normal Python compatibility error boundary.

The existing corrective-matrix runner automatically executes every
`test-strategy-lab-*.sh`, so the new focused regression enters the normal CI path without a
new workflow.

## Live handoff
