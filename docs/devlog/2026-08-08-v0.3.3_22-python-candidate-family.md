# 2026-08-08 — v0.3.3_22 Python candidate runtime and family screening

Migration Patch 5 moves the standard TLS 1.3 candidate lifecycle/readiness/interception policy and ordered Stage-50 family screening into Python 3.13.

## Implementation

Added `strategy_lab_py/candidate.py` as the standard candidate owner. It reuses the Patch-4 finite request layer and DNS ANSWER-section parser, qualifies runtime readiness from process identity/divert-socket/startup-log evidence, requires two stable readiness snapshots, rejects fatal startup-log text, performs endpoint-bound TLS 1.3/TCP checks, verifies selected remote IP and IPFW counter growth, and always requests cleanup.

Added `strategy_lab_py/family.py` as the Stage-50 family owner. It loads the existing seven-family catalog in order, runs one isolated candidate at a time, owns per-candidate timeout/cancellation, and incrementally persists the existing family result shape.

Added `strategy_lab_candidate_adapter.sh` as the narrow FreeBSD system boundary for WAN lookup, runtime-file preparation, reserved IPFW rules/counters, temporary access permissions, daemon launch/stop, process identity and divert-socket snapshots. The adapter deliberately has no family order, readiness verdict, candidate success or timeout policy.

`strategy_lab_candidate_runner.sh` and `strategy_lab_family_runner.sh` now launch Python. The standard candidate runner keeps its historical 3–7 argument/default contract and maps a diagnostic `error:true` result back to the existing non-zero infrastructure-failure boundary. `strategy_lab/family.sh` no longer contains a competing Stage-50 implementation.

## CI-driven compatibility repairs

The early Ready PR was used as the corrective-matrix arbiter. Exact failures were repaired without widening scope:

1. the legacy candidate-runtime fixture exposed the old three-argument smoke default; the thin Python runner restored the same defaults instead of weakening the fixture;
2. the same boundary required internal/runtime candidate failure to remain non-zero while retaining diagnostic JSON;
3. the family-screening fixture still invoked the retired shell `strategy_lab_family_screen()` function; it was moved to the authoritative Python family runner while preserving exact seven-family order, timeout and accepted/rejected assertions;
4. the interception fixture still required the standard candidate runner to source shell interception helpers; standard TLS 1.3 ownership checks now point to Python while QUIC/UDP shell ownership remains explicitly protected for Patch 6;
5. the live-matrix contract correctly rejected stale `_21` source metadata after the revision advanced to `_22`; source-candidate metadata was advanced while the published/owner-tested `_17` evidence remained frozen.

## Verification boundary

The patch adds a focused Python candidate/family regression and requires it in Linux validation and the FreeBSD 15 VM package gate. Package inspection must contain `candidate.py`, `family.py`, and `strategy_lab_candidate_adapter.sh` in addition to the earlier migration layers.

The authoritative corrective matrix remains the compatibility gate for the complete Strategy Lab surface. No source-side result is treated as owner-assisted OPNsense evidence.
