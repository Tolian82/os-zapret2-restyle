# v0.3.3_19 — Strategy Lab Python state persistence

Date: 2026-08-07
Scope: Migration Patch 2 only.

## Ownership cutover

The authoritative automated-job persistence boundary moves from shell jq transforms to
Python 3.13.

`strategy_lab_py/state.py` now owns:

- initial schema-2 `status.json` creation;
- revisioned state mutations;
- persisted stage/progress snapshots;
- cancellation state/timestamp persistence;
- `events.ndjson` append persistence;
- structured result embedding into the job state;
- lifecycle snapshot/restoration fields;
- stale-worker terminal reconciliation state;
- final circular-eligibility fields.

The shell `strategy_lab/state.sh` remains only as a compatibility adapter exposing the
existing function names to the still-shell stage machine.

## Atomicity and compatibility

Python serializes state/event writers with one per-state file lock. JSON is written to a
same-directory temporary file, flushed, fsynced, atomically replaced, and left mode 0644.
Existing revision behavior is preserved: every serialized status mutation increments the
revision once, including a mutation that is a semantic no-op because the job is already
terminal.

The public schema, stage keys, progress percentages, cancellation fields, lifecycle
fields, and result shapes are intentionally unchanged. Existing callers therefore do not
need to know which language owns persistence.

Shared lifecycle recovery can target either ordinary `status.json` or circular-session
`state.json`; the actual state path is supplied by the thin shell adapter and validated by
Python.

## Scope guard

The production service still launches `strategy_lab_worker.sh`. The shell worker still
owns stage ordering, time budgets, cancellation/finalization decisions, lifecycle calls,
probe/candidate execution, and search algorithms. Those responsibilities are not pulled
forward from Migration Patch 3 or later patches.

## Verification plan

The focused regression covers public schema parity, progress mapping, structured fields,
revision semantics, cancellation timestamp idempotence, concurrent writers/readers,
atomic NDJSON, file modes, temporary-file cleanup, circular-state-path compatibility,
deterministic invalid-path handling, and absence of shell `strategy_lab_state_transform`.

The existing corrective matrix remains required so the language cutover cannot silently
weaken lifecycle, cancellation, stale recovery, terminal result, or GUI-facing contracts.
FreeBSD 15 package CI additionally executes the state regression with
`/usr/local/bin/python3.13` and requires `strategy_lab_py/state.py` in the built package.

## Evidence boundary

This source migration does not close the owner-observed `_17` Stage-50 or GUI defects.
Published/owner-tested live evidence remains `_17`; `_19` is a migration source candidate
until later functional parity and owner-assisted live verification.
