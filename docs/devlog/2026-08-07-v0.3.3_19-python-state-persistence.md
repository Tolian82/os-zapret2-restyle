# v0.3.3_19 — Strategy Lab Python state persistence

Date: 2026-08-07
Scope: Migration Patch 2 only.

## Ownership cutover

The authoritative automated-job persistence boundary moves from shell jq transforms to
Python 3.13.

`strategy_lab_py/state.py` now owns automated-job:

- initial schema-2 `status.json` creation;
- revisioned state mutations;
- persisted stage/progress snapshots;
- cancellation state/timestamp persistence;
- `events.ndjson` append persistence;
- structured result embedding into the job state;
- lifecycle snapshot/restoration fields;
- stale-worker terminal reconciliation state;
- final circular-eligibility fields stored in the parent automated job.

The shell `strategy_lab/state.sh` remains only as a compatibility adapter exposing the
existing function names to the still-shell stage machine.

Private circular-session `state.json` is deliberately not cut over in this patch. Its
existing shell writer remains authoritative, and shared lifecycle code keeps a circular
fallback so that Python and shell do not become competing writers of the same private
session file. The automated-job Python writer explicitly rejects private circular
`state.json` paths; this boundary is protected by a negative regression.

## Atomicity and compatibility

Python serializes automated-job state/event writers with one per-state file lock. JSON is
written to a same-directory temporary file, flushed, fsynced, atomically replaced, and
left mode 0644. Existing automated-job revision behavior is preserved: every serialized
status mutation increments the revision once, including a mutation that is a semantic
no-op because the job is already terminal.

The public schema, stage keys, progress percentages, cancellation fields, lifecycle
fields, and result shapes are intentionally unchanged. Existing callers therefore do not
need to know which language owns automated-job persistence.

## Scope guard

The production service still launches `strategy_lab_worker.sh`. The shell worker still
owns stage ordering, time budgets, cancellation/finalization decisions, lifecycle calls,
probe/candidate execution, search algorithms, and private circular-session state
transitions. Those responsibilities are not pulled forward from Migration Patch 3 or
later patches.

## Verification plan

The focused regression covers public schema parity, progress mapping, structured fields,
revision semantics, cancellation timestamp idempotence, concurrent writers/readers,
atomic NDJSON, file modes, temporary-file cleanup, deterministic invalid-path handling,
explicit rejection of private circular state paths, and absence of shell
`strategy_lab_state_transform` from the automated-job state adapter.

The existing corrective matrix remains required so the language cutover cannot silently
weaken lifecycle, cancellation, stale recovery, terminal result, circular isolation, or
GUI-facing contracts. FreeBSD 15 package CI additionally executes the state regression
with `/usr/local/bin/python3.13` and requires `strategy_lab_py/state.py` in the built
package.

## Evidence boundary

This source migration does not close the owner-observed `_17` Stage-50 or GUI defects.
Published/owner-tested live evidence remains `_17`; `_19` is a migration source candidate
until later functional parity and owner-assisted live verification.
