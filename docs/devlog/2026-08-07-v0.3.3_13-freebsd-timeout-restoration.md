# 2026-08-07 — v0.3.3_13 FreeBSD Strategy Lab restoration timeout correction

## Scope

One logical live defect: stage 90 leaves an initially RUNNING Zapret2 service stopped after Strategy Lab failure on FreeBSD 15.

Stage 50 is intentionally excluded and remains the next independent corrective scope.

## Live evidence

Owner-assisted Scenario 1 on `os-zapret2-restyle-0.3.3_12.pkg`, job `job.sl7JGM`, passed stages 00–40, failed stage 50, then entered stage 90.

A one-second watcher proved that both restoration attempts actually built a healthy normal runtime:

- first runtime reached `ready` at 13:31:07 and remained healthy until the 45-second timeout expired;
- second runtime reached `ready` at 13:31:52 and remained healthy until the second 45-second timeout expired;
- after each timeout the normal runtime was torn down;
- final outcome was `RESTORE_FAILED` with Zapret2 stopped.

Evidence: `docs/verification/evidence/2026-08-07-v0.3.3_12-scenario-01-freebsd-timeout-restoration.md`.

## Root cause

FreeBSD `timeout(1)` without `-f` / `--foreground` runs as the reaper of the command and its descendants. `strategy-lab-start` intentionally creates long-lived dvtws2 and supervisor daemon descendants. `strategy_lab_timed_service_action()` therefore waited for those daemons after the service-control command had completed successfully and killed the healthy runtime when `STRATEGY_LAB_RESTORE_TIMEOUT=45` expired.

## Correction

`strategy_lab_timed_service_action()` now detects the runtime platform. On FreeBSD only, the daemonizing `strategy-lab-start` action uses `timeout -f`; stop and non-FreeBSD actions retain the existing normal timeout semantics. The lifecycle deadline still bounds the service-control process while FreeBSD long-lived runtime descendants remain outside timeout reaping.

`test-strategy-lab-semantic-restoration.sh` now supplies a FreeBSD `uname` fixture and a timeout fixture that requires `-f` for `strategy-lab-start` while rejecting it for `strategy-lab-stop`. Linux e2e behavior therefore remains unchanged while the FreeBSD daemon/reaper contract is deterministic in focused CI.

`PLUGIN_REVISION` advances from 12 to 13.
