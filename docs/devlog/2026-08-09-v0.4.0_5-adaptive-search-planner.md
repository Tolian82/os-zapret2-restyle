# 2026-08-09 — v0.4.0_5 adaptive-search `_31`

## Trigger

`_30` made the native Zapret2 DAG executable, but Stage 60 still consumed a precomputed
order, candidates resolved DNS independently, discovery/final publication retained a
five-item default and no durable timing corpus existed for timeout review. `_31` was the
approved boundary for making those four behaviors adaptive and reproducible.

## Implementation

Added `strategy_lab_py/endpoint_epoch.py`. Stage 40 now completes DNS before its bound TLS
probe, records the ordered answer set and selected address for every required endpoint,
and persists a hashed job/generation/target identity. Every later candidate path loads
that identity; `candidate.py` removed per-candidate DNS and renders IPFW/request bindings
only from the fixed epoch.

Added live frontier selection to `search_graph.py`. Stage 60 asks the graph for one next
node after every observation. PASS chooses a simpler compatible neighbor, FAIL chooses a
stronger neighbor, and resource-eligible branches remain reachable. The result preserves
the exact decision order and evidence rather than presenting an adaptive run as a static
plan.

The default Stage-60 winner target and Stage-85 publication limit are now three. Results
record a two-to-three normal band and stop after three winners/stable finalists; smaller
verified output remains truthful. The independent circular three-to-five contract was
not changed.

Added `strategy_lab_py/telemetry.py` with a job-local lock, schema validation, atomic
replacement and monotonic durations. Probe, candidate, family, search and orchestration
owners now contribute phase evidence without changing existing deadlines. Resource-init
time is honestly scoped inside launch/readiness until a later runtime model can measure it
separately.

Final shortlist replay verifies that stability, every source and every replay belongs to
the same epoch. Extended TLS/HTTP/QUIC/UDP results retain the same identity as well.

## Regression boundary

The new focused test proves endpoint identity/generation/mismatch rejection, PASS-vs-FAIL
neighbor selection, live decision ordering, full graph reachability, the default
three-winner early stop and durable timing events. Existing Stage-40 tests now assert
bound `--resolve` evidence; the real candidate runtime fixture makes DNS fail if called,
proving candidates use only the epoch. Family/search/extended/final-result fixtures carry
and verify the epoch end to end.

Linux and FreeBSD 15 CI run the focused test. Required-file and package-content contracts
include both new Python modules.

## Scope retained for later cycles

`_31` keeps cold one-candidate execution, all current timeout constants, the current
discovery request, full three-attempt stability execution and current finalist request.
Telemetry-driven deadline containment is `_32`; lightweight discovery, fail-fast 3/3 and
cold long-GET/16-KiB finalist evidence are `_33`. No warm model is selected.

`VERSION` remains `0.4.0`; `PLUGIN_REVISION` advances once from `4` to `5`. Latest
published and owner-tested testing candidate remains `v0.4.0_2`; `0.4.0_5` is a source
candidate until separately authorized publication/live evidence says otherwise.
