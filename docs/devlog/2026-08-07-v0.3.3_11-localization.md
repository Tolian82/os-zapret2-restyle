## Scope

Patch 6 of the third-audit corrective series implements `SL3-007`.

## Root cause

The backend persists the non-terminal job state `cancel_requested`, but Diagnostics did not define `CANCEL_REQUESTED` in its RU/EN status dictionary. The shared label helper therefore fell back to the raw technical key, exposing `CANCEL_REQUESTED` in the Russian UI during cancellation/restoration.

## Implementation

- Added explicit RU and EN mappings for `CANCEL_REQUESTED` in Diagnostics.
- Kept circular `STOP_REQUESTED` separate because circular ownership uses a distinct `stop_requested` machine state.
- Updated the progress/localization architecture contract so every supported visible backend state requires deliberate presentation.
- Kept backend JSON machine vocabulary unchanged.

## Regression coverage

`test-strategy-lab-progress-localization.sh` now creates a real Strategy Lab job, requests cancellation through `strategy_lab_request_cancel()`, derives the resulting `CANCEL_REQUESTED` presentation key from persisted backend state, and requires both RU and EN mappings. Existing stage progress, circular messages and typo rejection remain covered.
