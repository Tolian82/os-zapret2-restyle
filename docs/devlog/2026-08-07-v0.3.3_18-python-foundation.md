# v0.3.3_18 — Strategy Lab Python foundation

Date: 2026-08-07
Scope: Migration Patch 1 only — Python platform and compatibility foundation.

## Platform evidence

The supported OPNsense 26.7 toolchain was checked before source implementation:

- `opnsense/tools` `config/26.7/build.conf` selects `OS=15.1` and `PYTHON=313`;
- `opnsense/core` `src/bin/python3.link.in` installs `/usr/local/bin/python3` as the
  stable link to `python${CORE_PYTHON}`;
- OPNsense core itself depends on packages in the selected `py${CORE_PYTHON}` family.

The plugin therefore uses OPNsense-managed Python 3.13, launches through the stable
`/usr/local/bin/python3` path, and also declares `python313` directly in its package
metadata so the dependency is explicit rather than merely transitive.

## Implementation

Added a minimal standard-library-only Python package and entry point plus a thin POSIX-sh
launcher. The Python boundary can self-test and can delegate one validated Strategy Lab
job ID to the existing shell worker. Missing or unsupported Python produces a stable
startup error and exit 70.

The production service path is deliberately unchanged. `strategy_lab_worker.sh` remains
the sole authoritative Strategy Lab worker for `_18`; no state-machine ownership moves in
this patch.

## Automated evidence

Before publication, the focused foundation test was executed locally with Python 3.13.5
and passed import, `py_compile`, self-test, exact job-ID delegation, invalid-input handling,
missing-interpreter handling, unsupported-version handling, and the production-path guard.

Repository CI is extended to run the same foundation under Python 3.13 on Linux and
`python313` inside the FreeBSD 15 package job. Package inspection requires all new Python
files and the `lang/python313` dependency origin.
