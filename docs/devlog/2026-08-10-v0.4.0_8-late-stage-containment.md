# 2026-08-10 — v0.4.0_8 Strategy Lab late-stage containment

## Trigger

Owner-live `0.4.0_7` Standard and Extended jobs against `telegram.org` proved the Stage-60
fix and supplied clean late-stage telemetry. Stage 60 completed all 16 candidates in both
runs, but the evidence showed three remaining `_32` gaps:

1. Stage 70 had only 13–14 seconds of Standard-search budget left in the measured
   no-winner path and still lacked pre-attempt candidate admission;
2. Stage-80 candidate loops shared the proper overall stage envelope but did not reject a
   new candidate before launch when the remaining envelope became too small;
3. Stage 85 and Stage 90 adapter telemetry had no Python parent timeout at all.

The exact owner evidence is preserved in
`docs/verification/evidence/2026-08-10-v0.4.0_7-late-stage-pass.md`.

## Implementation

Candidate identity remains `VERSION=0.4.0`; `PLUGIN_REVISION` advances to `8`.

A narrow Python late-containment layer is routed through the existing compatibility entry
point. It does not change shell system-mutation ownership or the adaptive graph.

### Stage 70

The current stability algorithm remains unchanged, including three sequential attempts.
Before attempt 1 and every later attempt, the runner asks the same admission function used
by Stage 60 whether the full cold-candidate execution + termination + cleanup + guard
envelope fits the remaining parent window.

If not, the next attempt is not launched. `stability.json` is persisted with structured
partial evidence and the stage returns timeout to the normal orchestrator path.

### Stage 80

The existing Python extended TCP/QUIC/configured-UDP implementation is retained. Candidate
entry is wrapped by the same admission check against the action's remaining shared Stage-80
window. Capability/input skips remain cheap and unaffected.

An admission rejection persists the protocol result before returning timeout, so Stage 90
can restore with the completed evidence still available.

### Stage 85

The shortlist/replay semantics are not redesigned in `_8`; that would overlap `_33`.
Instead, Stage 85 now has an explicit 120-second parent operation bound, always capped by
the remaining overall search budget.

### Stage 90

Restoration remains outside exhausted search budget when required by the corrective
contract. The Python parent now has a separate 180-second bound. This value is intentionally
larger than the shell lifecycle's internally bounded transaction, which can contain two
45-second start attempts plus stop/normalization and cleanup work. A short parent bound
would recreate the earlier invalid `INCOMPLETE` failure mode by killing a correct native
service action in flight.

## Regression

`scripts/test-strategy-lab-late-stage-containment.sh` covers:

- Stage-85 parent timeout propagation;
- separate Stage-90 restoration parent bound;
- candidate envelope admission/rejection;
- Stage-80 rejection before candidate launch;
- structured partial persistence.

It is included in `scripts/test-strategy-lab-python-search-extended.sh`, so the existing
Python migration continuity gate executes it together with the full search/extended and
final-result regressions.

## Boundary after source qualification

If CI/FreeBSD qualification succeeds, `_32` is source-complete but remains owner-live
pending on the `v0.4.0_8` testing prerelease. `_33` is next and retains discovery,
fail-fast 3/3, finalist deep validation and related search-quality changes.
