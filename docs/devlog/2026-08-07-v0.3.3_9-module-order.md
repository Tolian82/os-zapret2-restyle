# 2026-08-07 — v0.3.3_9 Strategy Lab module-order cleanup

## Scope

Patch 4 of the third-audit corrective series implements `SL3-003` and `SL3-006`.

## Root cause

The main worker sourced multiple modules that defined the same shell functions. Later modules silently replaced earlier implementations, so source order selected behavior. The confirmed user-visible defect was circular eligibility: `worker_result.sh` used the TLS 1.3 circular subset, while the later `worker_state_serialization.sh` replacement used the general multi-protocol shortlist. Additional obsolete stage-orchestration hooks and a TLS-only shortlist implementation remained in earlier modules despite the explicit-stage architecture.

## Implementation

- Removed `worker_state_serialization.sh` and removed it from the main worker source list.
- Migrated its useful serialized persistence behavior to canonical owners using `strategy_lab_state_transform()` on the main-worker path.
- Kept standalone atomic fallbacks only where focused runner tests intentionally load a module without `state.sh`.
- Kept one circular-eligibility implementation in `worker_result.sh`; it persists `circular_count/circular_items` semantics and requires the TLS 1.3 eligible subset.
- Kept one unified shortlist implementation in `profile.sh`; removed the old TLS-only implementation from `stability.sh`.
- Removed obsolete `strategy_lab_skip_unfinished()` hooks from expansion/stability and removed obsolete `strategy_lab_skip_remaining()` hooks from expansion/stability/extended/QUIC/UDP.
- Added `test-strategy-lab-module-namespace.sh`, which parses the exact modules loaded together by the main worker and rejects duplicate function definitions.
- Expanded `test-strategy-lab-obsolete-surfaces.sh` to reject the removed override module, hooks, duplicate shortlist owner, and duplicate circular-eligibility owner.
- Updated `STRATEGY_LAB_OBSOLETE_SURFACES.md` to define canonical module ownership as an active architecture contract.

## Key regression

The existing unified-shortlist test builds an Extended result with five general items (`tls13,tls12,http,quic,udp`) and only three TLS 1.3 circular items. Circular eligibility must persist candidate count `3`, remain eligible, and build circular runtime from only the three TLS 1.3 entries.
