# v0.3.3_15 — Strategy Lab stage-50 family timeout ownership

Date: 2026-08-07
Scope: one live-proven stage-50 defect plus documentation of separately confirmed backlog defects.

## Live trigger

Owner-assisted Scenario 1 on installed `v0.3.3_14`, job `job.mCqg7Y`, advanced through
stage 40 successfully. The DNS log contained `NOERROR` and two A records, the clean TLS
1.3 baseline timed out as expected for a blocked target, and stage 50 then failed before
any family completed.

The worker log reported:

```text
/usr/local/opnsense/scripts/OPNsense/Zapret/strategy_lab_family_runner.sh: STRATEGY_LAB_TIMEOUT_BIN: parameter not set
```

The candidate summary remained `total:7, completed:0`.

## Root cause

`strategy_lab_family_runner.sh` executes with `set -eu` and sources only `common.sh`,
`result.sh`, and `family.sh`. The family module invokes `${STRATEGY_LAB_TIMEOUT_BIN}` but
`_14` does not define that variable in any module loaded by the runner. The shell exits on
the first expansion because `set -u` is active.

## Correction

- `family.sh` now owns `STRATEGY_LAB_TIMEOUT_BIN` with default `/usr/bin/timeout`.
- A focused regression invokes the production family runner with
  `STRATEGY_LAB_TIMEOUT_BIN` explicitly absent from the caller environment and requires
  all seven fixture families to complete under `set -u`.
- `PLUGIN_REVISION` advances from 14 to 15.

## Deferred confirmed defects

The same live run and source inspection confirmed defects that are intentionally not
mixed into this patch:

- baseline `target_type:"A"` corruption from shell-global `_strategy_lab_type` reuse;
- new job id displayed with stale previous `ERROR` state immediately after Run;
- GUI progress remaining at 0% while backend `status.json` advances through later stages;
- terminal/latest-job reload presentation violating the intended idle-after-terminal contract;
- DNS answer parsing that can accept `QUESTION SECTION` as if it proved an answer;
- DNS failure diagnostics flattening distinct failures to generic code 1.

These remain tracked in `docs/PROJECT_STATE.md` and the `_14` live evidence record.

## Verification boundary

This source patch does not claim Scenario 1 PASS. CI and a FreeBSD 15 package build must
succeed, then the installable testing candidate `v0.3.3_15` must be owner-tested on the
same blocked-domain scenario. The required live result is that stage 50 enters actual
family execution while the already proven stage-40 DNS and stage-90 restoration sub-gates
remain PASS.
