# Development log — v0.3.0 Zapret2 Service

Date: 2026-08-03

## Completed implementation

The Milestone 8 Zapret2 Service work package was completed through a sequence of
focused package revisions and live OPNsense tests.

### Release discovery and GUI launch

- Added `setup.sh show` and exact `setup.sh install VERSION` support.
- Added a validated stable-release cache with a one-hour freshness window.
- Serialized cache refresh with `lockf` and used atomic replacement.
- Added stale-cache fallback for temporary GitHub failures.
- Added dedicated one-parameter configd action `zapret setup_install`.
- Removed the configd `Parameter mismatch` caused by sending two parameters to one
  `%s` placeholder.
- Added the native Settings-page Zapret2 Service block and asynchronous status polling.

### Configd and package lifecycle

- Preserved the existing configd watcher and replaced only its worker when new actions
  were installed.
- Kept configd and the Web GUI healthy through package replacement.
- Preserved Started state through ordinary upgrades, `pkg add -f`, and
  `pkg install -f`.
- Preserved Stopped state without promoting it.
- Verified replacement dvtws2 and supervisor PIDs while the configd watcher PID stayed
  unchanged.

### Cold-start firewall ordering

A reboot test exposed that dvtws2 attempted to open its DIVERT4 socket before
`ipdivert` and `ipfw` were loaded. The lifecycle was corrected to prepare firewall
prerequisites before launcher startup.

Live verification after reboot confirmed:

- automatic `ipdivert` and `ipfw` loading;
- rule 19000 installation;
- dvtws2 and supervisor startup;
- execution state `13|13|ready|ok`;
- no manual `kldload` or service manipulation.

### Transactional upstream release activation

The first v1.0.4 → v1.0.3 GUI downgrade compiled successfully but failed after dvtws2
dropped to UID/GID 65534. Git checkout had recreated required Lua files as
`0640 root:wheel`, making them inaccessible to the runtime.

The managed release path was corrected to:

- impose `umask 022`;
- normalize Lua/blob files to `0644`;
- normalize runtime directories and executables to `0755`;
- keep an atomic active-release marker separate from candidate Git HEAD;
- preserve the previous Git commit and compiled binaries;
- restore the complete previous service state when candidate activation fails.

### Final live matrix

1. Stopped v1.0.3 → GUI Apply v1.0.4:
   - result `Stopped v1.0.4`;
   - Git tag and active marker both v1.0.4;
   - Lua files `0644`.
2. GUI Start:
   - service reached Started successfully.
3. Started v1.0.4 → GUI Apply v1.0.3:
   - result `Started v1.0.3`;
   - setup `ready`, busy `0`;
   - Git tag and active marker both v1.0.3;
   - Lua files remained `0644`;
   - no reboot or manual service restart.
4. Package replacement while Started:
   - replacement dvtws2 and supervisor PIDs;
   - service already Started when pkg completed.
5. Package replacement while Stopped:
   - no runtime processes or plugin ipfw rules;
   - service remained Stopped.

The project owner accepted the Zapret2 Service construction as working and authorized
publication of `v0.3.0`.

