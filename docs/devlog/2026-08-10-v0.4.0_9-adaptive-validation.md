# 2026-08-10 — v0.4.0_9 adaptive validation

## Input evidence

`v0.4.0_8` owner testing against `telegram.org` completed both Standard and Extended
pipelines without the Stage-50/60/late-stage timeouts seen earlier. Both runs checked all
16 Stage-60 graph candidates, reached Stage 85 and Stage 90, and ended truthfully as
`NO_CANDIDATE` with successful restoration. This closes the live `_32` boundary and moves
the next source cycle to search-quality validation rather than further timeout widening.

## Implementation choice

The current discovery request already used a real GET with a 64-KiB range. `_33` therefore
uses the least disruptive lightweight split: keep the proven three-second network deadline
but reduce discovery/stability body demand to 4 KiB. This avoids introducing an unmeasured
shorter latency cutoff while still separating mass discovery from final depth evidence.

Stability remains fresh-connection 3/3. The implementation now exits a candidate as soon
as one failed attempt makes 3/3 mathematically impossible and records the unused attempts.

Final publication validation moves from three redundant exact profile replays to one cold
exact-profile replay after the separate 3/3 stability gate. HTTP/TLS finalists request up
to 64 KiB and target at least 16 KiB of received body. Short successful resources are
explicitly `inconclusive` for byte depth, while network/protocol/interception/HTTP failures
remain `fail`.

## Containment

The `_8` timeout hierarchy is retained. Finalist replay has a 15-second child allowance and
uses the same execution + termination + cleanup admission formula before launch. Stage 85
continues to be capped by remaining overall search budget. A proactive Stage-85 timeout is
preserved as status 124 through the stage adapter so restoration/finalization semantics
remain truthful.

## Runtime boundary

Cold isolated dvtws2 remains the correctness reference. No warm pool, warm bucket,
parallel candidate probing or experimental dispatcher behavior is enabled by this patch.

## Verification

A focused Python 3.13 regression covers probe tiers, fail-fast execution, depth
classification and shortlist compatibility. The existing search/extended continuity gate
runs it on Linux and FreeBSD 15, and the canonical corrective matrix discovers it by name.
