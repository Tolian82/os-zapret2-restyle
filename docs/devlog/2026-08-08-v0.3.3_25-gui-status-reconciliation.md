## Root-cause reconciliation

The automated start path runs inside a launcher `lockf` transaction on FD 9. Its
`daemon(8)` invocation did not close FD 9 before starting the long-lived lifecycle worker.
The private circular launcher already had the required `9>&-` isolation.

The automated background worker could therefore inherit the launcher lock. Concurrent
status requests use the same nonblocking launcher lock; while it remained inherited they
could fail before emitting a usable job snapshot, allowing configd/PHP to return an empty
status payload for an otherwise active job.

Patch 8 closes FD 9 on the automated daemon invocation.

## GUI/API reconciliation

`StrategyLabController` now identifies empty or invalid configd output as a transient
transport/read failure. AJAX failures use the same transient marker.

Diagnostics now:

- validates job snapshots by job ID and persisted job state;
- renders visible state only from `data.state`, never from transport `data.status`;
- preserves the last valid state/progress when a transient status read occurs;
- retries transient polling with localized RU/EN messaging;
- renders accepted starts immediately as queued Stage 00;
- uses persisted Python `progress.percent` as the live source of truth;
- retries transient active-job discovery on reload while preserving explicit idle behavior;
- keeps private circular presentation stable across transient/busy status reads.
