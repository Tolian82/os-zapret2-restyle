# v0.3.3_16 — FreeBSD temporary candidate daemon startup

Date: 2026-08-07
Scope: one live-proven Strategy Lab stage-50 runtime defect.

## Live trigger

Testing prerelease `_15`, job `job.6eZM24`, again passed stages 00–40, failed stage 50
with `Temporary candidate runtime failed internally.`, restored the original Zapret2
service successfully at stage 90, and ended with stage 99 ERROR. The new job also
reconfirmed the separately tracked stale GUI `ERROR` and 0%-until-terminal progress
defects.

Evidence:
`docs/verification/evidence/2026-08-07-v0.3.3_15-scenario-01-stage50-freebsd-daemon-supervisor.md`.

## Root cause

`strategy_lab_candidate_start()` invoked FreeBSD `daemon(8)` synchronously with a child
pidfile and output file. Under FreeBSD semantics those options create a resident monitor
that waits while the dvtws2 child is alive. The readiness checks were therefore placed
after a command that intentionally does not return while the candidate is healthy.

The existing Linux regression used a fake daemon that spawned dvtws2 and returned
immediately, so it did not model the FreeBSD supervisor contract.

## Correction

- launch the `daemon(8)` monitor asynchronously;
- keep the existing child-pidfile ownership, dvtws2 identity, divert-socket, clean-log,
  stop, and residue checks unchanged;
- change the candidate-runtime fixture so its fake daemon remains resident until the
  dvtws2 child exits;
- bound the regression with an outer test timeout so a future reintroduction of the
  synchronous-start bug fails instead of hanging CI;
- advance package revision to `_16`;
- advance project state and live matrix to the `_15` failure / `_16` retest boundary.

## Explicit exclusions

This patch does not fix the already documented baseline target-type corruption, stale GUI
error, stuck GUI progress, terminal-result reload behavior, permissive DNS answer parsing,
or flattened DNS failure diagnostics.

## Verification gate

The production candidate-runtime regression must succeed with a resident supervisor model,
the mandatory Strategy Lab corrective matrix and full CI must pass, and a FreeBSD 15 amd64
package must build before squash merge and testing-prerelease publication. Live Scenario 1
then remains owner-gated on `_16`.
