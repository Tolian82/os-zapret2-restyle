# 2026-08-09 — v0.4.0_4 adaptive-search `_30`

## Trigger

`_29` established immutable `CandidateSpec` and job-scoped `ResourceInventory` evidence,
but Stage 50/60 still selected rows from fixed TSV catalogs and final profiles still
required `-d10`. `_30` was the approved boundary for replacing that policy with native
Zapret2 graph semantics and golden reachability regressions.

## Implementation

Added `strategy_lab_py/search_graph.py`. It builds and validates a deterministic DAG with
seven reconnaissance seeds and sixteen expansion nodes. Parent edges express meaningful
technique progression; Stage-50 results affect deterministic priority without filtering
the node set. A stable hash identifies the complete graph.

The expansion corpus covers BLOB-free multisplit/multidisorder/hostfakesplit branches,
Zapret2 built-in fake branches, inline syndata BLOBs and one installed-external
`fake_tls_7.bin` branch. It contains the agreed built-in and owner-proven `-d8` golden
strategies verbatim. No installed-resource enumeration is crossed with technique
parameters.

Planning checks the immutable job inventory semantically. Missing core Lua or external
BLOB dependencies produce per-node skip reasons. Missing `fake_tls_7.bin` skips only the
external golden candidate; unrelated installed files remain inventory evidence and never
become graph nodes.

`family.py` and `search.py` now generate strategy/spec files from graph nodes, pass the
serialized spec through the candidate runner, attach graph evidence to every result and
persist both reconnaissance and expansion plans. `candidate.py` restores and validates
the exact spec before runtime preparation. Stability carries the same spec rather than
reconstructing a fixed-range candidate.

`result.py` now accepts zero or one valid candidate-defined input/output range. It copies
that data into the user-ready profile without injecting `-d10`. Existing fixed non-graph
catalogs explicitly declare their unchanged `-d10` value.

## Regression boundary

The new focused test proves graph identity/acyclicity, 7/16 node counts, all four resource
classes, `-d8`/`-d10`/absent ranges, exact golden text and rendering, reachability with
empty or unrelated Stage-50 evidence, semantic external-resource skipping, absence of
`wireguard` Cartesian candidates, exact `CandidateSpec` handoff and persisted Stage-60
graph evidence.

Existing family, search/stability/extended and final-result regressions were moved from
test-only flat catalogs to the native graph where they exercise active policy. Linux and
FreeBSD 15 CI both run the focused test; required-file and package inspection contracts
include `search_graph.py`.

## Scope retained for later cycles

`_30` keeps the current cold-per-candidate runtime, current early-stop count, current
endpoint resolution behavior, timeout hierarchy and 3/3/deep-validation behavior. It
does not implement pass/fail-driven neighbor scheduling. Those changes remain split
across `_31`–`_33`, and warm-runtime selection remains evidence-gated by the A/B/C
experiment plan.

`VERSION` remains `0.4.0`; `PLUGIN_REVISION` advances once from `3` to `4`. Latest
published and owner-tested testing candidate remains `v0.4.0_2`; `0.4.0_4` is a source
candidate until separately authorized publication/live evidence says otherwise.
