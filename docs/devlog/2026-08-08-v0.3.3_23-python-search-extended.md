## Implementation

Added `strategy_lab_py/search.py` as the Stage-60/70 owner. Expansion reads accepted Stage-50 families, filters the existing expansion catalog, runs candidates serially with bounded timeout/cancellation, persists the existing result schema incrementally, and preserves the old early-stop reasons. Stability combines passing family/expansion sources, de-duplicates by strategy, ranks deterministically by line count, character count and id, runs the configured replay attempts in sequential fresh-connection mode, and preserves stable/unstable aggregation and early-stop behavior.

Added `strategy_lab_py/extended.py` as the Stage-80 owner. It preserves independent TLS 1.2 and HTTP first-working searches, QUIC capability skip semantics and first-working search, and configured generic-UDP input/skip/search semantics.

Extended `strategy_lab_py/request.py` with exact selected-endpoint QUIC execution and generic-UDP payload/response execution while retaining distinct return-code/stdout/stderr/timeout/termination/duration evidence.

Generalized `strategy_lab_py/candidate.py` instead of creating protocol-specific candidate state machines. TLS 1.3, TLS 1.2, HTTP, QUIC and generic UDP share one Python runtime/readiness/interception/cleanup owner. Protocol-specific transport/port/L7 details are passed to the narrow shell system adapter; candidate success still requires request success, selected-endpoint identity and IPFW packet-counter growth.

`strategy_lab_candidate_adapter.sh` now supports explicit protocol preparation and firewall rules while remaining limited to audited FreeBSD mutations/observations. Production expansion, stability, extended-TCP, QUIC and UDP runners are thin Python launchers. QUIC/UDP candidate compatibility runners only set protocol environment and delegate to the unified Python candidate runner.

Legacy shell expansion/stability/extended modules remain packaged for compatibility until Patch 7 retires obsolete orchestration surfaces; they are no longer production owners.
